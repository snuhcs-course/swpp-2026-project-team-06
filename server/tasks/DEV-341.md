## DEV-341 Make producer photo add and load fast with display-size previews instead of full PNG

- 이슈: [DEV-341](https://linear.app/sswp6/issue/DEV-341) · 앱 쪽 기록 `apps/producer/tasks/DEV-341.md` · 스펙 `docs/spec/tasks/DEV-341.md`
- 브랜치: `jangjinuite/dev-341-light-photos`
- 기능·인수 조건: FEAT-03/04 · AC-SRC-5(다른 농가 자료 접근 금지)·AC-SRC-6(사진 사본)·AC-SRC-11(판매페이지 작업 공간). 근거 `docs/spec/source-integration.md` 상품사진 줄
- 상태: PR #639 리뷰 중
- 위험 등급: 일반(고위험 경로를 바꾸지 않는다. 모델·마이그레이션 없음)

### 왜
생산자 피드백: 사진을 넣고 여는 것이 느리다. 로컬 측정(아래)에서
- 새 상품 화면이 상품사진마다 원본 해상도 무손실 PNG(12MP → 약 20MB)를 `no-store`로 받는다. 대표사진·첨부 칸이 같은 PNG를 따로 받아 사진 2장에 60MB, 10Mbps에서 대표사진이 50초 뒤에 보였다.
- 판매페이지 작업 공간 업로드는 상품 잠금 안에서 원본(최대 20MB)을 JPEG로 변환해, 변환하는 동안 같은 상품의 다른 요청이 기다린다.

### 결정 사항
- 11/17 표시 사본은 두 가지: `display`(긴 변 1600px 이하 JPEG q82 progressive, DEV-328 `public_photo`와 같은 변환) · `thumb`(짧은 변 480px·긴 변 1600px 이하). 첨부 칸은 정사각형 `cover`(약 170 CSS px)라 3x에 짧은 변 약 510px가 필요해 480px로 둔다. 비율은 유지하고 자르지 않는다.
- 11/17 원본 PNG는 그대로 분석·공개 반영의 원천이다. `variant` 없는 요청은 지금처럼 PNG·`no-store`. 가림 전(`sanitized=false`) 이미지의 미리보기는 만들지 않는다(400).
- 11/17 저장: 마이그레이션 없이 `photos.variant_key(key, variant)`(원본 키 prefix + sha256(`key:variant:버전`) 앞 32자). 상품사진은 업로드 때 한 번 디코딩해 PNG·display·thumb를 함께 쓴다. 없으면(DEV-341 이전 업로드, 문서 페이지) 첫 요청 때 PNG에서 만들어 저장한다. 로컬 저장은 임시 파일 + rename으로 반쯤 쓴 파일을 읽지 않게 한다.
- 11/17 cleanup: 살아 있는 페이지의 미리보기 키도 `used`, 자료를 지울 때 함께 지운다.
- 11/17 캐시: 앱이 주소에 `v=<revision>.<sanitizationVersion>`을 넣고, 현재와 같으면 `private, max-age=86400`, 아니면 `private, no-cache`. 둘 다 ETag·`Vary: Authorization`(같은 브라우저 다른 로그인은 재검증), 304는 소유 검사 뒤에만. `SourceRequestMiddleware`는 라우트가 붙인 값이 이 두 값과 정확히 같을 때만 그대로 두고 나머지는 계속 `no-store`(`caching.PREVIEW_CACHE_VALUES`).
- 11/17 작업 사진 미리보기(`GET product-workspaces/{pid}/photos/{id}`): DEV-328에서 `no-store`로 남겼지만, 편집 화면을 열 때마다 다시 받는 비용을 없애려고 `private, max-age=86400` + ETag + `Vary: Authorization`으로 바꾼다(기존 테스트 두 곳의 기대값을 새 계약으로 고침).
- 11/17 작업 사진 업로드: 잠금 없이 소유·작업 공간을 확인 → `db.rollback()`으로 읽기 트랜잭션을 닫음 → JPEG 변환·저장 → `workspace.owned`(advisory lock + FOR UPDATE)로 다시 확인하고 행만 넣는다. 잠금 뒤 확인이 실패하면 저장한 파일은 고아 정리가 지운다. 앱이 1600px로 줄여 보내므로 서버 변환도 짧다.
- 11/17 공개 반영 `copy_photo`는 `page_variant(display)`로 미리보기 바이트를 새 키에 복사한다(같은 변환이라 결과 동일, 12MP PNG 재디코딩 없음).
