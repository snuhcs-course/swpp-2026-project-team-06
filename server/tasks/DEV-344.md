## DEV-344 Let sold-out products raise their sales limit (resume check only when resuming)

### 왜
생산자 피드백(11/16): "품절된 상품에 물량을 추가하고 싶은데 추가가 안 된다." `update_sales_settings`가 판매 중지가 아닌 승인 상품을 저장할 때마다 재개 가능 검사(현재·미래 기간에 남은 박스와 kg)를 해서, 품절 상품은 판매 한도를 올리거나 주문당 상한만 바꿔도 409 `NOT_RESUMABLE`로 막혔다. 스펙은 "재개 시" 검사이고 Mock(`packages/api/src/mock/catalog.ts`)도 중지→재개일 때만 검사한다. DEV-4부터 서버만 달랐고 이 경우를 다루는 테스트가 없었다.

### 범위 (수정 허용 경로)
- `server/app/catalog/service.py`(`update_sales_settings` 재개 검사 조건·승인량 초과 문구)
- `server/tests/test_catalog.py`
- `server/tasks/DEV-344.md`(이 파일)

### 비범위 (건드리지 않음)
- 생산자 화면 안내(품절 안내, 판매 설정·기간 화면 오류 위치, 박스·한도 순서 안내) — 시안 확인 뒤 후속 이슈
- `put_stages`(박스 수 저장)와 kg 품절 판정 — 그대로
- Mock — 이미 스펙대로(재개 때만 검사, 같은 문구)

### 결정 사항
- 11/16 재개 검사는 저장 전 `sales_paused`가 true이고 요청이 false일 때만 한다. 불변식(사용량 ≤ 한도 ≤ 승인량)은 그대로 검사한다. 그래서 품절 상품은 한도를 먼저 올리든 박스를 먼저 늘리든 어느 순서로도 회복한다.
- 11/16 승인량 초과 문구를 Mock과 같게 "승인 물량을 넘어요. 물량 추가를 신청해 주세요."로 바꾼다(신청으로 안내).
