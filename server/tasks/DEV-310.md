## DEV-310 Guard the purge command against a mistyped keep id

- 이슈: [DEV-310](https://linear.app/sswp6/issue/DEV-310) (상위 DEV-302 UAT 준비, 선행 DEV-304 #574)
- 브랜치: `jinumeral/dev-310-purge-expect-farm-guard`
- 기능·인수 조건: 운영 도구(제품 동작 변경 없음). 선례 DEV-304 `app.admin.purge_except`
- 상태: 진행 중
- 위험 등급: 고위험(`server/app/admin/**`)

### 왜 (사고 기록)
11/11 운영에서 사람이 `python -m app.admin.purge_except --keep … --keep … --commit`을 실행했다. `--keep` ID 하나가 오타였고, 남아야 할 농가 `f-a6e6e175d1`이 함께 지워졌다. 실행 전에 백업 스냅샷을 만들지 않아 복구하지 못했다. 같은 실행 중 터미널 자동 고침으로 `--`가 `—`(em dash)로 바뀌어 다시 입력하는 일도 있었다. UAT 뒤에 같은 명령을 다시 돌리므로 그 전에 막는다.

### 목표
`--keep` 오타나 백업 누락이 있으면 `--commit`이 아무것도 지우지 않고 거부한다. 사람은 미리보기가 출력한 명령 줄을 그대로 복사해 실행한다.

### 결정 사항
- 11/11 `--commit`에는 `--expect-farm <farmId>`가 하나 이상 필요하다. 그 집합이 `--keep` 생산자가 가진 농가 집합과 **정확히** 같아야 한다. 비교는 `--keep` 검사·표 잠금 뒤, 지우기 전에 한다(잠근 뒤라 그사이 농가 주인이 바뀌지 않는다). 없거나 다르면 `PurgeRefused`로 거부하고 두 집합(남는 농가는 이름과 생산자 ID까지)과 차이를 출력한다.
- 11/11 `--expect-farm`은 미리보기에서도 받는다(같은 검사, 필수 아님).
- 11/11 `--commit`에는 `--backup-done`도 필요하다. 없으면 Railway → Postgres → Backups에서 수동 스냅샷을 만들고 끝날 때까지 기다리라고 안내하고 거부한다. 백업이 실제로 있는지는 서버가 확인할 수 없다(사람의 확인 표시).
- 11/11 플래그 검사는 `parse`가 아니라 `purge_in`에서 한다. 남는 농가 집합을 DB에서 읽어야 두 집합을 보여 줄 수 있고, `purge()`를 직접 부르는 경로도 같은 검사를 받는다. 여러 문제(집합 불일치·백업 누락)는 한 번에 모두 보여 준다.
- 11/11 미리보기는 '지워질 농가'(ID·이름·생산자 ID)도 보여 준다. 커밋 줄의 `--expect-farm`은 미리보기의 `--keep`에서 만들어지므로, 미리보기 단계에서 이미 `--keep`이 틀렸다면 복사한 줄도 통과한다. 그 경우는 사람이 이름을 보고 잡아야 하고, 11/11처럼 남아야 할 농가가 빠지는 경우는 '남을 농가' 목록보다 '지워질 농가' 목록에서 눈에 띈다(scan-before-commit 1회차 지적).
- 11/11 미리보기 출력 끝에 남을 농가(ID·이름·생산자 ID)와 그대로 복사할 커밋 명령 한 줄을 출력한다: `railway ssh --service farmclub-api -- .venv/bin/python -m app.admin.purge_except --keep … --expect-farm … --backup-done --commit`. 값은 `shlex.join`으로 감싼다. 운영 runbook이 `railway ssh`로 실행하므로 그 형태 그대로 낸다(로컬 미리보기에서 복사해도 운영에 로컬 ID가 없어 거부된다).
- 11/11 엄격한 파서는 그대로 두고(모르는 인자 거부), `—`(em dash)·`–`(en dash)가 들어간 인자는 '자동 고침으로 바뀐 대시' 안내와 함께 거부한다.
- 11/11 `--commit` 감사 이벤트 `request_summary`에 `expectFarms`를 더한다(실행자가 확인한 남길 농가).

### 운영 실행 runbook (사람이 함, UAT 뒤 정리)
1. **미리보기**(트래픽이 적은 시간에): `railway ssh --service farmclub-api -- .venv/bin/python -m app.admin.purge_except --keep <userId> --keep <userId> --expect-farm <farmId> --expect-farm <farmId>`. 실행 전에 PM이 남길 농가 ID를 따로 적어 두고 미리보기에도 `--expect-farm`으로 넣는다(`--keep`이 틀리면 미리보기부터 거부). 출력의 '남을 농가'와도 대조한다. '지워질 농가'에 남아야 할 농가가 있거나 '남을 농가' 이름이 하나라도 다르면 멈춘다.
2. **백업**: Railway 대시보드 → Postgres 서비스 → Backups → 수동 스냅샷을 만들고 완료될 때까지 기다린다.
3. **실행**: 미리보기 마지막 줄(`… --expect-farm … --backup-done --commit`)을 고치지 말고 그대로 복사해 실행한다. 손으로 다시 치지 않는다(오타·대시 자동 고침).
4. **확인**: `curl -s https://farmclub-api-production.up.railway.app/health`, `curl -s https://farmclub-api-production.up.railway.app/api/farms`(남긴 농가만), 관리자 웹 사용자 목록.
