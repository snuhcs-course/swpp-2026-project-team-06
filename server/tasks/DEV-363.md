### 결정 사항
- 11/18 **PM 결정**: 로그인 아이디는 이메일이 아니라 아이디(username). 비밀번호 찾기는 이메일 없이 로그인 화면의 ‘비밀번호를 잊었다면 farmclub에 문의해 주세요’ + 운영자가 관리자 웹에서 임시 비밀번호 발급 → 그 비밀번호로 로그인하면 바로 바꾸게 한다. 로그인한 사용자는 설정에서 비밀번호를 바꾼다. 두 앱 모두. 카카오 계정과 자동 병합하지 않는다. DEV-198의 ‘아이디·비밀번호 로그인은 만들지 않는다’를 뒤집는다(스펙 이력에 적음).
- 11/18 **PM 결정**: 공개 가입 없음, 운영자가 계정 생성(위 설계 이력). 첫 로그인 순서: ① 임시 비밀번호 → 강제 변경 ② 카카오 가입과 같은 필수 동의(소비자 SCR-06 약관·개인정보·만 14세, 생산자 `/consent` 약관·개인정보) ③ 평소 흐름(생산자는 SCR-20). 동의 전에는 계정을 쓸 수 없다. 생산자 승인 전 화면(SCR-21)에 ‘비밀번호 변경’ 링크(PM이 권고 수락).
- 11/18 운영자 계정 만들기 `POST /admin/id-accounts`(`Idempotency-Key` 필수, `{app, username, nickname?, phone?}`): 소비자는 닉네임 2~12자 필수·휴대폰 선택(비면 첫 로그인 SCR-06이 받는다 — 심사자는 휴대폰을 줄 수 없을 수 있다), 생산자는 이름(2~20자, 비면 ‘농가 사용자’, 가입 신청의 대표자 이름으로 바뀜). 서버가 임시 비밀번호(12자)를 만들고 해시만 저장, `must_change_password=true`. 소비자는 카카오 가입처럼 farmclub 문의 대화방을 연다. **감사는 `run_manager_action`**(`id_account.create`)으로 하되, 그 함수가 응답을 멱등 기록(`idempotency_records.response`)에 저장하므로 `run`의 결과에는 비밀번호를 넣지 않고 이번 요청에서 실제로 만든 경우에만(`issueId`가 맞을 때) 응답에 붙인다. 같은 키 재시도는 계정은 그대로·비밀번호 `null`(관리자 웹이 ‘임시 비밀번호’로 다시 발급하라고 안내). 목록 `GET /admin/id-accounts?app=&q=&limit=`(임시 비밀번호 사용 중·필수 동의 여부·농가 상태).
- 11/18 계정 관문(`core/security.get_current_user`, 경로·메서드 허용 목록, 거부가 기본): ① `must_change_password` → 내 정보·비밀번호 변경만(403 `PASSWORD_CHANGE_REQUIRED`) ② 아이디 계정이고 지금 버전 필수 동의가 없으면 → 내 정보·동의 조회·저장·`PATCH /me`(온보딩 프로필)·비밀번호 변경·탈퇴만(소비자 403 `ONBOARDING_REQUIRED` — 앱이 SCR-06을 연다, 생산자 403 `CONSENT_REQUIRED` — 앱이 `/consent`를 연다). 공개 API(`get_optional_user`)는 관문에 걸린 계정을 비로그인으로 본다. 카카오·테스트 계정의 기존 관문은 그대로.
- 11/18 아이디 규칙: 앞뒤 공백을 지우고 ASCII면 소문자로 바꾼 뒤 `^[a-z][a-z0-9]{3,19}$`. 대소문자 구분 없이 같은 아이디(저장값이 소문자라 유일 제약이 곧 대소문자 무시 유일). 예약어(admin, farmclub, support, root, system, operator, manager, kakao, test 등)는 못 쓴다. 켈빈 기호 같은 비ASCII는 소문자로 접지 않는다(다른 아이디로 들어오지 않게).
- 11/18 아이디 유일성은 **(아이디, 역할)** 마다(ADR 0010 계정 분리, 카카오 `(kakao_id, role)`와 같은 꼴). 로그인은 그 앱 역할의 계정만 찾으므로 다른 앱 아이디는 ‘맞지 않아요’로 같게 실패한다.
- 11/18 해시: argon2id, **OWASP 권장 최소값 m=19MiB(19456 KiB)·t=2·p=1**(11/19 scan W1). 해시·검증은 `threading.BoundedSemaphore(4)`로 4개까지만 동시에 돌린다(인증 없는 로그인 폭주가 단일 Railway 프로세스의 메모리를 다 쓰지 않게). 더미 검증도 같은 매개변수·같은 세마포어라 시간 차이가 없고, 더미 해시는 앱이 뜰 때 미리 만든다(lifespan). 로그인은 사용자 ID·해시를 읽은 뒤 **argon2를 돌기 전에 요청 세션을 `rollback`해 DB 연결을 돌려준다**(세마포어를 기다리는 동안 연결 풀을 묶지 않게). 시도 수는 그 전에 따로 짧은 트랜잭션으로 센다. 나중에 매개변수를 바꾸면 로그인 성공 때 `check_needs_rehash`로 다시 해시하는데, 조건부 UPDATE(`password_hash == 읽은 해시`)라 그사이 비밀번호 변경·임시 비밀번호 발급이 있었으면 덮어쓰지 않고, 검증 뒤 해시가 바뀌었으면 그 로그인은 401이다. 해시만 저장, 검증은 argon2 내부 상수 시간 비교, 해시 전에 UTF-8 512바이트 상한.
- 11/18 비밀번호 정책: 8~128자, 공백만은 안 됨, 아이디와 같으면(대소문자 무시) 안 됨, 흔한 비밀번호 목록(약 60개) 안 됨. 조합 규칙은 두지 않는다(NIST SP 800-63B).
- 11/18 평문이 남지 않게: 요청 검증 오류(400, 처리기는 `msg`만 돌려주고 입력값을 돌려주지 않음)에서 비밀번호 칸의 메시지를 고정 문구로 바꾼다(`masking.redact_secret_fields`). 로그인 실패·잠금 응답에는 입력값을 넣지 않는다. 서버에는 Sentry가 없고 요청 본문을 로그로 남기는 곳이 없다. 토큰·임시 비밀번호 응답은 `Cache-Control: no-store`. 운영자 감사·멱등 기록에는 임시 비밀번호가 없다(임시 비밀번호 재발급은 멱등 기록을 쓰지 않고 감사 행만 직접 쓴다). 앱: PostHog는 입력칸을 다 가리고 본문을 녹화하지 않는다. `/password`를 `PRIVATE_PATHS`에 더한다.
- 11/18 로그인 잠금(DB 카운터 `auth_throttles`, 워커가 여럿이어도 같음, 키는 `HMAC-SHA256(JWT_SECRET, 원문)`, 하루 지난 행은 쓸 때 지움, 요청 트랜잭션과 따로 바로 커밋): 아이디(역할+아이디)당 15분 안에 10번 시도하면 15분 잠금 — 시도는 **검증 전에** 행 잠금 안에서 세어(10번째에 잠그고 11번째부터 429) 동시에 보내도 10번을 넘길 수 없고, 성공하면 커밋 뒤 지운다. 429 `RATE_LIMITED` + `Retry-After`(초) + `details.retryAfter`. 잠금 시각은 실제 시각(`throttle._now`, UTC) — `FIXED_NOW`를 쓰는 데모에서도 창이 끝난다.
- 11/18 **PM 결정: IP별 제한 없음, 아이디별 잠금만.** 처음에는 IP당 로그인 실패 상한(15분 50번)과 `CLIENT_IP_HEADER` 설정을 두었으나(uvicorn `--forwarded-allow-ips='*'`라 기본값이면 X-Forwarded-For 맨 왼쪽 값을 클라이언트가 바꿔 우회하거나 남의 IP를 잠글 수 있었다), PM이 IP별 제한을 아예 없앴다. 서버는 클라이언트 IP를 읽지 않고(`client_ip` 삭제, 설정 없음), 헤더를 위조해도 아무 효과가 없다(테스트 `test_AC_01_27_no_per_ip_limit_and_spoofed_forwarded_for_has_no_effect`). 운영 변수 작업도 필요 없다.
- 11/18 토큰 무효화: `users.token_version`(기본 0)을 JWT `ver`로 넣고, 다르면 401. 비밀번호 변경·임시 비밀번호 발급 때 1 올린다. `ver`가 없는 옛 토큰은 0으로 본다(배포해도 기존 로그인 유지). 비밀번호 변경 응답이 새 토큰을 준다. 변경은 사용자 행을 `FOR UPDATE`로 잠그고 최신 값(`populate_existing`)으로 지금 비밀번호를 검증한다.
- 11/18 임시 비밀번호(재발급 `POST /admin/users/{id}/temporary-password`): 서버가 `secrets`로 12자(헷갈리는 글자 0·O·1·l·I 뺀 영문 대소문자·숫자, 정책 통과)를 만들어 한 번만 응답. `must_change_password=true`, 토큰 버전 +1, 그 아이디의 로그인 잠금을 푼다(잠금 해제가 실패해도 이미 바뀐 비밀번호는 응답으로 준다). 감사 `user.temporary_password`(결과 `{status: ISSUED}`).
