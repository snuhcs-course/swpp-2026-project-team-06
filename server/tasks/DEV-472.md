## DEV-472 테스트·심사용 계정의 농가와 상품을 일반 사용자에게 숨김

- 이슈: [DEV-472](https://linear.app/sswp6/issue/DEV-472)
- 브랜치: `nemodleo/dev-472-hide-test-farms-from-public`
- 기능·인수 조건: R-29 / AC-06-10, AC-06-11, AC-07-11, AC-15-15, AC-19-4
- 상태: 리뷰 중

### 목표
원스토어 심사(11/23)가 소비자 앱을 "테스트를 목적으로 등록한 상품은 서비스 불가"로 반려했다. 공개 조건이 농가 승인 상태 하나라서 UAT·심사용으로 승인한 농가가 일반 사용자에게 보였다. 농가를 정지하지 않고, 주인이 테스트 계정인 농가를 테스트 계정에게만 보이게 한다.

### 범위 (수정 허용 경로)

- `server/app/messaging/service.py`, `server/app/messaging/router.py`(농가 확인 줄만)

- 리뷰 반영(PR #827, 고위험): `server/app/orders/service.py`(`create_order`의 농가 확인 한 줄), `server/app/accounts/models.py`·`server/app/admin/users.py`(주석만), `server/app/admin/spec.md`, 루트 `README.md`(심사 농가 절)
- `docs/spec/functional/rules.md`, `FEAT-06`·`FEAT-07`·`FEAT-15`·`FEAT-19`, `docs/spec/screens.md`, `docs/spec/tech-design/README.md`, `docs/wiki/Requirements-and-Specifications.md`

### 결정 사항
- 11/24 테스트 계정 = accounts의 기존 정의(`is_test_account` 또는 `ops_tester`, `test_account_clause`·`account_kind`). 농가 쪽(주인)과 보는 사람 쪽에 같은 정의를 쓴다. 시드 테스트와 운영 검증을 따로 나누지 않는다: 관리자 목록 `kind=test`(AC-23-12)와 테스트 농가 숨기기 주문 검사가 이미 둘을 한 묶음으로 본다.
- 11/24 조건은 `farms.public_farm_clause(db, viewer)` 하나. 목록은 SQL 조건으로, 한 농가는 그 조건으로 다시 조회한다(`public_farm`·`public_farms`·`public_farm_names`). 공개 경로가 쓰던 `get_approved_farm`·`approved_farm_names` 호출은 전부 바꿨고, `approved_farm_names`는 지웠다. `get_approved_farm`은 주문 생성(orders) 한 곳에만 남는다.
- 11/24 시드 선택 로그인(`MOCK_LOGIN_ENABLED`)이 켜진 환경은 거르지 않는다. 데모 시드의 대표 농가 강씨네 귤밭 주인이 시드 테스트 계정이라, 그대로 거르면 pytest 37개와 Playwright 비로그인 둘러보기(`discovery-and-gates` 등)가 깨지고 로컬 데모가 빈다. 운영은 README대로 이 값이 꺼져 있고(심사·UAT 포함), 켜면 시드 계정 선택 로그인이 열리는 상태라 그 자체로 심사 대상이 아니다. 새 설정 변수는 `core/config.py`(고위험)를 바꿔야 해서 쓰지 않았다.
- 11/24 일반 소비자가 전에 팔로우·대화한 테스트 농가는 정지 농가와 같게 처리한다: 팔로우 목록·채팅 목록·소식방 목록·팔로우 소식에서 빠지고, 대화·주문 문의를 열면 404. 주문 목록·주문 상세는 그대로 보인다(orders는 바꾸지 않음).
- 11/24 주문 생성(`POST /api/orders`)은 승인 상태만 본다(orders 고위험이라 그대로). 상품 상세가 404라 앱에서는 닿지 않지만, 상품 ID를 아는 일반 소비자가 API로 직접 주문하면 막지 않는다. 막으려면 `orders/service.py` `create_order`의 `get_approved_farm` 한 줄을 `public_farm(db, farm_id, consumer)`로 바꾸는 후속(고위험)이 필요하다. 결정 필요.
- 11/24 공개 사진 `/api/source-media/{photoId}`는 `<img>` 요청에 인증 헤더가 없어 보는 사람을 모른다. 승인 상태만 보는 `ANY_VIEWER`로 둔다. 사진 ID는 목록에 나오지 않고, 걸러 내면 테스트 계정이 보는 테스트 상품 사진이 깨진다.
- 11/24 공유 페이지 `/s/farms/{id}`는 로그인이 없어 테스트 농가는 누구에게나 404다(크롤러·메신저 미리보기 포함).
- 11/24 `ops_tester`의 뜻이 '테스트 농가 숨기기 주문 검사에서만 테스트'에서 '공개 범위에서도 테스트'로 넓어진다. 생산자에게 켜면 그 농가가 일반 사용자에게서 숨고, 소비자에게 켜면 테스트 농가가 보인다. `admin/spec.md`·`accounts/models.py` 주석은 고위험 경로라 고치지 않고 `farms/spec.md`·screens.md·tech-design에 적었다.
- 11/24 리뷰 반영(PR #827) — 위 결정 중 셋을 바꾼다:
  - 주문 생성도 이번 PR에서 막는다(PM·리뷰 결정). `create_order`가 `public_farm(db, farm_id, consumer)`를 쓰고, 일반 소비자의 숨긴 상품 주문은 없는 상품과 같은 404다. 기존 주문의 입금 안내(`request_deposit`, `get_farm_shared`)·조회는 그대로. 주문 진입은 `POST /api/orders` 하나뿐이다(재주문·장바구니 없음). 이제 `get_approved_farm`을 부르는 곳이 없어 지웠다. 그래서 PR은 고위험이다.
  - 거르지 않는 환경을 `APP_ENV=local`이면서 `MOCK_LOGIN_ENABLED=true`로 좁힌다. 근거: `server/tasks/DEV-305.md` 절차 3이 UAT 동안 운영 `MOCK_LOGIN_ENABLED=true`로 켰다. 그 값만 보면 그런 UAT 기간에 테스트 농가가 다시 보인다. 확인한 `APP_ENV`: pytest `conftest.py`·`make dev`·`scripts/demo.mjs`·`scripts/i3-preorder`는 `local`을 준다. Playwright 서버(`scripts/run-integration.mjs`)와 CI 워크플로는 `APP_ENV`를 주지 않아 설정 기본값 `local`이다. 운영은 README 변수 표대로 `production`.
  - `admin/spec.md`·`accounts/models.py`·`admin/users.py` 주석도 새 뜻으로 고친다(고위험이 됐으므로).
- 11/24 테스트 농가 주인의 `GET`·`PATCH /api/farms/me`는 `shareUrl`을 주지 않는다. 공유 페이지가 누구에게나 404라서다. 스키마는 이미 nullable이고, 생산자 앱은 값이 없으면 설정의 링크 칸과 현황 공유 막대를 숨긴다(승인 전 농가와 같은 처리, 새 문구 없음). '소비자 앱에서 내 농가 보기' 버튼은 남는데, 생산자가 소비자 앱에 테스트 계정으로 로그인하지 않았으면 404다(앱 변경이 필요해 바꾸지 않음, 결정 필요).
- 11/24 홈 `hero.caption`(고정 문구 '강씨네 귤밭 · 하우스 감귤 5kg 보러 가기')은 히어로 상품이 보는 사람에게 공개가 아니면 빈 문자열이다. hero 자체는 내리지 않는다(스키마 그대로). 소비자 앱 코드는 hero를 쓰지 않는다(`apps/consumer/src` 검색).
