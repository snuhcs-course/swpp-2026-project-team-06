### 작업
1. Extend the start schema and server service with the optional order context from step 1.
2. Atomically create/reuse the unique thread and record only a validated order connection.
3. Apply the shared eligibility decision to all affected read/write surfaces and add security, retry, and concurrency regressions.

### 완료 조건
- [ ] A valid owned paid-order start creates/reuses exactly one (farm,consumer) thread and one context link, adds no follow, and returns autoFollowed=false. Reopening a HUMAN thread preserves its mode, version, read markers, and messages.
- [ ] Starting alone creates no message, formal inquiry, escalation, AI call, unread increment, or “needs reply” work item. An empty authorized chat appears once in the consumer private list with the existing empty summary.
- [ ] The first GET messages succeeds for that empty conversation; orders includes the validated linked order summary and inquiries remains empty. GET requests create no data.
- [ ] List, message pages/cursors, read markers, AI-report access, thread-scoped private upload/read, and linked-order summaries use consistent participant/approved-farm/valid-context checks. Keep all response fields and private-data filtering compatible.
- [ ] Unfollowed send requires an explicit currently valid owned paid orderId for that farm, including when another order context is already linked. First text and photo-only sends work; invalid or mismatched orderId is rejected without any write.
- [ ] Unauthenticated, wrong-app, incomplete-onboarding, other-consumer, other-farm, nonexistent, unpaid-order, and unapproved-farm cases return the established 401/403/404 envelopes. Unauthorized order IDs do not reveal whether an order exists.
- [ ] Same key + same valid body replays once; same key + a different valid order body yields 409 IDEMPOTENCY_MISMATCH. Authorization is checked before returning a cached start response, including after farm eligibility changes.
- [ ] Simultaneous starts with the same and different keys, plus a generic-start/order-start race, never produce 500, duplicate threads, context links, or follows. A generic start may follow once by its own contract; order mode never adds a follow. Rollback never leaves a half-created context.
- [ ] Relevant server tests pass, including existing inquiries, attachments, AI/HUMAN race rules, saved sequence ordering, and read-marker monotonicity.
- [ ] 관련 테스트 실제 실행 및 결과 기록
- [ ] 사람 리뷰, main 머지 및 해당 배포 확인
