## DEV-498 Report unexpected server errors to PostHog
- 이슈: [DEV-498](https://linear.app/sswp6/issue/DEV-498)
- 브랜치: `zahra/dev-498-server-errors-posthog`
- 기능·인수 조건: 운영 관측(제품 동작 변경 없음). 관련 ADR 0005, 트래킹 플랜 `$exception`, DEV-496(앱 오류), DEV-100(서버 이벤트 모듈)
- 상태: 작업 중

### 목표
TA 공지(11/26)가 crash report를 요구한다. 앱·웹 오류는 DEV-496으로 PostHog에 가지만, 서버의 예상 못 한 오류(500)는 기록이 없다. 공통 처리기 `_internal_error`가 로그를 남기고 PostHog `$exception` 이벤트를 보내게 한다.

- `docs/spec/tech-design/README.md`(트래킹 플랜), `docs/spec/tech-design/adr/0005-analytics-posthog.md`(한 줄), `docs/spec/tech-design/stack.md`(에러 행), `docs/wiki/Design-Documentation.md`(영문 한 줄)

### 결정 사항
- 11/27 `_internal_error`에서 `logging`으로 traceback을 남긴다(Railway 로그).
- 11/27 전송은 `app/analytics/service.py`의 `report_server_exception`. httpx로 `{host}/i/v0/e/`에 POST, 제한 시간 2초.
- 11/27 속성: `$exception_list`(type, 정리한 value, 스택 프레임의 filename·function·lineno만), `$exception_level=error`, 경로 템플릿(`/api/orders/{order_id}`, 쿼리 없음), HTTP method, `source=server`. distinct_id는 고정 `server`(사용자 ID·이메일·IP 아님). 요청 본문·헤더·쿠키·쿼리 값은 보내지 않는다. 소스 줄·지역 변수도 보내지 않는다.
- 11/27 메시지 정리는 앱 `scrubErrorText`(`packages/analytics/src/privacy.ts`)와 같게 포팅: URL 쿼리 제거, 이메일 `[email]`, 4자리 이상 숫자열 `[number]`, 200자 자르기.
- 11/27 전송은 응답을 보낸 뒤 백그라운드 작업으로 돌고, 실패·시간 초과는 삼키고 로그만 남긴다. 500 응답은 바뀌지 않는다.
- 11/27 키(`POSTHOG_PROJECT_API_KEY`)가 비면 아무것도 하지 않는다(로컬·테스트·CI). 호스트 기본값 `https://us.i.posthog.com`.
