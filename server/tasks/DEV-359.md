## DEV-359 recompress_photos --commit이 운영에서 실패: 단독 실행 시 상품 테이블 모델이 등록되지 않음

- 이슈: [DEV-359](https://linear.app/sswp6/issue/DEV-359) · GitHub #656 (원 작업 DEV-328)
- 브랜치: `jangjinuite/dev-359-recompress-models`
- 기능·인수 조건: FEAT-03/04 · AC-SRC-6(공개 사진). 동작·규칙은 바꾸지 않는다(DEV-328 변환 명령의 실행 버그 수정)
- 상태: 진행 중
- 위험 등급: 일반(고위험 경로를 바꾸지 않는다. `models.py`는 불러오기만 한다)

### 왜
운영에서 `python -m app.source_analysis.recompress_photos --backup-done --commit`이 `session.commit()`에서
`sqlalchemy.exc.NoReferencedTableError: Foreign key associated with column 'source_public_photos.product_id' could not find table 'products'`로 실패했다.
명령은 단독 프로세스로 돌고 `app.source_analysis.models`만 불러온다. 그래서 FK 대상 테이블(catalog `products` 등)이 `Base.metadata`에 없고,
commit(flush)이 테이블 순서를 정하려고 FK를 풀 때 실패한다. 시험 실행(`--commit` 없음)은 flush가 없어 통과했다.
기존 테스트는 conftest·다른 테스트가 모든 모델을 먼저 불러와서 이 문제를 잡지 못했다.

### 목표
변환 명령이 단독 프로세스에서도 모든 모델을 등록해 `--commit`이 끝까지 돈다. 이 문제를 새 인터프리터에서 확인하는 회귀 테스트를 둔다.

### 결정 사항
- 11/17 **고치는 방법**: `migrations/env.py`와 같은 목록(accounts, admin, ai, analytics, catalog, core, farms, media, messaging, orders, source_analysis)의 `models`를 `recompress_photos.py`에서 `# noqa: F401`로 불러온다. 공용 "모든 모델 등록" 모듈을 새로 만드는 것은 `env.py`·`tests/migrations_models.py`까지 바꾸는 리팩터링이라 이 수정 범위를 넘는다(후속 후보).
- 11/17 **회귀 테스트**: `sys.executable -c`로 새 인터프리터를 띄워 `recompress_photos`만 불러온 뒤 `configure_mappers()`, `PublicPhoto.product_id` FK 대상이 `products`인지, `Base.metadata`의 모든 FK가 풀리는지 확인한다. DB에 연결하지 않는다(파일의 conftest autouse 시드는 그대로 돈다). 같은 프로세스에서는 이미 모든 모델이 올라와 있어 재현되지 않으므로 subprocess가 필요하다.
