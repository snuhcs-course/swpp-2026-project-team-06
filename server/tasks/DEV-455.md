### 결정 사항
- 기존 ManagerEvent 감사 테이블에 상태·결제/환불 시각 스냅샷과 작업 토큰을 기록한다. 배송지 원본은 복제하지 않는다. 새 DB 필드·마이그레이션 없이 구현한다.
- 주문별 마지막 작업 하나만 가능하다. 새 생산자 작업은 이전 토큰을 supersede하고, 실행 취소한 토큰도 다시 살아나지 않는다. 후속 주문/송장/결제/환불 상태가 다르면 거부한다.
- 상품→주문 순서로 잠그고 복구할 추가 물량은 옵션·상품 한도를 확인한다. 입금 대기 복구는 원래 기한/신고 시각과 농가 입금 코드 충돌을 확인하며, 코드 할당과 같은 advisory lock을 쓴다.
- 입금 확인 취소는 Payment 기록을 REVERSED로 보존하고 주문의 이전 확인 상태로 복구한다. 재승인 때 그 결제 행을 다시 승인한다. 환불 송금은 앱의 표시만 되돌리며 실제 송금을 되돌리지 않는다.
- 출하 취소는 송장/출하 시각을 복구하면서 trackingVersion은 증가시켜 이전 송장 정정 요청을 거부한다.
- POST /api/orders/:id/undo {actionId}, Idempotency-Key 필수. 성공 재시도는 작업을 반복하지 않으며 현재 권한/개인정보 가림이 적용된 최신 주문을 돌려준다.
- 화면 상단의 실행 취소 한 곳에서 가장 최근 처리의 대상·복구 상태를 확인한다. 같은 방문 중 여러 건 출하를 마쳤으면 그 묶음을 대상으로 한다. 새로고침 뒤에도 서버 이력의 최근 처리를 찾고, 여러 건은 주문별 실행하며 부분 실패를 숨기지 않는다.

- 결제 확인 취소(REVERSED)는 미입금이므로 관리자 환불 가능액에서도 제외한다. 환불 공통 진입점도 역전된 결제를 거부한다.
- 날짜 스냅샷은 UTC로 통일하여 요청 간 DB 재조회에도 동일 상태를 비교한다.

- 웹 새로고침에서도 방금 처리한 묶음을 유지하려고 사용자별 sessionStorage에 작업 토큰만 저장한다. 실제 사용 가능 여부와 주문 정보는 매번 서버 이력으로 검증한다.
