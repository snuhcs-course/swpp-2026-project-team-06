### 결정 사항
- 11/10 명령: `python -m app.admin.purge_except --keep <user_id> [--keep <user_id> …] [--commit]`. 기본은 미리보기(한 트랜잭션에서 지운 뒤 savepoint 롤백). 모르는 옵션·`--keep` 없음·값 없는 `--keep`은 거부한다.
- 11/10 `--keep` 대상은 PRODUCER이고 탈퇴(`deleted_at`)하지 않았고 농가가 있어야 한다. 아니면 아무것도 지우지 않고 거부한다.
- 11/10 남기는 집합: `role='ADMIN'` 사용자 전부(`u-admin`, `u-farmclub`), `--keep` 생산자와 그 농가, 농가의 상품·초안·옵션·기간·가격·배정·공급 요청, AI 설정·이력, 소식, 생산자 문의방(`thread-support-<farmId>`, 상대 `u-farmclub`)과 메시지·그 메시지가 가리키는 비공개 첨부, 남는 사용자의 `support_threads`, 남는 농가의 `public_media`·`source_*`, 남는 농가·사용자·상품·기간·공급 요청·문의방을 대상으로 한 `manager_events`, 남는 농가의 `producer_decisions`, `ai_usage`·`source_spend` 전부. 남는 감사 이벤트의 결과 JSON에 지운 주문 ID가 남을 수 있다(예: `orders.harvest_started`의 `orderIds`). FK도 개인정보도 아니고 로그라 그대로 둔다.
- 11/10 남기는 1:1 대화는 생산자 문의방(상대가 ADMIN)뿐이다. 남는 생산자가 다른 남는 농가와 나눈 대화도 지운다.
- 11/10 지우는 것: 그 밖의 모든 행. 주문·결제·환불·주문 문의·주문 대화 문맥은 **전부** 지운다(실거래 없음, 남는 사용자는 생산자·운영자). 남는 소식에 달린 지운 사용자의 반응·답장·읽음도 지운다.
- 11/10 표마다 '남기는 조건'을 명시한 규칙표(`RULES`)를 두고, 규칙이 없는 표가 생기면 실행을 거부한다(새 표가 조용히 남거나 지워지지 않게, 테스트로 검사). 삭제 순서는 `seed.clear()`처럼 `reversed(Base.metadata.sorted_tables)`.
- 11/10 FK 없는 ID 열: `idempotency_records`(전부 지움 — 남는 사용자 기록의 응답 JSON에도 지운 소비자 정보가 있을 수 있음), `manager_events.target_id`(대상 종류별), `private_attachments.order_id/thread_id`(남는 문의방 메시지가 가리키는 것만 남김), `thread_messages.order_id/inquiry_id`(비움)·`attachment_ids`(지운 첨부 제거), `broadcasts.quoted_reply_id`(지운 답장이면 비우고, 그 답장 본문 스냅샷 `reply_to`도 함께 비움. `quoted_reply_id` 없는 옛 인용 소식(0030~0031 사이)의 `reply_to`도 비움 — 인용 대상은 늘 소비자 답장). 비우기는 남는 행에만 하고(`RULES` 조건을 함께 건다) 미리보기에 '비운 열' 수로 보여 준다.
- 11/10 남는 행의 nullable 사용자 FK(`manager_events.actor_id/last_retried_by/resolved_by`, `capacity_requests.decided_by`, `escalations.resolved_by`)가 지우는 사용자를 가리키면 비운다. NOT NULL FK(`producer_decisions.manager_id`, `farm_ai_settings_history.saved_by`)나 다른 농가 미디어 URL을 남는 행이 가리키면 거부한다(추측해 고치지 않음).
- 11/10 정리 뒤 다시 셈: `farms.follower_count`(follows), `broadcasts.reaction_count`(reactions), `stage_allocations.reserved_count`(남은 주문의 `quantity - released_quantity`, 시드와 같은 식 — 사실상 0).
- 11/10 시작할 때 모든 표를 `LOCK TABLE … IN SHARE ROW EXCLUSIVE MODE`로 잠근다. 남길 집합을 정한 뒤 들어온 새 행(예: 남는 문의방의 새 메시지)을 지우지 않게 하려는 것이다. 읽기는 막지 않고, 미리보기도 끝날 때까지 쓰기를 막으므로 runbook에 트래픽이 적은 시간에 실행하라고 적는다. 잠금은 `--keep` 검사 뒤에 하고 `lock_timeout` 5초를 둔다. 오래 열린 쓰기 트랜잭션이 있으면 기다리지 않고 거부한다(뒤의 쓰기 요청이 줄줄이 막히지 않게).
- 11/10 `--commit`이면 같은 트랜잭션에 `ManagerEvent` 1건(`event_type=data.purge_except`, `target_type=system`, actor 없음, `request_summary.via=cli`, 남긴 사용자, 표별 삭제 수)을 남긴다.
- 11/10 저장소 파일: 지운 `public_media`·`source_assets`·`source_pages`·`source_public_photos`의 키를 출력한다. `--commit`이고 저장소가 R2(`SOURCE_STORAGE=r2`)면 DB 커밋 뒤 `Storage().delete`로 지운다(실패는 출력만, 남은 행이 쓰는 키는 건너뜀). 아니면 `source_analysis/worker.cleanup()`이 24시간 지난 미사용 키를 지운다고 안내한다.

### 운영 실행 runbook (사람이 함)
1. **백업**: Railway 대시보드 → Postgres 서비스 → Backups → 수동 스냅샷을 만들고 완료를 확인한다.
2. **user_id 조회(읽기 전용)**: Railway Postgres 쿼리 창에서
   ```sql
   select u.id, u.name, u.role, u.deleted_at, f.id as farm_id, f.name as farm_name, f.approval_status
   from users u left join farms f on f.producer_id = u.id
   where f.id in ('f-a6e6e175d1', 'f-3b3636acb6')
      or (u.role = 'PRODUCER' and u.deleted_at is null and u.is_test_account = false)
   order by f.id;
   ```
   (두 농가 ID는 공개 API에서 확인한 공개 농가다. 실명은 레포에 적지 않으므로 이름으로 맞는지는 실행자가 화면에서 본다.) 두 사람 모두 `role=PRODUCER`, `deleted_at` 비어 있음, 농가가 있는지 본다.
3. **미리보기**(트래픽이 적은 시간에. 실행하는 몇 초 동안 쓰기 요청이 기다린다): `railway ssh --service farmclub-api -- .venv/bin/python -m app.admin.purge_except --keep <f-a6e6e175d1 생산자 id> --keep <f-3b3636acb6 생산자 id>` → 출력(남는 사용자·농가·상품, 표별 삭제/유지 수, 저장소 키 수)을 PM이 확인한다.
4. **실행**: 같은 명령에 `--commit`을 붙인다.
5. **확인**: `curl -s https://farmclub-api-production.up.railway.app/health`, `curl -s https://farmclub-api-production.up.railway.app/api/farms`(두 농가만), 관리자 웹 사용자 목록(두 생산자 + 운영자만), 관리자 웹 문의함(두 농가 방).
