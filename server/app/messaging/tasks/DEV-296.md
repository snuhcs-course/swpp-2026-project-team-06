### 결정 사항
- 11/10 '답이 맞아요'와 바로잡기 결과를 남기려고 `escalations`에 `resolution`(CONFIRMED·CORRECTED, 그 밖은 null)과 `resolved_by`(users.id)를 더한다(마이그레이션 0032, #557 DEV-297의 0031 뒤로 옮김). `status`는 OPEN·ANSWERED 그대로 둔다(질문함 계약 유지). 답이 맞아요는 `status=ANSWERED`, `resolution=CONFIRMED`, `answered_at`=누른 시각, `answer`=null. 고위험.
- 11/10 바로잡기 = AI 답변을 인용한 농가 답장(DEV-289 `replyToMessageId`). 이 답장이 확인 요청을 닫으면 `resolution=CORRECTED`. 질문함 `answer`나 `answerToEscalationIds`로 닫을 때도 인용 대상이 없으면 서버가 그 AI 답변을 인용해 저장한다(닫힌 확인 요청 하나일 때만). 그래서 소비자 화면은 늘 '농가가 바로잡았어요' + 인용 블록이 짝을 이룬다.
- 11/10 메시지 응답에 `checkState`(REQUESTED·CONFIRMED·CORRECTED·null)를 더한다. 기존 `reported`는 그대로(요청이 있었으면 true).
- 11/10 새 엔드포인트 `POST /api/messaging/producer/chats/{consumerId}/messages/{messageId}/confirm`. 농가 주인만, 같은 키 없이도 멱등(이미 CONFIRMED면 그대로 200). 확인 요청이 없는 답변은 404, 이미 바로잡은 답변은 409 `ALREADY_CORRECTED`. AI 모드·읽음·대화 순서는 바꾸지 않는다(새 메시지를 만들지 않음).
- 11/10 건수: 대화 요약에 `aiCheckRequests`(열린 확인 요청 수), 현황 `todo.aiCheckRequests`(농가 전체 열린 확인 요청 수). `needsReply`(목록 필터, AC-13-5)는 지금처럼 확인 요청도 포함하고, 현황 `openQuestions`('답하지 않은 문의')는 확인 요청만 열린 대화를 빼고 센다(같은 일을 두 줄에 세지 않음).
- 11/10 할 일 줄 순서: Figma 1:62는 'AI 답변 확인 요청'이 맨 위지만 원산지·계좌 '필수' 줄이 맨 위여야 해서(DEV-121) '답하지 않은 문의' 바로 위에 둔다.
- 11/10 Figma 노트의 '깃발이 열린 동안 AI 자동 답 멈춤(선택)'은 하지 않는다. 후속 후보로만 남긴다.
- 11/10 '먼저 보기'는 정렬이 아니라 거르기: 누르면 확인 요청 대화만(`/chats?view=private&checks=1`), 오른쪽 글자가 '모두 보기'로 바뀐다. 현황 줄도 같은 주소로 연다. '1:1 채팅 N' 탭 숫자는 안 읽음 합계 그대로, 하단 탭 배지만 확인 요청 수를 더한다(Figma 10:158: 탭 3 · 배지 5).
- 11/10 확인 카드 인용 = 깃발 답변 뒤 첫 소비자 메시지(농가 답이 먼저 오면 인용 없음). 서버 필드를 늘리지 않고 화면이 계산한다.
- 11/10 스캔 반영: 확인 요청은 소비자 질문을 인용한 답장으로는 닫히지 않는다(질문 인용으로 닫히면 '바로잡았어요'인데 AI 답변 인용이 없는 경로가 생김). 전달 질문은 지금처럼 질문 인용으로 닫힌다.
- 11/10 옛 행(스캔 3회차 반영): 0032 전에 ANSWERED된 확인 요청은 `resolution`이 null이다. 그때 농가가 '맞아요'라고 답했는지 바로잡았는지 알 수 없어 `checkState=null`(깃발 없음)로 둔다. `reported`는 true라 소비자에게 '답변 확인 요청' 버튼도 다시 뜨지 않는다. 생산자가 confirm하면 409. 채우기 마이그레이션 없음.
- 11/10 `answerToEscalationIds`로 확인 요청을 지정하면서 다른 메시지를 인용하거나 확인 요청 여럿을 인용 없이 한 번에 닫으면 CORRECTED지만 AI 답변 인용은 붙지 않는다. 생산자 앱은 이 경로를 쓰지 않고(지정 없이 인용만), 계약 문서에 적어 둔다. 생산자 확인 카드는 서버가 `checkState`를 줄 때만 그린다(옛 서버에는 confirm이 없음).
- 11/10 '답이 맞아요' 뒤 인용 답장은 평범한 답장(11/10 PM 결정). CONFIRMED로 닫힌 AI 답변을 농가가 인용해 답해도 `resolution`·`answer`·`answered_at`·`resolved_by`는 그대로이고, 소비자는 계속 '농가가 확인했어요'를 본다. 열린 확인 요청을 인용 답장으로 닫으면 지금처럼 CORRECTED. 바로잡은 뒤의 '답이 맞아요'는 409 그대로. (AI 1차 리뷰에서 넣었던 'CONFIRMED → CORRECTED' 전환은 이 결정으로 뺀다.)
- 11/10 'AI 안내를 바로잡아요' 머리글은 화면이 불러온 목록에서 그 AI 답변을 인용한 첫 농가 답장에 붙인다(서버가 바로잡기 답장 id를 따로 주지 않음). 확인 요청 전에 같은 답변을 인용한 답장이 있거나, 실제 바로잡기 답장이 아직 안 불러온 이전 페이지에 있으면 다른 답장에 붙는 한계가 있다. 생산자 입력칸은 확인 요청 중(REQUESTED)인 AI 답변을 인용할 때만 'AI 안내를 바로잡아요'로 보여 보낸 뒤 결과(바로잡기)와 맞추고, '답이 맞아요'로 닫은 답변을 인용하면 '선택한 메시지에 답장'이다. 정확히 하려면 후속에서 바로잡기 답장 id를 응답에 담는다.
- 11/10 운영 DB의 0032 이전 닫힌 확인 요청 점검은 생략 — 실거래 없음(11/10 PM 결정). 옛 행이 있더라도 깃발 없음으로 보인다.
- 11/10 AI 전달 안내 문구 변경(11/10 PM). HANDOFF 때 저장하는 AI 메시지(`FORWARDED_TEXT`)를 ‘AI가 답하기 어려운 질문이라 농가에 답변을 요청했어요. 농가가 답하면 여기서 볼 수 있어요.’로 바꾼다. PM 요청은 ‘농가 운영자’였지만 이 레포에서 운영자는 플랫폼 관리자라 ‘농가’로 쓴다. 시드는 같은 상수를 쓴다. 이미 저장된 메시지는 옛 문구 그대로 둔다(실사용자 없음, 채우기 마이그레이션 없음). 직접 응대 상태 줄 ‘농가에 전달했어요 · 보통 N시간 안에 답해요’(DEV-208)는 AI 메시지가 아니라 그대로 두고, ‘AUTO 방 안내와 첫 마디가 같다’던 DEV-208 제안서에 메모를 단다. 평가 채점기(evals-v2 `grading.py`)의 전달 안내 판정이 ‘전달|넘겨’만 보아 새 문구를 실패로 볼 수 있어 ‘답변을 요청’을 더한다(옛 문구 판정은 그대로). 지난 평가 결과 문서는 고치지 않는다.
- 11/10 개인정보 처리방침(`packages/ui/src/legalContent.ts` 제11조 '잘못된 답' 줄)은 고치지 않는다. '농가가 바로잡고 회사가 확인합니다'가 새 흐름과 어긋나지 않고, 문구를 바꾸면 동의 버전(LEGAL_VERSION) 절차가 따라온다.
