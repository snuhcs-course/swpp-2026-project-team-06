### 목표
같은 폴더를 건드린 병렬 PR이 tasks.md 끝에서 매번 충돌하고(11/4 #393~#396에서 5회), 2천 줄 파일을 에이전트가 통째로 읽는 문제를 없앤다.

### 범위 (수정 허용 경로)
- 1단계(이 PR, 설계): `docs/spec/tech-design/adr/0014-per-issue-task-files.md`, `scripts/split-tasks.py`, `.agents/tasks/DEV-219.md`, `.agents/tasks.md`(링크 절 1개)
- 2단계(승인 뒤): 모든 `**/tasks.md` → `**/tasks/*.md`, `.github/spec-check/check.py`·`test_check.py`·`README.md`·`spec.md`, `.github/spec.md`, `.agents/skills/{spec,pr-context,pr-review}/**`, `AGENTS.md`, `CLAUDE.md`, `.agents/examples/*`, `.github/pull_request_template.md`, `docs/spec/README.md`, `docs/spec/tech-design/stack.md`, `README.md`

### 비범위 (건드리지 않음)
- `spec.md`(구현 결정) 구조, `figma_line.py`, `docs/wiki`의 과거 서술, PR #400의 Mock 테스트 글롭 러너

- 11/04 PM 결정: A안, 지금 적용(#400·#401·#402·#406 머지 뒤 main 8fdb6a8 위), 남은 draft #410·#411·#412는 작성자가 `--only`로 꺼냄, SWPP-18 머리 기록은 `docs/spec/tasks/SWPP-18.md`로 수동 이동, 같은 폴더 동시 작업은 범위가 겹칠 때만 순서를 정함.

- 11/04 checker는 옛 형식 `tasks.md#dev-xx`도 받고, 같은 폴더에 `tasks/<키>.md`가 있으면 그 파일을 읽는다(분리 전 PR 본문 호환).
- 11/04 안 A(`<폴더>/tasks/<키>.md`, 옛 tasks.md는 제목 줄+링크만 남긴 얼린 목록)를 추천. B(살아 있는 목록)는 목록 줄끼리 충돌이 남고, C(루트 `tasks/`)는 폴더 옆 `spec.md`와 떨어지고 같은 키가 여러 폴더에서 섞인다.
- 11/04 같은 폴더의 같은 키 절은 원래 순서대로 한 파일에 합친다. 키 없는 절·머리말은 목록에 남긴다.
- 11/04 `merge=union`은 #400 머지 전에 빠져 main에 없다(PM). 이 PR에서 할 일 없음.
- 11/04 분리 전에 연 PR은 main 병합 전에 `split-tasks.py --only <키> --apply`로 자기 절만 꺼낸다(임시 clone에서 충돌 없이 병합 확인).
