# DEV-219 [repo] Split per-folder tasks.md into per-issue task files

- 이슈: [DEV-219](https://linear.app/sswp6/issue/DEV-219)
- 브랜치: `nemodleo/dev-219-split-tasks-per-issue`
- 기능·인수 조건: 없음(저장소 운영 규칙). 설계: `docs/spec/tech-design/adr/0014-per-issue-task-files.md`
- 상태: 진행 중 (1단계 설계 · PM 승인 대기)
- 형식: 이 파일이 ADR 0014가 제안하는 새 형식의 첫 예시다. 옛 형식 checker를 위해 `.agents/tasks.md`에 링크만 있는 `## DEV-219` 절을 함께 둔다.

### 목표
같은 폴더를 건드린 병렬 PR이 tasks.md 끝에서 매번 충돌하고(11/4 #393~#396에서 5회), 2천 줄 파일을 에이전트가 통째로 읽는 문제를 없앤다.

### 범위 (수정 허용 경로)
- 1단계(이 PR, 설계): `docs/spec/tech-design/adr/0014-per-issue-task-files.md`, `scripts/split-tasks.py`, `.agents/tasks/DEV-219.md`, `.agents/tasks.md`(링크 절 1개)
- 2단계(승인 뒤): 모든 `**/tasks.md` → `**/tasks/*.md`, `.github/spec-check/check.py`·`test_check.py`·`README.md`, `.agents/skills/{spec,pr-context,pr-review}/**`, `AGENTS.md`, `CLAUDE.md`, `.agents/examples/*`, `.github/pull_request_template.md`, `docs/spec/README.md`, `docs/spec/tech-design/stack.md`, `README.md`, `.gitattributes`

### 비범위 (건드리지 않음)
- `spec.md`(구현 결정) 구조, `figma_line.py`, `docs/wiki`의 과거 서술, PR #400의 Mock 테스트 글롭 러너

### 결정 사항
- 11/04 안 A(`<폴더>/tasks/<키>.md`, 옛 tasks.md는 제목 줄+링크만 남긴 얼린 목록)를 추천. B(살아 있는 목록)는 목록 줄끼리 충돌이 남고, C(루트 `tasks/`)는 폴더 옆 `spec.md`와 떨어지고 같은 키가 여러 폴더에서 섞인다.
- 11/04 같은 폴더의 같은 키 절은 원래 순서대로 한 파일에 합친다. 키 없는 절·머리말은 목록에 남긴다.
- 11/04 분리 PR에서 `.gitattributes`의 `tasks.md merge=union`(PR #400)은 지운다. 파일 전체가 바뀌는 병합에서 union은 옛 내용과 새 목록을 섞는다.
- 11/04 분리 전에 연 PR은 main 병합 전에 `split-tasks.py --only <키> --apply`로 자기 절만 꺼낸다(임시 clone에서 충돌 없이 병합 확인).
