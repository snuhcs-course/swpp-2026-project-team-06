# P14 프로토타입 개요 (I1)

> SWPP-18 · 상태: 확정 (10/06 PM 결정 반영)
> 근거: Proposal, 10/04 유저스터디 분석 회의(SWPP-17), Notion Problem·Feature DB, 운영 구조 제안(10/04)

## 1. 한 줄 정의
**당도로 증명하는 고품질 감귤을, 수확 전에 더 싸게 예약한다.**
소비자는 농가를 팔로우하고 버블(Bubble)처럼 농부가 보내는 재배·수확 메시지를 받아보다가, 일찍 예약할수록 싼 단계별 가격으로 예약구매한다. 생산자는 기존 판매글을 붙여넣으면 AI가 상품 초안을 만들어 주고, 소비자 문의는 AI가 1차로 답한다.

## 2. I1 프로토타입이 보여줄 핵심 루프
```
[생산자] 기존 판매글 붙여넣기 → AI 상품 초안 → 수정·검토 요청
[운영자] 판매 단계·가격 설정 → 게시                (I1은 관리자 화면으로 처리)
[생산자] 팔로워에게 메시지 발송 (사진·당도·생육 소식)
                     ↓
[소비자] 농가 발견 → 팔로우 → 메시지·당도 확인 → 현재 단계 가격으로 예약구매(Mock 결제) → 주문 상태 확인
                     ↓                                   ↑
[소비자] 메시지방에서 질문 → AI 1차 답변 / 판단 필요 시 생산자에게 전달
[생산자] 주문 현황 확인 → 수확·발송 처리 → 소비자에게 상태 알림
```

## 3. 근거 — 10/04 유저스터디 분석
| 발견 | 프로토타입 반영 |
| -- | -- |
| 소비자 우선순위: **맛·당도 >> 신선도 = 품질 > 가격** | 상품·메시지의 핵심 지표를 **당도(Brix)** 로 고정 |
| 예약구매의 가장 큰 장벽은 **품질을 미리 알 수 없음** | 상품 상세에 품질 기준(목표 당도·등급), 메시지에 측정 당도 기록 |
| 기능 중 **재배·수확 콘텐츠**가 가장 매력적 | 농가 메시지(버블형)를 핵심 경험으로 |
| 생산자 소통과 AI 안내를 나눌 여지 있음 | 생산자는 발신, 반복 문의는 AI가 응대 |
| 품종 자체엔 관심 낮음, 품질이 더 중요 | 품종 무관(variety-agnostic), 품종은 보조 정보 |
| 대기 기간은 짧을수록 좋음 (추가 검증 필요) | 상품에 **배송 예정 시기** 필수 표시 |
| 일반 온라인 가격보다 비싸면 구매 안 함 | 단계별 가격: 이른 단계일수록 저렴, 마지막 단계도 일반 온라인가 수준 |
| 산지 직거래 경험 적음 / 20~30대는 정보 탐색을 싫어함 | 탐색은 큐레이션된 농가 목록 하나로 단순화 |
| 생산자는 예약판매 경험 적고 **사진을 거의 안 찍음** | 등록은 판매글 붙여넣기 + AI 초안, 메시지는 텍스트만으로도 가능 |

## 4. 대상 사용자
| 구분 | 1차 타깃 | 비고 |
| -- | -- | -- |
| 소비자 | 40~50대 (구매력·결정권, 농부와 적극 소통할 헤비 유저), 여성 경향 | 20~30대는 간접 사용자(부모님 대신 주문·선물) |
| 생산자 | 제주 감귤 중소농, 품종 무관, 고품질 생산 | 생산자 베타 4명 우선 |
| 운영자 | 팀 내부 | 판매 단계·가격 설정, 상품 게시 |

## 5. 가치 제안
- **소비자**: "이번 수확의 당도"를 미리 보고, 믿을 수 있는 농가의 감귤을 일찍 예약할수록 더 싸게 산다. 농부와 1:1로 대화하는 듯한 경험.
- **생산자**: 이미 쓰던 판매글로 상품을 올리고, 수확 전에 수요를 확인하며, 반복 문의는 AI가 대신 답한다.
- **차별점 3가지**: 단계별 예약판매 · 버블형 농부 메시지 · AI(등록·응대)

## 6. 프로토타입 범위
### 포함 (I1)
| # | 기능 | 사용자 | 우선순위 |
| -- | -- | -- | -- |
| 1 | 회원가입·로그인, 역할(소비자/생산자) | 공통 | Must |
| 2 | AI 상품 등록: 판매글 붙여넣기 → 상품 초안(중량 옵션 포함) → 수정·검토 요청 | 생산자 | Must |
| 3 | 판매 단계·가격 설정, 상품 게시 | 운영자 | Must (관리자 화면) |
| 4 | 농가 목록·프로필, 팔로우 | 소비자 | Must |
| 5 | 버블형 메시지: 생산자 → 팔로워 전체 발송(텍스트·사진·당도), 소비자는 1:1 대화처럼 보고 답장 | 공통 | Must |
| 6 | 상품 상세(품질 기준·당도·단계별 가격·배송 예정 시기) → 예약구매(Mock 결제, 사전 동의) | 소비자 | Must |
| 7 | 내 주문: 상태 확인, 출하 전 취소 | 소비자 | Must |
| 8 | 주문 관리: 예약 주문 집계·목록, 출하·발송 처리 | 생산자 | Must |
| 9 | AI 문의 응대: 메시지방 질문 → AI 1차 답변, 판단 필요 시 생산자에게 전달 | 공통 | Should |

### 제외 (I2 이후)
- 실결제·정산, 택배사 연동(송장 자동 추적), 푸시 알림(앱 내 알림 목록으로 대체)
- 비규격 상품 옵션, 체험·다른 품목, 주문 양도
- 소비자 간 소통, 콘텐츠·알림 레벨링, 민감 주제 AI 필터
- 흉작 시 수량 비례 배분 자동화 (정책만 정의, 처리는 운영자 수동)

## 7. 성공 기준 (I1 데모)
- 생산자가 판매글 붙여넣기로 상품 초안을 **3분 안에** 검토 요청까지 마친다.
- 소비자가 앱 첫 실행부터 예약구매 완료까지 **막힘 없이** 진행한다 (팀 외 1명 이상 테스트).
- AI 상품 초안의 주요 필드(상품명·중량 옵션·기존 가격·수확/발송 시기) 추출 정확도를 베타 생산자 판매글 5개 이상으로 확인한다.

## 결정 기록 (10/06)
- 소통: 소식+문의 방식을 **버블(Bubble)형 1:N 메시지 + AI 응답**으로 구현
- AI 범위: 상품 등록 AI **Must**, 문의 AI **Should**
- 가격: 운영 구조 제안 문서 기준 — **단계별 가격(이른 단계일수록 저렴), 단계 일정·가격은 플랫폼, 공급 물량은 생산자**
- 판매 단위: **상품 + 중량 옵션**
- 결제: **Mock** (주문 시 전액 결제 흐름만 재현)
