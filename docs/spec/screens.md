# farmclub 화면 명세 (I1-P21·P22)

I1 화면 25개(소비자 앱 14, 생산자 앱 11, 로그인 SCR-05는 두 앱 공통)의 구성·데이터·동작·예외와 API 계약을 정한다. P21 초안(제안서 기준)을 확정 스펙(`docs/spec`)과 합친 확정본이다. 동작·규칙의 원문은 기능 명세(FEAT·R·M)에 있고, 여기서는 ID로 가리킨다.

## 3. 공통 규칙

- **날짜·금액**: API는 ISO 8601(UTC 저장), 화면은 한국 시간(`Asia/Seoul`)으로 표시한다. 금액은 원 단위 정수로 주고받고 화면에 천 단위 구분을 넣는다(N-03).
- **크기**: 본문 16px 이상, 누르는 영역 48px 이상, 한 화면에 주요 행동 하나(N-02). 레이블은 [IA 4장](./ia.md#4-내비게이션과-진입-경로)을 쓴다.
- **로그인 관문**: 둘러보기는 로그인 없이 된다. 팔로우·예약하기·채팅하기(질문하기)·좋아요를 누르거나 소식·채팅·내 정보 탭을 열면 로그인(SCR-05)으로 가고, 끝나면 누른 화면과 행동으로 돌아간다(FEAT-01).
- **권한 오류**: 403이면 ‘볼 수 없는 화면이에요’와 첫 화면 이동을 보여준다. 권한은 서버가 검사한다(N-06).
- **쓰기 요청**: 성공하면 응답의 서버 값으로 화면을 갱신한다. 화면의 합계·반응 수는 미리보기이고 서버 값이 최종이다.
- **입력값 보존**: 쓰기가 실패하면(네트워크·검증·409) 사용자가 입력한 값과 고른 사진을 지우지 않는다. 로그인으로 갔다 돌아와도 유지한다.
- **중복 방지**: 처리 중에는 버튼을 잠근다. 주문 생성·결제는 `Idempotency-Key` 헤더를 보내 같은 요청이 두 번 처리되지 않게 한다(7.1).
- **목록**: cursor 페이지네이션(7.1). 다음 페이지 실패는 이미 보인 항목을 유지하고 하단에 다시 시도를 둔다.
- **이미지**: 대체 텍스트를 둔다. 불러오기 실패면 기본 이미지를 보인다.
- **테스트 표시**: I1은 결제·주문 화면과 하단에 ‘테스트 서비스’를 표시한다([정책 0장](./policy.md#0-문서-정보)).

## 4. I1 우선순위

> **팀 확인 필요.** 제안이다. Must는 S-1·S-2를 데모로 끝까지 보여주는 최소 경로이고, 나머지는 Should다. 일정이 모자라면 Should부터 덜어낸다(PRD 8장).

| 앱 | Must | Should |
| --- | --- | --- |
| 소비자 | SCR-01 홈 → SCR-03 농가 페이지 → SCR-04 상품 상세 → SCR-10 주문서 → SCR-11 결제(Mock) → SCR-12 주문 완료, 그리고 주문하려면 필요한 SCR-05 로그인 | SCR-02, 13, 14, 15, 16, 17, 18 |
| 생산자 | SCR-05 로그인 → SCR-24 AI 상품 초안 → SCR-25 상품 편집 → SCR-26 단계·가격·물량(게시 요청에 필요) → SCR-22 현황, 그리고 상품 승인 관리 API | SCR-20, 21, 23, 27, 28, 29, 30 |

생산자 Must 경로는 시드의 승인된 생산자 계정으로 시작한다. 가입·승인 화면(SCR-20·21)이 Should여도 승인 대기 계정과 관리 API는 시드로 둔다.

## 5. 소비자 앱

### SCR-01 홈·발견 `/`

- **관련**: FEAT-06(AC-06-4·5), FEAT-15 · 탭: 발견(첫 화면) · 우선순위: Must
- **목적**: 시즌 상품과 농가 소식을 둘러보고 상품·농가로 들어간다.
- **화면 요소·데이터**: 시즌 히어로(문구, 이미지, 연결 상품), 추천 상품 카드(상품명, 농가명, 지금 가격, 다음 단계 가격, 단계 마감일, 받는 시기, 품절 여부), 소식 미리보기(공개 소식 최신 3개: 농가명, 작성일, 본문 앞부분, 사진 한 장), ‘농가 전체 보기’, 하단 탭.
- **입력·출력**: 입력 없음. `GET /api/home`을 그린다. 상품 카드는 `productId`, 소식 카드는 `farmId`를 넘긴다.
- **버튼 동작**: 히어로 → 연결 상품이 있으면 SCR-04(없으면 누를 수 없음). 상품 카드 → SCR-04. 소식 카드 → 그 농가 SCR-03 소식 탭. 소식 더 보기 → 소식 탭(SCR-18, 로그인 필요). 농가 전체 보기 → SCR-02.
- **빈 상태·오류**: 판매 중 상품이 없으면 ‘현재 예약 가능한 상품이 없어요’와 소식 미리보기만. 소식이 없으면 그 칸을 숨긴다. 섹션별로 불러오기 실패를 표시하고 다시 시도를 두며 다른 섹션은 유지한다.

### SCR-02 농가 목록 `/farms`

- **관련**: FEAT-06(AC-06-1·2) · 탭: 발견 안 · 우선순위: Should
- **목적**: 승인된 농가를 마감 임박순으로 보고 검색한다.
- **화면 요소·데이터**: 검색창, 농가 카드(농가명, 지역, 대표 상품, 지금 가격, 단계 마감일). 정렬은 FEAT-06.
- **입력·출력**: 검색어(앞뒤 공백 제거, 비면 전체). `GET /api/farms?q=&cursor=&limit=`. 카드는 `farmId`를 넘긴다.
- **버튼 동작**: 농가 카드 → SCR-03. 아래로 끝까지 → 다음 cursor.
- **빈 상태·오류**: 검색 결과 없음 → ‘찾는 농가가 없어요’와 전체 목록으로. 불러오기 실패 → 다시 시도.

### SCR-03 농가 페이지 `/farms/:farmId`

- **관련**: FEAT-02, 06(AC-06-3), 15(AC-15-1~5), 19(AC-19-1·2), FEAT-12(AC-12-4) · 우선순위: Must
- **목적**: 농가를 알고, 판매 중 상품과 공개 소식을 보고, 팔로우하거나 채팅을 시작한다. 농가 링크의 도착점이다.
- **화면 요소·데이터**: 프로필(농가명, 지역, 소개, 대표 사진, 팔로워 수), 팔로우 버튼(켬·끔), 채팅하기, 탭 \[상품 \| 소식\](처음은 상품). 상품 탭: 판매 중 상품(상품명, 지금 가격, 받는 시기, 품절). 소식 탭: 공개 소식 최신순(작성일, 본문, 사진·영상, 좋아요 수와 내 좋아요).
- **입력·출력**: `GET /api/farms/{farmId}`, `GET /api/messaging/farms/{farmId}/news?cursor=`. 팔로우 `PUT`/`DELETE /api/farms/{farmId}/follow`. 좋아요 `PUT`/`DELETE /api/messaging/news/{broadcastId}/reaction`.
- **버튼 동작**: 팔로우 → 켬·끔(로그인 필요). 채팅하기 → 팔로우하지 않았으면 ‘팔로우하고 대화를 시작해요’ 확인 후 자동 팔로우, SCR-16. 상품 → SCR-04. 좋아요 → 켬·끔, 응답의 반응 수로 갱신.
- **빈 상태·오류**: 없는 농가·승인 취소된 농가 → ‘찾을 수 없는 농가’ → SCR-02. 판매 중 상품 없음 → ‘지금 판매 중인 상품이 없어요’. 소식 없음 → ‘아직 올라온 소식이 없어요’(채팅하기는 유지).

### SCR-04 상품 상세 `/products/:productId`

- **관련**: FEAT-07(AC-07-1·2), FEAT-12 · 규칙: R-05, R-06, R-16, R-20, M-15 · 우선순위: Must
- **목적**: 품질·받는 시기·지금 가격을 보고 예약을 시작한다.
- **화면 요소·데이터**: 상품명·품종·농가 요약(이름, 지역 → SCR-03), 사진, 당도(실측 또는 ‘예상’)·등급, 받는 시기, 단계별 가격(지금 단계 강조, 다음 단계 가격과 시작일, 단계 마감일, 남은 물량·품절), 중량 옵션, 배송비(무료·별도·도서산간), 설명, 원산지·상품정보(R-16), 최신 소식 한 개, 하단 고정 ‘예약하기’, 채팅하기.
- **입력·출력**: `GET /api/products/{productId}`. 예약하기는 `productId`와 고른 옵션을 SCR-10에 넘긴다. 가격·물량의 최종 확인은 서버가 한다.
- **버튼 동작**: 예약하기 → SCR-10(로그인 필요). 농가 요약 → SCR-03. 채팅하기 → SCR-03과 같다. 소식 → SCR-03 소식 탭.
- **빈 상태·오류**: 지금 단계가 없거나 품절 → 예약하기를 막고 ‘품절’과 다음 단계 시작일(AC-07-1). 판매 중이 아닌 상품 → ‘판매 중이 아닌 상품’ → SCR-03. 다시 열 때 가격·물량이 바뀌었으면 새 값으로 그린다.

### SCR-05 로그인 `/login` (두 앱 공통)

- **관련**: FEAT-01(AC-01-1~5) · 규칙: R-22, N-06 · ADR 0009 · 우선순위: Must
- **목적**: I1 테스트 계정을 골라 로그인한다(카카오 로그인은 I2).
- **화면 요소·데이터**: 로그인이 필요한 이유 한 줄, 테스트 계정 목록(이름, 역할 표시: 소비자·생산자(승인)·생산자(승인 대기)), 약관·개인정보 처리방침 링크, ‘테스트 서비스’ 표시.
- **입력·출력**: `GET /api/auth/test-accounts`로 목록, 고르면 `POST /api/auth/test-login`(`userId`) → 액세스 토큰과 사용자. 토큰은 packages/api가 보관한다.
- **버튼 동작**: 계정 선택 → 로그인 후 누른 화면·행동으로 복귀. 생산자 앱은 상태에 따라 농가 없음 → SCR-20, 승인 대기·반려 → SCR-21, 승인 → SCR-22, 정지 → 정지 안내.
- **빈 상태·오류**: Mock 로그인이 꺼져 있으면(404) ‘지금은 로그인할 수 없어요’. 실패하면 다시 시도. 취소(뒤로) → 원래 화면, 행동 실행 안 함.

### SCR-10 주문서 `/checkout/:productId`

- **관련**: FEAT-08(AC-08-1~5), FEAT-01(AC-01-1) · 규칙: R-03, R-06, R-17, R-20, R-23 · 정책 2장 · 우선순위: Must
- **목적**: 옵션·수량·받는 사람을 정하고 조건에 동의해 결제로 간다.
- **화면 요소·데이터**: 상품 요약(지금 단계 가격), 중량 옵션, 수량(1\~한 주문 최대 수량), 받는 사람·연락처·우편번호·주소·상세 주소, 배송 메모(선택), 저장한 배송지 고르기와 ‘이 주소 저장’, 금액(상품 금액 + 배송비 + 도서산간 추가금 = 합계), 결제 전 동의 4개(정책 2장)와 전체 동의, ‘결제하기’.
- **입력**: `optionId`, `quantity`, `recipientName`, `recipientPhone`(휴대폰 형식), `postalCode`, `address`, 선택 `addressDetail`, `deliveryNote`(100자 이하), 동의 4개, `saveAddress`. 저장한 기본 배송지가 있으면 채워 두고 고칠 수 있다(AC-08-5, `GET /api/auth/me/addresses`).
- **출력**: `POST /api/orders`(`Idempotency-Key`) → 결제 전 주문(`orderId`, `unitPrice`, `shippingFee`, `totalAmount`). 서버 합계를 보여주고 SCR-11로 간다.
- **버튼 동작**: 수량·옵션·주소 변경 → 합계 미리보기 갱신. 결제하기 → 필수값·동의 검증 후 1회 요청, 처리 중 잠금. 뒤로 → SCR-04.
- **빈 상태·오류**: 필드 아래에 형식 오류. 동의 누락 → 넘어가지 않음(AC-08-1). 409(단계가 바뀜·품절·수량 초과) → 서버 최신 가격·물량으로 다시 그리고 입력값은 유지, 다시 확인받음. 네트워크 오류 → 입력 유지, 다시 시도.

### SCR-11 결제(Mock) `/checkout/:productId/pay?orderId=`

- **관련**: FEAT-09(AC-09-1~3) · 규칙: R-01, R-02, R-06, R-13, R-17 · 우선순위: Must
- **목적**: 주문 금액을 카드로 한 번에 낸다(I1 Mock).
- **화면 요소·데이터**: 결제 금액, 카드 결제(Mock) 버튼, 데모용 성공·실패 선택, ‘테스트 서비스’ 표시.
- **입력·출력**: `POST /api/orders/{orderId}/pay`(`Idempotency-Key`, `mockResult`: `success`·`fail`) → 성공이면 주문이 예약 완료, 실패면 사유.
- **버튼 동작**: 결제 → 1회 요청, 처리 중 잠금. 성공 → SCR-12. 실패 → 사유와 다시 시도 또는 SCR-10.
- **빈 상태·오류**: 결제 순간 물량 0(409) → 실패 처리, 품절 안내, SCR-10으로(AC-09-1). 응답을 못 받으면 같은 `Idempotency-Key`로 다시 보낸다(AC-09-3).

### SCR-12 주문 완료 `/me/orders/:orderId/done`

- **관련**: FEAT-09, FEAT-06 · 우선순위: Must
- **목적**: 예약이 끝났음을 확인하고 팔로우·소식·채팅으로 이어간다.
- **화면 요소·데이터**: ‘예약 완료’, 주문 번호(복사), 상품·옵션·수량·합계, 받는 시기, 배송지 요약, 농가 팔로우 권유(이미 팔로우했으면 숨김), 소식 보기·채팅하기·주문 내역 보기.
- **입력·출력**: `GET /api/orders/{orderId}`로 최신 상태를 다시 읽는다.
- **버튼 동작**: 팔로우 → 켬. 소식 보기 → 그 농가 SCR-03 소식 탭. 채팅하기 → SCR-16. 주문 내역 → SCR-13. 홈으로 → SCR-01.
- **빈 상태·오류**: 결제 성공 뒤 상세 조회만 실패하면 완료 화면을 유지하고 다시 시도. `orderId`가 없으면 이 화면으로 오지 않는다.

### SCR-13 주문 내역 `/me/orders`

- **관련**: FEAT-10(AC-10-1) · 진입: 내 정보(SCR-17) · 우선순위: Should
- **목적**: 내 주문의 진행을 보고 할 일이 있는 주문을 찾는다.
- **화면 요소·데이터**: 주문 카드(상품, 상태, 받는 시기, 합계). 할 일 있는 주문(배송 기간 변경 동의, 구매 확정)이 먼저, 그다음 최신순.
- **입력·출력**: `GET /api/orders?cursor=&limit=`.
- **버튼 동작**: 카드 → SCR-14. 다음 페이지.
- **빈 상태·오류**: 주문 없음 → ‘아직 예약한 상품이 없어요’와 홈으로. 실패 → 다시 시도.

### SCR-14 주문 상세 `/me/orders/:orderId`

- **관련**: FEAT-10(AC-10-1~3), FEAT-11(AC-11-1·2), FEAT-17(AC-17-2·5) · 규칙: R-05, R-07, R-14, R-21, R-24 · 우선순위: Should
- **목적**: 상태·받는 시기를 보고 취소·구매 확정·기간 변경 응답을 한다.
- **화면 요소·데이터**: 진행 상태(예약 완료·출하 준비·출하·배송 완료·구매 확정·환불), 받는 시기(바뀌었으면 새 기간과 선택), 송장 번호(출하 후), 상품·금액·받는 사람·배송 메모, 지금 할 수 있는 행동, 환불이면 사유.
- **입력·출력**: `GET /api/orders/{orderId}`. 취소 `POST /api/orders/{orderId}/cancel`, 구매 확정 `POST /api/orders/{orderId}/confirm`, 기간 변경 응답 `POST /api/orders/{orderId}/delivery-window-response`.
- **버튼 동작**: 취소 → 확인 창 → 전액 환불(예약 완료·출하 준비만). 구매 확정 → 배송 완료 후. 새 기간 동의 / 전액 환불 → 기록.
- **빈 상태·오류**: 남의 주문 주소 → SCR-13. 409(이미 상태가 바뀜) → 최신 상태로 다시 그림. 출하 후에는 취소 버튼이 없다(AC-11-2).

### SCR-15 채팅 목록 `/chats`

- **관련**: FEAT-12, FEAT-13 · 탭: 채팅(첫 화면) · 규칙: M-02, M-04 · 우선순위: Should
- **목적**: 농가와의 1:1 채팅을 고른다.
- **화면 요소·데이터**: 채팅 카드(농가명, 마지막 질문·답 앞부분, 시각, 안 읽음, AI 안내 여부). 팔로우 중인 농가만, 최근 순. 팔로우를 해제하면 빠지고 다시 팔로우하면 이전 채팅이 보인다(FEAT-06). 농가 소식은 여기 나오지 않는다(AC-12-5).
- **입력·출력**: `GET /api/messaging/chats?cursor=&limit=`.
- **버튼 동작**: 카드 → SCR-16.
- **빈 상태·오류**: 채팅 없음 → ‘농가에 궁금한 점을 물어보세요’와 농가 둘러보기(SCR-02). 실패 → 다시 시도.

### SCR-16 농가 채팅 `/chats/:farmId`

- **관련**: FEAT-12(AC-12-1·2·4·5), FEAT-13(AC-13-1~4, AC-13-5는 I2) · 규칙: M-02, M-04~M-09, M-15, M-16, M-18, N-04 · 우선순위: Should
- **목적**: 농가에 질문하고, AI가 답할 수 있는 것은 바로 안내받는다.
- **화면 요소·데이터**: 농가 헤더(→ SCR-03), 시간순 타임라인(내 질문, AI 안내 배지가 붙은 답과 근거 요약, 농가 답, ‘농가에 전달했어요’ 상태), 입력창(글, 사진 최대 3장), 보내기. 처음이면 ‘팔로우하고 대화를 시작해요’ 한 줄.
- **입력**: `text`(앞뒤 공백 제외 1자 이상, 1,000자 이하), 선택 사진.
- **출력**: 들어오면 `GET /api/messaging/chats/{farmId}/messages?cursor=`(대화는 농가·소비자당 1개라 `farmId`로 찾는다). 보내기 `POST /api/messaging/chats/{farmId}/messages` → 저장된 질문(연락처 가림)과 AI 안내 또는 전달 상태(`handoffStatus`). 자동 팔로우는 여기서 하지 않고 SCR-03·04·18의 채팅하기·질문하기가 `POST /api/messaging/chats`로 한다.
- **버튼 동작**: 보내기 → 1회, 처리 중 잠금. AI 안내는 등록된 정보로만 답하고, 근거가 없거나 전달 주제면 ‘농가에 전달했어요’(M-06·M-07). 위로 → 이전 cursor. ‘틀렸어요’ 버튼은 I1에 없다(M-17, I2).
- **빈 상태·오류**: 아직 질문이 없으면 ‘궁금한 점을 물어보세요’. 팔로우하지 않은 농가의 채팅 주소로 바로 들어오면(403) 그 농가 SCR-03으로 보낸다(IA 5장 예외 경로). 보내기 실패 → 입력창에 글·사진 유지, 다시 보내기. AI 실패·시간 초과 → 전달로 처리(N-04). 불러오기 실패 → 이미 보인 것을 유지하고 다시 시도.

### SCR-17 내 정보 `/me`

- **관련**: FEAT-06(AC-06-3), FEAT-08(AC-08-5), FEAT-10 · 탭: 내 정보 · 우선순위: Should
- **목적**: 팔로우·주문·배송지를 관리하고 생산자 앱으로 간다.
- **화면 요소·데이터**: 프로필(이름, 테스트 계정 표시), 주문 내역(→ SCR-13, 할 일 있는 주문 수), 팔로우 목록, 배송지 관리(저장·수정·삭제, 기본 배송지), 농가로 시작하기(생산자 앱), 로그아웃.
- **입력·출력**: `GET /api/auth/me`, `GET /api/farms/following`, 배송지 `GET`·`POST`·`PATCH`·`DELETE /api/auth/me/addresses`.
- **버튼 동작**: 주문 내역 → SCR-13. 팔로우한 농가 → SCR-03. 배송지 저장 → 검증 후 저장. 농가로 시작하기 → 생산자 앱 주소. 로그아웃 → 토큰 삭제, SCR-01.
- **빈 상태·오류**: 팔로우 없음 → ‘팔로우한 농가가 없어요’와 농가 둘러보기. 저장 실패 → 입력 유지.

### SCR-18 소식 `/news`

- **관련**: FEAT-12(AC-12-3), FEAT-15(AC-15-3~5) · 탭: 소식(첫 화면) · 규칙: M-01, M-14 · 우선순위: Should
- **목적**: 팔로우한 농가가 올린 재배·수확 소식을 보고 반응하거나 질문한다.
- **화면 요소·데이터**: 소식 카드 시간순(농가명 → SCR-03, 작성일, 본문, 사진·영상, 공개·팔로워 전용 표시, 좋아요 수와 내 좋아요, 질문하기). 팔로우한 농가의 공개·팔로워 전용 소식이 모두 보인다.
- **입력·출력**: `GET /api/messaging/news?cursor=&limit=`. 좋아요 `PUT`/`DELETE /api/messaging/news/{broadcastId}/reaction` → 반응 수.
- **버튼 동작**: 좋아요 → 켬·끔(한 사람 한 번). 질문하기 → 그 농가 SCR-16. 농가명 → SCR-03. 아래로 끝까지 → 다음 cursor.
- **빈 상태·오류**: 팔로우한 농가가 없음 → ‘팔로우한 농가의 소식이 여기에 보여요’와 농가 둘러보기(SCR-01·02). 소식 없음 → ‘아직 올라온 소식이 없어요’. 좋아요 실패 → 이전 상태로 되돌림.

## 6. 생산자 앱

모든 화면은 생산자 앱이다. SCR-20·21 외에는 승인된 생산자만 열린다(AC-01-3).

### SCR-20 가입 신청 `/apply`

- **관련**: FEAT-01 · 규칙: R-22 · 정책 3장 · 우선순위: Should
- **목적**: 농가 정보를 입력해 입점을 신청한다.
- **화면 요소·데이터**: 농가명, 지역, 주 품목, 연락처, 확인 절차 안내(전화·방문), 입점 정책 동의, 신청하기.
- **입력·출력**: 필수 4개, 연락처는 휴대폰 형식. `POST /api/auth/producer-application` → 농가(승인 대기). SCR-21로.
- **버튼 동작**: 신청하기 → 검증 후 1회, 잠금.
- **빈 상태·오류**: 필드별 오류, 실패 시 입력 유지. 이미 신청했으면 SCR-21.

### SCR-21 승인 대기 `/pending`

- **관련**: FEAT-01(AC-01-3) · 우선순위: Should
- **목적**: 신청 상태를 보고, 반려되면 다시 신청한다.
- **화면 요소·데이터**: 상태(대기·반려), 다음 절차, 반려 사유와 다시 신청.
- **입력·출력**: `GET /api/auth/producer-application`.
- **버튼 동작**: 다시 신청 → SCR-20(이전 값 채움). 새로고침 → 승인됐으면 SCR-22.
- **빈 상태·오류**: 승인 전에는 다른 생산자 화면 주소로 가도 여기로 온다(AC-01-3).

### SCR-22 현황 `/`

- **관련**: FEAT-14(AC-14-1·2) · 탭: 현황 · 규칙: R-15 · 우선순위: Must
- **목적**: 할 일과 단계별 예약 수량을 한눈에 본다.
- **화면 요소·데이터**: 할 일(답할 질문 수, 출하할 주문 수, 승인 대기 상품), 소식 올리기·출하 처리 버튼, 단계별·옵션별 예약 수량과 남은 물량, 최근 주문(배송 완료 전만 배송 정보).
- **입력·출력**: `GET /api/orders/producer/dashboard`.
- **버튼 동작**: 소식 올리기 → SCR-27. 출하 처리 → SCR-29. 답할 질문 → SCR-28. 승인 대기 상품 → SCR-23.
- **빈 상태·오류**: 판매 중 상품 없음 → ‘새 상품’ 안내(SCR-24). 주문 없음 → ‘아직 예약이 없어요’. 실패 → 다시 시도.

### SCR-23 상품 목록 `/products`

- **관련**: FEAT-04(AC-04-2) · 탭: 상품 · 우선순위: Should
- **목적**: 내 상품과 상태를 보고 새 상품을 만든다.
- **화면 요소·데이터**: 새 상품, 상품 카드(상품명, 상태: 초안·승인 대기·반려·판매 중·종료, 반려 사유, 재승인 대기 여부). 할 일 있는 상품이 먼저.
- **입력·출력**: `GET /api/products/mine?status=&cursor=`.
- **버튼 동작**: 새 상품 → SCR-24. 카드 → SCR-25.
- **빈 상태·오류**: 상품 없음 → ‘첫 상품을 등록해 보세요’와 SCR-24.

### SCR-24 AI 상품 초안 `/products/new`

- **관련**: FEAT-03(AC-03-1~3) · 규칙: M-10~M-12, N-04 · 우선순위: Must
- **목적**: 쓰던 카톡·밴드 문구를 붙여넣어 상품 초안을 만든다(파일·사진 업로드는 P2, FEAT-29).
- **화면 요소·데이터**: 문구 입력(최대 3,000자, 글자 수), 초안 만들기, 진행 표시, 결과(상품명, 품종, 중량 옵션, 예상 당도, 등급, 받는 시기, 설명)와 빈 칸 강조, ‘가격은 단계 설정에서 정해요’ 안내, 편집으로.
- **입력·출력**: `POST /api/products/drafts`(`inputText`) → `draftId`, 추출 값, `missingFields`. 20초 안에 응답(N-04). 편집으로 → `POST /api/products`(`draftId`) → 초안 상품, SCR-25.
- **버튼 동작**: 초안 만들기 → 문구가 있을 때만, 처리 중 잠금. 편집으로 → SCR-25(값 채움). 직접 입력 → 빈 SCR-25.
- **빈 상태·오류**: 문구 없음 → 버튼 비활성. AI 실패·시간 초과 → 붙여넣은 문구를 보존하고 빈 편집 화면으로(AC-03-3). 가격이 문구에 있어도 채우지 않는다(AC-03-2).

### SCR-25 상품 편집 `/products/:id/edit`

- **관련**: FEAT-04(AC-04-1~4) · 규칙: R-16, R-18, R-20, R-21, R-23, R-25, M-13 · 우선순위: Must
- **목적**: 초안을 다듬고 게시를 요청한다.
- **화면 요소·데이터**: 기본 정보(상품명, 품종, 설명, 원산지, 보관 방법), 품질(예상·실측 당도, 등급), 중량 옵션·한 주문 최대 수량, 받는 시기(배송 예정 기간), 최대 지연 기한, 배송비(무료·별도)·도서산간, 사진, 상태와 반려 사유, 저장, 단계 설정으로, 게시 요청.
- **입력·출력**: `GET /api/products/mine/{productId}`, 저장 `PATCH /api/products/{productId}`, 게시 요청 `POST /api/products/{productId}/publish-request`.
- **버튼 동작**: 저장 → 초안 유지. 단계 설정으로 → SCR-26. 게시 요청 → 필수값·단계 가격이 모두 있을 때만 활성(AC-04-1) → 승인 대기. 판매 중 가격·옵션·단계 변경은 재승인 전까지 기존 값으로 판매(R-25).
- **빈 상태·오류**: 빠진 항목 표시. 저장 실패 → 입력 유지. 나가기 전 저장하지 않은 변경이 있으면 확인. 배송 예정 기간을 바꾸면 주문자 동의·환불 흐름 안내(R-21).

### SCR-26 단계·가격·물량 `/products/:id/stages`

- **관련**: FEAT-05(AC-05-1~3) · 규칙: R-06, R-17, R-18, R-25 · 우선순위: Must
- **목적**: 기본값으로 단계별 기간·가격·물량을 정한다. 이른 단계가 더 싸다.
- **화면 요소·데이터**: 기본값 고르기, 단계별 기간, 옵션별 가격·물량 표, 단계 사이 가격 차이 미리보기(“1단계에 사면 ○원 아껴요”), ‘이른 단계가 더 싸야 해요’ 안내, 저장.
- **입력·출력**: `GET /api/products/stage-presets`, 저장 `PUT /api/products/{productId}/stages`.
- **버튼 동작**: 기본값 선택 → 단계 수·기간·할인 폭 채움(AC-05-3). 저장 → 검증 후 SCR-25.
- **빈 상태·오류**: 칸별 이유 표시, 저장 안 함(AC-05-1·2). 실패 → 입력 유지.

### SCR-27 소식 올리기 `/broadcast/new`

- **관련**: FEAT-12(AC-12-2·3), FEAT-15 · 규칙: M-01, M-14, M-16 · 우선순위: Should
- **목적**: 팔로워에게 재배·수확 소식을 글·사진·영상으로 올린다.
- **화면 요소·데이터**: 본문, 사진(최대 5장, 장당 10MB)·영상(1개, 60초, 100MB) 첨부와 미리보기·제거, 공개 여부(공개: 농가 페이지에도 / 팔로워 전용), 받을 팔로워 수, 올리기.
- **입력·출력**: 본문이나 첨부 중 하나 이상. `POST /api/messaging/news` → `broadcastId`, 작성 시각. 연락처는 가려서 저장된다.
- **버튼 동작**: 올리기 → 1회, 성공 후 잠금 → SCR-22. 뒤로 → 쓰던 내용이 있으면 확인.
- **빈 상태·오류**: 형식·용량 오류는 파일별 사유(413). 첨부 실패 → 글은 유지하고 첨부만 다시 시도.

### SCR-28 질문함 `/questions`

- **관련**: FEAT-13(AC-13-2) · 탭: 질문함 · 규칙: M-06, M-07, M-09 · 우선순위: Should
- **목적**: AI가 넘긴 질문에 답한다.
- **화면 요소·데이터**: 답할 질문(소비자 이름 앞 글자, 질문, 전달 이유, 시각), 답한 질문, 소비자별 채팅 보기, 답 입력.
- **입력·출력**: `GET /api/messaging/questions?status=&cursor=`, 답 `POST /api/messaging/questions/{escalationId}/answer`(`text`). 답은 그 소비자 채팅에만 간다(M-09).
- **버튼 동작**: 답 보내기 → 1회, 답한 질문으로 이동.
- **빈 상태·오류**: 질문 없음 → ‘답할 질문이 없어요’. 실패 → 입력 유지.

### SCR-29 출하 처리 `/ship`

- **관련**: FEAT-17(AC-17-2~5, AC-17-1은 I2) · 규칙: R-07, R-15, R-19 · 우선순위: Should
- **목적**: 수확을 시작하고, 보낸 주문을 송장 번호와 함께 출하로 바꾼다.
- **화면 요소·데이터**: 상품별 ‘수확 시작’(예약 완료 주문 수), 출하할 주문 목록(주문 번호, 옵션·수량, 받는 사람·연락처·주소·배송 메모, 상태), 주문별 송장 번호 입력과 ‘출하로 바꾸기’, 상태 필터.
- **입력·출력**: `GET /api/orders/producer?status=&cursor=`. 수확 시작 `POST /api/orders/producer/harvest-start`(`productId`). 출하 `POST /api/orders/{orderId}/ship`(`trackingNumber` 선택, 50자 이하).
- **버튼 동작**: 수확 시작 → 확인 창 → 그 상품의 예약 완료 주문이 출하 준비(AC-17-3). 출하로 바꾸기 → ‘이 주문을 출하로 바꿀까요?’ 확인 → 출하, 출하일·송장 기록(AC-17-2). 배송 완료는 생산자가 바꿀 수 없다(AC-17-4).
- **빈 상태·오류**: 출하할 주문 없음 → ‘지금 보낼 주문이 없어요’. 409(이미 바뀜·허용되지 않는 상태) → 최신 상태로 다시 그림. 자연어 입력·AI 주문 찾기는 I2.

### SCR-30 농가 프로필·링크 `/farm`

- **관련**: FEAT-02(AC-02-1·2), FEAT-19(AC-19-1~3) · 탭: 농가 · 우선순위: Should
- **목적**: 프로필을 고치고 농가 링크를 단골에게 보낸다.
- **화면 요소·데이터**: 농가 링크 복사·휴대폰 공유, 프로필 편집(농가명, 지역, 소개, 대표 사진), 소비자 앱으로 가기.
- **입력·출력**: `GET`·`PATCH /api/farms/me`. 링크는 응답의 `shareUrl`(`/s/farms/{farmId}`).
- **버튼 동작**: 복사 → ‘복사했어요’. 공유 → 휴대폰 공유 창. 저장 → 검증 후 저장.
- **빈 상태·오류**: 필수값이 비면 저장하지 않고 빈 칸 표시(AC-02-2). 승인 전에는 링크를 보여주지 않는다.

## 7. API

### 7.1 공통

- **기준 주소**: 서버의 `/api`(앱), `/admin`(운영자, Swagger UI), `/s`(공유 링크). 버전 접두어는 쓰지 않는다([server/spec.md](/server/spec.md)).
- **인증**: `Authorization: Bearer <액세스 토큰>`. I1 토큰은 Mock 로그인(`POST /api/auth/test-login`)으로 받는다. 표의 ‘공개’는 토큰 없이 된다.
- **오류 형식**: 모든 오류는 `{"code": "...", "message": "...", "details": {}}`. `message`는 화면에 그대로 보일 한국어 문구(정책 문서), `details`는 필드별 오류·최신 값 등.

  | 상태 | code | 언제 |
  | --- | --- | --- |
  | 400 | `VALIDATION_ERROR` | 입력 형식·필수값. `details.fields`에 필드별 사유 |
  | 401 | `UNAUTHENTICATED` | 토큰 없음·만료 → 로그인(SCR-05) |
  | 403 | `FORBIDDEN` | 역할·승인 상태·소유권 부족(N-06) |
  | 404 | `NOT_FOUND` | 없음. 남의 주문·대화도 404 |
  | 409 | `CONFLICT` | 상태·물량 충돌. `details.reason`: `STAGE_CHANGED`, `SOLD_OUT`, `QUANTITY_LIMIT`, `INVALID_TRANSITION`, `IDEMPOTENCY_MISMATCH`. 최신 값을 `details`에 담는다 |
  | 413 | `PAYLOAD_TOO_LARGE` | 첨부 개수·용량 초과 |
  | 5xx | `INTERNAL_ERROR` | 서버 오류. AI 실패는 오류로 돌려주지 않고 각 FEAT의 대체 동작(전달, 빈 초안)으로 처리 |

- **페이지네이션**: 목록은 `limit`(기본 20, 최대 50)과 `cursor`. 응답 `{"items": [...], "nextCursor": "..." | null}`. 정렬은 각 화면의 순서를 따른다.
- **멱등 키**: `POST /api/orders`와 `POST /api/orders/{orderId}/pay`는 `Idempotency-Key`(UUID) 헤더가 필수다. 같은 사용자·같은 키는 처음 결과를 그대로 돌려주고, 같은 키에 다른 본문이면 409 `IDEMPOTENCY_MISMATCH`. 키는 24시간 보관한다.
- **시간 제한**: AI 초안 20초, 문의 응답은 시간을 넘기면 전달(N-04).
- **개인정보**: 응답·로그에 필요한 것만(N-05). 생산자에게 배송 정보는 배송 완료 전 주문만(R-15).
- **경로 순서**: 같은 prefix에서 고정 경로(`/mine`, `/me`, `/following`, `/drafts`, `/stage-presets`, `/producer`)를 경로 변수(`/{productId}`, `/{farmId}`, `/{orderId}`)보다 먼저 등록한다.

### 7.2 엔드포인트

I1 열: Must 화면(4장)이 쓰는 API는 Must, 나머지는 Should다. 단 Must 화면에 있어도 Should 기능으로 이어지는 좋아요·채팅 시작 API는 Should다. 운영자 API는 게시에 필요한 상품 승인만 Must다. **Must API는 23개**(전체 57개 중)다. Should API를 쓰는 버튼은 API가 준비될 때까지 프론트에서 숨긴다.

## 8. P21 5장 “확정할 항목” 정리

| # | P21 항목 | 상태 | 정해진 곳 |
| --- | --- | --- | --- |
| 1 | 결제 여부·시점, 취소·환불, 수량 한도·품절 | 정해짐 | 예약 때 전액 카드 결제(R-01·R-02, FEAT-09), 출하 전 전액 환불(R-07·R-08, FEAT-11), 출하 후 하자만(R-11, 정책 1장), 한 주문 최대 수량(R-23), 단계 물량 품절(R-06) |
| 2 | 로그인 방식, 계정 전환, 역할별 접근 제어 | 정해짐 | I1 Mock 로그인(ADR 0009, FEAT-01), 같은 계정으로 두 앱(IA-Q4), 서버 권한 검사(N-06, IA 6장) |
| 3 | 배송지 저장, 개인정보 보관·마스킹·삭제 | 일부 열림 | 저장 배송지 `ShippingAddress`와 주문 시점 복사(기술 설계), 배송 완료 후 가림(R-15), 연락처 가림(M-16). 보관 기간·탈퇴 처리는 열림(PRD Q-20, 정책 PQ-06) |
| 4 | 자료 업로드 형식·용량·개수·보존 기간 | 정해짐(I1) | 상품 초안은 텍스트만(M-10, 3,000자). 파일·사진은 P2(FEAT-29). 소식 첨부 한도는 FQ-05. 원본 보존 기간은 PQ-06과 함께 열림 |
| 5 | AI 초안 필드 필수 여부, 신뢰도 표기, 실패 재시도·사용량 | 일부 열림 | 출력 항목과 빈 칸 표시(FEAT-03, M-11), 가격은 안 채움(M-12), 20초(N-04), 실패하면 직접 입력(AC-03-3), 비용 한도는 Claude Console(stack.md 6장). 신뢰도 표기는 하지 않음(I1). 사용자별 횟수 제한은 열림 |
