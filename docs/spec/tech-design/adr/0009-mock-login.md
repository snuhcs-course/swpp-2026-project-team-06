# 0009 I1 로그인: 시드 테스트 계정 Mock 로그인

- 상태: 결정 (2026-10-07, P22 SWPP-26). 앱별 테스트 계정으로 갱신 (2026-10-07, SWPP-81, [0010](./0010-separate-accounts.md))
- 관련: FEAT-01, AC-01-1, 3~6, R-22, N-06, N-07, [0003](./0003-auth-kakao.md)(카카오, I2로 연기)

## 배경
I1 데모(10/9)는 소비자·생산자·승인 대기 생산자·운영자 흐름을 한 번에 보여줘야 한다. 카카오 로그인은 카카오 개발자 콘솔 설정, 리다이렉트 주소 등록, 실제 카카오 계정이 있어야 하고, 데모 때마다 여러 역할로 바꿔 들어가기 번거롭다. P21 화면 명세도 로그인 화면을 범위 밖으로 두었다.

## 결정
- I1은 시드된 테스트 계정 중 하나를 고르는 Mock 로그인을 쓴다. 계정은 앱별로 따로다(ADR 0010). 소비자 앱(SCR-05)은 소비자 2명(김민지·이서준), 생산자 앱(SCR-19)은 생산자 5명(강영수 승인·오미숙 확인 중·박순자 반려·최태호 정지·신규 생산자 농가 없음)을 보여준다. 운영자 작업은 Swagger UI의 관리 API로 한다(ADR 0008).
- 서버는 `GET /api/auth/test-accounts?app=`(그 앱의 계정 목록)와 `POST /api/auth/test-login`(`userId`, `app` → JWT)을 둔다. 계정의 역할이 `app`과 다르면 403 `WRONG_APP`이다. 둘 다 설정 플래그 `MOCK_LOGIN_ENABLED`가 켜져 있을 때만 동작하고, 꺼져 있으면 404다.
- 로그인할 수 있는 계정은 `User.isTestAccount = true`인 시드 계정뿐이다. 임의 계정을 만들거나 다른 사용자로 로그인할 수 없다(AC-01-4).
- 로그인 뒤 권한 검사(역할, 농가 승인 상태)와 JWT 형식은 카카오 로그인 때와 같다. 앱의 로그인 관문(팔로우·예약·채팅·좋아요 때만 로그인)도 그대로다.
- I1 데모 배포에서는 플래그를 켠다. I2에서 카카오 로그인(ADR 0003)으로 바꿀 때 플래그를 끄고, 테스트 계정은 지우거나 비활성화한다.

## 위험과 대응
- **누구나 테스트 계정으로 들어올 수 있다.** 데모 주소를 아는 사람은 누구든 아무 테스트 계정으로 로그인해 주문·채팅·소식을 만들 수 있다. 대응: 테스트 계정에는 실제 개인정보를 넣지 않는다(이름·연락처·주소는 가짜). 실제 결제도 없다(Mock 결제). 데모 전에 시드를 다시 넣을 수 있게 한다(N-07).
- **플래그를 끄지 않고 실운영으로 갈 위험.** 대응: 운영 환경 설정에서 기본값을 꺼짐으로 두고, 켜려면 환경 변수로 명시해야 한다. I2 카카오 전환 이슈의 완료 조건에 “플래그 끔”을 넣는다.
- **운영자 API는 Mock 로그인으로 열리지 않는다.** 테스트 계정에는 `ADMIN` 역할을 주지 않는다. 관리 API는 별도 운영자 계정으로만 쓴다(N-06).
- **개인정보 동의 흐름을 I1에서 검증하지 못한다.** 동의 기록은 카카오 로그인(I2)에서 구현한다. I1 화면에는 약관·처리방침 링크만 둔다(정책 5장).

## 결과
- 데모에서 앱마다 계정을 골라 S-1~S-4를 이어서 보여줄 수 있다. 생산자 상태(확인 중·반려·정지·농가 없음)도 시드 계정으로 바로 보여준다.
- 카카오 연동 코드는 I1에 없다. `server/.env.example`의 카카오 변수는 I2용으로 남긴다.
