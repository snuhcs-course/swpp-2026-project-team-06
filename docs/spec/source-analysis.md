# 기존 자료 일괄 분석 · 제품 명세 (DEV-53)

## DEV-186 두 단계 상세 초안 (2026-11-01)

이 절은 아래의 추출값 자동 반영·과거 판매 참고 규칙을 구체화한다. FEAT-03/04/07 · AC-SRC-1/2/3/5/6/7/10/11.

1. **추출**: 기존 방식대로 넓게 후보를 수집한다. 금액·과거 판매 문장은 `historicalSales`/`historical=true` 등의 원문 후보와 근거로 보존한다. 추출 단계에서 문장을 판매용으로 다시 쓰지 않는다.
2. **정리**: run의 전처리·추출이 모두 성공하고 현재 후보 집합 또는 프롬프트/안전 목록 버전이 바뀌면 대상 상품마다 한 번, 현재 유효한 후보의 ID·fieldKey·값·과거 여부·근거 인용을 정리 모델에 전달한다. 모호한 대상이나 다른 상품의 사실은 사용하지 않는다. 모듈 순서대로 `{modules:[{module,texts:[{value,candidateIds}]}], excluded:[{candidateIds,reason}]}`를 받는다. 동일 재분석은 입력 후보 집합·현재 프롬프트 버전·안전 목록 JSON SHA256이 모두 같은 저장 정리만 재사용하며 새 작업을 만들지 않는다. 버전이나 해시가 다르면 오래된 결과로 보고 다음 분석에서 다시 정리한다. 각 문구는 하나 이상의 후보 ID를 인용한다.
3. **검토·저장**: 정리 문구만 자동 채움하고 출처는 `REFINED`로 기록한다. 원문 후보는 변경하지 않고 검토 근거로 계속 표시한다. 생산자가 고친 내용은 `PRODUCER`다. 정리 실패 시 run을 종료하고 오류를 기록하며 기존 원문 제안으로 돌아간다. 이 경우에도 금액 있는 문구는 확정·저장할 수 없다. 정상 정리에서 누락·거절한 문구는 원문으로 자동 복원하지 않는다. 취소·자료 삭제·버전 변경으로 비활성 정리가 오래되면 원문 fallback을 허용한다. 현재 후보에 대한 REFINE이 실제 대기 중일 때만 fallback을 막는다.

허용하는 정리는 조각 연결·중복 병합·오탈자·제목/본문 분리이며 이모지·반복 !!·장식 기호/~·광고 구호를 제거한다. 원문의 존댓말과 숫자·단위·품종·인증명·부정·완곡 표현(간혹, ~할 수 있어요)을 유지한다(수치 범위의 ~는 보존). 새로운 사실·수치·건강/효능 주장·과장은 금지한다.

상세 문구에는 **어떤 금액도 넣지 않는다**. 현재/과거 판매가·배송비·반품비·무료배송 기준 금액을 포함한다. 금액 없는 완판·단골·판매 연수는 `farmStory`(농가 이야기), 금액이 있는 과거 판매 문장은 전체 제외한다.

2026-11-01 owner 변경: **R-19에 따라 출하는 판매자가 처리하므로 배송 방법은 상품 정보다.** 택배사, 포장·완충, 농장 직배송, 수확 직후 포장·발송, 도서산간 배송 가능 여부를 `delivery`(포장 섹션)에 보존한다. 아래만 제외한다.

- 기간(`period`): 판매/예약 기간(판매가 셀의 기간 포함), 품절·판매 종료·재입고, 배송 소요일·도착일·출고 요일(1-3일 이내, 월·수 출고, 주문 후 2-3일). 받는 시기는 생산자가 ② 판매·가격에서 정한다.
- 금액(`price`): 모든 금액과 배송비·무료배송 기준 금액. 배송비는 생산자가 ②에서 정한다(R-20).
- 팜클럽 공통 정책(`platform`): 교환·환불·반품·보상 조건, 고객센터·시간·연락 채널, 주문·결제·입금, 구매 한도, 중량/크기 옵션 선택.

상품 사실이 섞이면 그 사실만 남긴다: `재배 중 생긴 얼룩·점은 교환 불가` → appearanceFaq `재배 과정에서 얼룩·점·색 차이가 생길 수 있어요`, `1-3일 이내 제주에서 직배송` → delivery `제주 농장에서 직접 보내요`. 팜클럽 정책 문장을 새로 만들지 않는다. 수확·선별·포장 방법과 신선도 사실은 유지한다.

건강 효능(면역·소화·피로·다이어트·피부/미용·질병 예방·효능)과 이에 연결된 영양소 주장은 AI 문구에서 제거하고 생산자 직접 저장도 거절한다. `건강하게 키운`과 중립 영양소 정보는 허용한다. 맛·당도·과즙·식감·크기 사실은 summary에서 taste로 분리한다. 품종 기원/지역과 맛이 섞인 한 원문은 두 문구로 나누고 같은 후보를 인용할 수 있다. 개인정보·메뉴·워터마크·다른 상품 사실도 제외한다.

서버는 문구별로 금액·건강 효능, `scrub`이 바꾸는 개인정보, 인용 후보 값/근거에 없는 숫자 또는 숫자-단위 조합, 다른 상품/없는 후보 ID, 비텍스트 모듈을 거절하고 비공개 진단에 기록한다. 정제 출력의 플랫폼·기간 단어는 `PLATFORM_TEXT`/`PERIOD_TEXT` warning이며 거절하지 않는다. 제외 판단은 정리 모델 책임이다. 금액 있는 과거 후보 인용 및 과거 사실을 농가 이야기 밖에 배치하는 것도 거절한다. 조회 시 저장된 정리 문구도 현재 금액·건강 효능 detector로 재검사해 위반 문구를 빼고 price/health 제외 사유를 제공한다. 건강 효능 후보는 중립 영양소만 남기더라도 인용하지 않고 전체를 health로 제외한다. 확정/저장에서도 금액·건강 효능을 검사한다. editor 경로는 활성·비제외 필드만 검사하고, 비편집 `save_drafts`는 비활성 필드도 포함한 모든 CONFIRMED 필드를 검사한다. 생산자가 직접 쓴 플랫폼 문구는 저장을 허용하고 UI 경고만 표시한다. `REFINED` 수정 요청은 저장된 정리 문구와 인용 ID가 일치하며 현재 유효한 대상 근거일 때만 허용한다.

원문 fallback은 usable 대상별 후보 1개면 ready, 여러 개면 conflict를 먼저 적용한다. 금액·효능·플랫폼·기간 detector로 걸러낸 뒤 사용할 수 있는 대상별 후보가 없을 때만 공통(targetId=None) 후보를 unassigned로 표시한다. 성공한 정리가 생략한 필드는 원문으로 되살리지 않는다. 문구 선택 버튼은 공유 detector로 금액·효능 후보를 숨기고 플랫폼 후보는 유지한다.

SUCCEEDED REFINE의 일부 문구 거절은 diagnostics/refinement.excluded에만 남기며 Item.error는 null이다. FAILED REFINE 안내는 anchor 파일명을 붙이지 않는 문구 정리 전용 메시지다. 응답 뒤 자료/가림 변경으로 정리를 폐기해도 usage와 request_id는 실패 진단에 보존한다.

정리 단계도 동일 제공자/모델과 비용 예약·정산·한도를 사용한다. 실패·불확실 전송은 자동 모델 fallback/재호출하지 않는다. 재분석은 생산자의 수정·제외·확정 값을 덮어쓰지 않고, 공개 반영은 여전히 명시적 적용에서만 한다. 제외 내역은 아래 계약과 SCR-24 안내로 표시한다. 금액 없는 과거 사실이 농가 이야기에 반영되었다면 제외 안내에 넣지 않는다.

### 제외 내역 계약·생산자 안내 (결정4~7)
- 모델의 reason: `price | period | platform | health | pii | other_product | unsupported | duplicate`. 현재 대상 후보는 정리 문구에서 인용하거나 excluded에 포함해야 한다. 일부만 줄인 후보는 둘 다 가능하다.
- 서버는 미사용 후보를 `unused`로 채우고 검증 거절 문구의 후보도 금액→price, 효능→health, 개인정보→pii, 근거/형식→unsupported 사유로 기록한다. 플랫폼·기간 warning은 제외 사유를 강제로 만들지 않는다. 후보당 한 사유를 저장하고 검증 거절이 모델 사유보다 우선한다. 원문 후보는 변형하지 않는다.
- REFINE Item JSON에 modules/excluded/refinementVersion을 저장한다. 검토 API `refinementResults[targetId]`는 `{excluded:[{candidateId,value,reason}], refinementVersion}`을 제공한다. version은 정리 결과(모듈·인용·제외 목록)의 SHA-256이며 일반 reviewVersion/조회/저장/같은 결과 재분석으로 바뀌지 않는다. 현재 결과가 없으면 빈 목록/null이다.

## I3 평가 동결 (DEV-172, 2026-10-31)

FEAT-03/04/07 · AC-SRC-1/2/3/5/6/8의 평가 자료·채점 계약은 [I3 v1 평가 규칙/개인정보 검토](validation/source-corpus-i3-v1.md)와 [동결 manifest](validation/source-corpus-i3-v1.json)를 따른다. I2 실제12건+합성18건은 모두 development이며 vision6건은 실제12건의 부분집합이다. 계약 전용2건은 별도 보존한다. 독립 holdout IDs는 `[]`, 상태 **BLOCKED**다. 기존 holdout4건도 개발 반복에 노출되어 재사용할 수 없다. 신규 권한/개인정보 검토된 독립 자료를 형식별3건(총12건) 확보·gold 합의·새 버전 잠금한 뒤 측정한다.

필드/대상/전체 값 exact P/R을 주 점수로, 명시적 정규화는 별도 진단으로 보고한다. 실패·빈 응답·거절·미실행을 분모에서 빼지 않으며 중요 사실의 원본 대조 감사를 별도로 요구한다. 원문/gold 전문은 비공개, 저장소에는 값/근거 해시와 위치만 둔다. 기존 gold53개 중 OCR 입력과 근거 위치11개가 미연결이므로 해당 준비 상태도 BLOCKED다. 이 동결은 새 품질 측정·실제 농가 인수·운영 동작 변경이 아니다.

### 최종 페이지 문장 평가 (DEV-187, 2026-11-01)

## 백엔드 구현 범위 (DEV-54)
- 승인 생산자 전용 `/api/source-analysis/batches`에서 자료·비동기 분석·가림 검토·출처 후보·확인값·상품별 비공개 초안을 관리한다. 기능은 기본 비활성이고 Mock/실제 모드는 명시적으로 구분한다.
- 동일 내용 후보는 출처와 candidateIds를 합쳐 표시하고 다른 값은 충돌 목록으로 제공한다. 원문과 달라진 수동 편집은 PRODUCER 출처로 기록한다. AI 후보는 유효한 근거가 있어야 확인할 수 있다.
- 실제 분석은 준비된 사본의 privacy 승인 이후 진행한다. 가림/상품 연결 변경은 기존 결과를 outdated로 만들고, 확인값을 자동 삭제하거나 새 추출값으로 덮어쓰지 않는다.
- 저장은 schemaVersion=1의 18개 modules이며, previewModules에는 켜진 유효한 내용만 포함(자동 채움은 사용자 확인과 구분; 최신 AC-SRC-11은 source-integration.md 참조)하고 출처·검토 메타데이터를 제거한다. 공개 상품·운영 가격·재고·주문은 쓰지 않는다.
- 중복 파일은 DUPLICATE_SOURCE와 기존 sourceId로 안내한다. 대상 상품 ID는 유지하며 이름 변경/상품 추가를 지원한다. 대상 삭제는 새 batch 생성으로 처리한다.
- 분석·초안 저장은 멱등 키, 수정은 version/reviewVersion을 검사한다. 전송 결과 불명확 오류의 재시도는 비용 가능성 확인이 필요하다. API·설정·실행은 [서버 문서](../../server/app/source_analysis/README.md), 요청 스키마는 OpenAPI를 따른다.
- 실제 농가 자료 20묶음에 대한 Sol 품질·속도·비용 평가는 아직 하지 않았다. 선택적 AI 이미지 생성은 계속 고려 중이다.

## 목표와 확정 범위
- 생산자가 미리 지정한 상품 목록을 기준으로 기존 사진·판매 문구·명함·팜플렛을 일괄 분석하여 상품별 판매페이지 초안을 만든다. 임의로 새로운 상품을 만들지 않는다.
- 입력은 JPG/PNG/WebP/HEIC 사진·캡처, PDF, UTF-8 TXT, 붙여넣기 텍스트다. 명함·팜플렛은 촬영 이미지 또는 PDF로 받는다. 영상·음성·URL 수집·HWP/HWPX/DOCX 원본은 제외한다.
- 생산자 흐름은 상품 지정 → 자료 넣기 → 일괄 분석 → **자동 채움·항목별 ON/OFF·직접 편집** → 원본 사진 보충 → 단일 템플릿 미리보기 → 상품별 초안 일괄 저장이다.
- 현재 18개 요소와 구매자 중심 순서를 유지한다. 재고·가격·주문·예약 기간을 AI가 변경하거나 직접 게시하지 않는다.

## 모델 결정과 추후 측정
- **초기 분석 모델: OpenAI GPT-6.1 Sol.** 문서·이미지 이해, 상품별 항목 추출, 출처 연결, 충돌 후보 발견, 사실을 유지한 문구 정리에 사용한다. 렌더링과 데이터 검증은 일반 코드가 담당한다.
- 새 자료 분석 작업에 한해 서버 AI 어댑터에 모델을 설정한다. 기존 Claude 기반 상품 단건 초안·채팅 기능은 전환하지 않는다. 브라우저에 API 키를 두지 않는다.
- 선택은 사용자 결정이며 성능 검증 완료를 뜻하지 않는다. 기존 ‘Sonnet 우선’ 제안은 이번 결정으로 대체한다. 자동 모델 전환이나 복수 제공자 상시 호출은 초기 범위에 넣지 않는다.
- 실제 농가 자료로 필드 정확도·누락, 숫자/단위 오독, 상품 간 혼동, 출처 일치, 원문에 없는 주장 추가, 생산자의 수정량을 측정한다. 작업별 입력/출력 토큰·실제 API 비용·재시도 비용과 처리 시간(p50/p95)을 함께 기록한다.
- 개인정보를 제거한 동일한 정답 자료 묶음을 고정하고 모델·프롬프트 버전을 기록한다. 평가 후 모델과 비용 최적화를 재검토한다. 아직 측정값·정확도 보장·건당 비용을 확정하지 않는다.
- 공식 참고: [모델 비교](https://developers.openai.com/api/docs/models/compare), [파일 입력](https://developers.openai.com/api/docs/guides/file-inputs), [구조화 출력](https://developers.openai.com/api/docs/guides/structured-outputs). 구조화된 결과의 형식 준수가 사실 정확성을 보장하지는 않는다.

## 자료 분석과 검토
- 파일별 상품 지정 또는 농가 공통/여러 상품 자료 지정을 지원한다. 불명확한 상품 연결은 확인 대상으로 남긴다. 공통 설명을 모든 상품의 사실로 무조건 복사하지 않는다.
- 편집 카드는 항목·추출 내용·표시 스위치·선택적 원문 보기로 구성한다. 별도 검토 탭/개별 확정 절차는 두지 않는다. 상태는 확인 전/확인 완료/충돌/자료 없음/제외이며, 상품 연결 필요 자료는 별도 목록이다.
- 출처는 원본 파일·페이지·문구 또는 이미지 영역으로 연결한다. 원문과 다듬은 문구를 비교하고 수정·채택·제외할 수 있다. 출처를 찾지 못한 값을 확인 완료로 만들지 않는다.
- 중복 내용은 출처를 유지하며 합친다. 서로 다른 값은 후보를 나란히 보여 주고 생산자가 선택한다. 원문 날짜가 없으면 미상으로 남긴다.
- 상품명·품종·원산지·규격·구성·개수는 명시된 값만 추출한다. 무게로 개수를 계산하지 않는다.
- 문구는 중복·오탈자 정리, 제목/본문 분리 등으로 편집하되 새로운 판매 주장이나 과장을 추가하지 않는다. 광고 표현을 품질 증거로 취급하지 않는다.
- 당도·인증·품질 기록은 수치·단위·측정일·대상·유효기간 중 원문에 있는 정보만 함께 가져온다. 예상값을 실측으로 바꾸거나 오래된 자료를 현재 증빙으로 확정하지 않는다.
- 과거 가격·예약 기간·재고·행사는 참고 정보로 분리하고 현재 판매 설정·취소선 가격에 자동 반영하지 않는다. 배송·보관·문제 접수 조건도 현재 적용 여부를 확인받고 서비스 정책을 덮어쓰지 않는다.
- 자료가 없는 항목은 비워 두고 필요한 자료를 구체적으로 요청한다. 일반 지식으로 판매 사실을 보충하지 않는다.

## 사진과 상세 구성
- 문서 속 사진은 내용 이해에만 쓴다. 잘라서 판매 본문으로 재사용하지 않고, ‘상품 A의 실제 배송 상자 사진’처럼 상품·용도를 지정하여 원본 사진을 요청한다.
- 별도 원본 사진은 대표 상품/크기/단면/작업/포장/농가 전경 등의 용도를 제안하고 생산자가 연결·사용 여부를 확인한다. 내용과 비율을 보존하고 생성·복원·합성·자동 누끼를 제공하지 않는다.
- 사진에서 당도·중량·개수·인증·원산지·실측 크기를 추정하지 않는다. 기존 손 위 감귤 일러스트는 설명용 표시를 유지하고 생산자가 직접 선택한다.
- 순서는 상품 소개 → 구성·개수 → 맛·크기 → 품질·생산 → 포장·배송 → 보관 → 구매 전 확인 → 선택적 농가 이야기·소식이다. 생산자가 18개 요소를 켜고 끈다.
- 제작 화면에는 부족한 자료를 표시한다. 소비자 미리보기에는 미입력 자리·검토 출처·미해결 충돌/오래된 주장을 노출하지 않는다. 기존 전체 보기의 ‘모든 구성 예시 표시’는 디자인 검토용 동작으로 별도 유지한다.
- 저장은 비공개 초안이다. 판매 중 페이지의 공개 반영은 기존 상품 편집·권한·수정 가능 상태·버전 검사와 명시적 반영 절차를 따른다.

## 작업 상태·자료 보호·최소 인터페이스
- 분석 진행/부분 성공/완료/실패를 파일별로 표시한다. 실패 자료만 재시도하며 성공 결과와 생산자 편집을 보존한다. 실패를 Mock 예시로 대체하지 않는다.
- 작업과 결과는 재접속 후 복구한다. 재분석은 변경 후보로 제시하고 기존 확인·수정·제외 내용과 요소 선택을 자동 덮어쓰지 않는다.
- 원본은 농가별 비공개 자료로 저장한다. 소비자에게는 명시적으로 선택·반영된 사진과 본문만 공개한다.
- 외부 AI 전송 전에 내부 OCR·개인정보 인식 및 가림을 수행한다. 연락처·상세 주소·계좌 등 가림이 불확실하면 확인 전 전송하지 않는다. 원본과 OCR 전문은 일반 로그·분석 이벤트에 기록하지 않는다.
- 새 계약은 자료 등록/조회/삭제, 분석 시작/상태/재시도, 추출 결과 수정/확인, 상품별 상세 초안 저장을 다룬다. 기존 텍스트 초안 API와 detailContent는 호환성을 유지한다.
- 최소 엔티티는 분석 작업, 원본 자료, 상품 연결, 출처가 붙은 추출 항목, 확인 상태, 사진 용도, 상세 구성 선택이다. 운영 가격·물량과 상세 설명용 데이터는 분리한다.
- 텍스트/이미지 최대 30블록인 현재 detailContent에 표·공정·FAQ를 임의로 끼워 맞추지 않는다. 비공개 초안은 별도 schemaVersion=1의 18개 요소 계약을 사용하며 기존 상세 읽기는 유지한다.
- 초기 기본 한도: 작업당 상품10개·파일30개·전체100MB, 파일당20MB, PDF당20페이지·작업 전체60페이지, TXT/붙여넣기 합계30,000자. 한도는 측정 전 기본값이며 AI 요청 단위 한도에 맞춰 분할 처리한다. 기존 단건20초 목표를 일괄 작업 전체에 적용하지 않는다.

## 인수 조건
