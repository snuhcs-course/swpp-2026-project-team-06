### 결정 사항
- 11/19 PM: 첫 로그인 약관 동의 화면(기존 SCR-06 재사용)의 '동의하고 시작하기'는 필수 체크 전 꺼진 지금 방식 그대로 둔다(11/18 버튼 규칙의 예외, 체크 상자 화면이라). 처리방침 2026-11-20 시행은 그대로, 공지는 다음 로그인 재동의 화면으로 갈음한다(제14조 30일 사전 공지는 아이디 계정이 운영자 생성 심사·테스트용뿐이라 실질 변경이 적다고 판단).
- 11/18 **PM 결정 변경**: 공개 아이디 가입 없음, 운영자가 계정 생성. 관리자 웹 ‘아이디 가입 승인’(`/signups`)을 지우고 ‘아이디 계정’(`/id-accounts`)으로 바꿨다: 만들기 폼(앱·아이디·닉네임/이름·소비자 휴대폰 선택, 한 번 누름, 오류 칸만 빨갛게) → 서버가 만든 임시 비밀번호를 한 번만 보임(복사·닫기, 저장·콘솔 없음, 닫기·다시 그리기·페이지 떠날 때 DOM에서 지움, 재시도로 비밀번호가 없으면 ‘임시 비밀번호’로 다시 발급하라고 안내) + 목록(전체·소비자·생산자, 검색, ‘임시 비밀번호 사용 중’·‘약관 동의 전’·농가 상태 배지, 두 번 눌러 ‘임시 비밀번호’). 정지·삭제 버튼은 기존 관리자 패턴이 없어 두지 않았다.
- 11/18 공용 조각 `packages/ui/src/AuthForms.tsx`: 로그인 폼(가입 버튼 없음), 비밀번호 변경 폼, 오류 칸 스크롤. 서버 호출은 앱이 넘긴 함수가 한다. 규칙 문구·검사는 `packages/api/src/passwordRules.ts`(서버와 같은 규칙, 최종은 서버).
- 11/18 `Input`에 `secure`(가림 + ‘보기/숨기기’), `plain`, `autoComplete`, `onSubmitEditing`, `testID`를 더했다(기존 호출은 그대로).
- 11/18 클라이언트 `onAccountGate`: 403 `PASSWORD_CHANGE_REQUIRED`면 알림(토큰은 지우지 않음). 동의 전 403은 기존 `ONBOARDING_REQUIRED`(소비자)·`CONSENT_REQUIRED`(생산자) 처리를 그대로 탄다.
- 11/18 Mock: 공개 가입 핸들러를 지웠고(관리자 화면이 없어 테스트가 저장소에 계정을 넣는다), 서버와 같은 관문(임시 비밀번호 → 동의 전 아이디 계정). 비밀번호는 Mock에서도 원문 대신 `mockPasswordHash`(원문을 숨기는 값, 보안 해시 아님)만 둔다.
- 11/18 분석: `/password`를 `PRIVATE_PATHS`에 더한다(1차의 `/signup`·`/approval`은 화면과 함께 뺐다).
- 11/18 **PM 결정(처리방침)**: 처리방침에 아이디 계정 항목(아이디, 복원할 수 없는 방식으로 암호화한 비밀번호, 운영자가 만든 심사·테스트용 계정, 로그인 시도 기록 최대 1일)과 비밀번호 보호 조치를 더하고(‘비밀번호는 받지 않습니다(카카오 로그인)’ 문장을 고침) 동의 버전·시행일을 2026-11-20으로. 기존 회원은 다음 이용 때 기존 재동의 화면(SCR-06 ‘약관이 바뀌었어요’, 생산자 `/consent`)을 본다. `scripts/test-legal.mjs`의 ‘이 변경은 버전을 올리지 않는다’ 테스트들은 버전 고정값만 2026-11-20으로 바꿨다(그 변경들이 올리지 않은 사실은 변경 기록 문장 검사로 남음).
- 11/18 **PM 결정**: IP별 제한 없음(아이디별 잠금만), 로그인 화면 문의 경로 그대로.
