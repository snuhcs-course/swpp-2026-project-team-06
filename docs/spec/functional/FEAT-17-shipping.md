# FEAT-17 출하 처리

> 상위: [PRD](/docs/spec/prd.md) 7.1 · 규칙: [rules.md](./rules.md) · 화면: [IA](/docs/spec/ia.md), [화면 명세](/docs/spec/screens.md) · 추적표: [README](./README.md)

| 항목 | 내용 |
| --- | --- |
| 우선순위·출처 | P0 · PRD 7.1, S-4 |
| 앱·화면 | 생산자 앱 SCR-29 |
| 목적 | 보낸 주문을 송장 번호와 함께 출하로 바꾼다. I1은 주문별 상태 변경이고, 자연어 입력을 AI가 해석해 주문을 찾는 기능은 I2다 |
| 사전 조건 | 승인된 생산자이고 예약 완료 또는 출하 준비 주문이 있다 |
| 정상 흐름 | 1) 상품별 ‘수확 시작’ → 그 상품의 예약 완료 주문이 출하 준비 2) 출할 주문 목록 표시(받는 사람·연락처·주소·배송 메모) 3) 보낸 주문을 골라 송장 번호 입력(선택) 4) ‘출하로 바꾸기’ → ‘이 주문을 출하로 바꿀까요?’ 5) 확인 → 출하, 출하일·송장 번호 기록. (I2) 3)\~4) 대신 “김○○님 5kg 오늘 보냈어요, 송장 123-456”을 입력하면 AI가 주문과 송장 번호를 찾아 확인을 요청한다 |
| 예외 흐름 | E1 이미 바뀌었거나 허용되지 않는 상태(409) → 최신 상태로 다시 그림. E2 확인 창에서 취소 → 아무것도 바뀌지 않음. E3 다른 농가 주문 → 거부. E4 배송 완료로 바꾸려 함 → 생산자는 바꿀 수 없음(운영자, R-19) |
| 사후 조건 | 주문은 출하, 소비자는 더 이상 취소할 수 없고 주문 상세에서 송장 번호를 본다 |
| 입력·검증 | 송장 번호는 없어도 되고, 있으면 50자 이하. 생산자가 바꿀 수 있는 전이는 예약 완료 → 출하 준비(수확 시작), 출하 준비 → 출하뿐이다 |
| 규칙 | R-07, R-15, R-19 |

- [ ] AC-17-1. (I2, 자연어 출하) **Given** AI가 주문을 찾아 확인을 요청했다 / **When** 확인을 누르기 전이다 / **Then** 어떤 주문도 상태가 바뀌지 않는다
- [ ] AC-17-2. **Given** 출하 준비 주문이다 / **When** 확인을 누른다 / **Then** 소비자 주문 상세가 ‘출하’로 바뀌고 취소 버튼이 사라진다
- [ ] AC-17-3. **Given** 예약 완료 주문이 3건인 상품이다 / **When** ‘수확 시작’을 누른다 / **Then** 3건 모두 출하 준비가 되고, 소비자는 여전히 취소할 수 있다
- [ ] AC-17-4. **Given** 출하된 주문이다 / **When** 생산자가 배송 완료로 바꾸는 요청을 보낸다 / **Then** 거부되고 상태는 출하로 남는다
- [ ] AC-17-5. **Given** 출하 준비 주문에 송장 번호 “123-456”을 넣었다 / **When** 출하로 바꾼다 / **Then** 출하일과 송장 번호가 기록되고 소비자 주문 상세에 송장 번호가 보인다
