# FEAT-17 출하 처리

> 상위: [PRD](/docs/spec/prd.md) 7.1 · 규칙: [rules.md](./rules.md) · 화면: [IA](/docs/spec/ia.md), [화면 명세](/docs/spec/screens.md) · 추적표: [README](./README.md)

| 항목 | 내용 |
| --- | --- |
| 우선순위·출처 | P0 · PRD 7.1, S-4 |
| 앱·화면 | 생산자 앱 SCR-29 |
| 목적 | 보낸 주문을 송장 번호와 함께 출하로 바꾼다. I1은 주문별 상태 변경이고, 자연어 입력을 AI가 해석해 주문을 찾는 기능은 I2다 |
| 사전 조건 | 승인된 생산자이고 예약 완료 또는 출하 준비 주문이 있다 |
| 정상 흐름 | 0) (DEV-68) ‘입금 대기’ 탭에서 줄마다 ‘입금 확인 ›’ → 확인 시트 → 예약 완료(FEAT-09 AC-09-8). ‘환불’ 탭에서 입금했던 계좌로 송금한 뒤 ‘송금 완료로 표시 ›’ 1) 전체/입금 대기/예약/출하 준비/출하/환불 주문 조회(예약은 조회만) 2) 기존 출하 준비 주문 목록 표시(받는 사람·연락처·주소·배송 메모) 3) 보낸 주문을 여러 건 고르고, 줄마다 택배사·송장 번호 입력(선택) 4) ‘n건 출하로 바꾸기’ → 확인 시트 5) 확인 → 주문마다 출하 처리(주문별 API 반복), 출하일·택배사·송장 번호 기록. 소비자 주문 상세에는 ‘배송 중’과 배송 조회가 보인다. (I2) 3)\~4) 대신 “김○○님 5kg 오늘 보냈어요, 송장 123-456”을 입력하면 AI가 주문과 송장 번호를 찾아 확인을 요청한다 |
| 예외 흐름 | E1 이미 바뀌었거나 허용되지 않는 상태(409) → 최신 상태로 다시 그림. E2 확인 창에서 취소 → 아무것도 바뀌지 않음. E3 다른 농가 주문 → 거부. E4 배송 완료로 바꾸려 함 → 생산자는 바꿀 수 없음(운영자, R-19) |
| 사후 조건 | 주문은 출하, 소비자는 더 이상 취소할 수 없고 주문 상세에서 송장 번호를 본다 |
| 입력·검증 | 입금 대기 줄에는 배송지를 보여 주지 않는다(R-15). 송장 번호는 없어도 되고, 있으면 50자 이하. 현재 프론트가 제공하는 전이는 기존 출하 준비 → 출하뿐이다. 서버의 기존 RESERVED→PREPARING 계약은 유지하되 UI·프론트 호출 및 자동 전이는 없다 |
| 규칙 | R-07, R-15, R-19, R-28 |

- [ ] AC-17-1. (I2, 자연어 출하) **Given** AI가 주문을 찾아 확인을 요청했다 / **When** 확인을 누르기 전이다 / **Then** 어떤 주문도 상태가 바뀌지 않는다
- [ ] AC-17-2. **Given** 출하 준비 주문이다 / **When** 확인을 누른다 / **Then** 소비자 주문 상세가 ‘배송 중’(상태 `SHIPPED`)으로 바뀌고 취소 버튼이 사라진다
- [ ] AC-17-3. **Given** 예약 완료 주문이 3건인 상품이다 / **When** 현재 주문 화면을 연다 / **Then** 조회만 가능하고 수확 시작 UI·호출이 없으며 3건의 상태는 RESERVED 그대로다
- [ ] AC-17-4. **Given** 출하된 주문이다 / **When** 생산자가 배송 완료로 바꾸는 요청을 보낸다 / **Then** 거부되고 상태는 출하로 남는다
- [ ] AC-17-5. **Given** 출하 준비 주문에 송장 번호 “123-456”을 넣었다 / **When** 출하로 바꾼다 / **Then** 출하일과 송장 번호가 기록되고 소비자 주문 상세에 송장 번호가 보인다
- [ ] AC-17-7. (DEV-68) **Given** 전액 환불된 주문이다 / **When** 생산자가 입금했던 계좌로 보낸 뒤 ‘송금 완료’를 누른다 / **Then** 환불 송금 시각이 기록되고 소비자 주문 상세·내역에 ‘환불 완료’로 보이며 현황의 환불 할 일 수가 준다. 환불이 아닌 주문은 409다

### UI 1.6 추가 인수 조건

AC-17-6의 세부 기준은 [확정 Figma v6 프론트](../conversation-ui-1.6.md)의 공통·검증 절을 따른다. 기존 API/권한/상태 규칙을 변경하지 않는다.


### I2 생산자 오류 복구 (DEV-29/34/38)

출하 요청 중에는 확인창 닫기·중복 요청·선택 변경을 막는다. 일부 요청 또는 출하 뒤 목록 갱신이 실패하면 성공한 주문은 유지하고 오류와 목록 재시도를 보여 준다. 새 조회가 실패해도 송장 입력은 유지한다.
