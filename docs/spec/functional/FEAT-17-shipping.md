- [ ] AC-17-7. (DEV-68) **Given** 전액 환불된 주문이다 / **When** 생산자가 입금했던 계좌로 보낸 뒤 ‘송금 완료’를 누른다 / **Then** 환불 송금 시각이 기록되고 소비자 주문 상세·내역에 ‘환불 완료’로 보이며 현황의 환불 할 일 수가 준다. 환불이 아닌 주문은 409다. 운영자 부분 환불(주문은 계속 진행)의 농가 송금 표시는 이번 범위가 아니다(나중 고려)
- [ ] AC-17-8. (DEV-68) **Given** 송금 전인 환불 주문이다 / **When** 생산자가 줄에서 ‘미승인’을 누르고 사유를 적는다 / **Then** 사유가 없으면 400이다. 환불은 송금 대기로 남고 소비자 주문 상세에 ‘환불 송금이 늦어지고 있어요 · 사유’, 내역에 ‘환불 송금 늦어짐’이 보인다. 나중에 승인하면 사유는 지워진다. 이미 송금을 마쳤거나 환불이 아닌 주문은 409다

### I2 생산자 오류 복구 (DEV-29/34/38)

출하 요청 중에는 확인창 닫기·중복 요청·선택 변경을 막는다. 일부 요청 또는 출하 뒤 목록 갱신이 실패하면 성공한 주문은 유지하고 오류와 목록 재시도를 보여 준다. 새 조회가 실패해도 송장 입력은 유지한다.

## DEV-343 송장 표시
- 숫자를 입력하거나 붙여넣는 동안 택배사별 하이픈을 자동으로 붙이고, 중간 수정·선택 교체·구분자 앞뒤 삭제 시 숫자 기준 커서를 유지한다. CJ·한진·롯데·로젠의 12자리 숫자는 4-4-4, 우체국 13자리는 6-7, 로젠 11자리는 3-4-4로 표시한다. 이는 읽기 편한 표시이며 송장 유효성 검증이 아니다.
- 영문 포함 번호·기타 택배사는 원문을 보존한다. 포맷 때문에 기존 50자 허용 번호가 거부되지 않도록 긴 숫자는 구분자 없이 보존한다. 배송 조회 링크는 기존처럼 구분자를 제거하며, 출하 전 입력과 출하 후 수정에 같은 표시 규칙을 쓴다.

## DEV-455 잘못 누른 출하·환불 표시 실행 취소
- 마지막 출하, 환불 보류 사유 또는 송금 완료 표시를 이전 상태로 복구할 수 있다. 출하 뒤 송장 정정·배송 완료·취소·환불 등 후속 처리와 충돌하면 거부한다. 소비자/운영자의 취소·환불 자체는 생산자가 되돌릴 수 없다.
- 출하 실행 취소는 출하 전 상태·송장을 복구하고 송장 버전을 증가시킨다. 환불 완료 표시의 실행 취소는 송금 대기 표시로 되돌린다. 실제 택배 발송이나 은행 송금을 취소하는 기능이 아님을 확인 화면에 명시한다.
- 다건 작업은 주문별 실행 취소를 사용하며 성공과 실패를 구분해 표시한다.
- 실행 취소는 화면 머리의 ‘실행 취소’에서 연다. 서버가 되돌릴 수 있다고 알려 준 최근 처리(`undoAction`)를 새것부터 보여 주고, 하나를 고르면 대상 주문과 지금 상태 → 복구할 상태를 확인한 뒤 되돌린다. 주문 카드 상태 칩에서도 같은 확인으로 연다(DEV-466). 여러 건 출하는 주문마다 따로 되돌린다. 그사이 다른 처리가 이어져 409면 확인 시트를 닫고 이유와 최신 목록을 보인다.

## DEV-466 주문 카드
- SCR-29의 주문 줄을 주문 카드로 바꾼다(UAT cycle 2 뒤 시안 A ‘주문 카드’, 2026-11-24 사용자 선택). 카드 순서: 이름(18) · 주문 번호 · 주문 시각과 상태 칩 → 상품 사진(56, 내 상품 대표 사진) · 상품명(길면 상품명만 줄임, AC-17-10) · 옵션 × 수량 · 금액 → 지금 할 일 띠(입금 대기: 입금자명·입금 기한/입금 알림·미승인 사유, 배송 대기·출하: 택배사·송장 또는 ‘송장 미등록’, 환불: 송금 안내·송금 완료·미승인 사유) → 동작 줄(‘주문 상세’ 펼침 · 입금 대기 ‘채팅하기’ · 배송 대기·출하 ‘송장 입력/수정’).
- 입금 대기·환불(송금 전) 카드는 지금처럼 ‘미승인’ 1 : ‘승인’ 2 버튼과 줄 안 미승인 사유 칸을 둔다. 배송 대기 카드는 받는 곳 한 줄과 배송 예정 기간을 보이고(AC-17-3), 연락처·우편번호·메모는 ‘주문 상세’에서 본다. 입금 전에는 배송 정보를 보이지 않는다(R-15).
- 상태 칩을 누르면 대상 주문을 다시 보여 주는 ‘주문 상태 변경’ 시트가 열린다. 선택지는 서버가 받는 다음 처리(입금 대기: 배송 대기로 = 입금 승인 확인 시트, 미승인 / 배송 대기: 출하로 = 그 주문만 고른 출하 확인 시트 / 환불 송금 전: 환불 완료로, 미승인)와 서버가 알려 준 직전 처리 되돌리기뿐이다. 임의 상태로 바로 바꾸는 API는 없고, 배송 완료는 생산자가 바꾸지 않는다(R-19).
- 탭 위 검색칸에서 주문 번호·받는 사람 이름·입금자명·송장 번호로 지금 탭의 카드를 거른다. 송장은 하이픈 없이 숫자만 넣어도 찾는다.
