# FEAT-17 출하 처리(자연어)

> 상위: [PRD](/docs/spec/prd.md) 7.1 · 규칙: [rules.md](./rules.md) · 화면: [IA](/docs/spec/ia.md) · 추적표: [README](./README.md)

| 항목 | 내용 |
| --- | --- |
| 우선순위·출처 | P0 · PRD 7.1, S-4 |
| 앱·화면 | 생산자 앱 SCR-29 |
| 목적 | 버튼을 찾지 않고 말로 출하를 처리한다 |
| 사전 조건 | 승인된 생산자이고 예약 완료 또는 출하 준비 주문이 있다 |
| 정상 흐름 | 1) 상품별 ‘수확 시작’ → 그 상품의 예약 완료 주문이 출하 준비 2) 출할 주문 목록 표시 3) “김○○님 5kg 오늘 보냈어요, 송장 123-456” 입력 4) AI가 주문과 송장번호를 찾아 ‘이 주문을 출하로 바꿀까요?’ 5) 확인 → 출하, 출하일·송장번호 기록 |
| 예외 흐름 | E1 후보가 여러 개 → 생산자가 고름. E2 못 찾음 → 목록에서 직접 고름. E3 취소를 누르면 아무것도 바뀌지 않음 |
| 사후 조건 | 주문은 출하, 소비자는 더 이상 취소할 수 없다 |
| 입력·검증 | 자연어 문장 필수. 송장번호는 없어도 됨 |
| 규칙 | R-07, R-19 |

- [ ] AC-17-1. **Given** AI가 주문을 찾아 확인을 요청했다 / **When** 확인을 누르기 전이다 / **Then** 어떤 주문도 상태가 바뀌지 않는다
- [ ] AC-17-2. **Given** 출하 준비 주문이다 / **When** 확인을 누른다 / **Then** 소비자 주문 상세가 ‘출하’로 바뀌고 취소 버튼이 사라진다
- [ ] AC-17-3. **Given** 예약 완료 주문이 3건인 상품이다 / **When** ‘수확 시작’을 누른다 / **Then** 3건 모두 출하 준비가 되고, 소비자는 여전히 취소할 수 있다
