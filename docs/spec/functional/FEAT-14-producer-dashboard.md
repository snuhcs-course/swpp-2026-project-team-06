# FEAT-14 생산자 현황

> 상위: [PRD](/docs/spec/prd.md) 7.1 · 규칙: [rules.md](./rules.md) · 화면: [IA](/docs/spec/ia.md), [화면 명세](/docs/spec/screens.md) · 추적표: [README](./README.md)

| 항목 | 내용 |
| --- | --- |
| 우선순위·출처 | P0 · PRD 7.1, S-4 |
| 앱·화면 | 생산자 앱 SCR-22 |
| 목적 | 주문과 배송 현황을 한눈에 본다 |
| 사전 조건 | 승인된 생산자다 |
| 정상 흐름 | (DEV-294) 머리 ‘현황’과 농가명·날짜 한 줄. 할 일 한 줄 목록(오른쪽 건수·‘필수’ 태그: 원산지 표시제도 안내 읽기, 입금 계좌 등록(DEV-68), 입금 확인할 주문 → 입금 대기 탭, 수확을 시작할 예약 → 예약 기간이 가장 먼저 끝난 기간 카드(DEV-231), 환불 보낼 주문 → 환불 탭, 답하지 않은 문의 → 채팅 1:1 목록). 주문 4칸 한 줄 카드(전체(입금 대기 포함)·예약·출하 준비·출하, 누르면 배송 현황 해당 탭)와 ‘배송 현황 ›’. 대표 상품 아래 중량 옵션마다 ‘예약+출하 N박스 / 판매 M박스’와 진행 막대(DEV-300), 상품 줄 오른쪽에 작은 글자로 총 예약+출하 kg / 판매 한도. 채팅 내용·소식 작성·답변은 채팅 탭에만 두고, 현황에는 답하지 않은 문의 건수 한 줄만 둔다 |
| 예외 흐름 | E1 판매 중 상품이 없으면 빈 상태 안내 |
| 사후 조건 | 변화 없음(조회만). 단 원산지 표시제도 안내의 ‘확인했어요’는 읽은 시각을 남긴다(DEV-121) |
| 입력·검증 | 배송 정보는 배송 완료 전 주문만 보인다 |
| 규칙 | R-15 |

- [ ] AC-14-1. **Given** 현황 화면을 보고 있다 / **When** 새 주문이 입금 안내를 받고 생산자가 입금을 확인한다 / **Then** 다시 열면 입금 대기 할 일·전체/예약 주문 지표와 대표 상품의 그 옵션 ‘예약+출하 N박스’(DEV-300)·총 kg가 갱신된다
- [ ] AC-14-2. **Given** 배송 완료된 주문이다 / **When** 현황에서 그 주문을 본다 / **Then** 주소·연락처가 가려져 있다

- [ ] AC-14-3. 대표 상품의 판매량을 상품명과 함께 중량 옵션마다 따로 ‘예약+출하 N박스 / 판매 M박스’(모든 기간 합)로 표시하고 전체 주문 건수와 구분한다. 옵션끼리 박스를 더하지 않는다(공유 물량 이중 계산 방지, DEV-292). 총 예약+출하 kg / 판매 한도는 보조 글자로만 둔다(DEV-300, 11/10 농가 피드백). 옵션별 예약 중/출하 완료 분리는 서버 집계가 필요해 후속이다. 승인/추가 물량은 상품 관리에서 유지한다. 현황에는 채팅 내용·답변 진입이 없고, 할 일 ‘답하지 않은 문의 n건’(대시보드 `openQuestions`, 누르면 채팅 1:1 목록) 한 줄만 둔다(DEV-294, 11/09 PM 승인 Figma 검토본 1:62).
- [ ] AC-14-5. (DEV-231) **Given** 예약 기간이 어제 끝난 기간에 예약 완료 3건, 오늘까지 열린 기간에 1건이 있다 / **When** 현황을 연다 / **Then** 할 일 ‘수확을 시작할 예약 3건’(끝난 기간만, 한국 날짜 기준)이 보이고 누르면 그 상품의 예약 기간 화면, 그 기간 카드로 간다. 그 기간의 수확을 시작하면 이 줄이 사라진다
- [ ] AC-14-6. (DEV-121, 원산지표시법 제6조 ⑥·시행규칙 제4조의2 1호) **Given** 지금 버전의 원산지 표시제도 안내를 읽지 않은 생산자다 / **When** 현황을 연다 / **Then** 할 일 맨 위에 ‘원산지 표시제도 안내 읽기’(‘필수’ 태그, DEV-294)가 보이고, 누르면 안내 화면(`/origin-notice`)에서 표시 대상·방법, 거짓 표시 금지, 위반 시 제재를 본다. ‘확인했어요’를 누르면 서버에 읽은 시각·버전이 남고, 그 뒤로 현황 맨 아래에 ‘원산지 표시제도 안내 · ○월 ○일 확인함’ 줄이 늘 남는다(새로고침해도)
