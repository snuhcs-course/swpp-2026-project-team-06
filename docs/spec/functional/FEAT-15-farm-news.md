# FEAT-15 농가 소식 목록·반응

| 항목 | 내용 |
| --- | --- |
| 우선순위·출처 | P0 · PRD 7.1, S-3 |
| 앱·화면 | 소비자 앱 SCR-18 공개 소식방, SCR-18 소식(반응) · 생산자 앱 SCR-28 내 소식방 반응 줄·팬 답장 시트(DEV-297) |
| 목적 | 팔로우 전에도 농가가 공개한 재배 소식을 보고, 마음에 드는 소식에 좋아요로 반응한다 |
| 사전 조건 | 없음(좋아요는 로그인) |
| 정상 흐름 | 1) 농가의 공개 소식방: 공개 소식(글·사진·영상)을 채팅 시간순으로 보여준다. 홈의 공개 소식 가로 목록은 최신순이다 2) 소식마다 내 좋아요 여부를 말풍선 옆 작은 하트로 보여준다(채운 하트 = 내가 누름). 좋아요 수는 소비자 화면에 숫자로 보이지 않고 농가(생산자 소식방 ‘읽음 N · ♥ N · 답장 N ›’ 줄의 ‘♥ N’)만 본다. 버블처럼 ‘나와 농가 사이’로 느끼게 하려는 것이다(DEV-295) 3) 로그인한 사용자가 좋아요를 누르면 켜고, 다시 누르면 끈다(한 사람이 한 소식에 한 번) 4) 반응 종류는 ‘좋아요’ 하나 |
| 예외 흐름 | E1 소식이 없으면 빈 안내. E2 비로그인으로 좋아요 → FEAT-01 후 그 소식으로 돌아와 반영. E3 좋아요 실패 → 이전 상태로 되돌림 |
| 사후 조건 | 소식 조회는 변화 없음. 좋아요는 반응이 생기거나 지워지고 반응 수가 바뀐다 |
| 입력·검증 | 좋아요는 그 사용자가 볼 수 있는 소식에만 된다: 공개 소식, 또는 팔로우한 농가의 팔로워 전용 소식. 농가가 삭제한 소식은 404이고 화면에서 뺀다(M-23). 반응 수는 서버 값으로 갱신한다 |
| 규칙 | M-02, M-03, M-14, M-23 |

- [ ] AC-15-1. **Given** 비공개(팔로워 전용)로 올린 소식이 있다 / **When** 농가의 공개 소식방을 연다 / **Then** 그 소식은 보이지 않는다
- [ ] AC-15-2. **Given** 비로그인 상태다 / **When** 소식 탭을 연다 / **Then** 공개 소식이 보인다
- [ ] AC-15-3. **Given** 로그인한 소비자가 좋아요 수 3인 소식을 본다 / **When** 좋아요를 누르고 다시 누른다 / **Then** 처음에는 서버 반응 수 4와 내 좋아요 표시(채운 하트), 다시 누르면 3과 빈 하트로 돌아간다. 소비자 화면은 숫자를 그리지 않고 생산자 소식방 반응 줄의 ‘♥ N’이 4 → 3으로 바뀐다(DEV-295)
- [ ] AC-15-4. **Given** 비로그인 상태로 공개 소식을 본다 / **When** 좋아요를 누르고 로그인한다 / **Then** 그 소식으로 돌아오고 좋아요가 반영돼 있다
- [ ] AC-15-8. **Given** 소식방에 답장한 소비자가 그 농가의 팔로우를 끊었다 / **When** 그 농가 소식방을 연다 / **Then** 공개 소식과 본인 답장만 보이고 팔로워 전용 소식과 다른 소비자 답장은 보이지 않으며(M-02·M-14), 답장 보내기는 거부된다(403). 다시 팔로우하면 전부 돌아온다(DEV-230)
- [ ] AC-15-5. **Given** 팔로우하지 않은 농가의 팔로워 전용 소식이다 / **When** 그 소식에 좋아요 API를 호출한다 / **Then** 거부되고 반응 수는 바뀌지 않는다

## 소식별 읽음 수·팬 답장 (DEV-297, 2026-11-10)

PM이 11/10 범위를 둘로 줄였다(Figma 검토본 `TEN0IqovZJenoRqSIma3wL` 7:90·7:93). 소식방 안 읽음 수·새 소식 아바타 테두리, ‘팔로우한 지 N일째’, ‘질문’ 필터는 하지 않는다.

- **읽음 위치**: 팔로워가 소식방을 맨 아래(가장 최근 소식이 보이는 위치)까지 보면 그 소식까지 읽었다고 남긴다(`PUT /api/messaging/rooms/{farmId}/read`). 팔로워 한 사람의 위치는 하나이고 앞으로만 간다. 소식 하나의 읽음 수는 위치가 그 소식에 닿은(그 소식이나 그보다 뒤까지 읽은) 팔로워 수다. 그래서 같은 소식을 여러 번 봐도 1회이고, 새로 팔로우한 사람이 맨 아래까지 보면 그 앞 소식들도 1회씩 센다. 팔로우하지 않은 소비자·비로그인·생산자는 남기지 않는다. 팔로우를 끊어도 이미 읽은 기록은 남는다.
- **답장이 답한 소식**: 소비자 답장은 보낸 순간 그 농가의 가장 최근 지우지 않은 소식(공개·팔로워 전용·인용 소식 모두)에 연결되고 바뀌지 않는다. 소식이 없을 때의 답장은 어느 소식에도 연결되지 않는다.
- **반응 줄**: 생산자 내 소식방의 내 소식 바로 아래 오른쪽 한 줄 ‘읽음 N · ♥ N · 답장 N ›’. ‘답장 N ›’은 연결된 답장이 있을 때만 보이고 누르면 팬 답장 시트가 열린다. 읽음·답장 수는 농가만 보고 소비자 응답에는 없다(`readCount`·`replyCount`가 null).
- **팬 답장 시트**: 제목 ‘답장 N’, 소식 앞부분 인용 · 날짜, 칩 ‘전체 N / 안 읽음 N’, 오래된 순 줄(이름 첫 글자 아바타 · 가린 이름 · 결제된 주문이 있는 소비자는 ‘예약 고객’(탈퇴한 회원 제외) · 안 읽음 점 · 시각 · 본문 · ‘모두에게 답장’ · ‘1:1 채팅’). 안 읽음은 생산자가 시트에서 아직 확인하지 않은 답장이다. 시트를 열면 불러온 답장을 읽음으로 바꾸고, 열어 둔 동안 점·칩은 연 순간 상태를 유지한다. ‘모두에게 답장’은 FEAT-12 DEV-289의 익명 인용 흐름(입력칸 인용 → 확인 시트)을 쓰고, 이미 인용한 답장은 ‘모두에게 답장함 ✓’로 보인다. ‘1:1 채팅’은 그 소비자의 1:1 대화를 연다.

- [ ] AC-15-9. **Given** 팔로워 두 명이 있고 한 명은 최근 소식까지, 다른 한 명은 그 전 소식까지 소식방을 봤다 / **When** 생산자가 내 소식방을 연다 / **Then** 최근 소식 아래 ‘읽음 1’, 그 전 소식 아래 ‘읽음 2’가 보이고, 같은 소식을 다시 열거나 더 오래된 소식으로 다시 보내도 수가 늘지 않는다. 소비자 화면·응답에는 읽음 수가 없고 팔로우하지 않은 소비자의 읽음은 거부된다(403)
- [ ] AC-15-10. **Given** 농가가 소식 A를 올린 뒤 팔로워가 답장했다 / **When** 농가가 소식 B를 올리거나 A를 지운다 / **Then** 그 답장은 계속 A의 ‘답장 N’에 센다(나중 소식은 연결을 바꾸지 않음). A를 지운 뒤 온 답장은 A 이전의 가장 최근 지우지 않은 소식에 붙는다
- [ ] AC-15-11. **Given** 소식에 답장 둘(하나는 예약 고객)이 있고 생산자가 아직 확인하지 않았다 / **When** 생산자가 ‘답장 2 ›’를 눌러 시트를 연다 / **Then** ‘전체 2 / 안 읽음 2’, 예약 고객 태그, 안 읽음 점이 보이고 ‘안 읽음’ 칩은 그 둘을 보인다. 다시 열면 ‘안 읽음 0’이다. ‘모두에게 답장’으로 인용해 보내면 그 줄은 ‘모두에게 답장함 ✓’, ‘1:1 채팅’은 그 소비자의 1:1 대화를 연다. 다른 농가 생산자·소비자는 이 목록을 볼 수 없다(404/403)
