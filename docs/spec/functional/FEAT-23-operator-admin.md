# FEAT-23 운영자 화면 — 농가 정지·되돌리기·이력·활동 로그·홈

PRD FEAT-23(운영자 화면, P2)의 기능 파일. 관리자 페이지(`scripts/admin-web`, `admin.farmclub.kr`)의 기존 화면(가입 신청·공급 물량·테스트 농가·사용자·문의함·AI 비용)은 각 기능 파일과 screens.md 7.2에 있고, 이 파일은 11/10 개편부터 적는다.

스펙 I4 · DEV-306(관리자 개편 시안)·DEV-307(서버 API) · 관리자 페이지(화면은 DEV-308·309) · 규칙: R-22, R-24(11/10 계좌이체 예외), N-05 · API: [screens.md 7.2 운영자](../screens.md). 운영자가 농가를 정지·정지 풀기하고, 반려를 되돌리고, 농가·사용자의 이력과 활동을 한곳에서 보고, 홈에서 할 일 건수를 본다. PM 결정(2026-11-10)을 따른다.

- [ ] AC-23-1. 운영자가 승인(`APPROVED`) 농가를 사유와 함께 정지하면 농가는 `SUSPENDED`, 정지 사유는 운영자가 적은 사유가 된다. 상품 상태는 그대로 두고, 공개 경로가 승인 농가만 보여 주므로 농가·상품이 소비자에게서 숨는다. 생산자는 정지 안내에서 사유를 본다. 결정 이력(`SUSPENDED`, 사유, 운영자)과 운영자 감사(`farm.suspend`)가 남는다. 승인 농가가 아니면 409 `INVALID_TRANSITION`.
- [ ] AC-23-2. 출하 전 주문(입금 대기 `AWAITING_DEPOSIT`·예약 `RESERVED`·준비 `PREPARING`)이 하나라도 있으면 정지를 거부한다(409 `FARM_HAS_OPEN_ORDERS`, `details.orders`에 주문 ID·번호·상태·상품·소비자 ID·금액·시각, 입금 기한이 지났고 ‘입금했어요’도 없어 소비자·생산자가 주문을 열면 자동 취소되는 주문은 `depositExpired`). 계좌이체라 서버가 환불하지 않고 아무것도 바뀌지 않는다(R-24 예외). 입금 안내 전(`PENDING_PAYMENT`) 주문은 막지 않는 대신, 정지된 농가의 주문은 입금 안내(`POST /api/orders/{id}/deposit`)를 404로 받지 않는다.
- [ ] AC-23-3. 정지 미리보기(`GET /admin/farms/{farmId}/suspend-preview`)는 아무것도 바꾸지 않고 지금 상태, 할 수 있는 작업(`suspend`·`unsuspend`·`revert`·없음), 정지 종류(운영자 정지·테스트 숨김·탈퇴), 거부 사유, 막는 주문, 그 농가의 상품(상태)을 보여 준다.
- [ ] AC-23-4. 운영자가 정지한 농가를 사유와 함께 정지 풀면 `APPROVED`로 돌아가고 정지 사유가 지워진다. 상품 상태를 바꾸지 않으므로 판매 중이던 상품은 바로 다시 판매된다. farmclub 문의 대화방이 없으면 연다. 결정 이력(`UNSUSPENDED`)과 감사(`farm.unsuspend`)가 남는다.
- [ ] AC-23-5. 정지 풀기는 탈퇴한 농가(탈퇴 사유이거나 생산자 계정이 탈퇴)는 409 `FARM_WITHDRAWN`, 테스트 농가로 숨긴 농가는 409 `TEST_FARM_HIDDEN`(테스트 농가 되돌리기 `POST /admin/farms/{farmId}/restore`로 안내), 정지가 아니면 409 `INVALID_TRANSITION`으로 거부한다.
- [ ] AC-23-6. 운영자가 반려(`REJECTED`) 신청을 사유와 함께 되돌리면 확인 중(`PENDING`)이 되고 반려 사유·결정 시각이 지워진다. 신청 시각은 그대로다. 다시 승인·반려할 수 있다. 반려가 아니면 409 `INVALID_TRANSITION`.
- [ ] AC-23-7. 정지·정지 풀기·되돌리기는 모두 사유(1~500자, 공백만은 안 됨, 숨김·탈퇴 고정 문구와 같으면 안 됨)와 `Idempotency-Key`가 필요하다(없으면 400). 같은 키로 다시 보내면 처음 결과(거부 포함)를 돌려주고 한 번만 실행한다. 거부 뒤 다시 시도하려면 새 키를 쓴다. 두 요청이 겹치면 하나만 바뀌고 나머지는 409다. 정지와 입금 안내가 겹쳐도 정지된 농가에 입금 대기 주문이 생기지 않는다.
- [ ] AC-23-8. 농가 결정 이력(`GET /admin/farms/{farmId}/history`)은 신청·승인·반려·되돌림·정지·정지 풀기·숨김·복구·탈퇴를 오래된 순으로 보여 준다(종류, 시각, 사유, 운영자). 거부된 작업은 들어가지 않는다. 기존 `GET /admin/producers/{farmId}/decisions`는 승인·반려만 돌려준다.
- [ ] AC-23-9. 사용자 활동 로그(`GET /admin/users/{userId}/activity`)는 서버 기록을 최신순으로 보여 준다: 가입, 동의, 법정 안내 읽음, 탈퇴, 운영 검증 표시·해제, (생산자) 농가 결정 이력·상품 마지막 수정과 상태·공급 물량 신청과 결정·받은 주문·farmclub 문의 메시지, (소비자) 주문 생성·입금 확인·출고·배송 완료·구매 확정·환불·farmclub 문의 메시지. 메시지 본문과 받는 사람 이름·전화·주소는 내려 주지 않는다(N-05). 계정 종류와 탈퇴 여부를 함께 준다.
- [ ] AC-23-10. 활동 로그는 서버에 PostHog 읽기 전용 개인 키와 프로젝트 ID가 모두 있을 때만 그 사람(앱이 identify한 내부 userId)의 최근 30일 이벤트 50개(이름·시각·앱·경로)를 함께 준다. 키가 없으면 `disabled`로 비우고, 조회가 실패하거나 5초를 넘으면 `unavailable`로 표시하며 페이지는 항상 200이다. 프로젝트 ID가 있으면 PostHog 사람 페이지 링크를 준다. 키는 로그·응답에 남지 않는다.
- [ ] AC-23-11. 홈 건수(`GET /admin/home`)는 가입 신청 대기, 공급 물량 대기, 답변 대기 문의, 열린 예외(`OPEN`·`FAILED`), 입금 기한 지남(입금했어요 + 기한 지남)을 각 목록 API와 같은 정의로 센다. 앞의 셋은 계정 필터를 따른다.
- [ ] AC-23-12. 사용자·가입 신청·공급 물량·문의함 목록은 `kind=real|test|all`(기본 `real`)로 거른다. 테스트는 시드 테스트 계정 또는 운영 검증 계정이다. 행마다 계정 종류(`REAL`·`SEED_TEST`·`OPS_TESTER`)와 탈퇴 여부를 주고, 탈퇴 계정은 실사용자로 센다. 잘못된 값은 400.

## 정해 둔 것
- 정지 거부(AC-23-2)는 PM 결정(11/10)이다. 무통장 입금이라 돈이 농가 계좌로 바로 가서 서버가 돌려줄 수 없다. 운영자는 막는 주문을 농가·소비자와 정리(취소·환불 확인·출고)한 뒤 다시 정지한다. R-24의 '정지 시 출하 전 주문 전액 환불'은 카드 결제를 전제한 문장이라 계좌이체에서는 이 거부로 대신한다.
- 숨김(테스트 농가 숨기기, DEV-93·98)과 정지는 같은 `SUSPENDED` 상태를 쓰고 정지 사유 문구로 구분한다. 그래서 정지 풀기는 숨긴 농가를 되돌리지 않는다(되돌리기는 숨김 쪽 API 하나로). 숨김은 UAT 정리용으로 남는다.
- 결정 종류는 마이그레이션 없이 `producer_decisions.decision`에 `SUSPENDED`·`UNSUSPENDED`·`REVERTED`를 더한다. 숨김·복구는 운영자 감사 기록에서, 신청은 결정 행의 신청 시각과 농가의 지금 신청 시각에서, 탈퇴는 사용자 탈퇴 시각에서 모은다.
- 상품 생성 시각은 저장하지 않아 활동 로그는 상품 마지막 수정 시각과 공급 물량 신청을 쓴다.
- PostHog 조회는 `distinct_id = userId` 이벤트만 본다. 로그인 전 익명 이벤트는 PostHog 사람 페이지에서 본다. 운영 키는 사람이 Railway 변수로 넣는다(`POSTHOG_PERSONAL_API_KEY`, `POSTHOG_PROJECT_ID`, 필요하면 `POSTHOG_HOST`).
- 화면(홈 배지, 사용자·농가 상세 한 화면, 정지 확인 시트)은 DEV-308·309가 만든다. 그 전까지 지금 관리자 화면은 `kind=all`로 지금처럼 모든 계정을 본다.
