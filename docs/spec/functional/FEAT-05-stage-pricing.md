- [ ] AC-05-1. **Given** 후기 기간 5kg가 25,000원이다 / **When** 이른 기간 5kg를 27,000원으로 입력하고 저장한다 / **Then** 저장되지 않고 이유가 보인다
- [ ] AC-05-2. **Given** 앞 기간이 10/7\~10/20이다 / **When** 다음 기간을 10/15부터로 입력한다 / **Then** 기간이 겹쳐 저장되지 않는다
- [ ] AC-05-3. **Given** 신규 상품이다 / **When** 화면이 열린다 / **Then** 빈 기간 한 개가 있고 기간을 자유롭게 추가하며 단계 번호·고정 프리셋을 보이지 않는다

- [ ] AC-05-4. 기간을 정렬해도 stageId와 예약 수량을 보존하고 예약 이력 기간의 삭제·날짜 수정을 거부한다. 가격은 신규 주문부터 변경 가능하다.
- [ ] AC-05-5. 가격 변경은 즉시 공개되고 기존 결제 주문을 바꾸지 않는다. 미결제 주문은 조건 변경을 재확인한다.

[1.4 공급·가격 계약](../capacity-1.4.md)이 필드·잠금·오류 기준이다.

## DEV-339 좁은 화면·기간 검증
- 상품 수정의 예약 기간 날짜는 기간 카드 제목의 날짜 칸을 눌러 달력 시트에서 고른다(DEV-486, 예전 시작일·종료일 칸 대체). 기간 날짜의 유효성·앞뒤 순서·겹침과 시간순 가격 증가를 ‘수정 담기’ 전에 검사하고, 오류는 칸 강조와 토스트(판매 조건 시트)·화면 아래 오류 줄(판매·가격)로 한 번 보인다. 저장 본문도 시작일로 정렬하며 stageId를 유지한다.
- 배송 시작 전까지 추가할 날짜가 없거나 판매 전 한 날짜짜리 기간을 더 나눌 수 없으면 추가 버튼은 막지 않고 누르면 토스트로 이유를 알린다(DEV-486, 예전엔 버튼을 끄고 아래 줄로 이유 표시). 첫 기간이 오늘 이후라면 그 앞의 빈 날짜에 얼리버드 기간을 추가할 수 있다.
- 생산자 MyStage.hasOrders는 취소·환불을 포함한 모든 주문 이력을 반영하며, 이 값이 참인 기간은 서버와 동일하게 날짜 변경·삭제를 잠근다. 검증·연결 실패는 입력을 버리지 않는다.
