# FEAT-05 예약 기간·가격·물량 설정

> 상위: [PRD](/docs/spec/prd.md) 7.1 · 규칙: [rules.md](./rules.md) · 화면: [IA](/docs/spec/ia.md), [화면 명세](/docs/spec/screens.md) · 추적표: [README](./README.md)

| 항목 | 내용 |
| --- | --- |
| 우선순위·출처 | P0 · PRD 7.1, S-1 |
| 앱·화면 | 생산자 앱 SCR-26 |
| 목적 | 날짜 범위별 가격·물량과 상품 총 판매 한도를 정한다 |
| 사전 조건 | 상품에 중량 옵션이 1개 이상 있다 |
| 정상 흐름 | 1) 빈 기간 한 개로 시작 2) 날짜·가격·물량 입력 및 기간 추가/삭제 3) 상품 총 판매 한도 확인 4) 저장 → FEAT-04 게시 요청 |
| 예외 흐름 | E1 검증 실패 → 칸별 이유 표시, 저장 안 함. E2 승인 후 변경 → 검증 후 즉시 적용하며 기존 결제 주문 보존(R-25) |
| 사후 조건 | 단계·단계 가격·단계 물량이 저장된다 |
| 입력·검증 | 단계 기간은 겹치지 않고, 마지막 예약 종료일은 배송 예정 시작일보다 이르다. 같은 옵션에서 이른 단계 가격 < 다음 단계 가격. 가격은 1원 이상 정수, 물량은 0 이상 정수 |
| 규칙 | R-06, R-17, R-18, R-25 |

- [ ] AC-05-1. **Given** 후기 기간 5kg가 25,000원이다 / **When** 이른 기간 5kg를 27,000원으로 입력하고 저장한다 / **Then** 저장되지 않고 이유가 보인다
- [ ] AC-05-2. **Given** 앞 기간이 10/7\~10/20이다 / **When** 다음 기간을 10/15부터로 입력한다 / **Then** 기간이 겹쳐 저장되지 않는다
- [ ] AC-05-3. **Given** 신규 상품이다 / **When** 화면이 열린다 / **Then** 빈 기간 한 개가 있고 기간을 자유롭게 추가하며 단계 번호·고정 프리셋을 보이지 않는다

- [ ] AC-05-4. 기간을 정렬해도 stageId와 예약 수량을 보존하고 예약 이력 기간의 삭제·날짜 수정을 거부한다. 가격은 신규 주문부터 변경 가능하다.
- [ ] AC-05-5. 가격 변경은 즉시 공개되고 기존 결제 주문을 바꾸지 않는다. 미결제 주문은 조건 변경을 재확인한다.

[1.4 공급·가격 계약](../capacity-1.4.md)이 필드·잠금·오류 기준이다.

## 스펙 1.4

- [ ] AC-05-6: 가격은 신규 주문부터 즉시 적용, 기존 결제 스냅샷 보존, 미결제 재확인. 상세는 [1.4 계약](../capacity-1.4.md).
