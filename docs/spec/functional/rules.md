# 비즈니스 규칙 상세 (R·M)

> 상위: [기능 명세 README](./README.md) · [PRD](/docs/spec/prd.md) 7.2

PRD 7.2에서 옮긴 규칙 전문이다. MUST NOT 규칙은 테스트 서비스에서도 지킨다. 결제 구조는 2026-10-18 팀 결정(DEV-68, C안)으로 **소비자가 농가 계좌로 직접 무통장 입금**하는 방식이다. farmclub은 통신판매중개자이고 돈을 받거나 보관하지 않는다. 사용자에게 보일 약관·안내 문구는 서비스 정책이, 상태 전이·데이터 제약은 기술 설계가 이 ID를 인용해 쓴다.

## 1.1 주문·결제·가격

| ID | 규칙 |
| --- | --- |
| R-01 | 결제수단은 **농가 계좌로의 무통장 입금**만 받는다(DEV-68 개정). 카드·PG·farmclub 계좌 수취·페이머니는 받지 않는다(MUST NOT). farmclub은 통신판매중개자로서 돈을 받거나 보관하지 않고, 입금 확인만 중개한다. 카드 결제(PG 지급대행)는 후속 검토다. |
| R-02 | 주문 시 전액을 한 번에 입금한다. 예약금·잔금 분할은 없다. farmclub은 에스크로를 제공하지 않으며, 구매안전서비스(은행 에스크로이체)를 소비자가 원하면 자기 은행에서 이용할 수 있다는 사실만 입금 안내에 한 줄 고지한다. 권유 문구는 쓰지 않는다(전자상거래법 13조② 10호). |
| R-03 | 결제 전에 배송 예정 기간, 최대 지연 기한과 초과 시 자동 전액 환불, 흉작·수량 부족 시 처리, 취소 조건을 보여주고 별도 동의를 받는다. 동의 시각과 동의한 문구의 버전을 기록한다(MUST). |
| R-04 | 최대 지연 기한 값은 PRD Q-07에서 정하고 설정값으로 둔다(카드 승인 취소 기한 근거는 R-01 개정으로 삭제). |
| R-05 | 결제 화면과 주문 내역에 배송 예정 기간을 항상 표시한다. 단계가 바뀔 때 주문자에게 진행 알림을 보낸다(SHOULD, I1 제외 → FEAT-18). |
| R-06 | 기간 옵션 물량과 상품 총 판매 한도(R-26)를 모두 넘지 않는다. 결제·취소·중지·한도 변경은 같은 상품 잠금 아래 원자적으로 처리한다. 품절이어도 다음 기간을 앞당기지 않는다. |
| R-17 | 결제 전 가격 기간이 바뀌면 STAGE_CHANGED로 재확인한다. 결제된 주문의 단가·기간 ID는 이후 편집과 무관하게 고정한다. |
| R-18 | 생산자는 날짜 범위별 예약 가격·물량을 직접 추가한다. 고정 3단계/할인 기본값 UI는 사용하지 않는다. 같은 옵션의 이른 기간 가격은 이후보다 엄격히 낮고, 기간은 겹치지 않으며 예약 종료는 배송 시작보다 이르다. 승인 후 판매한다. |
| R-20 | 배송비는 생산자가 상품마다 무료배송과 별도 부과 중에서 정한다. 별도면 결제 전에 상품 금액과 배송비를 나눠 보여주고 합계를 결제한다. 도서산간 지역과 추가 운임도 생산자가 상품마다 정하고, 주문서에서 주소가 그 지역이면 결제 전에 표시한다. 무료배송 유도 방식은 이후 유저 스터디로 정한다. |
| R-21 | 배송 예정 기간은 결제 전에 명시한다(R-03). 이 기간을 벗어나게 되면 주문자에게 알리고, 새 기간에 동의하거나 전액 환불받는 것 중 고르게 한다. 이 처리 방식도 결제 전에 고지한다. |
| R-22 | 생산자는 가입 신청 후 farmclub이 농가임을 확인하고 승인해야 상품을 올릴 수 있다. 생산자 계정은 소비자 계정과 따로이고, 가입 신청이 생산자 계정 만들기를 겸한다(ADR 0010). 로그인은 I1은 시드 테스트 계정(Mock), I2부터 카카오이고, 농가 확인은 전화·방문으로 한다. |
| R-23 | 한 주문은 한 중량 옵션을 여러 개 담을 수 있다. 한 주문의 최대 수량은 생산자가 상품마다 정하고, 배송지는 주문당 1곳이다. 수량은 단계 물량(R-06)을 넘지 않는다. |
| R-25 | 상품 공급 총중량은 최초·증액만 승인한다. 승인 한도 안의 가격·옵션·기간 변경은 검증 후 신규 주문부터 즉시 반영한다. 기존 결제 주문값은 보존하며, 예약 기간 삭제·날짜/옵션 중량 변경 잠금은 유지한다. [1.4 계약](../capacity-1.4.md)을 따른다. |

## 1.2 환불

| ID | 규칙 |
| --- | --- |
| R-07 | 출하 전 취소는 사유와 관계없이 전액 환불한다. 위약금·수수료는 받지 않는다(MUST NOT). |
| R-08 | 환불은 카드 승인 취소로만 한다. 포인트·크레딧·충전금·예치금·상품권 같은 금전성 기능은 만들지 않는다(MUST NOT). |
| R-09 | 최대 지연 기한까지 출하되지 않은 주문은 자동으로 전액 환불한다. |
| R-10 | 흉작·수량 부족이면 가능한 수량을 주문에 비례 배분하고 부족분을 즉시 환불한다. |
| R-11 | 배송 후에는 하자가 있을 때 환불·교환한다. 기한과 절차는 서비스 정책이 정한다. |
| R-12 | 환불은 법정 기한 안에 처리한다. 구체 기한은 서비스 정책이 정한다. |
| R-24 | 농가 승인이 취소(활동 정지)되면 그 농가의 출하 전 주문은 모두 전액 환불한다. 다른 농가로 대체하지 않는다. 소비자 주문 상세에 환불 사유를 표시한다. 흉작으로 수량만 부족한 경우는 R-10을 따른다. |

## 1.3 정산·개인정보·표시·출하

| ID | 규칙 |
| --- | --- |
| R-13 | 주문마다 결제일(=생산자 또는 운영자가 입금을 확인한 시각)·배송 완료일·구매 확정일을 반드시 기록한다. 정산의 근거다. |
| R-14 | 농가 매입·정산은 구매 확정 시점에 확정된다. 구매 확정은 소비자가 직접 하거나, 배송 완료 후 8일이 지나면 자동으로 된다(네이버 방식). I1은 기록만 남긴다. |
| R-15 | 생산자는 배송에 필요한 정보(받는 사람·연락처·주소)만 보고, 배송 완료 후에는 가린다(SHOULD). |
| R-16 | 법정 표시 의무(원산지, 상품정보, 사업자 정보)를 지킨다. 항목은 서비스 정책이, 위치는 화면 명세가 정한다. |
| R-19 | 출하는 생산자가 처리한다. 생산자가 주문을 골라 송장번호와 함께 출하로 바꾸고, 확인해야 반영된다. 생산자는 출하까지만 바꾸고, 배송 완료는 택배 조회로 수령을 확인해 바꾼다. I1은 운영자가 처리하고, 택배 연동은 FEAT-22다. (I2) 자연어(예: 송장번호와 함께 “김○○님 5kg 보냈어요”)로 입력하면 AI가 해당 주문과 바뀔 상태를 보여주고 생산자가 확인한다. AI가 혼자 상태를 바꾸지 않는다(MUST NOT). |

## 1.4 소통

| ID | 규칙 |
| --- | --- |
| M-01 | 소식(전체 메시지)은 생산자만 올리고, 그 농가를 팔로우한 소비자 전원의 채팅 안 소식방에 간다. 글·사진·영상을 보낼 수 있고, 용량·형식 제한은 기술 설계가 정한다. |
| M-02 | 소비자의 채팅(질문·답장)은 그 소비자와 농가만 본다. 다른 소비자에게 보이지 않는다(MUST NOT). |
| M-03 | 소비자끼리 대화하는 기능은 없다. 단체방·댓글을 만들지 않는다. |
| M-04 | 일반 1:1 대화는 팔로우한 농가에 보낸다(새 대화는 안내 후 자동 팔로우). 본인 결제 이력 주문 문의는 팔로우 해제 후에도 해당 농가와 가능하다. 농가 답변과 AI 안내를 구분한다. |
| M-14 | 생산자는 소식을 올릴 때 공개 여부를 고른다. 공개 소식은 농가 페이지 소식 목록에 남아 누구나 볼 수 있고, 팔로워 전용 소식은 팔로워의 채팅 안 소식방에만 간다. 소비자의 채팅은 항상 비공개다(M-02). |
| M-16 | 메시지·답장에 전화번호·계좌번호·외부 메신저 ID가 있으면 자동으로 가린다(예: 010-○○○○-○○○○). 거래와 소통을 플랫폼 안에 두기 위해서다. |

## 1.5 AI

| ID | 규칙 |
| --- | --- |
| M-05 | 농가 AI 설정이 ON이고 방이 AUTO일 때만 AI 응답을 시도한다. 플랫폼 규칙 > 확정 상품·본인 주문 사실 > 농가 원칙·FAQ 순서이며 충돌·근거 부족은 전달한다. |
| M-06 | 근거로 답할 수 없으면 추측하지 않고(MUST NOT) “농가에 전달했어요”라고 알린 뒤 생산자에게 넘긴다. |
| M-07 | 농약·재배 방식, 환불·보상 요구, 항의·불만, 가격 할인·흥정, 배송 일정 변경 약속, 개인적인 대화·주관적 맛/품질/파손 판단은 항상 생산자에게 넘기고, 환불·보상 요구는 메시지 저장 성공 뒤 운영자에게도 알린다. |
| M-08 | AI는 농가 본인인 척하지 않는다. 모든 AI 응답은 AI 안내로 표시하고 실제 사용한 상품·주문·농가 설정 근거와 설정 버전을 기록한다. |
| M-09 | 생산자는 전달 질문뿐 아니라 자기 농가의 모든 1:1 대화를 본다. 답은 해당 소비자에게만 가고 저장과 HUMAN 전환은 원자적이다. 명시적으로 AUTO를 켜야 이후 질문에 AI가 다시 답한다. |
| M-10 | 생산자가 쓰던 문구(텍스트)로 상품 초안을 만든다. 입출력 항목은 이 문서 FEAT-03에서 정한다. |
| M-11 | 입력에 없는 값은 필드별로 빈 칸으로 두고 표시한다. 당도·배송 시기를 포함해 이름·설명·옵션의 숫자 사실도 지어내지 않는다(MUST NOT). 같은 중량의 kg·키로 계열 표기는 같은 근거로 본다. |
| M-12 | AI는 가격·예약 기간을 확정하지 않는다. 생산자가 날짜별로 직접 정한다(R-18). |
| M-13 | 초안은 생산자가 확인해 게시를 요청하고 farmclub이 승인해야 공개된다. AI가 직접 게시하지 않는다. |
| M-15 | 당도 질문은 AI가 등록된 당도로 답한다. 실측값이 있으면 실측값을, 없으면 예상값임을 밝힌다. 둘 다 없으면 농가에 전달한다. 실측값은 대부분 수확 직전 농가가 측정해 공개한다. |
| M-17 | (I2) AI 안내마다 ‘틀렸어요’ 버튼을 둔다. 소비자가 누르면 그 질문을 농가 질문함에 넣고, 농가가 바로잡는 답을 보낸다. 어떤 AI 답이 틀렸다고 표시됐는지 기록한다. |
| M-18 | AI에 보내는 질문과 상품명·FAQ·농가 원칙 등 모든 근거 복사본에서 연락처·주소 등 개인정보를 뺀다(MUST NOT 전송). 로컬 주제/FAQ 매칭에 쓰는 원본은 바꾸지 않고, 주문 상태·배송 예정 기간처럼 답에 필요한 값만 넘긴다. |

## 1.6 스펙 1.2 운영 규칙

세부 필드·권한·동시성은 [공통 계약](../contracts-1.2.md)을 따른다.

| ID | 규칙 |
| --- | --- |
| R-26 | 상품별 approvedSupplyGrams와 salesLimitGrams를 분리한다. 예약 중+출하 완료≤실제 판매 한도≤승인 한도를 지킨다. kg 표시·정수 g 계산, 주문/기간 물량은 박스. 출하 전 취소·미공급만 한 번 복원한다. [1.4 계약](../capacity-1.4.md)을 따른다. |
| R-27 | 판매 중지 상품은 공개 화면에 남되 신규 예약·입금 안내 전 주문의 입금 안내를 막는다. 기존 입금 대기·확인 주문의 확인·출하는 유지한다. 재개는 유효한 현재/미래 기간과 잔여 물량을 필요로 한다. |
| R-28 | 입금 대기(`AWAITING_DEPOSIT`) 주문도 물량을 잡는다(입금 안내 시점에 선점). 입금 기한은 안내 시각부터 설정값(기본 24시간)이고, 지나면 자동으로 취소하고 물량을 돌려준다. 입금자명은 주문 번호(`FC-MMDD-NNNN`, NNNN은 무작위 4자리 — 연번이면 거래 건수가 드러난다)이고 금액은 합계 그대로다. 입금 확인은 돈을 받는 생산자가 통장과 대조해 누르고, 운영자가 대신 확인할 수 있다. 소비자의 ‘입금했어요’ 신호만으로 예약 완료가 되지 않는다(MUST NOT). 기한이 지나도 소비자가 ‘입금했어요’를 보낸 주문은 자동 취소하지 않고 운영자가 생산자에게 연락한다. 생산자는 입금·환불을 미승인할 수 있고 그때 사유는 필수이며 소비자에게 그대로 보인다(입금 미승인은 입금 대기 유지 또는 주문 취소 중 선택). 환불은 농가가 소비자가 입금했던 계좌로 보내고 앱은 송금 완료 표시만 중개한다(DEV-68). |
| M-19 | 소식방에서 생산자는 방송과 모든 소비자 답장을, 소비자는 방송과 본인 답장만 본다. 요약·페이지네이션도 동일하다. 소식 답장에는 AI가 답하지 않는다. |
| M-20 | 농가 AI OFF는 모든 방 AUTO보다 우선한다. HUMAN 전환 후 늦은 AI 응답 저장도 막는다. 설정 미리보기는 메시지·문의·설정에 영향을 주지 않는다. |
| M-21 | 주문 문제 문의·사진은 본인 소비자와 해당 농가만 본다. 접수는 HUMAN으로 넘기며 해결 표시는 환불/보상 결정이 아니다. 주관적 맛·품질·파손 판단은 생산자가 응대한다. |

## 스펙 1.5 보완
M-14의 공개 소식 노출 위치는 농가 소식 탭 대신 공개 소식방이다. M-19의 답장 격리는 유지하며 미팔로우/비로그인에는 공개 방송만 제공한다. M-13의 승인은 스펙 1.4 최초·증액 물량만 뜻한다. 상세 생성은 초안이며 생산자 저장 전 공개하지 않는다. [상세 계약](../storefront-1.5.md).
