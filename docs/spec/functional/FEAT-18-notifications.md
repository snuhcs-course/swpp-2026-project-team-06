# FEAT-18 알림 (1차: 농가 주문 알림톡)

> 상위: [PRD](/docs/spec/prd.md) 7.1(FEAT-18), 10장 Q-13 · 규칙: [rules.md](./rules.md) · 추적표: [README](./README.md) · 구현: `server/app/notifications/spec.md`, 이슈 파일 `server/app/notifications/tasks/DEV-495.md`

| 항목 | 내용 |
| --- | --- |
| 우선순위·출처 | P1 · 11/27 생산자 QA "주문이 들어와도 농가가 모른다"(DEV-495). PRD의 소비자 알림(R-05 진행 알림)은 이 1차 범위가 아니다 |
| 앱·화면 | 화면 없음(카카오 알림톡). 운영자는 관리 API `/admin/notifications`(Swagger) |
| 목적 | 농가가 앱을 열지 않아도 새 주문과 '입금을 마쳤어요'를 바로 알아 입금 기한(R-28) 안에 입금을 확인한다 |
| 사전 조건 | 승인된 농가, 생산자 신청 연락처(`Farm.contact_phone`)가 휴대폰 번호, 운영 변수 `NOTIFY_PROVIDER=solapi`와 업체 설정(사람이 넣음) |
| 정상 흐름 | 1) 소비자가 입금 안내를 받아 주문이 입금 대기(`AWAITING_DEPOSIT`)가 된다 → 그 상품 농가에 '새 주문' 알림톡 2) 소비자가 '입금을 마쳤어요'를 누른다 → 같은 농가에 '입금 알림' 알림톡 3) 알림톡이 카카오 쪽에서 실패하면 발송 업체가 대체 문자(LMS)로 보낸다 4) 버튼 '주문 보기'는 생산자 앱 입금 확인 목록(`/ship?status=AWAITING_DEPOSIT`) |
| 예외 흐름 | E1 업체 장애·시간 초과·키 없음 → 주문은 그대로 성공하고 알림만 늦거나 안 간다 E2 보내기 직전 주문이 이미 취소·확인됐거나 입금 신호가 지워졌으면 보내지 않는다 E3 6시간 넘게 못 보낸 알림은 버린다 E4 테스트 계정 농가·승인 안 된 농가·알림 끈 농가·휴대폰이 아닌 번호·한도 초과는 보내지 않는다 |
| 사후 조건 | 알림마다 기록 한 줄(상태 `PENDING`·`SENDING`·`SENT`=업체 접수·`FAILED`·`SKIPPED`+사유). 실제 도착은 업체 콘솔에서 본다 |
| 입력·검증 | 없음(서버가 주문 상태 변화에서 만든다) |
| 규칙 | R-28(입금 기한), R-15·N-05·M-16(연락처 가림) |

**보내지 않는 것**: 주문서 단계(`PENDING_PAYMENT`), 입금 전 취소·기한 만료, 농가 자신이 한 일(입금 확인·미승인·출하), 운영자 일(배송 완료), 입금 뒤 소비자 취소(2차, PM 11/28 결정 2), 소비자에게 가는 알림, 앱·웹 푸시.

**문구(정보성, 광고·송금 유도 없음, 받는 사람 이름·주소·연락처 없음)**: 새 주문은 농가명·상품명·수량·입금자명·입금 금액·입금 기한, 입금 알림은 상품명·수량·입금자명·입금 금액. 원문은 이슈 파일 설계 3. 템플릿은 카카오 검수 뒤 고칠 수 없어 문구를 바꾸면 새 템플릿을 검수받는다.

- [ ] AC-18-1. **Given** 입금 안내 전 주문이다 / **When** 소비자가 입금 안내를 받아 입금 대기가 된다 / **Then** 그 상품 농가 앞으로 '새 주문' 알림이 정확히 하나 생긴다. 같은 멱등 키 재요청, 다른 키 재요청, 입금 확인 뒤 실행 취소로 입금 대기에 돌아온 경우에도 늘지 않는다
- [ ] AC-18-2. **Given** 입금 대기 주문이다 / **When** 소비자가 '입금을 마쳤어요'를 누른다 / **Then** '입금 알림'이 하나 생긴다. 이미 알린 상태에서 다시 눌러도 늘지 않고, 생산자 미승인(입금 대기 유지)으로 신호가 지워진 뒤 다시 알리면 새 알림이 하나 더 생긴다
- [ ] AC-18-3. **Given** 발송 업체가 오류·시간 초과를 내거나, 키가 없거나(`NOTIFY_PROVIDER=none`), 알림 기록을 넣다가 DB 오류가 난다 / **When** 입금 안내·'입금을 마쳤어요'를 요청한다 / **Then** 주문 응답과 상태는 알림이 없을 때와 같다(주문 요청은 업체를 부르지 않는다). 키가 없으면 알림은 `SKIPPED`(`provider_disabled`)로 남는다
- [ ] AC-18-4. **Given** 농가 생산자가 테스트 계정이거나, 농가가 승인 상태가 아니거나, 농가 알림이 꺼졌거나, 신청 연락처가 휴대폰 번호가 아니거나, 농가당 1시간 30건·서버 전체 하루(KST) 1,000건을 넘는다 / **When** 알림을 넣거나 보내려 한다 / **Then** 보내지 않고 `SKIPPED`와 사유를 남긴다. 테스트 계정·승인·끄기·번호는 넣을 때와 보내기 직전에 두 번 본다. 운영 검증 실계정(`ops_tester`)은 보낸다
- [ ] AC-18-5. **Given** 알림을 넣고 보내고 다시 시도한다 / **When** 서버 로그와 관리 API 응답을 본다 / **Then** 전체 전화번호, 알림 변수 값(입금자명·상품명 등), 요청 본문, API 키·서명이 없다. 번호는 끝 4자리(`●●●●1234`)만 보인다
- [ ] AC-18-6. **Given** 보낼 알림이 있다 / **When** 발송 루프가 돈다 / **Then** 한 알림은 한 루프만 보낸다(임대 60초, 여러 프로세스 안전). 연결 오류·시간 초과·5xx·429는 1분 → 5분 → 30분 뒤 다시 보내고 그래도 안 되면 `FAILED`, 4xx·업체 접수 실패는 바로 `FAILED`. 보내기 직전에 주문이 그 상태가 아니면(새 주문 알림인데 취소·확인됨, 입금 알림인데 신호가 지워지거나 바뀜) `SKIPPED`(`order_state_changed`), 만들어진 지(운영자 재시도면 재시도한 지) 6시간이 지났으면 `SKIPPED`(`stale`). 시간 초과 재시도로 드물게 같은 알림이 두 번 갈 수 있다(PM 11/28 결정 7)
- [ ] AC-18-7. **Given** 운영자다 / **When** `GET /admin/notifications?orderId=&status=`, `POST /admin/notifications/{id}/retry`(`Idempotency-Key`)를 부른다 / **Then** 상태·시도 횟수·끝 4자리·업체 코드·업체 그룹/메시지 id·시각을 본다. 재시도는 `FAILED`만 되고(아니면 409) 감사 기록이 남으며, 알림 발송이 꺼져 있으면 409 `NOTIFY_DISABLED`. 운영자가 아니면 403
- [ ] AC-18-8. (사람, 운영 확인) **Given** 업체 계정·채널·템플릿·운영 변수가 준비됐다 / **When** `ops_tester` 농가 상품을 `ops_tester` 소비자로 1개 주문해 입금 안내 → '입금을 마쳤어요' / **Then** 농가 폰에 알림톡 두 개가 오고, 관리 API에 `SENT`와 업체 메시지 id가 있으며 업체 콘솔 발송 내역과 맞는다. 주문은 입금 전 취소로 정리한다

### 결정 (PM 11/28, "추천대로")
1. 1차 이벤트는 새 주문(`ORDER_AWAITING_DEPOSIT`)과 입금 알림(`DEPOSIT_REPORTED`) 두 가지. 2. 입금 뒤 취소 알림은 2차. 3. 받는 번호는 `Farm.contact_phone`(승인 뒤 바꾸는 길이 없어 당분간 운영자가 처리). 4. API 프로세스 안 발송 루프. 5. 끄기는 서버의 농가별 칸만(앱 화면 없음, 운영자가 요청받아 끈다). 6. 업체 접수 결과만 기록(웹훅 없음). 7. 시간 초과도 재시도. 8. 처리방침은 배포일 시행, 동의 버전 안 올림(처리방침 문구는 위탁 법인명 확인 뒤 후속 PR). 9. 한도 농가당 1시간 30건, 전체 하루 1,000건.
