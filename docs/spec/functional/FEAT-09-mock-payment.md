- [ ] AC-09-2. **Given** 입금 대기 주문이다 / **When** 입금 전에 취소한다 / **Then** 환불 없이 취소되고 남은 물량이 돌아오며 주문 내역에 사유와 함께 남는다
- [ ] AC-09-3. **Given** 입금 안내 요청을 보냈다 / **When** 같은 멱등 키로 다시 보낸다 / **Then** 물량 선점은 한 번만 일어나고 같은 결과를 받는다. (DEV-320) 주문서는 요청 전에 원래 주문·옵션·수량·입금 키를 기억한다. transport 실패·5xx로 결과가 불확실하면 폼 편집 후에도 원래 주문의 입금 요청을 같은 키로 먼저 재생하고 새 주문 생성을 막는다. 단일 GET이 `PENDING_PAYMENT`여도 문맥을 지우지 않는다. 성공하면 원래 주문의 입금 안내를 제공하고 뒤에 편집한 주문서 내용은 저장되지 않았음을 알린다. 반복 불확실 실패·재생의 `IDEMPOTENCY_MISMATCH`에도 같은 문맥을 유지한다. 명확한 도메인 400/409 거부가 확인됐을 때만 해제하고 기존 입력 오류·가격/물량 재확인 흐름으로 복귀한다. 같은 화면의 제출은 직렬화하고 이전 계정·세션의 응답·복구 콜백으로 새 요청이나 이동을 실행하지 않는다.

## 스펙 1.2

DEV-318 (AC-09-9/10): 미승인 후 다시 ‘입금을 마쳤어요’를 보냈다면 현재 알림 시각이 지난 미승인 사유보다 우선한다. 서버에 남은 과거 사유는 지우지 않되 소비자 현재 제목·본문·경고에서 다시 입금을 재촉하지 않는다. 다시 미승인하면 알림 시각이 비워지므로 새 사유를 표시한다.

[공통 계약](../contracts-1.2.md)을 적용한다.

## DEV-455 잘못 누른 입금 처리 실행 취소
- 자기 농가의 마지막 입금 확인 또는 입금 미승인(입금 대기 유지/취소)을 서버에 저장한 이전 상태로 복구할 수 있다. 다른 처리 뒤에는 거부하고, 재시도는 같은 작업을 반복하지 않는다.
- 입금 확인 취소는 결제 행을 역전 기록으로 남기고 이전 paidAt/확인 주체/사유/신고 상태를 복구한다. 다시 입금 확인이 가능하다. 실제 은행 송금 취소는 아니다.
- 미승인 취소로 풀린 물량을 되잡는 경우 지금의 옵션 물량·전체 판매 한도와 기존 입금 기한을 확인한다. 입금자명이 다른 입금 대기 주문과 충돌하면 복구하지 않는다.
- SCR-29 머리 ‘실행 취소’의 최근 처리 목록과 주문 카드 상태 칩(DEV-466)에서 실행 취소를 찾고, 대상 주문(이름·주문 번호·상품·금액)과 지금 상태 → 복구할 상태를 확인한 뒤 요청한다. 취소됐지만 실행 취소 가능한 미승인 주문은 전체 목록에서 해당 작업을 되돌릴 수 있다.
