# FEAT-09 무통장 입금(소비자 → 농가 계좌 직접)

> 상위: [PRD](/docs/spec/prd.md) 7.1 · 규칙: [rules.md](./rules.md) · 화면: [IA](/docs/spec/ia.md), [화면 명세](/docs/spec/screens.md) · 추적표: [README](./README.md)
> 2026-10-18 DEV-68로 카드 결제(Mock)에서 무통장 입금으로 개정. 근거는 Linear 문서 「farmclub 결제 구조 변경 제안 — C안」(farmclub은 통신판매중개자, 돈을 만지지 않음). 파일 이름은 링크 호환을 위해 유지한다.

| 항목 | 내용 |
| --- | --- |
| 우선순위·출처 | P0 · PRD 7.1, S-2, DEV-68 |
| 앱·화면 | 소비자 앱 SCR-10 → SCR-11(입금 안내) → SCR-12 · SCR-14 / 생산자 앱 SCR-29(입금 확인) · SCR-30 하위(입금 계좌) |
| 목적 | 소비자가 농가 계좌로 주문 금액을 한 번에 입금하고, 생산자가 통장과 대조해 입금을 확인하면 예약이 완료된다. farmclub은 돈을 받지 않는다 |
| 사전 조건 | 동의를 마친 결제 전 주문(`PENDING_PAYMENT`)이 있고, 농가에 입금 계좌(은행·계좌번호·예금주)가 등록돼 있다 |
| 정상 흐름 | 1) 주문서 ‘예약하기’ → 서버가 물량을 선점하고 입금 대기(`AWAITING_DEPOSIT`)로 바꾸며 입금 기한(안내 시각 + 24시간)을 정한다 2) 입금 안내 화면에 농가 계좌·입금액·입금자명(=주문 번호)·기한·판매자 정보·중개자 고지·에스크로 안내를 보여 주고 계좌번호·입금자명을 복사할 수 있다 3) 소비자가 자기 은행에서 보낸 뒤 ‘입금을 마쳤어요’(힌트 기록) 4) 생산자가 주문 현황 ‘입금 대기’ 탭에서 통장과 대조해 ‘입금 확인’ → 예약 완료(`RESERVED`), 결제일 기록 5) 소비자 주문 상세가 예약 완료로 바뀐다 |
| 예외 흐름 | E1 입금 대기 중 소비자 취소 → 환불 없이 취소(`CANCELED`), 물량 복구. E2 입금 안내 순간 물량 0 → 409 `SOLD_OUT`, 주문서로. E3 응답을 못 받아 다시 보냄 → 같은 멱등 키면 처음 결과, 선점은 한 번만. E4 기한 안에 확인되지 않음 → 자동 취소(사유 ‘입금 기한 초과’), 물량 복구, 소비자 상세에 표시. E5 농가에 계좌가 없음 → 409 `NO_FARM_ACCOUNT`(상품 승인 요청 단계에서 먼저 막는다). 계좌 없이 이미 판매 중인 상품(DEV-68 전에 승인된 상품 등)은 주문 생성(`POST /api/orders`)에서 같은 409로 막아 결제 전 주문을 남기지 않고, 주문서는 사유를 안내하며 예약하기를 끈다(DEV-72). E6 이미 확인된 주문을 다시 확인 → 그대로(멱등) |
| 사후 조건 | 입금 안내: 주문은 입금 대기, 단계 물량 선점. 입금 확인: 예약 완료, 결제일(=확인 시각)·확인 주체 기록, `Payment(BANK_TRANSFER/FARM_ACCOUNT)` 생성 |
| 입력·검증 | 입금 안내 요청에 멱등 키(`Idempotency-Key`) 필수(화면 명세 7.1). 입금 확인은 자기 농가 주문만(남의 농가 404). 입금 계좌는 은행·계좌번호(숫자·하이픈 6~32자)·예금주를 함께 저장 |
| 규칙 | R-01, R-02, R-06, R-13, R-17, R-28 |

- [ ] AC-09-1. **Given** 남은 물량이 1이다 / **When** 두 사람이 동시에 입금 안내를 받는다 / **Then** 한 명만 입금 대기가 되고 다른 한 명은 품절 안내를 받는다
- [ ] AC-09-2. **Given** 입금 대기 주문이다 / **When** 입금 전에 취소한다 / **Then** 환불 없이 취소되고 남은 물량이 돌아오며 주문 내역에 사유와 함께 남는다
- [ ] AC-09-3. **Given** 입금 안내 요청을 보냈다 / **When** 같은 멱등 키로 다시 보낸다 / **Then** 물량 선점은 한 번만 일어나고 같은 결과를 받는다
- [ ] AC-09-7. **Given** 입금 대기 주문의 기한이 지났다 / **When** 소비자·생산자가 조회하거나 운영자가 만료 일괄 API를 부른다 / **Then** 소비자가 ‘입금했어요’를 보내지 않은 주문은 취소(사유 ‘입금 기한 초과’)되고 물량이 돌아오며, 뒤늦은 입금 확인은 409다. 소비자가 ‘입금했어요’를 보낸 주문은 취소하지 않고 입금 대기로 남아 운영자 목록(`GET /admin/orders/deposit-overdue`)에 나오며, 운영자가 생산자에게 연락한다. 생산자가 나중에 승인하면 예약 완료가 된다(2026-10-18 결정)
- [ ] AC-09-8. **Given** 입금 대기 주문이다 / **When** 그 농가 생산자(또는 운영자)가 입금 확인을 누른다 / **Then** 예약 완료가 되고 결제일이 기록되며, 다시 눌러도 그대로이고 다른 농가는 404다
- [ ] AC-09-9. (DEV-68) **Given** 입금 대기 주문이다 / **When** 그 농가 생산자가 줄에서 ‘미승인’을 고르고 사유를 적는다 / **Then** 사유가 없으면 400이다. ‘입금 대기로 두기’면 주문은 입금 대기로 남고 소비자 주문 상세·내역에 사유가 보이며 소비자는 다시 ‘입금했어요’를 보낼 수 있다(기한은 그대로). ‘주문 취소’면 사유 ‘입금 미승인 · {사유}’로 취소되고 물량이 돌아간다. 다른 농가는 404, 입금 대기가 아니면 409다
