- [ ] AC-09-1. **Given** 남은 물량이 1이다 / **When** 두 사람이 동시에 결제한다 / **Then** 한 명만 성공하고 다른 한 명은 품절 안내를 받는다
- [ ] AC-09-2. **Given** 결제 전 주문이다 / **When** 거절되는 카드(Mock: 끝 4자리 0000)로 결제한다 / **Then** 사유가 보이고 남은 물량이 줄지 않으며 주문서로 돌아갈 수 있다
- [ ] AC-09-3. **Given** 결제 요청을 보냈다 / **When** 같은 멱등 키로 다시 보낸다 / **Then** 결제와 단계 물량 차감은 한 번만 일어나고 같은 결과를 받는다

## 스펙 I2 — PortOne 샌드박스 결제 (DEV-36)

서버에 PortOne V2 테스트 채널(상점 ID·채널 키·API 시크릿)이 설정되면 `GET /api/payments/config`가 `enabled=true`를 돌려주고, SCR-11은 Mock 카드 입력 대신 PortOne 결제 창(카드)을 연다. 앱은 승인 뒤 받은 `paymentId`를 `POST /api/orders/{orderId}/pay`에 보내고, 서버가 PortOne에서 결제를 조회해 상태 `PAID`·금액 일치·`customData.orderId` 일치를 확인한 뒤에만 물량을 차감하고 `RESERVED`로 바꾼다. 설정이 없으면 I1 Mock 계약(`mockResult`) 그대로다. PortOne 웹훅 `Transaction.Paid`(`POST /api/payments/portone/webhook`)는 앱이 확인을 못 보낸 경우를 메우며, 같은 결제를 두 번 반영하지 않는다. 실결제 전환은 사업자 등록·PG 계약 뒤 채널 키만 바꾼다.

- [ ] AC-09-7. **Given** PortOne이 켜져 있고 결제 전 주문이다 / **When** PG가 `PAID`·주문 금액과 같은 결제 ID로 확인을 보낸다 / **Then** 물량이 한 번 차감되고 `RESERVED`가 되며 같은 멱등 키 재시도는 같은 결과를 돌려준다. PG가 `FAILED`·`CANCELLED`이거나 금액·주문이 다르면 실패 사유를 돌려주고 물량·상태는 그대로다. PortOne이 꺼져 있는데 `paymentId`를 보내면 400
- [ ] AC-09-8. **Given** 결제 전 주문의 `Transaction.Paid` 웹훅이 온다 / **When** 같은 웹훅이 두 번 온다 / **Then** 첫 번째만 예약 완료로 바꾸고 두 번째는 무시한다. 웹훅 시크릿이 설정돼 있으면 서명이 틀린 요청은 401
