# FEAT-10 주문 내역·상세

> 상위: [PRD](/docs/spec/prd.md) 7.1 · 규칙: [rules.md](./rules.md) · 화면: [IA](/docs/spec/ia.md), [화면 명세](/docs/spec/screens.md) · 추적표: [README](./README.md)

| 항목 | 내용 |
| --- | --- |
| 우선순위·출처 | P0 · PRD 7.1, S-2·S-4 |
| 앱·화면 | 소비자 앱 SCR-13, SCR-14 (내 주문 탭) |
| 목적 | 내 주문의 진행과 받는 시기를 보고 필요한 행동을 한다 |
| 사전 조건 | 로그인했다 |
| 정상 흐름 | 0) 두 번째 탭 내 주문 1) 목록: 확정/미확정/취소·환불 탭, 미확정 내 할 일이 있는 주문 먼저, 그다음 최신순 2) 상세: 상태(소비자 문구: 예약 완료·수확·포장 중·배송 중·배송 완료·구매 확정·환불), 배송 예정 기간, 택배사·송장 번호·배송 조회(배송 중부터), 금액, 받는 사람·배송 메모 3) 배송 기간이 바뀌면 ‘새 기간 동의’ 또는 ‘전액 환불’ 선택 4) 배송 완료 후 ‘구매 확정’, 없으면 8일 뒤 자동 확정 |
| 예외 흐름 | E1 남의 주문 주소로 접근 → 내 주문 내역. E2 농가 정지로 환불 → 사유 표시 |
| 사후 조건 | 동의·환불·구매 확정을 고르면 그 상태와 시각이 기록된다 |
| 입력·검증 | 없음 |
| 규칙 | R-05, R-13, R-14, R-21, R-24 |

- [ ] AC-10-1. **Given** 배송 기간이 바뀐 주문이 있다 / **When** 주문 내역을 연다 / **Then** 미확정 탭에서 그 주문이 우선 표시되고 동의하거나 환불받기 전까지 남는다
- [ ] AC-10-2. **Given** 배송 완료 후 8일이 지났다 / **When** 소비자가 구매 확정을 누르지 않았다 / **Then** 자동으로 구매 확정된다
- [ ] AC-10-3. **Given** 농가 정지로 환불된 주문이다 / **When** 주문 상세를 연다 / **Then** 환불 사유가 보인다

## 스펙 1.2

[공통 계약](../contracts-1.2.md)을 적용한다.

- [ ] AC-10-4. 결제 이력 주문 상세에서 주문 문제 문의로 진입하며 주문 문맥을 해당 농가 대화에 유지한다.

## 스펙 1.3

- [ ] AC-10-5. 두 번째 내 주문 탭에서 목록·상세·문의에 접근하며 결제 완료·로그인 복귀·뒤로가기는 `/orders` 경로와 일치한다.

## 스펙 1.4

- [ ] AC-10-6: 상단 탭은 확정 → 미확정 → 취소·환불이며 기본은 미확정이다. 미확정은 RESERVED/PREPARING/SHIPPED/DELIVERED, 확정은 COMPLETED, 취소·환불은 CANCELED/REFUNDED/PARTIALLY_REFUNDED다. 결제 전 주문은 제외한다. 모든 페이지를 집계한 건수를 표시하고, 미확정 내 응답 필요 주문을 우선한 뒤 최신순으로 정렬한다. 선택은 filter=pending|confirmed|canceled로 상세 왕복·로그인 복귀에도 유지한다. 기존 API 반환 범위는 변경하지 않는다. 상세는 [1.4 계약](../capacity-1.4.md).

- [ ] AC-10-7: 구매 확정·환불 후 목록 복귀 시 탭 소속과 건수가 갱신된다. 초기 로딩, 탭별 빈 상태, 실패 재시도와 50건 초과 집계를 지원한다.
