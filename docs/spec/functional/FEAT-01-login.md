## 스펙 I2 — 카카오 로그인 (DEV-32)

소비자 앱 SCR-05에 ‘카카오로 시작하기’를 둔다. 카카오 인가 화면 → `/auth/kakao`로 복귀 → 인가 코드를 `POST /api/auth/kakao`(`code`, `redirectUri`, `app`)로 보내면 서버가 카카오에서 회원번호(`id`)와 카카오계정 이메일(동의 항목 `account_email`), 전화번호(동의 항목 `phone_number`, 카카오 필수 동의. 2026-11-17 비즈 앱 동의 항목 심사 통과 뒤 두 앱의 인가 요청 scope를 `account_email,phone_number`로 보낸다(동의 항목 ID는 쉼표로 잇는다), DEV-78. 이름 `name`은 신청하지 않았으므로 scope에 넣지 않는다. 콘솔에 없는 항목을 넣으면 카카오 로그인이 실패한다, DEV-142)를 받아 (회원번호, 역할)에 해당하는 그 앱 계정을 찾거나 만들고 JWT를 준다(ADR 0003·0010). 식별은 회원번호로 하고, 이메일은 연락용으로 `User.email`에 둔다. release 실서버 앱은 카카오 사용 여부와 관계없이 테스트 계정 목록을 요청·표시하지 않고(DEV-367), 개발 빌드에서는 카카오 비활성·조회 실패 때만 시드 목록을 보이며 명시적 앱 Mock은 카카오와 목록을 함께 둔다(DEV-136), REST API 키가 없으면 `GET /api/auth/kakao/config`가 `enabled=false`를 돌려주고 버튼을 숨긴다.

**첫 가입 온보딩(SCR-06, 사용자 결정 10/18)**. 카카오로 처음 만든 소비자 계정은 `needsOnboarding=true`로 시작한다. 가입은 당근처럼 가볍게 한 화면에서 끝낸다(사용자 결정 10/23, DEV-142): 닉네임(2~12자, 농가 채팅·소식방·농가 화면에 보이는 이름), 휴대폰 번호(형식 검증만, 인증번호 없음), 가입 동의(이용약관·개인정보 수집·이용·만 14세 이상 필수, 농가 소식·혜택 알림 선택). 이름과 배송지는 가입 때 받지 않고, 첫 주문서(SCR-10)의 받는 사람·주소로 받는다(배송지 저장은 주문서에서 고른다). 전화번호는 카카오 필수 동의 항목으로 받으며(2026-11-17 심사 통과, 인가 요청 scope에 `phone_number`, DEV-78), 카카오톡에 등록된 번호라 따로 인증번호를 보내지 않는다. 빈 칸에만 채우고 사용자가 고친 값은 덮지 않는다. 카카오 전화번호는 온보딩 휴대폰 칸과 첫 주문서의 연락처 칸을 미리 채운다. 이름은 카카오에서 받지 않고 첫 주문서의 받는 사람으로 직접 입력한다(당근처럼, 10/23 결정). 카카오계정에 전화번호가 없으면 직접 입력한다. 생산자는 같은 값으로 가입 신청(SCR-20)의 연락처를 미리 채운다. 닉네임·휴대폰·필수 동의 중 하나라도 없으면 `needsOnboarding=true`이고, 그동안 주문·팔로우·좋아요·채팅·소식방 답장은 403 `ONBOARDING_REQUIRED`로 거부하며 앱은 온보딩으로 보낸다. 둘러보기·내 정보·배송지 관리는 된다. 온보딩을 닫으면 계정은 남고 다음 관문에서 다시 온보딩이 열린다. 테스트 계정과 생산자 계정은 온보딩 대상이 아니다(생산자는 SCR-20이 대표자 이름·연락처를 받는다). 농가에 보이는 소비자 이름은 닉네임이다(R-15). 테스트 계정처럼 닉네임이 없으면 이름 앞 글자 + ○○이다.

**배송지(사용자 결정 10/18)**. 저장 배송지는 계정당 50개까지다. 내 정보의 배송지 관리(SCR-17 하위)에서 고치고 지우며, 기본 배송지를 지우면 가장 최근 배송지가 기본이 된다. 주문서 받는 곳은 기본 배송지를 채우고 ‘다른 배송지’에서 저장 목록 중 고르거나 새 주소를 넣는다. 50개가 찼으면 새 주소는 그 주문에만 쓰고 저장하지 않는다.

## 스펙 I4 — 아이디·비밀번호 로그인 (DEV-363, PM 결정 11/18)

> 이력: DEV-198(평가용 주소 `?evaluator=1`)은 ‘아이디·비밀번호 로그인은 만들지 않는다’고 적었다. 원스토어 제출(마감 11/20)과 UAT가 카카오 없이 두 앱에 들어와야 해서 11/18 PM 결정으로 **뒤집는다**. 같은 날 처음 설계(앱의 공개 아이디 가입 + 운영자 승인 대기)는 PM 결정으로 **바뀌었다**: **공개 아이디 가입은 없고, 운영자가 관리자 웹에서 아이디 계정을 만든다**(원스토어 심사자·UAT 테스터용). 일반 사용자는 카카오로 가입한다. 카카오 로그인은 유지한다. 테스트 계정 노출 정책은 아래 DEV-367(11/19)로 대체한다.

두 앱의 로그인(SCR-05·SCR-19)에 카카오와 함께 아이디·비밀번호 로그인을 둔다. 카카오가 켜져 있으면 칸은 접어 두고 화면 아래 ‘아이디로 로그인’ 글자로 펼친다(DEV-378, AC-01-35). 가입 버튼은 없다. 아이디 계정은 카카오 계정과 따로이고 합치지 않는다. 계정 분리(ADR 0010)대로 아이디는 앱(역할)마다 따로다.

- **계정 만들기(운영자)**: 관리자 웹 ‘아이디 계정’에서 앱(소비자·생산자), 아이디, 소비자는 닉네임(필수)·휴대폰(선택), 생산자는 이름(선택, 비면 ‘농가 사용자’)을 넣는다. 서버가 임시 비밀번호(12자)를 만들어 운영자에게 한 번만 보이고 해시만 저장한다(감사·멱등 기록에도 평문 없음).
- **아이디**: 앞뒤 공백을 지우고 소문자로 저장한다(ASCII만 소문자로). 영문 소문자로 시작하는 영문 소문자·숫자 4~20자. 대소문자만 다른 아이디는 같은 아이디다. 운영처럼 보이는 예약어(admin, farmclub, support 등)는 못 쓴다. 이메일은 받지 않는다.
- **첫 로그인**: 임시 비밀번호로 로그인하면 ① 새 비밀번호로 바꾸기 전에는 비밀번호 변경 화면만 열리고(서버 403 `PASSWORD_CHANGE_REQUIRED`) ② 바꾸면 카카오 가입과 같은 필수 동의(소비자 SCR-06의 약관·개인정보·만 14세, 생산자 SCR-19a의 약관·개인정보)를 지금 버전으로 해야 쓸 수 있다(서버: 동의·온보딩 API와 탈퇴만 열리고 소비자 403 `ONBOARDING_REQUIRED`, 생산자 403 `CONSENT_REQUIRED`). 소비자는 휴대폰을 운영자가 넣지 않았으면 같은 화면에서 받는다. ③ 그다음 평소 흐름(생산자는 가입 신청 SCR-20 → 운영자 승인 SCR-21).
- **비밀번호**: 8~128자, 공백만은 안 됨, 아이디와 같으면 안 됨, 흔한 비밀번호 목록에 있으면 안 됨. 조합 규칙(특수문자 필수 등)은 두지 않는다. 변경 화면에 규칙 ‘8~128자 · 아이디와 같거나 흔한 비밀번호는 쓸 수 없어요’를 늘 보인다. 서버는 argon2id 해시만 저장한다(평문은 DB·로그·오류 응답·분석 도구 어디에도 남지 않는다).
- **로그인**: 틀린 아이디·틀린 비밀번호는 같은 문구 ‘아이디 또는 비밀번호가 맞지 않아요’. 아이디마다 15분 안에 10번 시도하면 15분 잠근다. 잠긴 동안은 맞는 비밀번호도 받지 않고 남은 시간을 알린다(429). **IP별 제한은 두지 않는다**(PM 11/18: 아이디별 잠금만 — 서버가 클라이언트 IP를 읽지 않아 X-Forwarded-For 위조로 남을 잠그거나 우회할 수 없다).
- **비밀번호 찾기**: 이메일 재설정은 없다. 로그인 화면에 ‘비밀번호를 잊었다면 farmclub에 문의해 주세요’와 사업자 정보 연락처 안내. 운영자가 관리자 웹(사용자·아이디 계정 목록)에서 임시 비밀번호를 다시 발급하면 한 번만 보이고, 그 비밀번호로 로그인하면 새 비밀번호로 바꾸기 전에는 다른 화면·API를 쓰지 못한다.
- **비밀번호 변경**: 소비자 ‘내 정보’·생산자 ‘환경설정’과 승인 전 화면(SCR-21)의 ‘비밀번호 변경’(아이디 계정만). 지금 비밀번호가 맞아야 하고, 바꾸면 그 계정의 다른 로그인이 모두 풀린다.
- **탈퇴**: 아이디·비밀번호 해시를 지운다. 아이디는 예약하지 않아 운영자가 같은 아이디로 다시 만들 수 있고, 그러면 새 사용자다.

- [ ] AC-01-32. **Given** 아이디 계정이다 / **When** 탈퇴한다(동의 전에도 된다) / **Then** AC-01-20에 더해 아이디·비밀번호 해시를 지우고, 운영자가 같은 아이디로 다시 만들면 새 사용자다
- [ ] AC-01-33. **Given** 운영자가 만든 생산자 아이디 계정이다 / **When** 첫 로그인에서 비밀번호를 바꾸고 `/consent`에서 동의한다 / **Then** 농가 없는 생산자 계정으로 가입 신청(SCR-20) → 운영자 승인(SCR-21) 흐름으로 간다(따로 승인 층 없음). 이 계정은 소비자 앱에서는 로그인되지 않는다

- [ ] AC-01-35. **Given** 소비자·생산자 로그인 화면이고 카카오 설정이 켜져 있다 / **When** 화면을 연다 / **Then** 아이디·비밀번호 칸과 ‘로그인하기’는 접혀 있고 사업자 정보 칸 바로 위에 ‘아이디로 로그인’ 글자 링크(`aria-expanded=false`)만 있다. 누르면 칸·버튼·비밀번호 찾기 안내가 그대로 펼쳐지고 다시 누르면 접히며, 접었다 펼쳐도 적은 아이디는 남는다. 로그인 실패 문구가 보이는 동안은 링크가 흐려지고 접히지 않으며, 문구가 사라지면 다시 접힌다. 웹 `/login?id=1`은 처음부터 펼친다(`from`·`next`·`reason`과 함께 써도 된다). 카카오가 꺼졌거나 설정 조회가 실패하거나 5초 안에 답이 없으면 칸은 펼친 채이고 링크는 없다. 펼친 뒤 로그인 흐름(임시 비밀번호 → 변경 → 동의)은 AC-01-22~33 그대로다(DEV-378, PM 11/21)

> AC-01-24·25·28(공개 가입의 운영자 승인·반려, 가입 남용 제한)은 같은 날 설계 변경으로 없앴다(번호는 다시 쓰지 않는다).

## 계정 삭제 안내 (DEV-423)

Google Play는 앱마다 로그인 없이 열리는 ‘계정 삭제 URL’을 요구한다. 탈퇴 자체(AC-01-20·32)는 바뀌지 않고, 앱 밖에서 읽는 안내 한 장을 둔다(문안·위치는 `policy.md` ‘계정 삭제 안내 위치’).

- [ ] AC-01-36. **Given** 로그인하지 않았고 JavaScript가 없어도 된다 / **When** 소비자·생산자 웹의 `/account-deletion`을 연다 / **Then** 그 앱의 정적 페이지가 열리고 첫 화면에 앱 이름(‘farmclub’ / ‘farmclub 농가’)·개발자 이름(상호, 비면 ‘farmclub 운영자’)·실제 화면 이름으로 쓴 탈퇴 4단계와 ‘로그인하기’(소비자 `/login?next=/me`, 생산자 `/login`)가 보인다. 아래로 로그인할 수 없을 때 이메일 요청(10일 안 처리, 이메일이 비면 처리방침과 같은 대체 문장), 바로 지우는 정보(탈퇴 시트와 같은 줄), 탈퇴 뒤 보관하는 정보와 기간(처리방침 제3조 표와 같은 행), 탈퇴를 막는 주문, 일부만 지우는 방법이 있다. 처리방침·약관·이 페이지의 하단 링크 줄에 ‘계정 삭제’가 있다

> 처리방침(PM 11/18): 아이디 계정의 아이디·암호화한 비밀번호를 처리 항목에 더해 약관·처리방침 동의 버전을 **2026-11-20**으로 올렸다(시행 2026-11-20). 예전 버전에 동의한 기존 회원은 AC-01-17·18의 재동의 흐름으로 다음 이용 때 다시 동의한다.

## I4 평가용 진입 폐기 (DEV-367, PM 11/19)

아이디 계정을 쓸 수 있으므로 운영 UAT·심사자는 운영자가 따로 발급한 아이디·비밀번호로 로그인한다. release 실서버 앱은 시드 목록을 요청하지 않고 선택 UI·고정 하단 바를 숨긴다. 카카오 비활성·설정 조회 실패에도 같다. 옛 `?evaluator=1`, 기기의 `farmclub:evaluator`와 `EXPO_PUBLIC_EVALUATOR_LOGIN` 빌드 플래그는 사용하지 않는다. 개발 빌드 또는 명시적 앱 Mock에서만 테스트 계정 선택을 유지한다. 개발 실서버는 카카오 비활성·조회 실패 때 목록을 보이고, 앱 Mock은 카카오와 목록을 함께 보인다. 서버 테스트 API의 설정 가드(AC-01-5)는 별도이며 UI 숨김으로 대체되지 않는다.

- [ ] AC-01-34. **Given** 소비자·생산자 release 앱이 실서버 전송 모드다 / **When** 일반 로그인·옛 평가 쿼리·저장 표시·평가 빌드 플래그로 진입하거나 새로고침하고 카카오 설정이 켜짐·꺼짐·조회 실패다 / **Then** 시드 목록 요청과 테스트 로그인 요청은 0건, 시드 선택·하단 바는 없고 아이디 로그인은 남는다. 카카오가 켜졌으면 버튼도 남는다. 개발 실서버의 카카오 비활성·오류 시 시드 로그인, 명시적 앱 Mock의 카카오·목록 동시 표시는 유지한다. 카카오·아이디의 앱별 인증·동의·복귀 계약은 바뀌지 않는다.
