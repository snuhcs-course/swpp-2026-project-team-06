## 스펙 I2 — 카카오 로그인 (DEV-32)

소비자 앱 SCR-05에 ‘카카오로 시작하기’를 둔다. 카카오 인가 화면 → `/auth/kakao`로 복귀 → 인가 코드를 `POST /api/auth/kakao`(`code`, `redirectUri`, `app`)로 보내면 서버가 카카오에서 회원번호(`id`)와 카카오계정 이메일(동의 항목 `account_email`)을 받아 (회원번호, 역할)에 해당하는 그 앱 계정을 찾거나 만들고 JWT를 준다(ADR 0003·0010). 식별은 회원번호로 하고, 이메일은 연락용으로 `User.email`에 둔다. 카카오가 켜져 있으면 테스트 계정 로그인은 숨기고(꺼진 CI·Mock 플래그 환경에서만 보임), REST API 키가 없으면 `GET /api/auth/kakao/config`가 `enabled=false`를 돌려주고 버튼을 숨긴다.

**첫 가입 온보딩(SCR-06, 사용자 결정 10/18)**. 카카오로 처음 만든 소비자 계정은 `needsOnboarding=true`로 시작한다. 지금 서비스가 쓰는 정보를 한 번에 받는다: ① 닉네임(2~12자, 농가 채팅·소식방·농가 화면에 보이는 이름), 이름(2~20자, 주문서 받는 사람), 휴대폰 번호(형식 검증만, 인증번호 없음), 가입 동의(이용약관·개인정보 수집·이용·만 14세 이상 필수, 농가 소식·혜택 알림 선택) → ② 기본 배송지(받는 사람·연락처는 ①로 채움, ‘주문할 때 입력할게요’로 건너뛸 수 있음). 카카오에서 온 값은 미리 채우고 빠진 값만 직접 입력한다. 이름·전화번호 동의 항목은 비즈 앱 심사 뒤(2단계) 인가 요청에 추가하며, 그때도 빈 칸에만 채우고 사용자가 고친 값은 덮지 않는다. 닉네임·이름·휴대폰·필수 동의 중 하나라도 없으면 `needsOnboarding=true`이고, 그동안 주문·팔로우·좋아요·채팅·소식방 답장은 403 `ONBOARDING_REQUIRED`로 거부하며 앱은 온보딩으로 보낸다. 둘러보기·내 정보·배송지 관리는 된다. 온보딩을 닫으면 계정은 남고 다음 관문에서 다시 온보딩이 열린다. 테스트 계정과 생산자 계정은 온보딩 대상이 아니다(생산자는 SCR-20이 대표자 이름·연락처를 받는다). 농가에 보이는 소비자 이름은 닉네임이고, 닉네임이 없으면 이름 앞 글자 + ○○이다(R-15).

**배송지(사용자 결정 10/18)**. 저장 배송지는 계정당 50개까지다. 내 정보의 배송지 관리(SCR-17 하위)에서 고치고 지우며, 기본 배송지를 지우면 가장 최근 배송지가 기본이 된다. 주문서 받는 곳은 기본 배송지를 채우고 ‘다른 배송지’에서 저장 목록 중 고르거나 새 주소를 넣는다. 50개가 찼으면 새 주소는 그 주문에만 쓰고 저장하지 않는다.

- [ ] AC-01-14. **Given** 온보딩에서 동의한다 / **When** `POST /api/auth/me/consents`가 저장된다 / **Then** 항목(이용약관·개인정보·만 14세·알림 수신)마다 동의 여부·문구 버전·시각이 한 줄씩 남고, 다시 동의하면 그 줄의 버전·시각이 바뀐다
- [ ] AC-01-15. **Given** 저장 배송지가 있다 / **When** 배송지 관리에서 고치거나 지우거나 51번째를 저장한다 / **Then** 수정은 보낸 필드만 검증해 바꾸고, 기본 배송지를 지우면 가장 최근 배송지가 기본이 되며, 51번째 저장은 409 `ADDRESS_LIMIT`으로 거부된다(주문의 ‘기본 배송지로 저장’은 주문은 그대로 두고 저장만 건너뜀). 다른 사람의 배송지는 404다
