# FEAT-08 예약 주문

> 상위: [PRD](/docs/spec/prd.md) 7.1 · 규칙: [rules.md](./rules.md) · 화면: [IA](/docs/spec/ia.md), [화면 명세](/docs/spec/screens.md) · 추적표: [README](./README.md)

| 항목 | 내용 |
| --- | --- |
| 우선순위·출처 | P0 · PRD 7.1, S-2 |
| 앱·화면 | 소비자 앱 SCR-04(옵션·수량 시트), SCR-10과 배송지 입력 하위 화면, SCR-17 배송지 관리(`/me/addresses`) |
| 목적 | 조건에 동의하고 예약 주문을 만든다 |
| 사전 조건 | 로그인했고, 상품이 판매 중이며, 지금 단계가 있고 남은 물량이 1 이상이다 |
| 정상 흐름 | 1) 옵션·수량 선택 2) 받는 사람·연락처·우편번호·주소·상세 주소(‘우편번호 찾기’로 우편번호·도로명 주소를 채우거나 직접 입력한다. 웹·앱 모두, DEV-314)·배송 메모(선택) 입력(저장된 배송지가 있으면 기본으로 채움, 새 주소는 저장할 수 있음) 3) 합계(화면 이름 ‘총 입금액’, DEV-293) = 단계 가격 × 수량 + 배송비 + 도서산간 추가금(해당 시) 4) 동의 5개(R-03 4개 + 개인정보 제3자 제공, DEV-120) 5) 예약하기(버튼 ‘N원 예약하기’, DEV-293) → 멱등 키와 함께 1회 요청. 주문서가 본 기간·단가·옵션 중량을 함께 보내고 서버가 단계·가격·물량을 재확인(DEV-216) 6) 주문 생성(결제 전), 동의 시각 기록 → FEAT-09 |
| 예외 흐름 | E1 그사이 단계가 바뀌거나 품절·판매 중지 → 409, 입력값 유지. 사유(`details.reason`)마다 안내와 다음 행동이 다르다: 가격·기간·중량이 본 값과 다름(`STAGE_CHANGED`, 지금 기간 있음) → 이전→지금 금액을 보이고 ‘바뀐 금액으로 예약하기’로 다시 확인받음(AC-08-8). 지금 예약 기간 없음 → ‘상품으로 돌아가기’. 판매 중지(`SALES_PAUSED`) → 예약하기를 끄고 ‘다시 확인하기’. 고른 옵션 품절(`SOLD_OUT`) → ‘옵션 바꾸기’, 전체 물량 소진(`TOTAL_LIMIT_REACHED`) → 수량 바꾸기 또는 상품으로(AC-08-9). 물량은 잡아두지 않고 결제 순간 선착순으로 확정한다. E2 같은 요청이 두 번 감(중복 탭·재전송) → 같은 멱등 키면 주문은 하나만 생긴다 |
| 사후 조건 | 결제 전 주문이 생기고 주문서 금액을 기록하되 결제 시 기간·가격을 재확인하고 바뀌면 STAGE_CHANGED로 다시 확인받는다. 동의 시각과 문구 버전이 기록된다 |
| 입력·검증 | 받는 사람 이름·연락처(휴대폰 형식)·우편번호·주소 필수, 상세 주소·배송 메모(100자 이하) 선택. 주소·배송 메모는 주문에 복사해 저장한다(저장 배송지를 바꿔도 지난 주문은 그대로). 동의 5개(R-03 4개 + 개인정보 제3자 제공) 모두 필수. 수량은 1\~최대. 주소가 생산자가 정한 도서산간 지역이면 추가금 적용 |
| 규칙 | R-03, R-06, R-17, R-20, R-23 |

- [ ] AC-08-1. **Given** 동의 5개(R-03 4개 + 개인정보 제3자 제공) 중 하나를 체크하지 않았다 / **When** 예약하기를 누른다 / **Then** 다음으로 넘어가지 않는다(버튼이 꺼져 있다)
- [ ] AC-08-7. **Given** 주문서에서 ‘개인정보 제3자 제공(판매자)’에 동의하지 않았다 / **When** 예약한다 / **Then** 서버는 400(`consents`)으로 거부하고 주문이 생기지 않는다. 동의하면 주문의 `consent_at`·`consent_version`(`policy-2026-10-23` 이후)에 남는다. 문구는 제공받는 자(농가명)·목적·항목·보유 기간·거부 시 예약 불가를 보인다(개인정보보호법 제17조, DEV-120)
- [ ] AC-08-2. **Given** 한 주문 최대 수량이 3이다 / **When** 수량을 고른다 / **Then** 4 이상은 고를 수 없다
- [ ] AC-08-3. **Given** 배송비 별도 상품이다 / **When** 주문서를 연다 / **Then** 상품 금액·배송비·합계(‘총 입금액’)가 나뉘어 보인다
- [ ] AC-08-4. **Given** 받는 주소가 생산자가 정한 도서산간 지역이다 / **When** 주소를 입력한다 / **Then** 추가 운임이 합계에 더해져 보인다

* [ ] AC-08-5. **Given** 내 정보에 배송지를 저장해 두었다 / **When** 주문서를 연다 / **Then** 받는 사람·연락처·주소가 채워져 있고 고칠 수 있다

## 스펙 1.2

[공통 계약](../contracts-1.2.md)을 적용한다.

- [ ] AC-08-6. 주문 수량은 한 주문 상한·상품 총 잔여·해당 기간 옵션 잔여의 최솟값 이하이며 서버가 재검증한다.
- [ ] AC-08-8. **Given** 주문서를 연 뒤 농가가 지금 기간의 가격(또는 옵션 중량)을 바꿨거나 기간 경계가 지났다 / **When** 예약하기를 누른다 / **Then** 서버는 주문서가 보낸 `expectedStageId`·`expectedUnitPrice`·`expectedUnitWeightGrams`를 지금 값과 비교해 409 `STAGE_CHANGED`(`details.previous`·`current`)로 거부하고 주문이 생기지 않는다. 주문서는 ‘29,000원 → 30,000원’처럼 바뀐 값과 새 합계(처음 본 합계는 취소선)를 보이고 받는 곳·메모·동의·수량을 그대로 둔다. ‘바뀐 금액으로 예약하기’를 눌러야 지금 값으로 주문이 생긴다. 동의는 다시 받지 않는다(DEV-216). 기대값은 이번 이터레이션에 선택(없으면 지금 값으로 생성), 다음 이터레이션에 필수로 바꾼다
- [ ] AC-08-9. **Given** 주문서를 연 뒤 판매가 중지됐거나, 고른 옵션이 품절됐거나, 예약 기간이 끝났다 / **When** 예약하기를 누른다 / **Then** 가격이 함께 바뀌었어도 판매 중지 → 지금 기간 없음 → 전체 물량 → 기간 물량 → 본 값 비교 순서로 앞의 사유가 409로 온다. 주문서는 ‘바뀐 금액으로 예약하기’를 보이지 않고 사유별 안내와 다음 행동(판매 중지: 꺼진 예약하기 + ‘다시 확인하기’, 품절: ‘옵션 바꾸기’, 기간 종료·전체 소진: ‘상품으로 돌아가기’)을 보인다(DEV-218)
