# FEAT-12 1:N 소식·1:1 채팅

> 상위: [PRD](/docs/spec/prd.md) 7.1 · 규칙: [rules.md](./rules.md) · 화면: [IA](/docs/spec/ia.md), [화면 명세](/docs/spec/screens.md) · 추적표: [README](./README.md)

| 항목 | 내용 |
| --- | --- |
| 우선순위·출처 | P0 · PRD 7.1, S-3 |
| 앱·화면 | 생산자 앱 SCR-27 / 소비자 앱 SCR-18(소식), SCR-15·SCR-16(채팅), SCR-03·SCR-04(채팅하기) |
| 목적 | 농가는 팔로워 전체에 소식을 올리고, 소비자는 그 농가와 1:1 채팅으로 묻는다 |
| 사전 조건 | 생산자는 승인됨. 소비자는 로그인함. 일반 채팅은 그 농가를 팔로우한 상태(없으면 안내 후 자동 팔로우), 본인 결제 주문 문의는 예외 |
| 정상 흐름 | 1) 생산자가 본문·사진·영상과 공개 여부를 입력해 소식을 올림(소식방 입력칸 전송은 받는 사람 수·미리보기 확인 시트를 거친다, AC-12-13) 2) 전화번호·계좌번호·외부 메신저 ID 가림 3) 팔로워 전원의 소식방(SCR-18)에 말풍선으로 들어감 4) 공개면 SCR-18 공개 소식방에도 남음 5) 소비자가 소식방에서 답장하면 같은 방에 본인 말풍선으로 남음. 명시적으로 농가 정보·상품 상세의 ‘1:1 채팅’을 누름 → 그 농가 채팅(SCR-16). 팔로우하지 않았으면 “팔로우하고 대화를 시작해요” 안내와 함께 자동 팔로우 6) 글·사진으로 질문 → 그 소비자와 농가의 채팅에만 저장(가린 상태로) → FEAT-13 |
| 예외 흐름 | E1 팔로워 0명이어도 올릴 수 있고 공개면 소식에 남는다. E2 비로그인으로 질문하기·채팅하기 → FEAT-01 후 그 채팅으로. E3 팔로우한 농가가 없음 → 채팅 안 소식방 빈 상태와 농가 둘러보기 안내. E4 팔로우를 해제하면 소식방에서 빠지고, 본인 결제 주문 문의는 계속 가능하다. 다시 팔로우하면 이전 채팅이 그대로 보인다. E5 생산자가 자기 소식을 삭제하면 모든 소비자 화면에서 빠지고 소비자 답장은 남는다. 본문 수정은 가능하며 이탤릭 수정됨을 표시한다(M-23, DEV-289) |
| 사후 조건 | 소식·질문이 저장된다(가린 상태로). 채팅하기로 시작했으면 팔로우가 생긴다 |
| 입력·검증 | 소식: 본문과 첨부 중 하나는 필수. 첨부는 사진 최대 5장(장당 10MB), 영상 1개(60초, 100MB). 채팅 질문: 글 1,000자 이하, 사진 최대 3장(장당 10MB), 영상 안 됨. 서버에서 다시 검사한다. 1:1 목록·대화에는 소식이 나오지 않는다 |
| 규칙 | M-01\~M-04, M-14, M-16, M-23 |

- [ ] AC-12-1. **Given** 소비자 A가 농가에 채팅으로 질문했다 / **When** 소비자 B가 같은 농가 채팅을 열거나 API를 호출한다 / **Then** A의 질문은 어디에도 나오지 않는다
- [ ] AC-12-2. **Given** 본문에 “010-1234-5678로 연락주세요”가 있다 / **When** 보낸다 / **Then** 번호가 가려진 채 저장·표시된다
- [ ] AC-12-3. **Given** 공개를 고른 소식이다 / **When** 올린다 / **Then** 팔로워의 채팅 안 소식방과 농가의 공개 소식방에 모두 보인다
- [ ] AC-12-4. **Given** 로그인한 소비자가 팔로우하지 않은 농가다 / **When** 채팅하기를 누른다 / **Then** “팔로우하고 대화를 시작해요” 안내와 함께 팔로우되고 그 농가 채팅이 열린다
- [ ] AC-12-5. **Given** 팔로우한 농가가 소식을 올렸다 / **When** 채팅의 1:1 구분과 그 농가 1:1 대화를 연다 / **Then** 소식은 나오지 않고 1:1 질문·답만 보인다

- [ ] AC-12-6. 소비자 A의 소식 답장은 A와 생산자에게만 보이고 B의 목록 미리보기·cursor·직접 API에도 노출되지 않는다. 생산자는 자기 소식방의 모든 답장을 본다.
- [ ] AC-12-7. 생산자 채팅 탭에서 소식방 / 1:1 채팅 두 선택지와 모든 1:1 대화를 볼 수 있으며 AI가 답한 방도 열어 직접 응대한다.
- [ ] AC-12-8. 활성 화면 2초 갱신과 이전 페이지를 합쳐도 중복·누락·스크롤 점프가 없고, 비활성 화면은 polling을 멈춘다.

소식방은 방송+비공개 답장, 1:1은 별도 대화다. 새 경로·읽음·사진 권한은 [1.2 계약 4·6장](../contracts-1.2.md)을 따른다.

## DEV-210 소식 보내기 확인·삭제 (HE 후속)

입력칸 1:N 전송은 확인 뒤에 보내고, 보낸 소식은 생산자가 지울 수 있다(M-23). 사진 소식 작성 화면(SCR-27)은 이미 미리보기·받는 사람 수가 있는 확인 화면이라 시트를 더하지 않는다. 화면·문구는 [제안 보드](/docs/design/proposals/dev-210-news-confirm-delete.html), API는 [공통 계약](../contracts-1.2.md) 4장.

- [ ] AC-12-13. **Given** 생산자가 자기 소식방 입력칸에 글을 적었다 / **When** 전송을 누른다 / **Then** 「팔로워 N명에게 보낼까요?」 시트에 소비자에게 보일 미리보기가 나오고, 「아니요」면 요청 없이 글이 입력칸에 남고, 「확인 · 보내기」면 한 번만 올라간다. 입력칸 안내는 「팔로워 N명에게 보내기」다(DEV-295에서 「…소식 보내기」를 줄임)
- [ ] AC-12-14. **Given** 생산자가 자기 농가 소식을 보냈다 / **When** 우클릭·길게 누르기 → 「삭제·다시 쓰기」 → 확인 시트의 「삭제」를 누른다 / **Then** 팔로워 소식방·채팅 목록 미리보기·소식 목록·농가 공개 소식방에서 빠지고, 그 소식의 좋아요는 404다. 소비자 답장은 남는다. 같은 삭제를 다시 보내도 성공(204)이다
- [ ] AC-12-15. **Given** 다른 농가의 소식이거나 없는 소식이다 / **When** 생산자가 삭제 API를 부른다 / **Then** 404이고 소식은 그대로다. 소비자·미승인 생산자는 403이다
- [ ] AC-12-16. **Given** 생산자가 글 소식을 보냈다 / **When** 우클릭·길게 누르기 → 「삭제·다시 쓰기」 → 확인 시트의 「삭제하고 다시 쓰기」를 누른다 / **Then** 소식이 삭제되고 본문이 입력칸에 돌아온다. 사진·영상 소식에는 이 버튼이 없다

## DEV-289 채팅 UX 보완
- 양쪽 사용자는 같은 방의 메시지를 인용 답장한다. 전송 실패 시 인용·본문·첨부를 보존한다. 생산자 인용 답장은 연결된 OPEN 전달 질문만 처리하며 주문 문제 문의 완료와 구분한다.
- AI 조작은 농가 전체 1:1에 적용하는 ON/OFF 버튼이다. 생산자의 마지막 성공 발송부터 해당 방만10분 직접 응대하고 추가 발송은 연장한다. 서버 시각 기준이며 중복 재시도는 연장하지 않는다. 전체OFF면 만료돼도 AI는 답하지 않는다. 만료 후 새 질문부터 적용하며 민감주제 전달 기준은 유지한다.
- 틀렸어요는 답변 확인 요청 버튼으로 바꾸고 소식방/1:1 문구를 구분한다. 시각 디자인 변경은 제외한다.

DEV-289 사용자 후속: 답장은 말풍선 옆 20px 인용 답장 아이콘(44px 터치 영역), 답장 취소는 × 아이콘으로 표시한다. 전체 AI 전환은 생산자 채팅 헤더의 24px 반짝이 아이콘으로 옮기고 ON은 주황색·상태점, OFF는 회색·사선으로 구분한다. 접근성 이름·동작은 유지한다. 대기 상태는 활성화된 경우에만 별도 짧은 문구로 표시한다.

## DEV-289 메뉴·메시지 수정 (사용자 확정)
- AI 아이콘 아래 AI 답변 ON/OFF를 표시한다. 답장·수정 아이콘을 말풍선에 상시 노출하지 않는다. 데스크톱 우클릭·모바일 500ms 길게 누르기로 메뉴를 열고 Escape·바깥 누르기로 닫는다.
- 1:1과 소식방 모두 본인이 보낸 글의 본문만 수정한다. 소비자 소식방 답장은 기존 비공개 범위를 유지하며 AI·타인 메시지는 수정할 수 없다. 수정된 메시지 하단에 이탤릭 수정됨을 표시한다.
- 수정 시각·수정 버전을 서버에 보존한다. 기존 발송 시각·첨부·좋아요·읽음·직접 응대 종료 시각·메시지 수를 바꾸지 않으며 재발송이나 AI 재생성을 하지 않는다. 기존 인용 스냅샷도 유지한다.
- 최신 버전 불일치는 충돌로 거부한다. 전송 실패 시 수정 입력을 보존하고 같은 입력 재시도에는 같은 멱등 키를 쓴다. 지연 조회·저장 응답이 더 높은 수정 버전을 덮지 않도록 한다.

### 소식방 인용 답장 (DEV-289, 11/09 승인)
- 소비자 원문은 본인과 농가에게만 보인다. 생산자 우클릭/길게 누르기 메뉴의 답장은 익명 소비자 본문을 인용한 팔로워 방송을 작성한다. 인용·답변 모두 개인정보를 가리며 사진·작성자·원문 ID는 공개하지 않는다.
- 인용은 발송 시점의 본문 스냅샷이며 원문이 수정되어도 바뀌지 않는다. 전체 공개란 해당 소식방 팔로워 전체를 뜻하며 비로그인/비팔로워에 공개하지 않는다.
- 같은 농가 소비자 소식방 글만 인용할 수 있다. 타 농가 글/없는 글/생산자 방송 인용은 거부하며 소비자는 인용 방송을 만들 수 없다.
- 답장 취소와 실패 시 입력 보존, 재시도 중복방지, 팔로워 수·인용 내용 전송 확인을 적용한다. 별도 1:1 채팅 메뉴는 기존 개인 대화를 연다. 인용 방송은 1:1 대화·AI 타이머를 변경하지 않는다.

- 인용 방송의 인용·답변은 전화번호·계좌번호와 이메일 주소를 가린다.

인용 작성 UI는 원문의 editVersion을 replyToVersion으로 함께 보내며, 발송 시 원문이 수정되었으면409로 거부하여 재선택을 안내한다. 확인 미리보기의 이메일도 가린다.

## DEV-295 버블 채팅 모양 (2026-11-09, 서버 변경 없음)
- 화면 기준은 [conversation-ui-1.6.md ‘버블 채팅 모양’](../conversation-ui-1.6.md#버블-채팅-모양-dev-295-2026-11-09). 동작·권한·API는 바꾸지 않는다.
- 메시지 메뉴(우클릭·500ms 길게 누르기)에 ‘복사’를 더한다. 글이 있는 메시지면 답장이 없는 방(farmclub 문의 대화방)에서도 메뉴가 열리고 ‘복사’만 보인다. 답장·수정 노출 조건은 위 DEV-289 그대로다.
- 1:1 읽음 표시: 대화 조회의 상대 읽음 위치(`thread.producerLastReadMessageId`/`consumerLastReadMessageId`)까지의 내 마지막 말풍선 옆에 ‘읽음’. 새 API·저장 없음.
- 소식방 인용 방송은 말풍선 안 인용 블록으로 보인다. 소비자에게는 ‘팔로워의 답장’, 생산자에게는 ‘팔로워의 답장 · 이름은 가려져요’. 위 인용 규칙(익명·스냅샷·가림)은 그대로다.
- 생산자 소식방 입력 안내는 ‘팔로워 N명에게 보내기’(수를 모르면 ‘모든 팔로워에게 보내기’)로 줄인다. 확인 시트 문구는 AC-12-13 그대로다.
