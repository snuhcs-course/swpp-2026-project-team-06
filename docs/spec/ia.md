# farmclub IA·사용자 흐름 (I1-P15)

> 현재 프론트 화면 기준: [대화 중심 UI 1.6](./conversation-ui-1.6.md). 이전 화면 배치를 대체하며 API·권한·주문 전이는 유지한다.


> 농가/상품 상세·공개 소식방의 현재 기준: [스펙 1.5](./storefront-1.5.md). 기존 농가 소식 탭 설명을 대체한다.

> 공급 물량·승인·가격의 현재 기준: [스펙 1.4](./capacity-1.4.md). 기존 박스 한도/가격 재승인 계약을 대체한다.

I1 화면은 기존 화면과 SCR-31·32·33을 포함한다(로그인은 앱별로 소비자 SCR-05, 생산자 SCR-19). 그 밖에 하위 화면 7개(배송지 입력, 배송지 관리, 정지 안내, 소비자별 채팅, 프로필 항목 고치기, 소비자 소식방, 생산자 소식방)와 공통 권한 오류 화면이 있다. 운영자는 I1에서 화면 없이 Swagger UI로 관리 API를 호출했지만, 관리자 UI(`https://admin.farmclub.kr`)를 만들어 바꿨다(아래 운영자 절). 소비자 앱의 첫 화면은 홈·발견이고, 농가가 보낸 링크로는 농가 페이지에 바로 들어온다. 로그인은 팔로우·예약·채팅·좋아요를 누를 때만 한다. 앱은 소비자 앱과 생산자 앱 두 개(모바일 웹)로 나누고, 계정도 앱별로 따로다(소비자 계정·생산자 계정, ADR 0010. I1은 테스트 계정, 카카오 로그인은 I2).

스펙 1.2의 채팅·판매 설정 상세는 [공통 계약](./contracts-1.2.md)을 따른다. 과거 결정은 변경 이력이며 현재 화면 구조는 [1.3](./navigation-1.3.md)이며 SCR-33까지 적용한다.

&#91;embedded content: 소비자 앱 사이트맵 · 15개\]

소비자 앱은 홈·발견(SCR-01)에서 시작하고, 농가 링크로는 SCR-03에 바로 도착한다. 로그인은 팔로우·예약·채팅·좋아요를 누를 때만 거친다.

&#91;embedded content: 생산자 앱 사이트맵 · 13개\]

생산자 앱은 생산자 계정 로그인(SCR-19) → 가입 신청 → 승인 대기를 거쳐야 탭이 열린다(시드의 승인된 생산자 계정은 바로 SCR-22, 정지된 계정은 정지 안내). 운영자는 승인·배송 완료·환불을 운영자 전용 관리 API로 처리한다. I1에서는 화면 없이 Swagger UI로 호출했지만 관리자 UI를 만들어 바꿨다. 생산자 가입 신청과 상품 공급 물량 신청의 승인·반려는 임시 관리자 페이지(`scripts/admin-web`, DEV-82·DEV-83·DEV-87, 문의함 DEV-111)에서 한다. 로그인(`/login`, 공용 접속 비밀번호) → 가입 신청(`/producers`): 신청 목록 → 승인(두 번 눌러 확인) / 반려(사유 입력) → 결정 이력. 공급 물량 승인(`/capacity`, DEV-87): 상품별 첫 판매·증량 신청 목록 → 신청량 전체 승인(두 번 눌러 확인) / 반려(사유 입력). 테스트 농가(`/farms`, DEV-98): 운영 검증에 쓴 농가 목록 → 숨기기 / 다시 공개 → 미리보기(거부 사유, 출하 전 테스트 주문) → 두 번 눌러 실행. 숨긴 농가는 모든 소비자 화면에서 사라지고, 테스트 계정이 아닌 소비자 주문이 있으면 거부한다. 사용자(`/users`, DEV-107): 이름·닉네임·ID·농가 이름·전화 끝 4자리로 검색, 역할·테스트 여부 필터 → 팀원이 카카오로 가입한 운영 검증 계정을 「테스트로 표시」/해제(두 번 눌러 확인). 표시한 계정의 주문은 테스트 농가 숨기기에서 테스트 주문으로 센다. 사용자 찾기(`/user`, `/users/<id>`, DEV-106): 사용자 ID·주문 ID·주문 번호(입금자명)로 찾기 → 주문·입금·환불 내역 → 입금 확인 대행 / 배송 완료 / 환불(금액·사유)을 두 번 눌러 실행(기존 운영자 주문 API). 받는 사람 전화·주소는 보이지 않는다. 문의함(`/inbox`, DEV-111): 생산자가 farmclub 대화방에 남긴 문의 목록(답변 대기 먼저) → 대화 보기(열면 읽음) → farmclub으로 답장. AI 비용(`/ai-cost`, DEV-144): 기능별(코드 리뷰 spec-check·상품 초안·상세 초안·AI 답변·자료 분석)과 전체 합계를 이번 달·최근 7일·전체로 보는 표, 기능으로 거르는 호출 목록(모델·토큰·금액, spec-check는 PR·결과). 왼쪽 메뉴에 관리 화면을 하나씩 늘려 간다. 결정은 운영자 계정(`u-admin`)으로 기록되고, 로컬 또는 운영 주소 `https://admin.farmclub.kr`(Vercel, DEV-91)에서 중계가 운영자 토큰을 붙여 실서버를 부른다.

**공통**: 개인정보 처리방침 `/privacy`, 이용약관 `/terms`는 두 앱에 있고 로그인·승인 상태와 상관없이 열린다(DEV-113, R-16). 배포에서는 같은 문안의 정적 HTML이 응답해 JS 없이도 읽힌다. 하단 사업자 정보(policy.md 6장)는 소비자 홈(SCR-01)·로그인(SCR-05)·내 정보(SCR-17), 생산자 로그인(SCR-19)·설정 끝에 둔다. 푸터는 스크롤 내용의 맨 아래에 붙고, 내용이 짧으면 화면 바닥(하단 바 바로 위)까지 내려간다(DEV-116). 가입 동의(SCR-06)의 ‘보기’ 시트에서 전문으로 간다.

**공통**: 권한 오류(403) 화면은 두 앱에 있다. ‘볼 수 없는 화면이에요’와 첫 화면으로(screens.md 3장).

**운영자**: 운영자 전용 관리 API로 생산자·상품 공급 물량 승인, 배송 완료, 환불을 처리한다. I1에서는 화면 없이 Swagger UI로 호출했지만, 관리자 UI(FEAT-23, `scripts/admin-web`, `https://admin.farmclub.kr`, 공용 비밀번호 로그인)를 만들어 바꿨다. 지금 화면은 가입 신청(`/producers`), 공급 물량 승인(`/capacity`), 테스트 농가(`/farms`), 사용자(`/users`)·사용자 찾기(`/user`), 문의함(`/inbox`), AI 비용(`/ai-cost`)이고, 메뉴를 하나씩 늘린다.

로그인은 옵션 시트에서 ‘주문서로’를 누른 뒤에만 거치고, 끝나면 고른 옵션·수량 그대로 주문서로 돌아온다. 입금 안내 뒤에는 내 주문 탭(SCR-13)으로 이동할 수 있고, 생산자가 주문 현황(SCR-29)에서 입금을 확인하면 예약 완료가 된다(DEV-68).

디자인 흐름도 F-3~F-5(`docs/design/screens/f-3.html` 등)는 아래 F-3·F-4와 F-5·취소를 화면 그림으로 그린 것이다.

**F-3. 소식과 AI 응답 (S-3)**

1. 생산자: 채팅 → 자기 소식방에서 글 전송 또는 첨부 → 소식 올리기 → 방 복귀 (SCR-28 → SCR-27)
2. 소비자: 채팅 → 소식방 목록에서 팔로우한 농가를 골라 방송을 읽고 좋아요·비공개 답장을 보내거나 ‘1:1 채팅’ (SCR-18 → SCR-16). 공개 소식은 비로그인도 해당 농가 소식방(SCR-18)에서 읽는다
3. 농가 AI ON·방 AUTO에서 AI가 같은 채팅에 답하거나 ‘AI가 답하기 어려운 질문이라 농가에 답변을 요청했어요. …’ 안내 (SCR-16)
4. 생산자: 채팅에서 질문을 눌러 소비자별 채팅에서 답변 → 그 소비자의 채팅에만 표시 (SCR-28 → 소비자별 채팅 → SCR-16)

**F-4. 출하와 취소 (S-4)**

1. 생산자: 현황의 ‘배송 현황’ (SCR-22 → SCR-29)
2. 기존 출하 준비 주문 중 보낸 주문을 골라 줄마다 ‘송장 입력’으로 택배사·송장 번호를 넣고 ‘n건 선택 · 출하 처리’ → 확인 (SCR-29). 소비자 주문 상세는 수확·포장 중 → 배송 중(배송 조회)으로 바뀐다. 자연어 입력과 AI 주문 찾기는 I2
3. 소비자: 내 주문 → 주문 상세에서 보내기 전 취소 → 환불 완료 표시와 토스트 (SCR-13 → SCR-14)

**F-5. 배송 기간 변경 (R-21)**

1. 배송 예정 기간이 바뀌면 주문 내역에 표시가 뜨고, 주문 상세에서 새 기간 동의 또는 전액 환불을 고른다 (SCR-13 → SCR-14). I1은 알림이 없으므로 앱 안 표시만 한다

**F-6. 구매 확정 (R-14)**

1. 배송 완료 후 주문 상세에서 ‘구매 확정’을 누르거나, 8일이 지나면 자동 확정 (SCR-14)

## 6. 접근 권한

권한은 서버에서 검사한다(PRD N-06). 화면에서 숨기는 것만으로 막지 않는다.

| 화면 | 비로그인 | 소비자 계정 | 생산자 계정(승인 전·반려) | 생산자 계정(승인 후) |
| --- | --- | --- | --- | --- |
| SCR-01\~05 소비자 앱 공개 화면 | 가능 | 가능 | 소비자 앱에는 로그인할 수 없음(비로그인으로 둘러보기만) | 같음 |
| SCR-10\~18·32 소비자 화면 | 안내 시트 → SCR-05 | 자기 주문·채팅만, 팔로우한 농가의 소식만 | 불가(403 `WRONG_APP`) | 불가(403 `WRONG_APP`) |
| SCR-19 생산자 로그인 | 가능 | 생산자 앱에는 로그인할 수 없음 | 가능 | 가능 |
| SCR-20·21 가입·대기 | SCR-19로 이동 | 불가(생산자 앱에서 따로 가입) | 가능 | — |
| SCR-22\~31 생산자 화면 | SCR-19로 이동 | 불가(403 `WRONG_APP`) | SCR-21로 이동(정지면 정지 안내) | 자기 농가·상품·주문만 |
| `/support` farmclub 문의 대화방 | SCR-19로 이동 | 불가(403 `WRONG_APP`) | 반려·정지는 자기 방만, 확인 중은 SCR-21로 이동(DEV-209) | 자기 방(채팅 탭과 같은 방) |

- 소비자 계정과 생산자 계정은 따로다(ADR 0010, IA-Q4 변경). 계정 하나는 역할 하나이고, 로그인은 앱별이다(I1은 앱별 시드 테스트 계정, I2부터 카카오). 생산자가 다른 농가 상품을 사려면 소비자 계정을 따로 쓴다. 생산자 앱 권한은 승인 후에만 열린다.
- 생산자는 배송 완료 전 주문의 배송 정보만 본다(R-15).

## 7. 열린 질문

- [x] IA-Q1. 하단 탭 4개 구성(4장)이 맞는가. 생산자는 탭 대신 대화형 한 화면(말로 모두 처리)이 나은가 → 결정: 역할별 하단 탭 4개(4장 그대로)

- [x] IA-Q3. 출하 처리(SCR-29)를 별도 화면으로 둘지, 현황 화면의 입력창으로 넣을지 → 결정: 별도 화면(SCR-29), 현황의 ‘출하 처리’ 버튼으로 진입. P22에서도 유지
- [x] IA-Q4. 생산자가 소비자로도 주문할 수 있게 할지(역할 전환) → 결정: 가능. 소비자 앱과 생산자 앱을 따로 두고 같은 계정으로 둘 다 사용 → **변경(SWPP-81)**: 소비자·생산자 계정 완전 분리. 계정 하나는 역할 하나, 로그인은 앱별(SCR-05·SCR-19), 다른 앱 토큰은 403. 생산자가 소비자로 주문하려면 소비자 계정을 따로 쓴다([ADR 0010](./tech-design/adr/0010-separate-accounts.md))

### SCR-24 제외 문구 안내 (DEV-186·DEV-188, 2026-11-01)
AI 채움 결과의 excluded가 있으면 “이 정보들은 상세 페이지에 못 넣어서 빼 뒀어요 🙂” 모달을 batch/refinementVersion별 한 번 표시하고 확인/닫기 뒤 사진 위 칩으로 다시 연다. 부제는 작은 muted 글씨로 “AI가 자료에서 찾았지만 팜클럽 상세에는 맞지 않는 내용이에요.”를 표시한다. 단일 상품은 칩 “AI가 뺀 문구 N개”와 제목에 상품명을 붙이지 않고, 여러 상품이면 칩·제목 앞에 “<상품명> · ”를 붙인다. 제외0개인 상품의 칩은 숨긴다. 칩은 기존 accent 토큰을 연하게 적용한 주황 배경과 주황 글씨다.

사유마다 짧은 이모지 pill과 보통 굵기 설명을 둔다. 💰 금액(price, 반품 배송비 포함)은 “가격·배송비는 다음 단계(판매·가격)에서 직접 정해 주세요.”, 📅 기간(period)은 “판매 기간이나 받는 날은 다음 단계(판매·가격)에서 정해요.”, 🛡️ 팜클럽 정책(platform)은 “교환·환불·문의는 팜클럽이 같은 기준으로 안내해 드려요.” 뒤 작은 muted 줄에 “출하 전 취소는 전액 환불, 배송 후 하자는 교환·환불이에요.”(R-07/R-11/M-04), 🚫 건강 효능(health)은 “건강 효능은 상세 페이지에 넣을 수 없어요.”를 표시한다. 이 네 pill은 연한 주황이다. 나머지는 중립 pill(🔒 개인정보, 📦 다른 상품, ❔ 근거 없음, 🔁 중복, 💤 미사용)과 기존 설명을 유지한다([전체 사유 문구](./source-analysis.md#제외-내역-계약생산자-안내-결정47)). 원래 후보 문구는 기울임·muted 색상·얇은 주황 왼쪽 막대·들여쓰기와 최대2줄 인용으로 표시한다.

모달은 화면 높이90% 이하이며 본문은 최대400px ScrollView 안에서 마지막 인용까지 스크롤한다. 제목·부제와 footer는 스크롤 밖에 둔다. footer는 “맨 위 'AI가 뺀 문구'에서 다시 볼 수 있어요”와 고정 확인 버튼이다.

AI 시트 업로드 위 문구: “가격·배송비·받는 시기는 다음 단계에서 직접 입력해요”(DEV-294). R-19에 따라 판매자가 출하하므로 배송 방법은 상품 정보다. story 금액/효능 입력 아래 즉시 힌트를 표시하고 저장을 거절한다. 생산자 플랫폼·기간 문구는 경고와 함께 저장 가능하다. SCR-24b 구매자 미리보기와 SCR-04 소비자 상세는 제외 칩/모달을 렌더링하지 않는다. 전체 계약: source-analysis.md DEV-186.

- DEV-186 리뷰 보완(AC-SRC-1/2/11): DEV-188부터 SCR-24와 자료 작업의 제외 칩·모달 제목은 여러 상품일 때만 상품명을 함께 표시한다. 다상품은 모달 하나씩 큐에서 확인한 뒤 다음 상품을 연다. 판매·가격 다음 단계 inline 안내는 새 상품 composer에만 표시하고 기존 상품 판매페이지 편집에는 표시하지 않는다.


### DEV-179 SCR-24·SCR-29 보완 (2026-11-02 owner 결정)
- SCR-24·상세 편집은 상단 고정 '구매자 화면 미리보기'/'편집으로 돌아가기'로 같은 화면에서 전환하고 미저장 값을 보존한다. AI 배지와 원문 보기/목록은 없으며 근거는 감사용으로 서버·review API에 남긴다. 적용 검토 진입은 '공개 전 검토'. 분석 시작은 대표사진 없이 가능하나 품종은 필수이며 새 상품 AI 시트의 시작 버튼 위에서 입력한다.
- SCR-29: 모든 주문 줄에 옵션×수량·주문 총액을 표시한다. 입금 승인은 기존 이름 마스킹 규칙을 따른 이름·옵션×수량·금액 확인 시트에서 최종 승인 후 실행한다. 주문 상세 화면은 추가하지 않는다. SHIPPED 줄의 ‘송장 수정’은 기존 편집 시트에서 현재 값을 불러와 저장한다. 자기 농가만, 택배사 필수·송장 50자 이하·버전/멱등 검사 후 수정하며 소비자는 새 값으로 배송을 조회한다. 이력(전후 값·시각·actor)은 서버 감사에만 남고 양쪽 UI에는 표시하지 않는다(AC-17-9).
