# 원문 보존 초안 · DEV-452

FEAT-03/04/07 · AC-SRC-2/3/5/6/7/10/11 · M-11/13/18. 사용자는 원문 문체를 보존하면서 OCR/문장/반복을 점검하고 가격·시점 등 조건부 정보를 생산자가 별도로 확인하는 방향을 선택했다. 이는 개별 사실이나 출시 승인과 다르다.

## 입력과 제안
기존 생성문이 인용한 후보만 재사용하지 않는다. 현재 유효한 추출 후보 전체의 검증된 근거 인용을 원문 위치/revision/가림 version과 함께 사용한다. 원자료 OCR의 정확성이나 추출 누락까지 해결했다고 주장하지 않는다. 모든 입력은 포함/중복/검토/제외 사유로 기록하고, 원문을 자르거나 미해결 항목을 조용히 복구하지 않는다. 같은 출처 위치와 인용문의 중복만 합친다. 기존 모듈 분류를 사용하며 배치가 모호하면 확인을 요청한다.

기존 batch는 기존 정책을 유지한다. 새 앱의 분석 자료 작업은 원문 보존 정책을 명시하고, 기존 작업은 생산자가 전환할 수 있다. 이 정책에서는 유료 문장 재작성 REFINE을 호출하지 않는다. 정책/규칙/입력/출처 해시를 기록한다.

## 확인 종류
- 문장 점검: OCR로 끊긴 단어·미완결 문장·정확 반복을 표시하고 명확한 공백 수정만 제안한다. 원문과 제안을 함께 보며 자동 의역/삭제하지 않는다. 제목/옵션 표기는 종결 부호가 없다고 오류가 아니다. 전반적 문법 및 의미상 중복이 자동 검증됐다고 하지 않는다.
- 현재 정보 확인: 가격/수수료, 상대·과거·날짜 시점, 계절/재고, 결제·반품 및 발송·배송 조건. 상대 날짜를 시스템이 추측하지 않는다. 가격도 비공개 본문에 원문대로 보이며, 현재 가격 여부와 판매 설정 일치 여부를 설명과 함께 확인한다. 생산자는 확인/수정/제외/판매 설정에서 확인 의사를 기록한다.
- 배치·안전: 모듈 충돌과 개인정보/건강 효능/금액/다른 상품·서비스 정책도 비공개 검토에서 원문과 이유를 표시한다. 개인정보 가림과 실제 대상 범위 검사는 유지한다. 공개 제한 문구는 안전한 수정/제외가 필요하며, 일반 문장·시점·과장 의심은 확인 이유를 남겨 처리한다.

## 저장과 적용
항목 확인은 생산자 소유 batch/target 및 원문 위치/revision/가림 version/인용/정책 version에 묶어 저장한다. 저장에는 현재 planHash와 reviewVersion이 필요하다. 관련 원문이 그대로라면 재분석·관계없는 자료 추가 뒤에도 확인을 유지하고, 원문 변경/삭제 시 관련 확인은 재사용하지 않는다. 자동 제안은 기존 생산자 확정/수정/제외 칸을 덮어쓰지 않는다.

기존 편집기의 비공개 저장·재진입·생산자 수정 보호·명시 적용 계약을 유지한다. 확인 저장이나 정책 전환 자체로 공개 상품을 바꾸지 않는다. 미확인 문구도 비공개 초안에 포함하고 항목별 설명을 표시한다. 비공개 저장·재진입은 막지 않는다. 공개 반영 시 현재 출처에 묶인 검토 미완료 항목이 있으면 설명과 함께 확인을 요구한다. 검토 저장만으로 공개되지 않는다. 구조적 한도나 대상 모호성으로 본문 배치가 불가능하면 원문 전체를 검토 화면에 유지하고 이유를 표시하며 조용히 자르지 않는다.

## 평가
동일한 개발 자료에서 기존 baseline과 전체 후보 기반 원문 보존 결과를 따로 기록한다. 자동 초안과 생산자 완성본을 섞지 않으며 대기/제외·오류와 분모를 보존한다. 사진/시각 벤치마크·새 holdout은 범위 밖이다. 사용자 승인 골드 개정은 DEV-447/448 별도 version으로 양쪽 결과에 동일 적용하고, 생성기 효과와 측정 변경을 분리한다. 사람 코드 리뷰와 실제 생산자 인수/배포 확인은 별도다. Figma 후속 DEV-430.


## 생산자 첫 원문 비교 검토 반영 (2026-11-25, DEV-452/453)
- 평범한 홍보·선별·맛 표현은 검토 경고로 올리지 않는다. 명백한 극단적 우월/절대 보장만 별도 홍보 확인을 요구한다. 개인정보·질병 효능 및 가격·날짜·배송 등의 확인 기준은 유지한다. 이 변경은 원문 보존 경로에만 적용하고 기존 scorer/v11 공용 목록은 바꾸지 않는다.
- 같은 자료/쪽의 순서가 검증된 인접 원문 구간이 문장의 뒷부분이면 공백만 넣어 연결한다. 원문 passage/인용/ID는 그대로 두고 조립 provenance를 추가한다. 한 추출 항목 안의 명확한 연결은 미완결 경고를 해제한다. 서로 다른 추출 항목/모듈의 연결은 비공개 문장에 반영하되 CONTINUATION_CONTEXT 설명과 확인 대기를 유지한다. 빠진 문장은 만들지 않고 역순·건너뛴 span·옵션/제목·독립 주제·명시적 생산자 수정은 자동 연결하지 않는다.
- 옵션은 원문에서 같은 제목 span과 정확한 제목을 공유하는 경우에만 상품 구성의 한 블록으로 조립한다. 제목은 한 번, 크기·과수·포장을 그 아래 원문 순서로 둔다. 다른 옵션/쪽/출처/개정과 섞지 않고 공통 크기 안내는 별도로 유지한다. 원래 인용과 모든 후보 ID·수량·조건은 보존한다. 생산자가 명시적으로 고른 다른 모듈 위치는 자동 조립이 바꾸지 못한다.
- 신뢰된 batch 원문 보존 정책에서만 과거 자료의 텍스트 필드를 검토 대상으로 받아들인다. historical=true를 지우거나 필드를 historicalSales로 바꾸지 않는다. 숫자/개인정보/대상/출처 revision/span/인용 검증은 계속 적용한다. 텍스트와 vision chunk 경로, 캐시 정책 일치와 실행 중 정책 변경을 모두 검사한다. 기존 저장된 실행은 소급 수정하지 않으며 새 분석/재시도에 적용한다. 평가용 복구는 저장된 추출 결과의 독립 재검증임을 표시한다.
- 전반적인 문법·의미 정확도를 자동 인증하지 않는다. 원자료가 흐릿하다는 추측만으로 누락 원인을 단정하지 않고 OCR→추출→거절→조립을 추적한다.


## 원문 줄바꿈과 본문 흐름 (DEV-452)
포스터의 단일 줄바꿈은 본문에서 공백으로 연결한다. 빈 문단·옵션·속성 표·목록·생산자 명시 수정은 보존한다. 원본 인용/증거와 항목 검토 binding은 그대로 두고 조립 결과에 별도 layout version/provenance를 남긴다. 공개 적용은 공백 재배치/옵션 조립 뒤에도 제외/수정된 원문 재등장을 검사한다. 일반 문법 추론이나 누락 사실 복원은 범위 밖이다.


## 블록 우선 추출 비교 (DEV-453, 실험)
같은 저장 OCR을 모든 모델에 제공하고 OCR 자체는 다시 실행하지 않는다. 모델은 인접 여부와 무관하게 관련 문장·옵션의 원문 span 참조를 묶은 뒤 분류하고, 서버가 해당 원문 전체를 그대로 복원한다. 가격·날짜·모름·일반 홍보를 제거하지 않는다. 대상/분류 불명 블록은 비공개 검토 원장에 원문과 설명을 유지하고, 상품 본문으로 임의 귀속하지 않는다. 모든 입력 span은 블록 또는 명시 제외 이유와 연결되어야 한다. 제외는 장식·내비게이션·가림/연락처·명시 판독불가·정확한 중복만 별도 검증한다. 누락/중복 참조·잘못된 제외·변환 한도·후속 검증 거절을 따로 보고하며 실패를 숨기지 않는다.
모델이 쓴 설명은 관측된 사실/내부 추론 증명이 아니다. 조용히 건너뛴 원문은 이유 미상으로 보고한다. 기존 개발 자료와 gold는 고정하고 모든 팔에 같은 채점기를 적용한다. 기본 운영 worker/추출 정책을 바꾸지 않는 명시 실행 실험이다. 원본 PDF 쪽 정보가 없는 평문 OCR에는 합성 transcript 위치를 사용한다고 표시한다.


## 동일 초안의 Astra 조립 비교 (DEV-451, 실험)
기존87/94검토 초안의106개 완성 텍스트를 그대로 고정하고, 같은 사실을 Astra가 재배치·최소 문장 정리하는 명시 실험이다. 추가 OCR/추출/원문 구간이나 gold힌트를 주지 않는다. 블록별 ID와 기존 확인 사유만 모델에 보내고 원문 증거122개는 독립 검증에만 유지한다. 입력 블록 ID 전부를 출력/명시 제외로 회계하되 인용만으로 의미 보존을 인증하지 않는다. 새 숫자·범위·개인정보·누락/불명 ID·실제 문구 변경·제외 설명을 분리 보고한다. 생산자 확인 사유는 서버에서 출처 ID에 따라 합치고 모델이 해제할 수 없다. 운영 자동 추출·초안 정책과 공개 반영은 바꾸지 않는다.


## 선택적 후속 조립과 검증 (DEV-452)
원문 보존 초안 뒤의 모델 조립은 source_presentation_enabled로 별도 제어하며 기본값은 꺼짐이다. 47건 비교에서 전체 사실 보존 증가는 결정적 원문 보존 단계에서 이미 발생했고 추가 모델은 같은 보존율을 보였으므로 자동 채택하지 않는다. 켜진 원문 보존 batch는 추출 완료 후 대상별 ASSEMBLE 작업을 기존 refinement JSON에 영속화한다. 완료 batch의 명시 전환 경로도 중복 없이 처리한다. 모델 호출은 한 번이며 유료 자동 재시도하지 않는다. mock 모드는 외부 호출하지 않는다.

모든 입력 텍스트 ID와 원문 근거를 보존하고 관련 비인접 블록도 각자 인용한 채 묶을 수 있다. 새 숫자·범위·의미 변경을 허용하지 않는다. 검증 가능한 제한적 공백·문장부호 정리 외 변경은 해당 원문 표현으로 되돌린다. 누락/불명/중복 ID, 제외, 구조·필드 길이·필드당 후보 ID 100개 한도 초과는 전체 결정적 초안으로 돌아간다. 자르거나 일부 근거를 버려 저장하지 않는다. 과거 문맥은 기존 모듈과 이야기 순서를 유지한다. 원래 passage·확인 사유는 모델이 해제하거나 변경할 수 없다.

요청 전과 결과 반영 전 현재 자료/원문/확인 결정/편집 칸의 값·상태·근거·사진 snapshot을 검사한다. 생산자 작업 뒤 도착한 결과는 폐기한다. 활성 결과는 reviewVersion을 올려 오래된 저장을 막는다. GET·검토 저장·편집기·공개 반영은 같은 resolver를 쓰며 실제 문구/배치/출처 변경은 이전 조립을 무효화한다. 단순 확인은 기존 표시 배치를 보존하고 생산자의 명시적 다른 배치는 존중한다. UI는 대기/적용/원문 유지/다시 확인 상태를 한국어로 설명하며 내부 모델명·실패 코드를 노출하지 않는다. 이 단계도 공개 전 생산자 확인을 대체하지 않는다.

## DEV-484 원문 문장·문단 연결과 검토 표시
원문 보존은 OCR 줄바꿈을 화면의 독립 문장으로 유지한다는 뜻이 아니다. 동일 후보의 전체 value와 인용들을 공백 외 글자 변경 없이 대조하고, 같은 원문/버전/페이지에서 유일하고 연속된 span임이 확인될 때 서술을 문단으로 잇는다. 텍스트 입력의 s0/s1 식별자도 같은 순서 규칙으로 처리한다. 중간 절이 같은 후보의 후속 인용으로 완결됨이 확인되면 앞선 미완성 절과 연결할 수 있다. 옵션/제목/사진 캡션/문단 공백/불명확한 순서·간격·사용자 수정은 합치지 않는다. 원문에 마침표 없이 완결된 문장은 별도 블록으로 유지해 새 구두점을 추측하지 않는다.
외관과 맛을 설명하는 혼합 문장은 완성된 일반 상품 소개로 배치하며, 원래 필드·인용·후보 ID와 문맥 검토 상태는 보존한다. 연결할 수 없는 미완성 절은 기존 검토 큐에 남긴다. 자동 연결은 일반 문법·사실 검증이 아니며 가격·날짜·시점·안전 검토를 해제하지 않는다. 평가 동결본58c8ae4f와 이전 결과는 변경하지 않고 새 실험 버전으로 분리한다.

## DEV-485 공개 전 확인 질문과 완료 표시
확인 카드는 해당 원문에 대한 질문·이유·확인 내용을 제공한다. ‘10년차/10년 전’은 작성 기준연도와 현재 적절성을 묻고 무관한 가격·배송 안내를 섞지 않는다. 일반 확인은 부드러운 황색 카드, 금액·미완성 문장 등은 주의 기호, 개인정보·질병 효능·다른 상품 등 기존 공개 제한은 산호색 강조와 ⚠ 표시를 사용한다. 색상만으로 중요도를 구분하지 않는다.
‘✓ 확인했어요’는 기존 KEEP 결정을 서버에 저장한 뒤 완료 카드로 접고, 저장 실패 시 대기 상태를 유지한다. 직접 수정과 제외는 기존 결정 원장에 기록한다. 기존 공개 제한은 단순 확인으로 해제하지 않는다. 자동 연결된 문단은 전체 인용 단위를 함께 확인하며, 모든 구성 단위가 같은 배치를 승인하면 연결 문장을 유지한다. 미저장 수정·오래된 버전 검사와 공개 전 검토 조건은 그대로 적용한다.
