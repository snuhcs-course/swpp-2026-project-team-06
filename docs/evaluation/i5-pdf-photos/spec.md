## Extractor JSON v1

The Python module exposes extract_pdf(data: bytes, output_dir: Path, *, source_id='source', source_revision=1, sanitization_version=1, redactions=None, limits=None) -> dict and a CLI python -m app.source_analysis.pdf_photo_extract INPUT.pdf --output DIR --source-id ID. Module import has no application/config/DB/network side effects. CLI writes manifest.json and local PNG assets; stdout contains aggregate counts only. Require an empty/exclusive output location and safe IDs/relative asset paths. Data and returned manifest are private.

Top-level keys: schemaVersion=1, extractorVersion='pdf-photo-v1', source={id,sha256,revision,sanitizationVersion}, status='SUCCEEDED'|'PARTIAL'|'FAILED', pageCount, processedPages (one-based array), skippedPages (one-based array), limits, occurrences (array), warnings (array of codes), errors (array of codes), metrics={objectsVisited,decodedImages,candidateCount,elapsedMs,outputBytes}.

Occurrence keys: id (stable hash of source hash/revision/sanitization/page/object path/bounds/extractor version), page, bounds (normalized top-left [x1,y1,x2,y2] in the rendered page orientation), nativeWidth, nativeHeight, width, height (exported pixels), status='REVIEW_REQUIRED'|'FILTERED'|'UNSUPPORTED'|'ERROR', reasonCodes=[], imagePath (safe relative PNG or null), pixelSha256 (PNG file bytes hash or null), duplicateOf (stable earlier occurrence ID or null), sourceObjectType='native_image'|'composite'. All usable candidates remain REVIEW_REQUIRED, never human-approved. Preserve duplicates as occurrences but reuse safe asset bytes where identical. Unknown type/product stays unknown.

Use existing pypdfium2/Pillow/psutil, no new dependency. Export page-rendered VISIBLE clipped photo regions, not raw underlying image streams that can reveal hidden/covered pixels. Render approved visible PDF annotations and supplied redaction rectangles first; source PDF is still diagnostic/unverified, not automatically approved for production. redactions is dict[int page -> list[normalized top-left rectangles]]; enforce bounds/types, preserve opaque redactions in every candidate. Account for rotation/page crop boxes, transforms and nested images; unknown geometry safely unsupported. Never upscale beyond known native image dimensions; record low-resolution/composite/tiny statuses rather than calling every decoded object a photo. Do not imply price/contact text has been checked or removed.

Frozen limits: pageCap20, objectCap200 per document, recursionDepth4, candidateCap30 per document, maxInputBytes100MiB, maxImagePixels40M native, maxPagePixels8M, maxOutputBytes64MiB, maxElapsedSeconds30, maxRssMiB512 (CLI child monitor), renderScale2. Tiny candidate rule: either native edge<64 -> FILTERED/TINY; full visible page coverage>=0.85 -> UNSUPPORTED/COMPOSITE_PAGE. Retain attempted/failure/cap records; limits can only be tightened by caller. Keep exact duplicate occurrences; do not perceptually merge variants. No OCR, model, external requests or production use. Bounded subprocess enforcement should be used by CLI for wall-time/memory where supported; fail closed on malformed inputs. Tests use invented PDFs, including a covered/redacted underlying image, rotation, duplicates, no-image and limit cases.

## Contact sheet module interface

Export renderContactSheet(manifests, options={}) -> HTML string; manifests array follows extractor schema above. Default renderer reads no files/network. CLI: node scripts/pdf-photo-contact-sheet.mjs MANIFEST.json [more...] --output REPORT.html; require reports and asset files in the same report tree, copy no private file outside it, and produce portable relative links. CLI output aggregate counts only. Cards show source/page, source region preview when supplied as pageImagePath (optional), recovered picture, candidate status/reason, native/output resolution, duplicates, processing/skipped pages and failures. Missing imagePath renders explicit unavailable card. escape all text; reject absolute/traversal/javascript/http image paths rather than making unsafe links. No business judgments, fake captions, auto-approval or model call. State diagnostic only, all human review pending; no production renderer claim. Tests exercise hostile text/paths, missing/composite/duplicate/failed entries, all four empty statuses and exact inventory counts. Node built-in test only.

## Scoring reference and prediction contract

Export scorePdfPhotos(reference,prediction) -> report. CLI node scripts/pdf-photo-score.mjs REFERENCE.json PREDICTION.json --output REPORT.json. Reject malformed/duplicate IDs, wrong schema/dataset/version, inconsistent denominators and unknown referenced IDs. Pure file-free function and no model/network. CLI never dumps private labels/text.
Reference={schemaVersion:1,datasetId:string,status:'PENDING'|'VERIFIED',reviewer:string|null,reviewedAt:string|null,photos:[{id:string,sourceId:string,page:int,applicability:'native'|'assisted',useful:boolean,allowedSections:string[]}],sources:[{id:string,status:'READY'|'FAILED'|'EMPTY'}]}.
Prediction={schemaVersion:1,datasetId:string,items:[{id:string,sourceId:string,page:int,referenceId:string|null,status:'RECOVERED'|'FAILED'|'FILTERED'|'UNSUPPORTED',shown:boolean,section:string|null}],sources:[{id:string,status:'SUCCEEDED'|'PARTIAL'|'FAILED'|'EMPTY'}]}.

Explicit referenceId matching is a supplied human-verified/proposed mapping, never inferred by token/image similarity. Matched useful reference recovered only if RECOVERED and source/page association valid; each reference counts at most once; recovery denominators include every useful reference including failed/missing source, native subset separate. Relevance denominator includes ALL shown prediction items (duplicates and unknown/unwanted count as unwanted; no duplicate credit); numerator counts one correctly recovered useful reference per source/reference. Conditional acceptable-section accuracy over items with section != null, and coverage over ALL useful native reference photos (including extraction misses) reported separately. No division by zero; use null. Failure/missing source with leftover items grants no recovery/relevance/placement credit but keeps denominators and diagnostics. Baseline no photos yields zero recovery and null relevance.

Reference PENDING or absent reviewer/date yields status='PROVISIONAL', decision='PENDING_HUMAN_REVIEW' regardless of metrics. VERIFIED only with identity/date and all integrity checks; use status='EVALUATED'. Proposed targets nativeRecovery>=0.9 and suggestionRelevance>=0.9 for native-scoped gallery; overall recovery always reported. Placement>=0.85 AND coverage>=0.7 only reports an optional placementGoal, not a release gate. Any source failure/missing source or unknown/inconsistent matching blocks automatic PASS; empty supported zero-photo source is not automatically failure if expected empty. expose raw hit/total/rate groups, duplicates, failed/missing source IDs, warnings and limits. No claim of full-corpus accuracy or release adoption. Tests specifically cover all-failed, pending/unreviewed, zero denominators, duplicates inflating relevance, missing source, incorrect IDs and abstaining on every photo. Do not tune on actual private source labels.

## Explicit failure representation (DEV-458 integration review)

Unknown geometry uses bounds=null only on non-exporting UNSUPPORTED occurrences; never guess a crop. CLI oversized/unreadable input may use source.sha256=null with an explicit input/preflight failure diagnostic, rather than hashing empty placeholder bytes. Accepted ordinary inputs retain their exact precomputed hash even after worker time/RSS termination. Forms are conservatively retained as unsupported composite occurrences; their contained native photos remain unrecovered in evaluation rather than being removed from reference denominators.
