디자인 무브

1해제는 한 번, 되돌리기도 한 번

확인 시트 대신 토스트 ‘팔로우를 끊었어요’ 오른쪽에 되돌리기(누르는 영역 48). 되돌리기가 있는 토스트만 4초(오류 토스트와 같은 길이), 남은 시간 막대 2px. 소식방과 주문 완료 화면(HE-X4) 두 곳이 같은 토스트를 쓴다. 되돌리기 = PUT /api/farms/:id/follow, 실패하면 공통 오류 토스트 ‘연결이 불안정해요 · 다시 시도’.

2방을 비우지 않는다 — 내 글은 흐리게 남김

해제 뒤에도 서버가 내 답장을 계속 준다. 화면은 말풍선 모양·자리·시각을 그대로 두고 투명도만 45%로. 지울지 말지는 사용자가 정한 적이 없으므로 사라지게 하지 않는다. 팔로워 전용 소식은 규칙(M-14, AC-15-1)대로 숨기고, 공개 소식과 좋아요는 그대로.

3흐린 이유는 한 줄로, 한 자리에

판매 품목 바로 아래 흰 띠: ‘팔로우를 끊어 새 소식이 오지 않아요’ + 밑줄 글자 버튼 ‘다시 팔로우’. 토스트가 사라진 뒤 다시 들어온 사람에게도 같은 설명이 보인다. 띠는 내 답장이 있는 방(=예전에 팔로우했던 방)에만 — 처음 온 사람에게는 지금처럼 ‘팔로우하고 답장하기’.

4강조색 버튼 대신 잠긴 입력칸

예전 팔로워에게는 하단의 강조색 ‘팔로우하고 답장하기’를 빼고, 같은 자리에 회색 입력칸 + 자물쇠 ‘다시 팔로우하면 답장할 수 있어요’(누를 수 없음, 전송 버튼 없음). 화면의 다시-팔로우 경로를 띠·헤더 둘로 줄이고, 강조 버튼 위치 규칙(화면 아래에는 하단 바·시트만)과도 맞는다.

5채팅 목록: 끊은 방은 아래 묶음에 흐리게 숨기기 선택

소식방 목록 끝에 13 굵게 ‘팔로우 끊은 농가’ 묶음, 줄은 사진 회색·이름 보조색·셋째 줄 ‘팔로우 끊음’. 흐림이 기본이고 숨기기는 사용자가 고를 때만 — 줄 오른쪽 면색 버튼(48). 숨긴 방은 다시 팔로우하면 돌아온다.

6‘팔로잉’은 체크로 상태를 말한다

README에 이미 있는 “면색 + 체크 + 팔로잉”을 코드에 맞춘다(지금은 체크가 없다). 평가자가 채워진 버튼을 “불이 들어온” 것으로 읽은 문제(HE-02)를 아이콘 하나로 줄인다. 다시 팔로우하면 모든 것이 해제 전과 같다 — 서버에서 지우는 데이터가 없다.

if not can_reply:
    broadcasts = broadcasts.where(Broadcast.visibility == "PUBLIC")
    replies = (replies.where(RoomReply.consumer_id == user.id)
               if user is not None and user.role == "CONSUMER"

답장 행은 해제 때 지우지 않는다(farms.set_follow는 Follow 행만) → 다시 팔로우하면 지금도 그대로 돌아온다(무브 6은 서버 변경 없음).

채팅 목록 GET /api/messaging/rooms

rooms()(368행)는 팔로우한 농가만 돌고 _room_summary(..., True)로 고정. 바꿀 것: 팔로우한 농가 ∪ 내 답장이 있는 승인 농가, 요약의 canReply는 실제 팔로우 여부. 새 필드는 없다 — 앱은 canReply=false인 줄을 ‘팔로우 끊은 농가’로 묶는다. Mock packages/api/src/mock/rooms.ts도 같게.

요약 lastMessage는 같은 _room_rows를 쓰므로 위 수정으로 ‘내 답장’이 미리보기가 된다.

위험과 확인할 것

  • 공개 범위: 더 보이는 것은 본인 글뿐(M-02 유지). 다른 소비자 답장·팔로워 전용 방송은 계속 숨김. pytest로 고정.

  • 쓰기는 그대로 막힘: send_room은 팔로우 검사 유지, 좋아요도 기존 규칙(공개 소식만).

열린 질문

Q1. 숨기기를 이번에 넣을까

넣는다면 기기 저장(서버 변경 없음, 다른 기기에서는 다시 보임)으로 할지, 서버 저장(모델·마이그레이션, 고위험)으로 할지. 제안: 이번엔 기기 저장 또는 빼고 후속.

Q2. 숨긴 팔로워 전용 소식의 자리

흐린 답장 “첫 바구니 사진 반가워요!”가 무엇에 대한 답인지(전용 소식) 안 보인다. 그 자리에 ‘팔로워 전용 소식’이라는 빈 줄을 둘지 — 내용은 안 보이지만 있다는 것과 시각이 드러난다(AC-15-1 “보이지 않는다”와 충돌 가능). 제안: 두지 않음.

Q3. 다시-팔로우 입구가 셋(헤더·띠·토스트)

헤더 ‘팔로우’는 README 강조색 예외라 그대로 두었다. 띠의 ‘다시 팔로우’를 빼고 헤더 하나로 할지, 헤더를 해제 상태에서 테두리 버튼으로 낮출지.

Q4. 되돌리기 토스트 4초

성공 토스트 2초 규칙(D-19)에 “되돌리기가 있으면 4초” 예외를 두는 안. 2초면 누르기 전에 사라진다는 HE 의견이 있으면 그대로, 아니면 띠가 있으니 2초도 가능.

Q5. 예전 팔로워의 판정

띠·잠긴 입력은 “이 방에 내 답장이 있음”으로 판정한다(서버 새 필드 없음). 답장 없이 팔로우만 했다 끊은 사람은 처음 온 사람과 같은 화면(‘팔로우하고 답장하기’)이 된다 — 괜찮은지.

Q6. Figma v6

승인 뒤 SCR-03 해제 상태·SCR-15 묶음·토스트 되돌리기·‘✓ 팔로잉’ 프레임 반영 요청(PR Figma: 후속 — DEV-230).
