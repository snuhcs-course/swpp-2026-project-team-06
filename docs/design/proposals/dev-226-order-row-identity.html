HE-03(심각도 3): 소비자 내 주문에 같은 줄이 두 개 생긴다. HE-12 일부: 생산자 주문 줄에 상품명이 없다. HE-X5: ‘작성 중’의 이름 없는 초안을 서로 구별할 수 없다. 세 가지 모두 API가 이미 주는 값을 화면에 그리지 않아서 생긴 문제라, 앱만 고친다.

1단계 · 제안, 승인 대기 서버 변경 없음 위험 등급 일반 DEV-207 줄 구조 유지 Figma v6 후속

문제 요약

HE-03 소비자 내 주문

하우스 감귤 5kg × 1을 두 번 주문하고 둘 다 ‘입금을 마쳤어요’를 누르면 /orders?filter=pending에 글자까지 똑같은 줄이 두 개 생긴다.

“무슨 주문이 입금 확인 중인지 알 수가 없습니다” (평가자, H6)

입금 단계에서는 부제가 ‘○일 입금 알림 · 금액’으로 바뀌어 SCR-13 카드 항목인 받는 시기도 빠진다.

HE-12 생산자 주문 줄

ship.tsx의 who()가 김민지 · 5kg × 1만 만든다. 하우스 5kg와 노지 5kg를 가를 수 없다. 이 함수를 줄, 출하 고르기, 송장 줄, 송장 시트, 입금 승인 시트, 출하 확인 시트 6곳이 쓴다.

같은 앱 1:1 채팅 주문 패널은 이미 상품명 · 옵션 × 수량이다.

HE-X5 생산자 초안 줄

‘새 상품’을 열 때마다 작성 중 상품이 하나 생기고(SCR-24), 이름을 안 넣으면 카드가 모두 “이름 없는 초안”이다. 만든 날도 저장 시각도 없다.

디자인 무브

1구별 정보는 맨 아래 메타 한 줄

소비자 줄 맨 아래에 13/18 보조색 한 줄 FC-1104-0013 · 11월 4일 주문. 굵은 줄(상태 · 다음 일)이 여전히 처음 읽히고, 번호는 확인할 때만 읽는 값이라 가장 작은 글자로 둔다.

번호는 생산자 줄 첫 줄·입금자명과 같은 글자라, 농가와 문의할 때 그대로 말하면 된다. 위치는 질문 Q1.

2입금 단계에만 받는 시기 되살리기

입금 단계 부제는 DEV-207이 ‘지금 상태를 만든 사건의 날짜 · 금액’으로 정했으므로 건드리지 않고, 상품 줄 바로 아래에 15/22 보조색 11월 10일~20일 도착 예정을 넣는다. 다른 단계는 부제가 이미 받는 시기라 줄을 더하지 않는다.

3생산자 이름 줄에 상품명을 끼운다

who()를 김민지 · 하우스 감귤 5kg × 1로 바꾼다. 줄 수는 그대로. 줄·시트 6곳이 한 함수를 쓰므로 한 번에 같아진다. 1:1 채팅 주문 패널의 순서(상품명 → 옵션 × 수량)와도 맞는다.

4상품명만 줄인다

상품 줄은 한 줄. 넘치면 상품명만 말줄임하고 이름과 옵션 × 수량은 끝까지 보인다(옵션·수량이 잘리면 출하가 틀린다). 소비자 상품 줄도 같은 규칙. 화면 읽기 라벨은 줄이지 않은 전체 글자.

5초안에는 마지막 저장 시각

작성 중 카드 이름 아래 13/18 보조색 11월 4일 오후 2:20 저장(updatedAt). 생산자가 기억하는 건 “아까 쓰던 것”이라 만든 날보다 마지막 저장이 맞다. 자료 요약은 응답에 없어 이번엔 넣지 않는다(Q4).

썸네일

소비자 줄은 지금처럼 64(디자인 README ‘거래 요약’). 같은 상품을 두 번 산 경우 사진도 같아서 썸네일로는 가를 수 없고, 그래서 글자(번호·주문일)로 가른다. 생산자 주문 줄에는 썸네일을 새로 넣지 않는다: 줄 아래 버튼 한 쌍과 체크 고르기가 이미 폭을 쓰고, 같은 농가 감귤 사진은 서로 비슷해 상품명 글자가 더 확실하다(Q3).
