값이 없을 때 자리표시자 대신, 값 종류마다 규칙 하나

예상 당도가 비면 구매자 화면에 “당도 예상 -Brix”, 예약이 0건이면 “0명 예약 · 마감 D-9”, 마감일이 없으면 “마감 ”, 배송비 금액이 없으면 “배송비 ”가 나온다. 예약할 수 없는 상품은 화면마다 ‘현재 예약 불가’ / ‘이번 기간 품절’ / ‘현재 기간 품절’로 부르고, 소식방 말풍선만 ‘오전 09:40’이다. 지금 코드는 “값이 없으면 빈 글자”까지만 정해 두고, 그 앞에 붙는 라벨은 그대로 남긴다. 이 보드는 값 종류(당도·예약 수·마감·배송비·받는 시기·예약 가능 상태·시각)마다 빈 값일 때 무엇을 보일지 한 가지씩 정한다.

스펙이 정한 것과 정하지 않은 것

당도: 실측 / 예상까지만

FEAT-07 입력·검증 “당도는 실측값이 있으면 실측, 없으면 ‘예상’으로 표시”, AC-07-2 실측이 있으면 예상 대신 실측. 둘 다 없을 때는 정하지 않았다.

M-11: 입력에 없는 값은 빈 칸으로 두고 지어내지 않는다. M-15: 당도 질문에 둘 다 없으면 AI는 농가에 전달한다. 당도는 게시 필수 항목이 아니라(server/app/catalog/service.py missing_fields) 둘 다 빈 채 공개될 수 있다.

예약 가능 상태: 이름이 셋

ia.md 레이블 표 “품절 — 단계 물량 소진 — 쓰지 않는 말: 매진”. 코드는 availability 6값(AVAILABLE·NOT_OPEN·PERIOD_SOLD_OUT·TOTAL_SOLD_OUT·PAUSED·ENDED)을 이미 주지만, 카드의 Price는 soldOut 하나로 ‘현재 예약 불가’, 상세는 표(ProductPage.tsx AVAILABILITY), 생산자 목록은 따로 쓴 글자(productGroups.ts)다. Figma는 ‘이번 기간 품절’.

시각: 도우미가 이미 있다

packages/ui/src/format.ts time() = “오후 3:12”(한국 시간, 시 앞 0 없음). 1:1 대화(ChatThread.tsx)는 이걸 쓰고, 소식방(NewsRoom.tsx:447-450)만 기기 시간대 toLocaleTimeString + hour: "2-digit"라 “오전 09:40”. 입금 기한 deadline()의 “01:06”은 마감 시각 표기라 그대로 둔다.

결론: 새 화면·새 부품 없이 문구 규칙만 바꾼다. “라벨 + 값”을 한 덩어리로 보고 값이 없으면 라벨째 뺀다. 빼면 뜻이 사라지는 곳(당도, 받는 시기)에만 끝난 문장을 둔다. 예약할 수 없는 이유는 availability 하나에서 이름을 뽑아 세 화면이 같은 표를 쓴다. AI가 당도를 못 채우는 문제(grounding)는 DEV-228에서 따로 다룬다. 여기서는 그리는 쪽만 고친다.

디자인 무브

1라벨과 값은 한 덩어리

“마감 D-9”, “배송비 4,000원”, “12명 예약”처럼 라벨+값을 한 조각으로 만들고, 값이 없으면 조각째 뺀다. 조각은 “ · ”로 잇고 빈 조각은 버린다(joinMeta). format.ts의 “없으면 빈 글자” 규칙은 그대로 두고, 부르는 쪽이 라벨을 혼자 남기지 않게 한다.

2당도는 세 상태, 숫자는 지어내지 않는다

실측(큰 숫자) → 예상(“당도 예상 12Brix”) → 등록 전(“당도 등록 전” + 1:1 채팅 안내). 셋째 상태는 예상 줄과 같은 자리·아이콘·크기라 레이아웃이 흔들리지 않는다. “-”, “0”, “?”는 쓰지 않는다(M-11).

30은 사회적 증거가 아니다

예약 수는 1명부터 보인다. 0명은 수를 말하지 않고 마감만 남긴다. “0명”은 상품이 안 팔린다는 신호로 읽혀 첫 예약을 막는다. 생산자 목록의 ‘n명 예약’도 같은 규칙.

4예약할 수 없는 이유는 availability에서 나온다

상태 6개 → 이름 6개 표 하나(packages/ui)를 소비자 카드·상세·생산자 목록이 같이 쓴다. ‘현재 예약 불가’(이유를 숨김)와 ‘현재 기간 품절’(Figma에 없음)은 없앤다. 카드 가격 자리에는 이유 이름이 들어간다.

5시각은 time() 하나

화면에 찍는 하루 안 시각은 모두 format.ts time()(한국 시간, “오전 9:40”). 기기 시간대·2-digit을 직접 부르지 않는다. 마감 시각(deadline())만 24시 두 자리로 따로 둔다.

6미리보기는 빈 값을 채우지 않는다

생산자 미리보기는 “구매자가 이렇게 본다”를 보여 주는 곳이라 빈 값을 오늘 날짜로 채우면 거짓 미리보기가 된다. 빈 받는 시기는 DEV-184 점선 칸, 빈 당도·배송비는 무브 1·2 규칙 그대로(소비자 화면과 같은 글자).

검산: 바뀌는 곳 6개 화면 모두 새 부품 없이 기존 글자 변형(sub·meta·na·statusblock)과 기존 점선 칸만 쓴다. 새 문구는 4개(‘당도 등록 전’, ‘궁금하면 1:1 채팅으로 농가에 물어보세요’, ‘배송비 별도’, ‘받는 시기를 정하면 여기에 보여요’), 나머지는 이미 코드·Figma에 있는 이름이다.

열린 질문 (PM)

Q1. 당도가 둘 다 없을 때

A(추천) ‘당도 등록 전 / 궁금하면 1:1 채팅으로 농가에 물어보세요’ 줄을 남긴다. B 블록을 숨긴다. A는 당도 중심 서비스에서 빈 정보도 알려 주고 M-15 흐름과 이어진다.

Q2. 예약 0명 카드

추천: 수를 빼고 ‘마감 D-9’만. 대안: ‘첫 예약을 받아요 · 마감 D-9’. 메타 줄이 통째로 비면 줄 자리(18px)를 남길지 — 추천은 남기지 않음(카드는 가로 스크롤이라 높이 차이가 잘 안 보임).

Q3. 예약 불가 이름 표 승인

카드 가격 자리 ‘현재 예약 불가’를 상태 이름으로 바꾼다. DEV-215에서 승인한 “판매 품목에는 ‘현재 예약 불가’”가 ‘판매 일시 중지’로 바뀌는 것이라 다시 확인한다. ia 레이블 ‘품절’은 ‘이번 기간 품절’·‘전체 물량 품절’ 둘로 나뉜다.

Q4. 생산자 ‘예약 대기 · 판매 기간 확인’

‘예약 시작 전 · 판매 기간 확인’으로 이름만 맞출지(추천), 생산자 쪽은 그대로 둘지.

Q5. Brix 띄어쓰기

실측 큰 숫자는 ‘11.8 Brix’, 예상 줄은 ‘12Brix’, design README 예시는 둘 다 붙여 씀. 이번 이슈에서 맞출지 — 추천은 그대로 두고(큰 숫자 줄은 Figma 기준) 별도로.

Q6. Figma v6

새 부품 없이 상태 프레임 문구만 바뀜(상세 당도 셋째 상태, 홈 카드 0명, 판매 품목 이름, 미리보기 점선 받는 시기). 승인 뒤 Figma v6 반영 요청(PR Figma: 후속).
