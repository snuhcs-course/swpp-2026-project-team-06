DEV-215 · 디자인 제안 · BEFORE / AFTER

판매를 잠시 멈춘 상품은 소비자 앱에서 “판매 일시 중지”로 보이고 예약하기가 꺼지게

생산자가 하우스 감귤 5kg / 10kg(강씨네 귤밭)을 일시 중지해도 API는 availability=PAUSED, soldOut=false를 준다. 그래서 홈 추천 첫 칸과 농가 목록 대표 상품에 그대로 남고, 상세에는 가격과 ‘42박스 남음 · 마감 D-5’가 나오며 예약하기를 누르면 옵션 시트가 열린다. 막히는 곳은 마지막 주문 단계(서버 SALES_PAUSED)뿐이다. I3-DISC-05 FAIL(baseline i3-b2-87792b7, PR #402).

PM 승인 대기기준: Figma v6 · docs/design/README.md 토큰계약: R-27 · AC-04-6 · FEAT-06 · AC-07-1 · AC-07-32026-11-04

스펙이 정한 것

숨기지 않는다 — 공개 화면에는 남긴다

R-27(rules.md): 판매 중지 상품은 공개 화면에 남되 신규 예약을 막는다. AC-04-6: 중지 중에도 상품은 보인다.

→ 상품 상세 링크·농가 소식방 ‘판매 품목’에서 사라지면 안 된다.

홈 추천·농가 대표는 ‘판매 중’만

FEAT-06 입력·검증: 정렬은 판매 중 상품의 현재 단계 마감순, 판매 중 상품이 없는 농가는 맨 아래, 홈 추천은 같은 정렬의 상위 N개. AC-06-5: 판매 중인 상품이 없으면 ‘현재 예약 가능한 상품이 없어요’.

지금 품절·기간 공백 상품도 이 두 곳에서 빠진다(if not c.sold_out). 중지 상품도 같이 빠지는 것이 스펙과 맞다.

상세는 상태를 구분해 예약을 막는다

AC-07-3: PAUSED/기간 공백/품절/종료를 구분하여 예약 버튼을 제한한다. AC-07-1(품절): 상태와 다음 단계 시작일, 예약하기 안 눌림. screens.md SCR-04: “PAUSED/공백/품절/종료는 기존 예약 제한과 다음 시작 안내 유지”, “품절에 가짜 가격 없음”.

문구는 이미 코드에 있다: packages/ui/src/ProductPage.tsx AVAILABILITY.PAUSED = "판매 일시 중지". soldOut일 때만 보여서 안 나올 뿐이다.

결론: 숨김이 아니라 ‘판매 중이 아님’으로 다룬다. 품절과 같은 결로 홈 추천·농가 대표에서는 빠지고, 소식방 판매 품목과 상세에는 남아 ‘현재 예약 불가’ / ‘판매 일시 중지’로 보이며 예약하기는 꺼진다. 스펙이 이미 정해 둔 동작이라 새 규칙은 없고, 서버 판정 한 줄이 계약을 어기고 있다.

디자인 무브

1‘판매 중’ 판정은 한 곳

서버 카드의 soldOut을 “지금 예약할 수 없음” = availability ≠ AVAILABLE로 정의한다(Mock은 이미 이렇게 계산). 홈·농가 목록·소식방·상세·주문서가 모두 이 값 하나를 보므로 화면 다섯 곳이 한 번에 맞는다.

2추천·대표는 빼고, 소식방·상세에는 남긴다

FEAT-06의 “판매 중 상품만”과 R-27의 “공개 화면에 남되”를 둘 다 지킨다. 숨김 플래그나 별도 목록을 만들지 않고 품절과 똑같이 다룬다.

3가격 대신 상태 — 가짜 가격 없음

상세는 옵션 가격·취소선·남은 박스·마감 줄을 걷고 그 자리에 ‘판매 일시 중지’(22 굵게) + 보조 한 문장. 목록 부품은 기존 Price의 ‘현재 예약 불가’. SCR-04 “품절에 가짜 가격 없음”을 중지에도 적용.

4중지에는 날짜를 약속하지 않는다

nextStageStartsAt은 기간 때문에 막힌 경우(기간 공백 NOT_OPEN, 기간 물량 소진 PERIOD_SOLD_OUT)에만 준다. 중지·종료는 null → 보조 문장은 기존 ‘지금은 새 예약을 받지 않아요.’

5막는 곳은 첫 단추, 서버 409는 안전망

예약하기를 상세에서 끄고, 1:1 채팅은 남겨 “언제 다시 여나요?”를 물을 길을 둔다. 주문 생성의 SALES_PAUSED 거절은 그대로 두어 상세를 연 채 중지된 경우를 막는다(contracts-1.2 4장).

서버 변경 (승인 뒤)

A안(제안): sold_out 뜻을 계약대로 — 필드 추가 없음

server/app/catalog/service.py card():

state = sales_state(db, item)
blocked = state.availability != "AVAILABLE"
dated = state.availability in ("NOT_OPEN", "PERIOD_SOLD_OUT")
...
sold_out=blocked,
next_stage_starts_at=nxt.starts_at if dated and nxt else None,

farms/service.py home()·farm_cards()·by_deadline()는 그대로(이미 sold_out으로 거르고 정렬). 응답 필드·타입이 같아 API 호환. Mock packages/api/src/mock/derive.ts는 soldOut이 이미 같고, nextStageStartsAt만 같은 규칙으로 맞춘다.

B안(안 씀): reservable 새 필드

앱 5곳(홈·농가 목록·소식방·상세·주문서)과 productPresentation.ts가 모두 soldOut을 보므로 새 필드는 클라이언트를 다 고쳐야 하고, 이름과 뜻이 다른 두 값이 남는다. 상태별 문구는 이미 availability로 나뉜다.

같이 고쳐지는 것·그대로인 것

  • 같은 결함: 상품 총 한도로 막힌 TOTAL_SOLD_OUT도 지금은 soldOut=false(기간 박스만 봄). A안으로 함께 ‘전체 물량 품절’·예약하기 꺼짐.
  • 기존 AC-07-1 테스트 2개(레드향 기간 공백·하우스 기간 물량 소진의 nextStageStartsAt)는 그대로 통과해야 한다.
  • 그대로: 주문 생성 SALES_PAUSED(server/app/orders/**, 고위험 — 안 건드림), 생산자 앱 상품 그룹(availability·salesPaused 기준), 마이그레이션·모델 없음.
  • server/app/catalog·server/app/farms의 service는 AGENTS.md 고위험 목록이 아니다(목록은 */models.py·orders/** 등) → 위험 등급: 일반.

열린 질문

Q1. 농가 목록에서 ‘판매 일시 중지’라고 말할까

제안은 품절과 같은 ‘지금 판매 중인 상품 없음’(새 문구 없음). 단골이 “문 닫았나?” 오해할 수 있다면 featured가 없을 때 둘째 줄을 ‘판매 잠시 멈춤’으로 바꾸는 안도 있다 — 서버에 이유 필드가 필요해 범위가 커진다.

Q2. 상세 보조 문장을 더 구체적으로

‘지금은 새 예약을 받지 않아요.’ 대신 ‘농가가 판매를 잠시 멈췄어요. 1:1 채팅으로 물어볼 수 있어요.’처럼 중지에만 다른 문장을 둘까. 재개 알림 기능은 없어 “다시 열면 알려 드려요”는 쓰지 않는다.

Q3. 전체 물량 품절(TOTAL_SOLD_OUT)도 같이 고칠까

같은 한 줄로 고쳐진다. 범위를 넓히는 것이라 PM 확인. 제외하려면 blocked를 PAUSED만 보게 해야 하는데 그러면 Mock과 다시 어긋난다.
