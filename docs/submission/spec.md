# I1 제출 문서 구현 기준

- 관련 이슈: SWPP-34. FEAT-01~15, FEAT-17·19·32·33 및 R/M/N 규칙을 영문 제출 문서로 정리한다.
- 제품 동작 원본은 `docs/spec/`, 구현 근거는 같은 커밋의 앱·서버·마이그레이션이다. 계획과 구현을 구분하며 문서화 과정에서 제품 동작은 바꾸지 않는다.
- Wiki 원본은 `docs/wiki/`. 추후 PDF 제출본을 만들 때도 같은 Markdown과 그림을 사용한다. 이번 작업에서는 사용자 지시에 따라 PDF 출력을 보류한다.
- Abstract는 한 문단, 기능은 Connextra 스토리와 Given/When/Then, 비교·권한·API는 표, 순차 동작은 번호 목록으로 쓴다.
- Proposal은 개요·동기를 짧은 문단으로, 기능·목표·범위를 목록/표로 쓴다. 버전별 스펙 부록을 덧붙이지 않고 본문에 통합하며 상세 규칙은 Requirements/Design에 연결한다. 경쟁 비교는 공식 자료에 근거하고 한국어 PRD의 같은 설명도 동기화한다.
- 정적 화면은 `docs/design/screens/`에서 캡처하고 설계 참조임을 표시한다. 실제 실행 증빙과 혼동하지 않는다.
- AI 보고서와 일정표를 임의 작성하지 않는다. PDF 빌더 및 제출 ZIP은 이번 변경에 포함하지 않는다.
- 그림은 저장소에서 열리는 PNG와 편집 가능한 SVG로 보관한다. 임시 이미지·렌더링 결과는 저장소 밖 tmp에 둔다.

## I2 AI 협업 보고서 기여분 (SWPP-112)

- 사용자 요청에 따라 기존 `docs/wiki/AI-Collaboration-Report---Iteration-2.md`에 Minsun의 PM 기여를 채운다. 기존 1~7장, 기여 표, 세션 검토 체크리스트를 유지하고 별도 보고서 파일을 만들지 않는다.
- 가이드 v1.1과 Session Exporter 안내를 기준으로 도구/모델, 실제 프롬프트, 유용했던 사례, 오류, 프롬프트 수정, 수동 수정 근거와 한계를 기록한다. 확인되지 않은 모델 버전·시간 절감·사람의 코드 수정은 만들지 않는다.
- 원문 프롬프트는 날짜와 대화 turn ID로 추적한다. 긴 근거와 선택 프롬프트는 같은 페이지의 접이식 영역에 둔다. Codex 로컬 대화 및 로컬 산출물의 접근 한계를 명시하고 원본 세션·비밀값은 올리지 않는다.
- 다른 팀원 기여, 전체 세션/개인정보 검토, 최종 500~700단어 편집은 미완료로 남긴다. 이 변경은 Minsun 기여 초안이며 최종 제출본·라이브 모델 검증·전체 테스트 완료를 의미하지 않는다.
- 제품 동작·FEAT/AC·UI·Figma·PDF·일정표는 변경하지 않는다. 문서 구조·범위·인용과 저장된 근거 수치만 정적으로 검토한다.
- 10/22 후속 사용자 요청: eTL Q3 안내에 따라 내보낸 입력 기록은 별도 Wiki Prompt Log 페이지로 게시하고 보고서·사이드바에서 연결한다. 원래 보고서 형식과 사용자가 웹에서 수정한 내용은 유지한다. 이 명시적 요청이 앞선 '한 페이지 안의 긴 프롬프트' 결정을 대체한다.
- 공개 대상은 개인정보를 가린 입력 전용 Markdown이다. 원본 세션 ZIP·응답·JSONL·자격증명은 게시하지 않는다. 10/22 시점의 20개 로컬 세션과 별도 표시된 continuation에서 추출한 141개 입력 기록이며, 10/23 미래 기록이나 다른 팀원의 전체 이력을 포함한다고 주장하지 않는다.

## I2 Testing Documentation 최종 대조 (SWPP-112)

- 기존 `docs/wiki/Testing-Documentation.md`를 Testing Documentation Guidelines 4의 일정에 맞춰 책임·일정, Unit/Integration Plan/Results, I3~I5 예정 항목으로 정리한다. 기존 계획은 기준 커밋의 원문 링크로 보존하고 변경 이유를 명시한다.
- 내부 시험 77건의 상태·절차·기준·실제 결과·환경·일시·증빙·후속 조치는 사용자 제공 `SWPP_Internal_Testing_1_Final.xlsx`만 따른다. 네 탭과 요약·작성가이드·12개 셀 주석을 모두 확인한다. 원본 파일은 수정하지 않는다.
- 후속 사용자 지시로 GitHub의 CI 로그·워크플로·PR·기존 계획도 확인한다. 추가 자동화 결과는 실행 커밋·시각·명령·출처를 구분하며, workbook의 기능 상태를 임의로 바꾸지 않는다.
- 코드 커버리지 수치·사전 목표·화면 증빙을 찾지 못하면 미확인으로 표시한다. 기능 PASS율을 코드 커버리지로 대체하지 않으며, 과거 목표/결과를 소급해서 만들지 않는다. 미충족 필수 항목과 필요한 보완을 본문에서 밝힌다.
- 기존 제출 문서·프로덕트 동작·워크북·AI 보고서·다른 팀원 기록·일정표·PDF·ZIP은 수정하지 않는다. 로컬 문서 편집과 원본/집계/링크 검토만 수행하고 새 제품 테스트 실행이나 외부 게시·머지는 별도 요청으로 남긴다.
- 10/22 후속 사용자 지시로 지정 브랜치 `llovablanche-testing-documentation-revision`에 커밋·push하고 main 대상 PR을 생성한다. 문서 전용 범위와 필수 증빙의 미충족 표시는 유지한다. main 머지·PDF 제출은 포함하지 않는다.

## I2 최종 문서·일별 기록·데모 검토본 (SWPP-112)

- 사용자 요청에 따라 Requirements/Design을 2026-10-22 코드 기준으로 갱신하고 I1 구조·AC ID·유효한 내용을 유지한다. Testing은 머지된 #233의 77건 결과를 보존하며 새 측정은 별도 날짜·커밋으로 추가한다.
- 일별 기록은 확인되는 10/12–10/21의 작업·결정·장애물·다음 행동만 기존 Agenda/Discussion/Decisions/Action Items 형식으로 정리한다. 근거 없는 구두 회의·참석·미래 결과·완료 주장을 만들지 않는다. 비밀값·원문 기록·개인 신상·내부 재무 사정은 저장소에 넣지 않는다.
- 별도 로컬 `iteration-2-demo` 브랜치에 현재 main 코드와 루트 README를 준비한다. 발표 자료에서 확인한 전체/소비자/생산자/운영자 4개 영상과 실행 환경·명령·범위·한계를 포함한다. 기존 원격 데모 브랜치를 덮어쓰지 않고 승인 후 fast-forward 가능한 최신 main을 기준으로 한다.
- 사용자는 커밋 전 직접 검토를 요청했다. 모든 변경은 로컬 미커밋 상태로 제공한다. 이 요청에서는 커밋·push·PR·main 머지·외부 문서/서비스 변경을 하지 않는다.
- 사용자가 로컬 테스트·coverage 측정을 명시 승인했다. 측정 전에 목표·도구·범위를 기록하고 새 실행의 실제 성공/실패/coverage를 보고한다. 테스트는 격리 DB와 mock 제공자를 사용하며 운영 데이터·실제 송금·유료 모델 호출을 사용하지 않는다.

- 10/23 후속 사용자 요청으로 검토본을 `llovablanche-final-deliverables-for-iteration-2`에 통합하여 로컬 커밋한다. 루트 README도 검토된 demo 작업 트리의 내용과 동일하게 포함한다. 앞선 커밋 보류는 이 명시 요청으로 해제되며 push·PR·main 머지는 아직 승인 범위가 아니다. 사용자 지정 브랜치명은 일반 이슈 키 이름 규칙보다 우선하고 커밋에는 SWPP-112를 유지한다.
