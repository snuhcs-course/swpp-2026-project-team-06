# Bulk source analysis — specification

## Planned bulk source analysis — specified, not implemented

The Korean source of truth is [the follow-up specification](../spec/source-analysis.md), agreed on 2026-10-14. Producers identify the products first, then upload existing photos, photographed business cards/pamphlets, PDFs, UTF-8 TXT files or pasted text. The workflow is bulk analysis → review extracted fields and source evidence → supply original photos → preview the existing single template → save private drafts for multiple products. AI does not create additional products or publish content.

**Initial analysis model: OpenAI GPT-6.1 Sol, explicitly selected by the user.** This supersedes the earlier tentative Sonnet recommendation for this new feature only. Existing Claude-backed drafting/chat behavior and configuration are unchanged. Actual farm-source evaluations will measure field accuracy, omissions, number/unit errors, cross-product contamination, source alignment, unsupported claims, producer edits, latency (p50/p95), tokens and actual request/retry costs. No measured accuracy, per-job cost or performance superiority is claimed. Model/prompt versions and a fixed privacy-scrubbed evaluation set will support later reassessment; automatic provider switching is not part of the initial scope.

Each extracted candidate retains its source file/page/text or image region. Review states are unreviewed, confirmed, conflicting, missing and excluded; ambiguous product assignments require review. Duplicate facts retain all references. Wording may be shortened and corrected without strengthening or inventing claims. Old prices, reservation dates, inventory and promotions remain historical reference material, not current sales settings. Expected quality is never upgraded to measured evidence. Missing counts, certification, quality measurements and shipping policies are not inferred.

Embedded document photos are analyzed for meaning only, not cropped into sales assets. The feature requests product-specific original photographs and proposes roles for separately uploaded originals, subject to producer confirmation. Original pixels/aspect ratios are preserved. Existing explanatory hand illustrations remain optional and labeled. The 18-element template and producer toggles remain; consumer previews exclude missing placeholders, review metadata and unconfirmed claims. Draft creation never updates a live product, operational prices, inventory or orders.

Sources and jobs are farm-private and persist across reconnects. Partial failures can be retried without losing successful results or producer edits; reanalysis proposes changes rather than overwriting confirmed work. Local/internal OCR and privacy scrubbing precede external model processing, with uncertain redaction requiring review. Raw files/OCR text are excluded from ordinary logs and analytics. Source text is data, not executable model instructions. New contracts cover source CRUD, asynchronous analysis/status/retry, evidence-backed review and per-product draft saving, while existing text-draft/detail APIs remain compatible. A versioned content contract for the 18 modules must be defined in the follow-up implementation design rather than silently forcing them into the existing 30 text/image blocks.

Initial limits are 10 products, 30 files and 100MB per job; 20MB per file; 20 pages per PDF and 60 total PDF pages; 30,000 combined TXT/pasted characters. JPG/PNG/WebP/HEIC, PDF and UTF-8 TXT are supported; video, audio, URL crawling and native Word/Hangul files are excluded. These are initial operating defaults pending measurement, not a claim that one model request accepts the whole job. Existing single-draft 20-second targets do not apply to an entire bulk job.

AC-SRC-1–8 cover product separation, source navigation/review, conflicting or historical facts, original-photo requests, failure/reconnect/edit preservation, access/privacy protection, private draft isolation and 360/390/430px usability with legacy behavior retained. Follow-up implementation will align FEAT-03/04/07, M-10–13/M-18, IA/screens/API, AI ADR and implementation tasks under a separate issue. This documentation change does not implement or migrate those systems.

**Optional producer-added AI-generated imagery is under consideration only.** Generation subjects, workflow and model are undecided and excluded from the committed implementation scope. This does not change the existing pre-generated decorative asset workflow.
