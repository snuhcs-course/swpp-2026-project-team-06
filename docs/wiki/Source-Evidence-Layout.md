# Korean line-wrap evidence repair (DEV-453)

This isolated prototype fixes a narrow extraction-validation loss: a model quote can preserve all source characters while removing a physical line break between Korean syllables. The existing matcher treated this as nonverbatim even when the original cited spans supported it. The [Korean contract](../spec/source-evidence-layout.md) defines the exact boundary; [diagnosis and replay](../evaluation/i5-evidence-layout/README.md) separate it from unresolved extraction problems.

Keep the existing exact and whitespace-run matching first. The additional fallback folds only a single LF/CRLF between Hangul syllables, optionally surrounded by spaces/tabs, and stores the **exact original substring**. It requires cited spans to be consecutive in the supplied page's source order; skipped, reordered or repeated spans cannot earn new wrap recovery. It does not change the candidate value or source/page/revision/span references. Ordinary spaces, paragraphs, numeric/unit/Latin/punctuation boundaries, changed words and invented separators remain protected. It is not fuzzy matching or a semantic truth check.

All historical-field, target, private-data, number/count/certification and evidence guards remain. Downstream money, health, exaggeration and policy checks still apply. A recovered extraction quote is not permission to publish. Existing producer confirmations/edits/exclusions, explicit application and version protections remain; saved candidates and public pages are not automatically rewritten.

Only the extraction pipeline version changes to source-v9-coverage-wrap1; prompt body and model remain unchanged. Existing run-version checks prevent stale reuse/execution without introducing automatic retries. Any new analysis uses existing user initiation, cost and review controls.

Targeted offline reconstruction across three development sources exactly reproduced 68 accepted candidates and 16 rejection codes. Eight rejected candidates become evidence-valid. Echoing their values through the unchanged page-safety validator leaves six, with one health claim and one exaggeration still rejected. Six historical/field conflicts and two other quote mismatches stay rejected. Original provider chunks were not retained: reconstruction uses unique offsets in the saved flat OCR transcript, checked against all accepted quotes and cited-span bounds. This is not new OCR, repeated model generation or page-quality/recall acceptance.

Historical table currentness, numeric-boundary layout and changed-word cases remain unresolved/rejected. No page-cap expansion, OCR replacement, holdout access, gold/scorer changes or new paid calls. Human review, release-scope decision and production adoption remain separate. The code has not been merged or deployed by this work.
