### 결정 사항
- 박스 수는 `UNLIMITED_BOXES = 99_999`로 보낸다(int4 안, 예약 수보다 작아질 일 없음). 서버를 바꾸지 않고 화면만 바꾼다.
- 기존 상품의 작은 박스 수: 진우 결정(11/25)으로 서버 규칙을 바꾸지 않고 운영 데이터만 한 번 정리한다. 아래 SQL을 사람이 실행한다(에이전트는 운영 DB를 만지지 않음).
- 박스 수만 다른 것은 판매 조건 변경으로 세지 않는다(`termsKey`에서 뺌). 열자마자 ‘수정됨’이 뜨지 않게.
- 정리 뒤에는 기간 박스 수가 99,999라 ‘24박스 / 199,998박스’처럼 보이므로(스캔 1차), 현황·상품 목록·물량·판매 설정의 옵션 줄은 ‘N박스 예약’만 보이고 현황의 옵션별 막대는 상품 kg 막대 하나로 바꾼다.
- ‘이번 기간 품절’ 안내·‘판매 조건에서 박스 늘리기’는 물량·판매 설정 화면과 함께 (2/2)에서 정리한다. 정리 SQL을 배포 직후 실행하면 그 상태가 생기지 않는다.
- `sold-out-guidance` e2e는 박스 칸 대신 가격을 1,000원 올려 반영하고, 끝나면 읽어 둔 기간 값(가격·박스 수)으로 되돌린다.

### 운영 데이터 정리 (사람이 실행)
**이 PR 배포 직후** 한 번(늦을수록 기간 품절 상품이 박스 칸 없는 안내를 오래 본다). 실행 전 백업·건수 확인.
```sql
-- 확인: 제한 없음 값보다 작은 기간 박스 수
SELECT count(*) FROM stage_allocations WHERE quantity < 99999;
-- 정리: 예약된 수보다 작아지지 않게(99,999 > 예약 수)
BEGIN;
UPDATE stage_allocations SET quantity = 99999 WHERE quantity < 99999;
-- 결과 확인 후
COMMIT;
```
운영 셸 접속·실행 방법은 AGENTS.md ‘금지’대로 사람이 한다. 실행 뒤 판매 중 상품의 ‘이번 기간 품절’이 사라졌는지 상품 상세 API로 확인한다.

- 판매 재개는 확인 없이 바로, 판매 중지는 확인 한 번 더(다시 재개할 수 있다고 적음).
