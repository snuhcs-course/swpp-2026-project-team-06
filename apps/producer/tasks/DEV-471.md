## DEV-471 농가 앱 새 상품·상품 수정 빈 화면 (원스토어 반려)

- 이슈: [DEV-471](https://linear.app/sswp6/issue/DEV-471)
- 브랜치: `nemodleo/dev-471-guard-composer-beforeunload`
- 기능·인수 조건: FEAT-03 새 상품(자료 작업 → composer), FEAT-04 상품 수정(`/products/:id/detail`, SCR-24 composer). 동작·규칙 변경 없음(앱에서 화면이 열리게만 한다)
- 상태: 리뷰 중

### 목표
원스토어 심사(2026-11-23)에서 생산자 Android 앱이 반려됐다: "상품 > 새 상품", "상품 > 작성중 > 상품수정"을 누르면 어두운 회색 빈 화면이 되고 반응이 없다. 웹(Vercel)은 같은 화면이 동작한다. 앱에서도 판매페이지 화면(composer)이 열리게 하고, 같은 실수가 다시 들어오지 않게 검사를 붙인다.

### 원인
- 두 경로 모두 composer로 간다: 새 상품 `src/app/(tabs)/products/new.tsx:30-45`(자료 작업을 서버에 연 뒤 `/products/source-analysis`로 replace → 초안이 먼저 생겨 작성 중 초안이 쌓였다), 상품 수정 `src/app/(tabs)/products/[id]/detail.tsx:69-89` → `src/app/(tabs)/products/source-analysis.tsx:9` `<NewProductComposer/>`.
- `src/lib/NewProductComposer.tsx:866-868`(수정 전): beforeunload effect가 `typeof window === "undefined"`만 보고 `window.addEventListener`를 부른다. React Native는 `global.window = global`로 window를 정의하지만(`react-native/Libraries/Core/setUpGlobals.js:18-21`) 전역에 addEventListener가 없어 마운트 직후 `TypeError: window.addEventListener is not a function`.
- RN은 렌더러 오류를 non-fatal로 넘기고(`ReactFiberErrorDialog.js`, `handleException(error, false)`) 앱에 ErrorBoundary가 없어 React가 루트 트리를 지운다 → 앱은 안 꺼지고 빈 화면.
- 어두운 회색: 제출 APK의 `AppTheme`가 `Theme.AppCompat.DayNight.NoActionBar`이고 창 배경 지정이 없다. `userInterfaceStyle: "light"`는 `expo-system-ui`가 없어 Android에 적용되지 않는다(prebuild 경고). 다크 모드 기기에서 기본 어두운 배경이 보인 것으로 추정.
- 같은 계열 두 번째: `src/lib/fields.tsx` `DateInput`이 분기 없이 DOM `<input type="date">`를 그린다(DEV-3부터). 판매 중 상품의 상품 수정 → '판매 조건 고치기'(`SalesTermsEditor.tsx:433-434`, live 모드 예약 기간 칸)를 열면 `Invariant Violation: View config getter callback for component \`input\``으로 같은 빈 화면이 된다(에뮬레이터 재현).
- 같은 코드를 `src/lib/DetailEditor.tsx:109`는 DEV-33 때 `Platform.OS !== "web"`로 막았고 composer(DEV-184에서 생김)만 빠졌다. 기존 검사 `scripts/test-native-config.mjs`는 `packages/*`만 봐서 놓쳤다.
- 제출 APK: `farmclub-producer-2026-11-21.apk`(versionCode 5, 런처 이름 'farmclub 농가') → 5a125004(DEV-377) 기준으로 추정. 그 커밋과 현재 main(22b66cc5) 모두 같은 줄이다.

### 비범위 (건드리지 않음)
- ErrorBoundary(예외 시 안내 + '다시 시도'): 지금 없다. 화면·문구가 생기므로 디자인 순서와 함께 따로 판단한다.
- `expo-system-ui`·Android 창 배경색: 네이티브 변경이라 fingerprint가 바뀌고 새 빌드가 필요하다. 따로 판단한다.
- `src/lib/fields.tsx`의 네이티브 TextInput `outlineStyle: "none"`: 에뮬레이터에서 숫자 칸이 정상으로 떠서 문제 없음.
- 소비자 앱 우편번호 찾기(`apps/consumer/src/lib/postcodeSearch.ts` ↔ `postcodeSearch.native.tsx`): 웹 파일 확장자가 `.ts`, 앱 파일이 `.tsx`라 Metro가 `postcodeSearch.ts`를 먼저 찾아 앱에도 웹 구현이 들어간다(소비자 Mock 번들에 앱 쪽 `postcode.map.kakao.com` 문자열 없음). 주문서 → 받는 곳 변경 → 새 주소 입력 → '우편번호 찾기'에서 `ReferenceError: Property 'document' doesn't exist`로 빈 화면(에뮬레이터 재현). 원인이 달라(모듈 해석) DEV-474(#830)에서 고친다.
- `DateInput` 오류 상태를 읽기 도구에 알리기: RN `accessibilityState`에는 '오류' 값이 없어 새 문구(힌트·라벨) 없이는 알릴 수 없다. 문구가 생기지 않는 범위라는 조건이라 이번에는 하지 않는다(DEV-473 보드에서 문구와 함께).

### 결정 사항
- 11/24 분기는 DetailEditor와 같은 `Platform.OS !== "web" || typeof window === "undefined"`로 한다(웹 동작은 그대로).
- 11/24 검사는 새 파일로 둔다(`test:mock`이 글롭으로 모음). `apps/*/src`에서 window·document 이벤트 구독, `document.*` DOM 접근, `window.innerWidth/Height`가 감싸는 effect·함수 안에 `Platform.OS`(또는 `isWeb`) 분기가 있어야 한다. `typeof window`는 분기로 치지 않고, `typeof document`는 친다(RN에 document는 없음). `.native` 쌍이 있는 웹 파일과 `*.web.*`은 보지 않는다.
- 11/24 `DateInput`은 앱에서 같은 칸 모양 버튼 + 기존 기간 달력 시트(`DateSheet`, D-27)의 하루 고르기로 받는다. 지금까지 앱에서는 이 칸이 아예 열리지 않았으므로 새 화면 모양이다(웹은 그대로). 디자인 확인이 필요하면 Figma 후속으로 둔다.
- 11/24 검사에 DOM 요소(`<input>`·`<div>` 등 JSX, `createElement("input")`)를 더하고 `packages/ui/src`도 본다.
- 11/24 (리뷰 반영) 검사를 정규식에서 TypeScript 구문 트리 걷기로 다시 썼다. 문자열·주석·JSX 텍스트는 저절로 빠진다.
  - 대상: RN에 없는 전역 이름(document·localStorage·sessionStorage·location·history·confirm·prompt·matchMedia·getComputedStyle·*Observer·HTMLElement·DOMParser, 가려진 이름·typeof 피연산자·타입 위치 제외), `window`·`globalThis`·`self`·`navigator` 멤버(RN에도 있는 setTimeout·fetch·FileReader·URL 등은 제외, 옵셔널 체이닝 포함), 소문자 JSX 태그 전부, `createElement("소문자")`. FileReader·`URL.createObjectURL`은 RN이 polyfill해서(`setUpXHR.js`) 넣지 않았다.
  - 분기: `Platform.OS`와 `"web"` 비교(=== / !== / == / !=)와 `isWeb`만. 존재 검사 `typeof X === "undefined"`는 RN에 없는 그 이름에 한해서만(`typeof window` 불인정). if·삼항·&&·|| 조건 안이거나, 감싸는 함수(화살표 포함) 안에서 걸린 곳보다 앞에 있으면 인정한다. 가장 가까운 함수만 보면 Tour.tsx `tick`(분기한 effect 안의 콜백)이 걸려서 바깥 함수까지 보되, 모듈 최상위는 보지 않는다(파일 위쪽 `Platform.OS` 하나로 통과하던 문제).
  - 파일: `apps/*/src`, `packages/ui·api·analytics/src`. `*.web.*`과, Metro 순서로 android·ios 모두에서 플랫폼 파일이 먼저 잡히는 웹 파일만 뺀다. `.native`·`.android`·`.ios` 파일은 분기를 인정하지 않고 바로 건다. 짝 판정은 DEV-474 `scripts/test-native-pairs.mjs`와 같은 Metro 순서이고, 두 브랜치가 각자 작은 함수(`resolveLikeMetro`)를 둔다.
  - `try`로 감싼 storage 접근도 건다(앱에서는 죽지 않지만 기억을 잃는다). 걸린 두 곳은 고쳤다: `NewProductComposer.tsx` '이미 반영한 초안'과 `SourceExclusions.tsx` '제외 안내 확인'은 웹은 예전 그대로(sessionStorage·localStorage), 앱은 공용 `readStore`/`writeStore`(SecureStore). 화면·문구 변화 없음. 예외 주석 형식은 필요 없어서 두지 않았다.
  - 소비자 `postcodeSearch.ts`는 DEV-474(#830)에서 고치므로 검사의 `PENDING`에 기한 있는 표시로 둔다. 파일이 없어지거나 앱 번들에서 빠지거나 걸리는 곳이 없어지면 테스트가 실패해 지우게 된다.
  - 코드 모양을 문자열로 보던 테스트는 검사기에 조각을 넣어 결과를 보는 동작 테스트로 바꿨다. origin/main 스냅샷에서는 composer 두 줄, `fields.tsx:38`, postcodeSearch 11곳, storage 7곳이 걸리고 리뷰 실험 경우가 모두 걸린다.
- 11/24 JS만 바뀌어 fingerprint는 제출 APK와 같다(`3e2110120b62d27cb58050ecba1252cf3b3b4c18`, `expo-updates fingerprint:generate --platform android`). preview 채널 OTA로도 닿지만, 재심사는 새 APK로 내는 편이 안전하다(심사자가 새로 설치해 한 번만 열 수 있음).

### 기록
- 11/24 기기 재현은 못 했다. 에뮬레이터(AVD `Medium_Phone`)와 adb는 있지만, Mock release 빌드 중 Gradle이 NDK 27.1(수 GB)을 자동 설치하기 시작했고 디스크 여유가 7.6GB라 가득 찰 위험이 있어 중단했다. 제출 APK는 운영 서버에 심사 계정으로 로그인해야 해서 쓰지 않았다. 디스크를 비운 뒤 `EXPO_PUBLIC_API_MOCK=1`로 prebuild → `assembleRelease`하면 Mock에서도 상품 수정 → composer 경로로 재현·확인할 수 있다.
- 11/24 에뮬레이터 재현(AVD `Medium_Phone`, Android 다크 모드, 네트워크 끔). 네이티브 빌드 대신 제출 APK(fingerprint가 main과 같음)의 `assets/index.android.bundle`만 `EXPO_PUBLIC_API_MOCK=1 npx expo export --platform android`로 만든 Hermes 번들로 바꾸고 임시 키로 다시 서명해 설치했다. 운영 서버 로그인은 하지 않았다.
  - 수정 전(origin/main): 상품 > 판매 중 > '상품 수정' → 어두운 회색(#303030) 빈 화면, 뒤로 가기는 앱을 닫는다. logcat `E ReactNativeJS: { [TypeError: undefined is not a function] … at NewProductComposer … at ProductDetailEditor`.
