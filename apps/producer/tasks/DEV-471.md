## DEV-471 농가 앱 새 상품·상품 수정 빈 화면 (원스토어 반려)

- 이슈: [DEV-471](https://linear.app/sswp6/issue/DEV-471)
- 브랜치: `nemodleo/dev-471-guard-composer-beforeunload`
- 기능·인수 조건: FEAT-03 새 상품(자료 작업 → composer), FEAT-04 상품 수정(`/products/:id/detail`, SCR-24 composer). 동작·규칙 변경 없음(앱에서 화면이 열리게만 한다)
- 상태: 리뷰 중

### 목표
원스토어 심사(2026-11-23)에서 생산자 Android 앱이 반려됐다: "상품 > 새 상품", "상품 > 작성중 > 상품수정"을 누르면 어두운 회색 빈 화면이 되고 반응이 없다. 웹(Vercel)은 같은 화면이 동작한다. 앱에서도 판매페이지 화면(composer)이 열리게 하고, 같은 실수가 다시 들어오지 않게 검사를 붙인다.

### 원인
- 두 경로 모두 composer로 간다: 새 상품 `src/app/(tabs)/products/new.tsx:30-45`(자료 작업을 서버에 연 뒤 `/products/source-analysis`로 replace → 초안이 먼저 생겨 작성 중 초안이 쌓였다), 상품 수정 `src/app/(tabs)/products/[id]/detail.tsx:69-89` → `src/app/(tabs)/products/source-analysis.tsx:9` `<NewProductComposer/>`.
- `src/lib/NewProductComposer.tsx:866-868`(수정 전): beforeunload effect가 `typeof window === "undefined"`만 보고 `window.addEventListener`를 부른다. React Native는 `global.window = global`로 window를 정의하지만(`react-native/Libraries/Core/setUpGlobals.js:18-21`) 전역에 addEventListener가 없어 마운트 직후 `TypeError: window.addEventListener is not a function`.
- RN은 렌더러 오류를 non-fatal로 넘기고(`ReactFiberErrorDialog.js`, `handleException(error, false)`) 앱에 ErrorBoundary가 없어 React가 루트 트리를 지운다 → 앱은 안 꺼지고 빈 화면.
- 어두운 회색: 제출 APK의 `AppTheme`가 `Theme.AppCompat.DayNight.NoActionBar`이고 창 배경 지정이 없다. `userInterfaceStyle: "light"`는 `expo-system-ui`가 없어 Android에 적용되지 않는다(prebuild 경고). 다크 모드 기기에서 기본 어두운 배경이 보인 것으로 추정.
- 같은 코드를 `src/lib/DetailEditor.tsx:109`는 DEV-33 때 `Platform.OS !== "web"`로 막았고 composer(DEV-184에서 생김)만 빠졌다. 기존 검사 `scripts/test-native-config.mjs`는 `packages/*`만 봐서 놓쳤다.
- 제출 APK: `farmclub-producer-2026-11-21.apk`(versionCode 5, 런처 이름 'farmclub 농가') → 5a125004(DEV-377) 기준으로 추정. 그 커밋과 현재 main(22b66cc5) 모두 같은 줄이다.

### 범위 (수정 허용 경로)
- `apps/producer/src/lib/NewProductComposer.tsx`(beforeunload effect 분기, `Platform` import)
- `scripts/test-app-web-globals.mjs`(새 검사)
- `apps/producer/tasks/DEV-471.md`

### 비범위 (건드리지 않음)
- ErrorBoundary(예외 시 안내 + '다시 시도'): 지금 없다. 화면·문구가 생기므로 디자인 순서와 함께 따로 판단한다.
- `expo-system-ui`·Android 창 배경색: 네이티브 변경이라 fingerprint가 바뀌고 새 빌드가 필요하다. 따로 판단한다.
- `src/lib/fields.tsx:132`의 네이티브 TextInput `outlineStyle: "none"`: 다른 원인 후보(크래시 여부 미확인), 목록만.

### 결정 사항
- 11/24 분기는 DetailEditor와 같은 `Platform.OS !== "web" || typeof window === "undefined"`로 한다(웹 동작은 그대로).
- 11/24 검사는 새 파일로 둔다(`test:mock`이 글롭으로 모음). `apps/*/src`에서 window·document 이벤트 구독, `document.*` DOM 접근, `window.innerWidth/Height`가 감싸는 effect·함수 안에 `Platform.OS`(또는 `isWeb`) 분기가 있어야 한다. `typeof window`는 분기로 치지 않고, `typeof document`는 친다(RN에 document는 없음). `.native` 쌍이 있는 웹 파일과 `*.web.*`은 보지 않는다.
- 11/24 JS만 바뀌어 fingerprint는 제출 APK와 같다(`3e2110120b62d27cb58050ecba1252cf3b3b4c18`, `expo-updates fingerprint:generate --platform android`). preview 채널 OTA로도 닿지만, 재심사는 새 APK로 내는 편이 안전하다(심사자가 새로 설치해 한 번만 열 수 있음).

### 기록
- 11/24 기기 재현은 못 했다. 에뮬레이터(AVD `Medium_Phone`)와 adb는 있지만, Mock release 빌드 중 Gradle이 NDK 27.1(수 GB)을 자동 설치하기 시작했고 디스크 여유가 7.6GB라 가득 찰 위험이 있어 중단했다. 제출 APK는 운영 서버에 심사 계정으로 로그인해야 해서 쓰지 않았다. 디스크를 비운 뒤 `EXPO_PUBLIC_API_MOCK=1`로 prebuild → `assembleRelease`하면 Mock에서도 상품 수정 → composer 경로로 재현·확인할 수 있다.
