## DEV-329 Let producers type Brix and size on the new product screen without a hidden lock, and accept decimal Brix

- 이슈: [DEV-329](https://linear.app/sswp6/issue/DEV-329) · 상위 [DEV-323](https://linear.app/sswp6/issue/DEV-323) 생산자 파일럿 피드백(11/15)
- 스펙: `docs/spec/screens.md` SCR-24·SCR-25, `docs/spec/functional/FEAT-04-product-edit.md`(원산지 칸·측정 당도)

### 왜
- 11/15 실제 농가(안드로이드, 카카오톡 브라우저 캡처): 새 상품 작성 화면에서 당도·'중량·수량' 칸을 눌러도 키보드가 안 뜬다.
- 원인: 판매페이지(상세 스토리)에 저장 안 한 수정이 있으면 품종·사이즈·측정 당도 칸을 읽기 전용으로 잠갔다(`locked = busy || activeRun || editorDirty`, DEV-184). 두 저장(상세 초안·기본 정보)이 같은 배치 버전을 다투지 않게 하려던 것. 이유 안내는 화면 아래 작은 글씨뿐이었다.
- '중량·수량' 줄은 소비자 상품정보 표 이름표인데, 새 상품 작성에서는 그 줄의 입력이 사이즈라 무게 칸으로 오해된다.
- 상품 편집 측정 당도(`NumField`, `inputMode="numeric"`)는 소수점을 칠 수 없고 '12.'이 '12'로 바뀌어 12.5가 125가 된다(로컬 재현, 360·390 폭).

### 결정 사항
- 11/15 PM '안내는 짧게'. 잠긴 칸을 누르면 판매페이지 수정을 자동 임시 저장(`saveEditor`)하고 바로 입력(칸은 더 이상 읽기 전용이 아님). 기본 정보 저장(blur)은 그 임시 저장이 끝난 뒤에만 해서 두 저장이 버전을 다투지 않는다. 저장 실패면 칸 아래 '판매페이지를 저장하지 못했어요. ‘임시 저장’을 눌러 주세요'(입력은 남고 다음 저장 때 함께), AI 작업 중(`activeRun`)이면 칸은 그대로 잠그고 'AI 작업이 끝나면 입력할 수 있어요'.
- 11/15 스캔 반영: 자동 임시 저장 중에도 칸은 읽기 전용이 되지 않는다(`autoSaving`, 포커스된 칸이 잠기면 휴대폰 키보드가 내려감). '임시 저장'·'다음'·나가기(`saveAll`)와 대표 사진 바꾸기(`pickCover`, `setRepresentative`도 review 버전을 올림)는 판매페이지 수정을 기본 정보보다 먼저 저장한다(`start()`와 같은 순서). 그래서 판매페이지 저장이 계속 실패하면 기본 정보와 상품 정보(상품명·원산지·보관·옵션)도 저장되지 않고 화면에 남는다(예전에는 이것들이 먼저 저장됐다). 기본 정보를 먼저 저장하면 수정 중인 판매페이지가 옛 버전으로 남아 다시는 저장되지 않기 때문이다. 상품 정보 저장은 기본 정보 값을 읽어서 앞으로 옮기지 않는다. AI 시트 품종명 칸도 같은 규칙이고, 칸 아래 안내는 원인이 사라지면 지운다. 개인정보 확인 중이면 '이전 분석을 취소하면 입력할 수 있어요'.
- 11/15 스캔 반영 2: 기본 정보 저장(blur)이 review 버전을 올려도 판매페이지 편집기를 잠그지 않는다(잠그면 편집기 글 칸의 키보드가 내려간다). 대신 `SourceDetailsEditor`가 저장 안 한 수정을 새 버전으로 옮긴다(rebase). 조건: 생산자가 고친 칸이 서버에서 그대로이고, 초안의 모듈 선택·숨김이 바뀌지 않음. 고치지 않은 칸은 새 서버 값을 쓴다(기본 정보 저장은 specification·qualityEvidence를 다시 만들기 때문, `server/app/source_analysis/editor.py` suggestions). 조건이 안 맞으면 지금처럼 거절한다. 같은 규칙을 편집기 `save()`에도 넣어, '임시 저장'·'다음'·나가기·대표 사진 바꾸기는 진행 중인 기본 정보 저장을 기다리고 최신 review를 넘겨 저장한다(화면이 다시 그려지기 전이라도 새 버전으로). 이 편집기를 쓰는 기존 2탭 작업 화면(`SourceWorkspace`)도 같은 규칙을 따른다. 옮길 때 모듈 켜기는 생산자가 고른 그대로 두고 다시 계산하지 않는다(새로 채워진 모듈이 저절로 켜지지 않음). AI 시트 품종명 칸의 실패 안내는 '‘AI로 채우기’를 누르면 먼저 저장해요'(시트가 열리면 '임시 저장' 버튼이 안 보인다). 자동 저장 실패 안내는 '판매페이지를 저장하지 못했어요. ‘임시 저장’을 눌러 주세요'(이미 포커스된 칸은 다시 눌러도 재시도가 시작되지 않기 때문). 알려진 한계: 편집기가 사진을 올리는 중에는 화면 전체가 busy라 기본 정보 칸도 잠긴다(이전부터 있던 잠금).
- 11/15 스캔 반영 3: 칸 자동 저장 중에는 상품명·원산지·보관 칸도 잠그지 않는다(`fieldsLocked = busy && !(autoSaving && !lock.current)` — 화면 전체 작업이 시작되면 예외를 끈다, 상품 PATCH 값이라 판매페이지 저장과 버전을 다투지 않는다). 'AI로 채우기'(`start`)도 같은 저장 순서(자동 저장 대기 → 기본 정보 저장 대기 → 최신 review·drafts)를 쓴다. 후속: 옮길 수 없는 판매페이지 수정이 남으면 '수정 버리고 최신으로 불러오기' 같은 탈출 경로([DEV-332](https://linear.app/sswp6/issue/DEV-332)). 초안 선택 비교(`draftChoices`)는 초안 목록 전체를 보므로 다른 화면이 저장만 해도 옮기지 않는다(거절 쪽이라 안전).
- 11/15 사이즈 줄 이름표는 새 상품 작성 화면 편집 모드에서만 '사이즈'(`ProductPageBody` `slots.infoLabels`). 구매자 미리보기는 소비자 화면과 같은 '중량·수량'. 소비자 화면 상품정보 이름표 '중량·수량'은 상품정보 제공 항목이라 그대로.
- 11/15 측정 당도 아래 '측정한 값을 Brix 단위로 입력해 주세요.' 삭제(칸 이름에 °Bx가 있음).
- 11/15 원산지 안내를 '예: 제주산, 서귀포시' + '표시 방법 보기 ›'로 줄임. 형식·표시 자리 설명은 원산지 표시제도 안내 화면에 있고, 빈 원산지는 판매 요청에서 계속 막는다.
- 11/15 `NumField`에 `decimal` 모드: `inputMode="decimal"`, 입력 중 글자를 따로 들고 있어 '12.'이 유지되고, 쉼표 소수점도 받는다. 가격·박스·kg 칸(정수)은 그대로.
- 11/15 첨부(사진·자료) 잠금은 그대로 두고 안내만 '판매페이지 수정을 '임시 저장'한 뒤에 첨부한 사진·자료를 바꿀 수 있어요.'로 줄임(대표 사진 바꾸기는 판매페이지를 먼저 저장하고 바로 된다).
