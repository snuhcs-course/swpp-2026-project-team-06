## DEV-481 로그인 상태가 잡히기 전에 누르면 탭 아래 화면이 다시 만들어져 동작이 사라짐

- 이슈: [DEV-481](https://linear.app/sswp6/issue/DEV-481)
- 브랜치: `nemodleo/dev-481-keep-taps-before-session-settles`
- 기능·인수 조건: screens.md 3장 ‘저장된 로그인으로 앱을 열 때’(이번에 더함), FEAT-01(로그인 유지), 원스토어 재심사(DEV-471·DEV-473)
- 상태: 리뷰 중

### 목표
로그인한 채 앱을 다시 열고(웹은 새로고침·주소 열기) 곧바로 누른 동작이 `GET /api/auth/me` 답이 온 뒤에도 남게 한다. 심사자가 앱을 열자마자 눌렀을 때 ‘반응 없음’으로 보이면 안 된다. 계정이 바뀌면 탭 상태를 버린다는 원래 의도는 지킨다.

### 결정 사항
- 11/25 원인 확정. `src/app/(tabs)/_layout.tsx`의 `key={user?.userId ?? "guest"}`(DEV-3, 3cc23328, 커밋에 이유 없음. 생산자 쪽 기록 `apps/producer/spec.md` 115행·`docs/spec/source-integration.md` 71행이 “사용자 전환 시 기존 상태 초기화”로 의도를 적음). 토큰은 동기로 읽히고(웹 localStorage, 앱 SecureStore `getItem`, `packages/api/src/storage*.ts`) 세션은 `user=null`로 시작해 `refresh()`의 `auth.me()` 답 뒤 `setUser`한다(`src/lib/session.tsx` `refresh`). 탭은 그 전에도 그려져 key가 "guest" → 사용자 ID로 바뀌는 순간 Tabs가 통째로 다시 만들어진다. 옵션 시트 상태가 사라지고, 다시 만든 Tabs는 첫 탭(홈)으로 시작한다. 앱(Android)도 같은 코드 경로(스플래시를 잡아 두는 코드 없음, `SplashScreen` 미사용)이고 에뮬레이터에서 재현했다(아래 기록).
- 11/25 생산자 앱은 key는 같지만 `if (!ready) return <ActivityIndicator …/>`(DEV-56, d4efd6db)로 첫 확인이 끝날 때까지 탭을 그리지 않아 이 틈이 없다. `ready`는 그 뒤 다시 false가 되지 않는다. 고치지 않는다.
- 11/25 고친 방법: key를 auth.me 답이 아니라 인증 이벤트(onAuthChange)에서만 바꾼다(`TabsKey`). 토큰이 생기거나 바뀌면 바꾸고, 지워지면 그 토큰으로 사용자를 확인한 적이 있을 때만 바꾼다. 화면 모양·문구 변화 없음.
- 11/25 버린 대안: (1) 생산자처럼 `ready`까지 탭 대신 로딩 표시 — 소비자 앱에 없던 로딩 화면이 첫 실행·로그인 직후(소비자는 auth 이벤트마다 `ready=false`)에 생기고 상품 화면이 늦게 뜬다(새 화면 모양). (2) 저장된 사용자 ID로 key 시작 — 토큰 옆에 사용자 ID를 새로 저장해야 하고, 저장값과 토큰이 어긋나는 경우를 따로 다뤄야 한다. 지금 방법은 저장소를 바꾸지 않는다. (3) 확인 전에는 그리되 누를 수 없게 — ‘반응 없음’으로 보여 비추천(브리프).
- 11/25 바뀐 점(회귀 아님): 같은 토큰의 auth.me가 일시적으로 실패했다 다시 성공할 때 전에는 key가 사용자 → guest → 사용자로 두 번 바뀌어 탭이 다시 만들어졌는데, 이제 그대로다(spec.md DEV-252 “일시적인 auth.me 실패는 UI만 숨긴다”와 맞음). 로그인 때 탭을 다시 만드는 시점이 auth.me 뒤에서 토큰 저장 순간으로 앞당겨졌다(그때 화면은 로그인 화면, 탭 밖).

- 11/25(PR #849 리뷰 반영) 확인된 사용자가 바뀌면 key를 올린다: `confirm(userId)`가 지금 key로 그린 뒤 확인한 사용자와 다른 사용자를 받으면 +1. 웹에서 다른 브라우저 탭이 로그아웃 → 다른 계정 로그인을 하면 이 탭의 토큰이 알림 없이 바뀌고, 알림 없이 도는 `refresh()`(약관·온보딩 관문)가 새 사용자를 확인한다. 전 key(사용자 ID)는 이때 다시 만들었다. 같은 사용자의 첫 확인·재확인은 그대로, 인증 이벤트로 이미 올린 뒤의 첫 확인은 다시 올리지 않는다(확인한 사용자를 인증 이벤트마다 비움). `session.tsx`의 key 시작값은 `TabsKey`에서 가져온다.
- 11/25(리뷰 반영) 계정이 바뀌면 탭 상태를 버리는지 재는 e2e는 두지 않았다. 내 주문 탭 묶음(filter)을 고른 채 로그아웃 → 다른 계정 로그인 → 내 주문 탭에서 묶음이 처음으로 돌아오는지 재는 e2e를 써 봤으나, key를 상수로 바꿔도 통과했다(로그아웃·로그인 흐름이 다른 경로로 이미 탭 첫 화면 상태를 지움, 그 경로는 따로 찾지 않음). key를 재지 못하는 테스트라 지웠다. 기존 `scripts/e2e/checkout-logout.spec.ts`(재로그인이 옛 주문서를 다시 열지 않음)·`scripts/e2e/chat-session-isolation.spec.ts`(401·WRONG_APP 뒤 같은 SPA 재로그인이 깨끗이 시작)가 계정 전환 동작을 재고, key 규칙(로그아웃·계정 전환·알림 없는 사용자 바뀜)은 `scripts/test-tabs-key.mjs`가 잰다. 알림 없는 사용자 바뀜은 e2e로 몰기 어려워(다른 브라우저 탭 + 알림 없는 refresh) 단위 테스트만.
