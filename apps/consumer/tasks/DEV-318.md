## DEV-318 소비자 입금 재알림·주문 상세·문의 복구
- 이슈: [DEV-318](https://linear.app/sswp6/issue/DEV-318)
- 브랜치: `llovablanche/dev-318-consumer-order-recovery`
- 기능·인수 조건: FEAT-09 AC-09-9/10, FEAT-10 AC-10-9, FEAT-33 AC-33-5
- 상태: 진행 중

### 목표
입금 재알림 뒤 지난 미승인으로 입금을 재촉하는 문구, 열린 주문 상세의 오래된 상태, 문의 첫 주문 조회 실패 후 복구 부재를 고친다.

### 범위 (수정 허용 경로)
- `apps/consumer/src/lib/orderText.ts`, `apps/consumer/src/lib/useOrderDetail.ts`
- `apps/consumer/src/app/(tabs)/orders/[orderId]/index.tsx`, `apps/consumer/src/app/(tabs)/orders/[orderId]/inquiry.tsx`
- `apps/consumer/spec.md`, 이 이슈 파일
- `scripts/test-order-text.mjs`, `scripts/e2e/consumer-order-recovery.spec.ts`
- `docs/spec/functional/FEAT-09-mock-payment.md`, `docs/spec/functional/FEAT-10-order-history.md`, `docs/spec/functional/FEAT-33-order-inquiries.md`
- `docs/spec/screens.md`, `docs/wiki/Requirements-and-Specifications.md`

### 비범위 (건드리지 않음)
- 서버·DB·결제 상태 전이·물량·권한 변경. 새 탐색·예약 기능, 기존 DEV-268 제안.
- 운영 데이터 변경·배포·머지.

### 결정 사항
- 11/14 사용자가 세 변경·새 브랜치·커밋·PR·CI 확인을 승인했다.
- 11/14 입금 미승인은 depositReportedAt을 비우므로, 현재 알림 시각이 있으면 현재 차례는 농가다. 과거 depositIssue는 서버에 보존하고 소비자 현재 상태/재촉 안내에서만 제외한다. 서버 필드나 상태 전이는 바꾸지 않는다.
- 11/14 주문 상세는 focus/앱 활성 복귀 및 활성 상태 8초 간격으로 읽는다. blur·계정/주문 변경·쓰기 시작 전 읽기를 무효화하고 쓰기 응답 뒤 오래된 읽기로 되돌리지 않는다. 조회 실패는 기존 값과 명시적 재시도를 제공한다.
- 11/14 문의 조회 실패는 공통 LoadError의 다시 시도를 사용하며 글·사진·유형은 화면에 유지한다. 문의 전송 계약은 유지한다.
- 11/14 화면 변경은 Figma 후속 이슈에 기록한다. 자동·사람 리뷰를 통과했다고 미리 표시하지 않는다.
