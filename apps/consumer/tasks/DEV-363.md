### 결정 사항
- 11/19 세 번째 scan: Playwright serial 재시도는 같은 DB를 재사용하므로 아이디 계정은 생성 때마다 고유한 영숫자 접미사를 붙이고 이후 로그인도 생성 응답의 아이디를 사용한다. 대문자 로그인 검증은 유지한다.
- 11/19 PM: 첫 로그인 약관 동의 화면(기존 SCR-06 재사용)의 '동의하고 시작하기'는 필수 체크 전 꺼진 지금 방식 그대로 둔다(11/18 버튼 규칙의 예외, 체크 상자 화면이라). 처리방침 2026-11-20 시행은 그대로, 공지는 다음 로그인 재동의 화면으로 갈음한다(제14조 30일 사전 공지는 아이디 계정이 운영자 생성 심사·테스트용뿐이라 실질 변경이 적다고 판단).
- 11/18 **PM 결정 변경**: 공개 아이디 가입을 없앴다. 1차로 만든 `/signup`(아이디 가입)·`/approval`(승인 대기·반려) 화면과 로그인의 ‘아이디로 회원가입’을 지웠다. 아이디 계정은 운영자가 관리자 웹에서 만든다.
- 11/18 로그인 화면: 카카오 버튼 아래 ‘또는 아이디로 로그인’ 구분선(카카오가 켜진 경우만) + 아이디·비밀번호 + ‘로그인하기’ + 비밀번호 찾기 안내(‘아이디 계정은 farmclub이 만들어 드려요’ 한 줄 포함). 테스트 계정 목록·하단 바는 그대로 아래. 버튼 이름 ‘로그인하기’는 테스트 계정 바 ‘○○ 로그인’(e2e `/로그인$/`)·관문 시트 ‘로그인’과 겹치지 않게.
- 11/18 첫 로그인: 세션 관문(`accountGatePath`)이 `mustChangePassword`면 `/password`만, 그다음 아이디 계정이 필수 동의 전이면 `/onboarding`만 연다(약관·처리방침은 열림). 온보딩은 기존 SCR-06을 그대로 쓰고, 동의 기록이 하나도 없는 아이디 계정이면 ‘약관에 동의하고 시작해요’·‘동의하고 시작하기’(그 밖에는 기존 ‘약관이 바뀌었어요’ 재동의 문구). 운영자가 휴대폰을 넣지 않았으면 같은 화면이 닉네임·휴대폰도 받는다. 동의 전에는 닫기 = 로그아웃(관문이 다시 이 화면으로 보내므로).
- 11/18 필수 칸 규칙(PM 11/18): 버튼은 늘 켜 둔다. 누르면 오류 칸만 빨간 테두리·문구, 첫 오류 칸으로 스크롤(`packages/ui` `useFieldErrors`·`ErrorScroll`).
- 11/18 비밀번호 변경(`/password`) 한 화면을 강제(임시 비밀번호)·설정 변경에 같이 쓴다. 강제면 뒤로 없음·로그아웃만, 끝나면 홈(동의 전이면 관문이 온보딩으로). 내 정보 ‘비밀번호 변경’은 `user.username`이 있을 때만.
