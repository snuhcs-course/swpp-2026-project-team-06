### 작업
1. Connect the metadata store to consumer farm-chat routes after fresh authorization.
2. Save positions when switching farms and feed validated snapshots back on return.
3. Clear protected view state at every actual session boundary and reject stale async work.

### 완료 조건
- [ ] On entry/focus/recreated route, obtain a fresh authorized head page for the current consumer/farm before applying a snapshot. Resolve the server threadId, discard mismatched metadata, and seed ChatThread using the authorized initialPage contract from DEV-242 step 4.
- [ ] A → private list → B → private list → A restores each farm's own anchor/window. Leaving via header Back or tab navigation captures the active timeline. Preserve the private-list selection and DEV-224 product/info/order back targets; no global tab/navigation redesign.
- [ ] Keep an identity key at least as strong as farmId (and composer context where required). Never fix restoration by removing route/component isolation or leaving every visited screen mounted.
- [ ] The store is cleared synchronously on explicit logout, token loss/401, WRONG_APP token clearing, different user login, and a new authenticated session. Ordinary same-session [auth.me](<http://auth.me>) refresh and screen focus retain positions.
- [ ] An in-flight initial load, older-page load, send refresh, or snapshot callback from an old auth generation cannot set page/ready state, restore an anchor, reinsert a snapshot, or show a previous user's messages.
- [ ] A terminal farm/thread authorization denial clears that conversation's snapshot and protected content. Temporary network/5xx errors retain safe metadata and expose retry without showing unvalidated message data.
- [ ] Selecting another paid order in the same thread preserves the thread's reading-position identity while send context follows DEV-242 rules. Pending photos/drafts cannot be attached to another order by restoration.
- [ ] Tests cover rapid A/B/A switching with responses deliberately returned out of order, same-user logout/relogin, A→B user switch, auth expiry while loading/restoring, wrong-app rejection, and approved-farm access loss. No private message content or image URL appears in persistent browser storage from this feature.
- [ ] Existing general-chat entry, paid-order entry, back navigation, privacy, polling activation, and support/producer callers remain functional.
- [ ] 관련 테스트 실제 실행 및 결과 기록
- [ ] 사람 리뷰, main 머지 및 해당 배포 확인
