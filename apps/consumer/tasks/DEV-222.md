- 브랜치: `nemodleo/dev-222-logout-checkout-nav`
- 기능·인수 조건: FEAT-01 / AC-01-12(관문 뒤 주문서 복귀, 그대로 유지) · screens.md SCR-17 "로그아웃 → 토큰 삭제, SCR-01" · 결정 25(관문 뒤 행동 이어서)

### 목표
주문을 넣은 뒤 로그아웃하면 홈(SCR-01)으로 가고, 다시 로그인해도 지난 주문서가 열리지 않게 한다. 스택에 남은 로그인 필요 화면이 사용자 변화(로그아웃·401)에 반응해 로그인 화면으로 바꾸지 않게 한다.

### 범위 (수정 허용 경로)
- `apps/consumer/src/app/checkout/[productId]/index.tsx`(로그인·온보딩 이동을 포커스일 때만)
- `apps/consumer/src/app/checkout/[productId]/pay.tsx`(완료 화면으로 갈 때 주문서 스택 정리)
- `apps/consumer/src/app/onboarding/index.tsx`(같은 구조의 로그인 이동)
- `apps/consumer/src/app/login.tsx`(관문 행동 `resume`을 로그인 없이 떠나면 지움)
- `apps/consumer/src/app/(tabs)/me/index.tsx`(직접 로그인 버튼은 남은 `resume`을 지움)
- `apps/consumer/src/lib/session.tsx`(로그아웃 뒤 이동, 401 로그인 이동)

- 서버(`server/**`), 화면 모양·문구(디자인 보드·Figma 불필요)

### 결정 사항
- 11/04 원인 확인: 입금 안내 → 완료 화면 `replace`가 입금 안내만 바꿔 주문서가 루트 스택에 남고, 주문서의 `useEffect`가 포커스와 상관없이 `user=null`이면 `/login?next=<주문서>`로 replace한다.
- 11/04 방식: 주문서·온보딩의 로그인 이동을 `useFocusEffect`로 바꾼다(expo-router `<Redirect>`와 같은 규칙: 보이는 화면만 이동). 입금 안내에서 완료 화면으로 갈 때 루트 스택을 첫 화면까지 닫고(`dismissAll`) 완료 화면을 연다.
