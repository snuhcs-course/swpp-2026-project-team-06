### 목표
앱이 입금 기한 지남('입금 확인 늦어짐'·'기한 지남')과 '오늘·어제'를 기기 시계(`Date.now()`)로 판단해, 서버 시각을 고정한(`FIXED_NOW`) 평가·데모 환경에서 방금 만든 주문이 늦은 주문으로 보인다. 서버 시각을 기준으로 판단해 문구가 서버의 기한 판단(R-28)과 맞게 한다. 문구·모양은 바꾸지 않는다.

### 범위 (수정 허용 경로)
- `apps/consumer/src/lib/orderText.ts`(`depositPhase`·`listHeadline`·`depositRefundSentence`의 `now`를 호출부가 넘기게)
- `apps/consumer/src/app/(tabs)/orders/index.tsx`, `apps/consumer/src/app/(tabs)/orders/[orderId]/index.tsx`(호출부에 `serverNow()`)
- `scripts/test-order-text.mjs`, `scripts/test-server-time.mjs`(새 파일)
- `docs/spec/screens.md`(3장 공통 한 줄, 7.1 헤더 한 줄), `docs/wiki/Requirements-and-Specifications.md`(영문 요약 한 줄)

### 비범위
- 문구·화면 모양(디자인 보드 불필요)
- 채팅 시각(`packages/ui/src/Messenger.tsx`)·생산자 현황 머리 날짜처럼 판단이 아닌 표시
- DEV-227 받는 시기 '○월 중순 이후 도착 예상'(`packages/ui/src/format.ts` `deliveryText`): 마지막 예약 종료일에서만 계산하고 지금 시각을 쓰지 않아 해당 없음

### 결정 사항
- 11/05 서버 시각 전달: 모든 응답에 `X-Server-Time`(ISO 8601, `app.core.clock.now()`, `FIXED_NOW` 반영) 헤더를 붙이는 미들웨어를 `server/app/core/server_time.py`에 두고 CORS `expose_headers`에 넣는다. 주문 응답 스키마(`server/app/orders/**`)·`config.py`·`security.py`·`masking.py`를 건드리지 않으므로 **위험 등급: 일반**. 표준 `Date` 헤더는 uvicorn이 실제 시각으로 붙여 `FIXED_NOW`를 반영하지 못하고, 응답마다 필드를 넣으면 스키마가 넓게 바뀌어 고르지 않았다.
- 11/05 앱: `packages/api`가 응답을 받을 때 `X-Server-Time - 받은 시각`을 차이로 보관하고 `serverNow()`(= 기기 시각 + 차이)를 내보낸다. 헤더가 없는 응답(브라우저 Mock·공유 Mock·옛 서버)은 차이를 바꾸지 않는다(처음 값 0 = 기기 시계).
- 11/05 판단 함수는 순수 함수로 두고 `now`를 필수 인자로 바꿔 호출부가 `serverNow()`를 넘긴다(기본값 `Date.now()`가 다시 쓰이지 않게).
