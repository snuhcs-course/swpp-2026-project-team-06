### 목표
The reading position currently exists only in ChatThread refs. It disappears when the route is recreated. Retaining whole screens or sharing a single scroll offset would risk mixing farm conversations. We need explicit, account-scoped reading-position metadata.

### 작업
1. Define a versioned snapshot containing a message anchor and relative viewport offset.
2. Implement a bounded in-memory store partitioned by authenticated consumer session and conversation.
3. Add invalidation and stale-generation tests before connecting screens.

### 완료 조건
- [x] Snapshot v1 records server threadId/farmId, first visible messageId, offset of that message relative to timeline top, near-bottom state, loaded oldest message boundary, adjacent visible message IDs with their relative offsets for fallback, and capture time. It contains no message body, order summary, photo bytes/URLs, draft, auth token, or attachment payload.
- [x] Store identity includes consumer app namespace, consumer userId, a login/session generation, and threadId; farmId may be a pre-validation lookup hint only. A new thread with the same farm cannot inherit an old thread's snapshot.
- [x] Memory only: no localStorage, AsyncStorage, URL parameter, analytics event, or backend persistence. Position restoration is guaranteed for same-session route round trips within the documented cache lifetime; hard reload/new login starts clean.
- [x] Use named defaults of 20 conversation snapshots and 30-minute idle TTL, with deterministic least-recently-used eviction. Tests use an injectable clock. Invalid version, non-finite geometry, negative scroll offsets/heights, mismatched identity, and expired snapshots are safely discarded. Signed relative message offsets are valid: a partly visible anchor can start above the viewport.
- [x] Expose synchronous clear-all, clear-conversation, and advance-generation operations. A callback carrying an old generation cannot write after clear/logout or into a new login, even if it resolves late.
- [x] Pure tests prove A/B farm separation, A/B account separation, same-user new-login separation, thread replacement, eviction/expiry, malformed snapshot rejection, and stale callback suppression. Importing the store has no auth or network side effects.
- [x] Document the metadata contract and retention policy, with session wiring explicitly left to step 3.
- [x] 관련 테스트 실제 실행 및 결과 기록
- [ ] 사람 리뷰, main 머지 및 해당 배포 확인
