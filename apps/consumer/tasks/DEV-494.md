## DEV-494 재동의 대기 계정의 채팅 배지 요청 폭주

- 이슈: [DEV-494](https://linear.app/sswp6/issue/DEV-494)
- 브랜치: `nemodleo/dev-494-fix-consumer-chat-consent-loop`
- 기능·인수 조건: FEAT-01 AC-01-17(약관 버전이 바뀌면 동의만 다시 받음), DEV-363 아이디 계정 관문. 동작·규칙 변경 없음(재동의 화면은 그대로, 뒤에서 도는 요청만 멈춤)
- 상태: 리뷰 중

### 목표
DEV-493 확인 중 소비자 앱에서 재동의가 필요한 계정으로 채팅 탭을 열면 "이 화면을 열지 못했어요"(logcat `Maximum update depth exceeded`)가 나왔다. 원인을 소스로 확정하고 고친다. 화면·문구는 바꾸지 않는다.

### 원인
- 보고한 오류 화면은 시험 데이터 탓이었다. 시드 테스트 소비자(`is_test_account`)에 로컬에서 아이디를 붙여서 `needsOnboarding=false`·`consentRequired=true` 조합이 됐다(`server/app/accounts/service.py` needs_onboarding은 테스트 계정이면 늘 false, consent_required는 아이디가 있으면 계산). 온보딩 화면은 `needsOnboarding`이 false면 바로 원래 화면으로 돌려보내고(`apps/consumer/src/app/onboarding/index.tsx`), 세션 관문은 다시 온보딩으로 보내 무한 렌더가 됐다. 운영에서는 이 조합이 생기지 않는다. 소비자 아이디 계정은 `is_test_account=False`로 만들어지고(`service.py` create_id_account), 테스트 계정에 아이디를 붙이는 경로는 생산자만 된다(`provision_id_credentials`, DEV-439).
- 실제 계정 모양으로 다시 재현한 진짜 문제는 요청 폭주다. 운영자가 만든 소비자 아이디 계정이 재동의 대기면 화면은 재동의(온보딩) 화면으로 맞게 가지만, 뒤에서 초당 약 6~10번 요청이 돈다(로컬 서버 실측: 15초에 채팅 목록 403 91건 + 내 정보 90건, 동의할 때까지 계속).
  - 소비자 탭 레이아웃의 채팅 배지 effect가 `[user]`에 걸려 있다(`apps/consumer/src/app/(tabs)/_layout.tsx`).
  - 배지 요청이 403 ONBOARDING_REQUIRED → `onOnboardingRequired` → 세션 `refresh()`가 내 정보를 다시 읽어 `setUser(u)`(내용이 같아도 새 객체) → effect가 다시 돌아 또 요청 → 또 403.
- 웹도 같은 코드라 같은 고리가 돈다(브라우저에서는 확인 안 함, 소스로만).
- 농가 앱도 배지 effect가 `[user, pathname]`이고 403 CONSENT_REQUIRED 때 같은 refresh를 한다. 재동의 대기(로컬, 시드 생산자 동의 삭제)로 열어 보니 동의 화면으로 가고 폭주는 없었다(15초 403 0건). 같은 모양이라 함께 막는다.

- 11/26 화면·흐름은 그대로 둔다. 재동의 화면은 이미 스펙대로 뜬다(AC-01-17). 고칠 것은 뒤에서 도는 요청뿐이다.
- 11/26 두 겹으로 끊는다.
  - 세션: `setUser((old) => keepUser(old, u))`. 같은 내용이면 같은 객체라 `[user]` effect가 다시 돌지 않는다. 프로필 화면(`me/profile.tsx`)의 `[user]` effect가 403마다 입력칸을 되돌리던 것도 함께 막힌다.
  - 탭 배지: 관문 중(`accountGated`: 비밀번호 변경·온보딩·재동의)에는 읽지 않고, effect 의존값은 `userId`와 켜짐 여부(원시값)만 쓴다. 관문이 끝나면 내 정보가 바뀌어 다시 시작한다.

### 기록
- 11/26 확인 환경: AVD `Pixel_API35_dev494`(Android 35 google_apis), 소비자 v12 APK(`farmclub-consumer-2026-11-25.apk`)와 농가 v9 APK의 번들만 바꾼 시험 APK(로컬 서버 `http://10.0.2.2:8000`·`http://localhost:8000`(adb reverse), cleartext 허용, 무선 업데이트 끔, 임시 키 서명). 로컬 서버 `APP_ENV=local`, 운영자 API로 만든 로컬 소비자 아이디 계정, 재동의 대기는 로컬 DB에서 그 계정의 동의 행을 지워 만들었다.
  - 수정 전(main 번들): 로그인 → 재동의 화면, 15초에 채팅 목록 403 91건·내 정보 90건.
  - 수정 후: 같은 계정·화면, 15초에 403 0건·내 정보 0건. 동의 → 홈 → 채팅 탭 정상.
  - 소비자 채팅 사진(소식방 비공개 답장, 실제 사진 선택기): `POST /api/messaging/attachments` 200 → 메시지 200 → 사진 표시.
  - 농가 채팅 사진(1:1, 실제 선택기 WebP): attachments 200 → 메시지 200 → 사진 표시.
- 11/26 시험 방법 주의: 제출 APK는 무선 업데이트(preview 채널)를 켠 채라, 번들만 바꾼 시험 APK도 두 번째 실행부터 받아 둔 운영 번들로 돌 수 있다. 시험 APK는 매니페스트 `expo.modules.updates.ENABLED`를 false로 바꿔야 한다. 이번에 처음 그걸 몰라 소비자 시험 APK가 운영 번들로 돌았고, 로컬 전용 아이디로 로그인 시도가 운영 서버에 몇 번 가서 401로 실패했다(로그인·업로드된 것은 없음).
