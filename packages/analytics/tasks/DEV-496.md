### 결정 사항
- 11/28: Sentry 대신 이미 들어 있는 PostHog(`posthog-react-native` 4.81.10, `posthog-js`)의 오류 추적을 켠다. Sentry는 네이티브 모듈이라 fingerprint 런타임 버전이 바뀌어 새 APK·원스토어 재심사가 필요하고, 새 의존성·새 처리위탁(수탁자)도 생긴다. PostHog는 이미 처리방침 제6조 수탁자다.
- 11/28: 잡는 범위는 JS 예외(잡히지 않은 예외·처리되지 않은 Promise 거부). 콘솔 오류는 잡지 않는다. 앱을 죽이는 JS 예외는 SDK가 기기 저장소에 남겼다가 다음 실행 때 보낸다(네이티브 플러그인 없이).
- 11/28: 오류 메시지에 개인정보가 섞일 수 있어 `before_send`에서 `$exception` 이벤트의 메시지(`value`)·URL을 지운다: 이메일·전화·계좌처럼 긴 숫자를 가리고, URL 쿼리를 지우고, 200자로 자른다. 오류 종류·코드 위치(파일·함수·줄)는 남긴다.
- 11/28: ANR은 JS 스레드 멈춤으로 잰다(`app_not_responding`, 속성 `blockedMs`). 1초 타이머가 5초 이상 늦게 돌면 한 번 보낸다(Android ANR 기준 5초). 앱이 백그라운드였던 시간은 세지 않는다. 한계: UI(네이티브) 스레드만 멈춘 경우와 OS가 띄운 ANR 대화상자 자체는 잡지 못한다. ANR rate = `app_not_responding`이 한 번 이상 있는 세션 / 전체 세션.
- 11/28: Response time은 코드 없이 기존 출처를 쓴다: 서버 응답 시간은 Railway HTTP 로그, AI 초안은 `draft_created.durationMs`. (Railway HTTP 로그에 요청별 시간이 있는지 확인한다.)
- 11/28: 웹(`posthog-js`)도 같은 규칙으로 `capture_exceptions`를 켠다. 웹은 기존처럼 공식 도메인에서만 켜진다(DEV-125).
