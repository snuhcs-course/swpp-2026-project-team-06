## DEV-122 PostHog 화면 녹화·분석의 국외 이전 근거 정리 (DEV-113 법률 검토)

- 이슈: [DEV-122](https://linear.app/sswp6/issue/DEV-122) · GitHub #249
- 브랜치: `nemodleo/dev-122-posthog-overseas-transfer-notice`
- 기능·규칙: N-05, R-16, policy.md 5장, stack.md TQ-01, AC-01-17(동의 버전)
- 상태: 리뷰 중

### 목표
PostHog(미국)로 보내는 이용 기록·세션 녹화의 국외 이전을 처리방침에 법정 기재 항목대로 적고, 근거를 "정당한 이익"에서 바로잡는다. 코드 동작(PostHog 설정·녹화·identify)은 바꾸지 않는다(안 A, 담당 박현 결정 11/06).

### 범위 (수정 허용 경로)
- `packages/ui/src/legalContent.ts`(처리방침 제1·2·3·5·6·10·14조 문구, 시행일, `LEGAL_VERSION` 주석)
- `packages/ui/spec.md`, `packages/ui/tasks/DEV-122.md`
- `scripts/test-legal.mjs`
- `docs/spec/policy.md`(문서 위치 문단, 5장, 9장), `docs/spec/tech-design/stack.md`(TQ-01, 변경 이력), `docs/wiki/Requirements-and-Specifications.md`

### 비범위 (건드리지 않음)
- `packages/analytics/**`(PostHog 설정·녹화·히트맵·identify·가림 범위), 동의 화면, `server/**`
- `CONSENT_VERSION`(서버·Mock·앱 모두 2026-10-29 그대로), 재동의 설계(DEV-124), 공지 배너
- 처리방침의 사업자 정보·다른 수탁자 줄

### 결정 사항
- 11/06 (사람 결정) 안 A: 녹화·분석 유지, 처리방침 서술만 국내 서비스의 일반적 방식(처리위탁·국외 이전 표 공개)으로 정리.
- 11/06 국외 이전 근거는 개인정보 보호법 제28조의8 ① 3호 가목(계약 체결·이행에 필요한 처리위탁·보관 + 제2항 각 호를 처리방침에 공개). 시행령 제31조 ① 2호가 처리방침에 "국외 이전의 근거와 제28조의8 ② 각 호"를 적게 하므로 다섯 항목(항목 / 국가·시기·방법 / 이전받는 자 명칭·연락처 / 목적·보유 기간 / 거부 방법·절차·효과)을 PostHog 줄과 아래 문단에 모두 채웠다. law.go.kr 현행본(법률 제21445호, 대통령령 제36671호, 2026.9.11 시행)을 11/06에 다시 읽음.
- 11/06 수집 근거(제2조 표)는 정당한 이익(제15조 ① 6호)을 빼고 계약 이행(4호)으로 적는다. 국외 이전을 3호(계약 이행을 위한 위탁)로 설명하면서 수집은 6호로 적으면 앞뒤가 맞지 않는다. 6호는 "명백하게 정보주체의 권리보다 우선"해야 해 세션 녹화에는 기준이 높다(검토 문서 #249). 3호·4호로 볼 수 있는지 자체는 변호사 확인 항목(SWPP-124).
- 11/06 이전 항목은 코드에서 확인한 것만 적었다: `packages/analytics/src/client.ts`(posthog-js 기본 기기·브라우저 속성, `$pageview`·`$pageleave`, autocapture·히트맵은 `mask_all_text`·`mask_all_element_attributes`로 위치·요소 종류만, 세션 녹화는 `maskAllInputs` + `maskTextFn`, 네트워크·콘솔 녹화 끔, URL 쿼리는 `before_send`에서 지움, identify는 `userId`와 `app`·`role`·`isTestAccount`), `privacy.ts`(트래킹 플랜 이벤트 4개와 허용 속성, `PRIVATE_PATHS`, 운영 도메인만 `PRODUCTION_HOSTS`). 접속 IP는 전송 자체로 PostHog에 가므로 넣었다(저장 여부는 PostHog 프로젝트 설정, 사람 확인). 서버 PostHog 이벤트는 아직 없음(`server/app/analytics/spec.md`).
- 11/06 연락처 `privacy@posthog.com`은 PostHog 공식 개인정보 처리방침(https://posthog.com/privacy)에서 확인.
- 11/06 보유 기간: ADR 0005·stack.md가 PostHog Cloud 무료 요금제라고 적고 있어, PostHog 공식 문서의 무료 요금제 값(이벤트 1년, 세션 녹화 최대 30일, 사람 정보는 지울 때까지)을 적었다(https://posthog.com/docs/data/events-retention, https://posthog.com/docs/session-replay/recording-retention, 11/06 확인). 실제 요금제·녹화 보관 설정은 사람 확인.
- 11/06 거부 방법: 서비스 안에 PostHog만 끄는 설정은 없다(`opt_out_capturing`·동의 분기 없음, `respect_dnt` 안 씀). 사실만 적었다: 추적 차단 확장 프로그램 등으로 `us.i.posthog.com` 전송을 막을 수 있고(운영 변수 `APP_POSTHOG_HOST`가 없어 기본 호스트), 막아도 서비스는 그대로 쓴다(`posthog-js` 전송 실패는 앱 동작에 영향 없음). 쿠키·저장소 차단만으로는 전송이 멈추지 않을 수 있다고 제10조에 적었다(posthog-js는 저장소를 못 쓰면 메모리로 이어 감).
- 11/06 **동의 버전(`CONSENT_VERSION`·`LEGAL_VERSION`)은 올리지 않는다.** 이번 변경은 동의를 받아 처리하는 항목이 아니라 계약 이행·처리방침 공개로 처리하는 항목의 근거·고지 문구 정리이고, 수집 항목(제2조)도 바뀌지 않는다. 법상 재동의는 동의 근거 항목의 목적·항목·기간이 바뀔 때(제15조 ② 후단)나 동의로 국외 이전하는 사항이 바뀔 때(제28조의8 ③)만 필요하다. 버전을 올리면 생산자 앱 전체가 재동의 전까지 막혀 진행 중 주문이 멈춘다(검토 문서 #251 권고 "문구만 바뀌는 변경은 버전을 올리지 않기").
- 11/06 그래서 `test-legal.mjs`의 "처리방침 시행일 = 동의 버전" 단언을 "버전 날짜가 변경 기록에 있고 시행일보다 늦지 않으며, 시행일이 더 늦으면 마지막 변경 기록이 재동의하지 않는다고 적는다"로 바꿨다. 서버·Mock·앱 버전이 같은지는 그대로 본다. 버전을 실수로 안 올리는 경우를 막는 힘은 줄지 않게, 시행일만 늦추려면 변경 기록에 이유를 적어야 통과하도록 했다.
- 11/06 시행일 2026-11-13: 처리방침 제14조가 "시행 7일 전부터 서비스 화면에 알림, 수집 항목·이용 목적·제3자 제공 같은 중요한 변경은 30일 전"을 약속한다. 이번은 수집 항목·목적·제공처가 바뀌지 않는 고지 정리라 7일로 봤다(사람 확인). 지금 코드에는 시행일 전 공지 배너가 없어 고지 방법은 사람 확인. 머지가 늦어지면 시행일을 머지일+7일로 옮긴다.

### 발견(범위 밖, 기록만)
- 세션 녹화 가림: 채팅(`ChatThread`)·소식방(`NewsRoom`)은 컴포넌트가 `data-ph-private`를 붙이고, 생산자 `/support`도 `ChatThread`라 가려진다. 글자가 아닌 **사진**(채팅·주문 문의 첨부, 상품 자료)은 `maskTextFn` 대상이 아니라 rrweb이 이미지 주소를 그대로 기록한다. 비공개 사진 주소가 서명 URL이면 만료 뒤엔 재생되지 않지만, 만료 전 재생·주소 노출 여부는 확인 필요(`blockSelector` 등은 이번 범위 밖).
- 네이티브(`client.native.ts`)는 허용 호스트 검사 없이 키만 있으면 이벤트·identify를 보낸다(녹화 없음). 앱 출시 전이라 처리방침은 웹만 적었다. 출시 때 제6조·제10조에 앱을 더한다.
