### 목표
On every new ChatThread mount near.current starts true. Initial content-size changes call scrollToEnd, while previous() only preserves in-place prepends. Saving scrollTop alone cannot restore a message outside the newest page or survive a delayed photo layout.

### 작업
1. Add optional snapshot input/output to ChatThread while keeping existing callers compatible.

### 완료 조건
- [ ] Optional view-state props consume the versioned metadata contract and report fresh snapshots. Use an authorized initialPage from the consumer route; callers without view-state props keep the existing default behavior.
- [ ] Capture the first visible message's actual layout position plus its relative viewport offset on scroll and on deactivation/unmount. Capture the latest refs, not values closed over at mount. Preserve the saved oldest-loaded boundary as well as the anchor.
- [ ] A history restore initializes near-bottom=false and suppresses initial scrollToEnd and automatic latest-message read updates until fresh data and anchor positioning complete. A bottom-pinned snapshot instead restores the latest edge and follows new messages as before.
- [ ] Starting from the newest authorized page, follow older cursors until the anchor and saved oldest-loaded boundary are found or history is exhausted. Preserve all pages already fetched, de-duplicate by ID, and use mergeChatMessages saved sequence ordering. Detect repeated/non-progressing cursors and allow retry of transient failures.
- [ ] For a found anchor, after layout scroll to messageTop minus savedRelativeOffset, clamped to valid scroll bounds. For the same viewport and content, the final anchor drift is at most 8 CSS px. Restore as layouts become measurable; do not rely on a fixed sleep.
- [ ] Late image decoding, text reflow, and prepended pages maintain the restored anchor while the user is reading history. Stop automatic anchor correction when the user intentionally scrolls or chooses latest; do not fight touch/wheel gestures.
- [ ] Incoming polling messages do not force a historical reader to the bottom or prematurely clear unread state. The existing new-message control still moves to latest and resumes normal read/bottom behavior.
- [ ] If the anchor was legitimately removed, use the nearest surviving saved visible ID and its captured offset, then a documented clamped geometry fallback. If history is unavailable or permission is denied, fail visibly, invalidate as appropriate, and do not silently show a different conversation.
- [ ] Deactivation/unmount cancels restore/pagination work and timers. Late results cannot update the next conversation or emit snapshots for an old identity.
- [ ] Geometry/state tests and targeted component/browser tests cover history/bottom modes, multi-page anchors, delayed photos, prepend, newly arriving messages, user interruption, empty history, missing anchor, failed load/retry, cursor non-progress, and no-read-before-restore.
- [ ] 관련 테스트 실제 실행 및 결과 기록
- [ ] 사람 리뷰, main 머지 및 해당 배포 확인
