## DEV-205 Android 앱에서 키보드가 입력칸을 완전히 가림 (채팅·주문서 메모)

### 목표
Galaxy(Android 16) APK에서 채팅 입력창·주문서 배송 메모·생산자 입력칸이 키보드 뒤로 가려지고(A1), 키보드가 없을 때도 채팅 입력창이 하단 내비 바에 절반 가려진다(A2). 근거: `docs/evaluation/he-2026-11-04/he-claude-phone-2026-11-03.md` A1·A2.

- `apps/consumer/src/app/_layout.tsx`, `apps/producer/src/app/_layout.tsx`, 각 앱 `tasks/DEV-205.md`

### 비범위 (건드리지 않음)
- 웹 동작(웹은 정상). `app.json`·`eas.json`·네이티브 의존성. `Sheet`(Modal) 안 입력. 생산자 도움말 투어(DEV-206)

### 결정 사항
- 11/05 app.json `android.softwareKeyboardLayoutMode`가 아니라 JS(`KeyboardAvoidingView`)로 푼다. Expo SDK 57 기본값이 이미 `resize`인데도 가려진다: Android 15+ edge-to-edge에서는 adjustResize가 창을 줄이지 않는다. `pan`은 네이티브 설정이라 새 빌드가 필요하고 화면 전체가 밀려 헤더가 사라진다. JS 안은 `eas update`만으로 반영된다.
- 11/05 두 앱 루트(Stack 바깥)에 `KeyboardRoot`를 둔다. Android만 `KeyboardAvoidingView behavior="padding"`, 웹·iOS는 감싸는 View 없이 children 그대로(웹 DOM 불변). 화면마다 넣지 않아 생산자 입력 화면 전체에 한 번에 적용된다. iOS는 배포하지 않아 확인할 수 없어 켜지 않는다.
- 11/05 루트가 키보드만큼 올라가면 화면 아래 고정 바(`TabBar`·`BottomBar`, absolute)가 키보드 바로 위에 떠서 입력칸을 가린다(에뮬레이터에서 주문서 '예약하기' 바가 배송 메모를 덮음). Android에서 키보드가 떠 있는 동안 두 바를 숨긴다(`useKeyboardShown`, 웹은 늘 false).
- 11/05 채팅 입력창 아래 여백: 앱은 `safe("bottom", 20)`(시작 때 잰 하단 인셋 + 20), 키보드가 떠 있으면 20(키보드가 내비 바를 덮음). 웹은 지금 값 20 그대로 — `safe`를 웹에도 쓰면 iOS Safari에서 env(safe-area-inset-bottom)이 더해져 웹이 바뀐다.
