### 결정 사항
- 11/04 스펙 확인: FEAT-07은 실측/예상까지만, 둘 다 없을 때는 침묵. M-11(지어내지 않음)·M-15(둘 다 없으면 농가에 전달)를 근거로 셋째 상태 문구를 제안. SCR-01 ‘n명 예약’, SCR-04 배송비도 빈 값 침묵 → 버그로 처리.
- 11/04 제안(보드): 무브 6개 — ① 라벨+값 한 덩어리(빈 조각째 뺌, `joinMeta`) ② 당도 세 상태(‘당도 등록 전’) ③ 0명은 수를 말하지 않음 ④ `availability` → 이름 표 하나(‘현재 예약 불가’·‘현재 기간 품절’ 없앰) ⑤ 시각은 `format.ts` `time()` 하나 ⑥ 미리보기는 빈 값을 오늘로 채우지 않음(DEV-184 점선 칸).
- 11/04 카드 `Price`의 ‘현재 예약 불가’를 상태 이름으로 바꾸는 것은 DEV-215 승인안(판매 품목 ‘현재 예약 불가’)을 바꾸는 것이라 PM 재확인(보드 Q3).
- 11/04 앱·공용 UI만 바뀌고 서버·고위험 경로 없음 → 위험 등급 일반.
- 11/04 PM 결정: Q1 A ‘당도 등록 전’ 줄 · Q2 0명은 수 빼고 ‘마감 D-9’, 메타 줄이 비면 자리도 안 남김 · Q3 카드 ‘현재 예약 불가’를 상태 이름 표로(DEV-215 문구 교체 승인) · Q4 생산자 목록 ‘예약 시작 전’ · Q5 Brix 띄어쓰기 그대로 · Q6 Figma 후속.
- 11/04 PM 무브 6 수정: 빈 받는 시기·배송비를 점선 칸으로 두지 말고 확정 전에는 데이터에서 유도한 ‘예상’ 근사값. 확인한 필드: 상품 `delivery_start/end`·`max_delay_until`(nullable, 게시 필수 AC-04-1), `shipping_fee`(int not null, 기본 0, 별도면 금액 필수 FEAT-04), 예상 수확 시기·농가 출하 리드타임·구조화된 농가 기본 배송비는 **없음**(`farms.reservation_shipping_policy`는 AI용 자유 글). 그래서 받는 시기 근사값은 마지막 예약 기간 끝날의 월·순 + ‘이후 도착 예상’(FEAT-05 “마지막 예약 종료일 < 배송 시작일”이 보장하는 범위만), 예약 기간도 없으면 ‘받는 시기 확정 전’, 배송비는 유도할 값이 없어 ‘배송비 확정 전’. 새 규칙 M-24·AC-07-7로 적음.
- 11/04 스펙 확인: 공개 상품은 받는 시기·배송비 금액이 게시 필수이고 R-03이 결제 전 확정 기간 고지를 요구해, ‘예상’ 상태는 실제로는 생산자 미리보기에서만 보인다. 그래서 주문서(`checkout/[productId]`)는 바꾸지 않았다(확정 기간 문장 그대로). 카드·상세·미리보기는 같은 `deliveryText()`를 쓴다.
- 11/04 `productGroups.ts`는 Mock 테스트가 node로 바로 읽어 `@farmclub/ui`를 import하지 않고 같은 글자를 두되, `test-empty-values.mjs`가 `AVAILABILITY_LABEL`과 같은지 확인한다. 도우미는 node로 바로 읽히도록 새 파일 대신 `format.ts`(import 없음)에 둔다.
- 11/04 예약 가능 상품의 옵션 하나만 다 팔리면 가격 자리 ‘이번 기간 품절’(`unavailableLabel("AVAILABLE")`).
