### 결정 사항
- 11/24 expo-router 57.0.25 코드 확인(`node_modules/expo-router/build/useScreens.js` `fromImport`·`BaseRoute`, `views/Try.js`, `layouts/withLayoutContext.js`). 독립 리뷰(PR #843)에서도 맞다고 확인:
  - 라우트 파일의 `export function ErrorBoundary`는 그 파일의 기본 컴포넌트를 `Try`로 감싼다. 탭 폴더 `_layout`에 두면 그 탭의 Stack 전체가 갈려 탭 바는 남지만, Stack이 내려가면서 하위 상태가 지워져(`useNavigationBuilder` 언마운트 정리) ‘다시 시도’가 죽은 하위 화면이 아니라 탭 첫 화면을 그릴 수 있다.
  - 레이아웃 prop `unstable_screenErrorBoundary`(Stack·Tabs 공통, `withLayoutContext`)는 React 컨텍스트로 내려가, 그 레이아웃 아래 **화면 하나하나**(`type === "route"`, 레이아웃은 아님)를 장면 안에서 `Try`로 감싼다. 스택·탭 바가 그대로고 ‘다시 시도’는 그 화면만 다시 그린다. 앱(네이티브 스택)과 웹이 같은 코드다. 이름에 unstable이 붙어 있어 expo-router를 올릴 때 e2e와 `scripts/test-screen-error.mjs`의 배치 검사로 확인한다.
- 11/24(리뷰 반영) 경계 배치: 두 앱 루트 `_layout`(루트 Stack prop `StackScreenBoundary` + 마지막 그물 `export ErrorBoundary`=`RootBoundary`), `(tabs)/_layout`의 Tabs prop `TabScreenBoundary`, 탭 폴더 Stack 9곳 prop `TabScreenBoundary`. 파일 수는 두 앱 합쳐 13개(보드와 같은 수). 처음엔 레이아웃 없는 탭 화면 3곳(소비자 홈, 생산자 현황·설정)에 `export ErrorBoundary`를 뒀으나, 루트 Stack 컨텍스트가 탭까지 내려와 앞으로 `(tabs)` 바로 아래 화면을 더하며 export를 빠뜨리면 탭 바 밑에 깔리는 `StackScreenBoundary`가 받는 함정이 있어 Tabs prop 하나로 바꿨다. 탭 폴더 Stack의 prop은 Tabs 것과 같지만 그대로 둔다(폴더를 따로 옮겨도 경계가 남게).
- 11/24 받는 범위(한계): 화면을 그리는 중(render)과 effect 안에서 바로 던진 예외만 받는다. 이벤트 핸들러(onPress 등)와 then·setTimeout 같은 비동기 콜백, 레이아웃 밖 Provider 초기화 예외는 어떤 React 경계도 받지 못한다(앱은 그대로 빈 화면·종료). 알려진 사례:

  | 사례 | 어디서 던지나 | 이 경계가 받나 | 확인 |
  | --- | --- | --- | --- |
  | DEV-471 상품 편집(`NewProductComposer`의 `window.addEventListener("beforeunload")`, 앱에 없음 → TypeError) | effect 안 동기 | 받음(상품 탭 Stack) | 에뮬레이터: 빈 화면 → 안내·탭 바, logcat `isComponentError: true` |
  | DEV-471 `DateInput`(`apps/producer/src/lib/fields.tsx`의 `<input type="date">`, 앱에 없는 요소) | 그리기 | 받음 | 코드 확인(이 경로는 에뮬레이터에서 따로 안 엶) |
  | DEV-474 우편번호 찾기(`apps/consumer/src/lib/postcodeSearch.ts` `openPostcodeSearch`의 `document.activeElement`, 앱 번들에 웹 구현이 잡힘) | 버튼 `onPress` → `postcode.open()` 안 동기(이벤트 핸들러) | 못 받음 | 에뮬레이터: 여전히 빈 화면, logcat `ReferenceError: Property 'document' doesn't exist`(컴포넌트 오류 표시 없음). DEV-474 수정이 따로 필요 |
- 11/24 ‘홈으로’는 죽은 화면이 든 스택을 첫 화면 하나로 되돌린 뒤 홈으로 바꿔 간다(`router.replace`). 웹은 주소 기록 때문에 순서가 중요하다: expo-router `useLinking`은 상태 변화마다 그때의 전체 상태를 읽어 기록을 고치므로, 되돌리기와 홈 이동이 한 번에 읽히면 ‘탭 바꿈 = push’로만 보여 죽은 화면 기록이 남는다(e2e로 재현). 그래서 되돌리기 뒤 주소가 바뀐 것(죽은 화면 기록이 탭 첫 화면 주소로 바뀜)을 본 다음 홈으로 간다(최대 1초). 처음 쓴 `setTimeout(0)`과 컨테이너 `state` 이벤트 방식은 타이밍 가정이거나(전자) 같은 문제를 다시 냈다(후자, e2e에서 실패). 앱은 주소 기록이 없어 바로 간다. `resetRoot`는 루트 내비게이터 이름이 앱의 `(tabs)`와 달라 아무 일도 하지 않아 버렸다. 죽은 화면이 홈 자신이면 ‘다시 시도’와 같다.
- 11/24 부품: `ScreenError({error, retry, home, support, aboveTabs})`. `aboveTabs`(탭 바 위로 버튼 올리기)를 더했고, 리뷰 반영으로 테스트용 `dev` prop은 뺐다(개발 한 줄은 그릴 때 전역 `__DEV__`를 읽음). `support`가 없으면 링크를 숨긴다.
- 11/24(리뷰 반영) 링크 숨김: 죽은 화면이 운영팀 방 자신(소비자 `/chats/support`, 생산자 `/chats/u-farmclub`·`/support`)이면 같은 방을 또 열어 다시 죽으므로 숨긴다. 생산자는 관문 규칙(`homeFor(user).allowed`)으로 그 방이 열리는 상태에서만 보인다: 로그인 전·가입 신청·심사 중·비밀번호 변경(`mustChangePassword`)·약관 동의 대기(`consentRequired`)면 눌러도 곧바로 되돌려지므로 숨긴다.
- 11/24(리뷰 반영) 접근성: 안내 묶음에 `accessibilityRole="alert"`(웹 role=alert)와 live region, 앱은 처음 그릴 때 `announceForAccessibility`로 제목을 읽힌다. 본문은 ScrollView 안이라 작은 화면·큰 글자에서도 하단 버튼과 겹치지 않는다.
- 11/24 개발 한 줄: `__DEV__`에서만 제목 아래 `error.message` 첫 줄(120자). 오류 이름·스택은 어디서도 그리지 않는다. 잡힌 오류는 React가 그대로 기록한다(웹 `console.error`, 앱 logcat `ReactNativeJS`).
- 11/24 파일 이름: `screenError.ts`는 macOS(대소문자 무시)에서 `ScreenError.tsx`와 겹쳐 `screenErrorText.ts`로 했다(DEV-348 `stairSteps.ts`와 같은 이유).
- 11/24 없는 주소: `+not-found` 파일이 없어 expo-router 기본 화면(영문 ‘Unmatched Route / Page could not be found’, 개발 빌드는 Sitemap 링크)이 보인다(웹 Mock에서 두 앱 확인). 오류가 아니라 이 경계와 무관하고, 한국어 화면은 후속으로 남긴다.
