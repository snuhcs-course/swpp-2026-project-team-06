## DEV-341 Make producer photo add and load fast with display-size previews instead of full PNG (api package)

- 이슈: [DEV-341](https://linear.app/sswp6/issue/DEV-341) · 주 기록 `server/tasks/DEV-341.md` · 앱 결정 `apps/producer/tasks/DEV-341.md`
- 브랜치: `jangjinuite/dev-341-light-photos`
- 상태: 구현·로컬 검증 끝, 커밋 전

### 범위 (수정 허용 경로)
- `src/privatePhoto.ts`(새 파일), `src/sourceAnalysis.ts`(`sourcePageImage`), `src/productWorkspace.ts`(`photo`)

### 결정 사항
- 11/17 `privatePhotoBlob(url)`: 로그인 토큰 + 주소 기준으로 Blob 약속을 공유(최대 60개), 실패는 기억하지 않음, 진행이 30초 동안 멈추면 끊는다(idle 시간 제한: 응답을 조각으로 읽고 조각마다 시계를 다시 맞춤, 느려도 계속 받는 큰 사진은 끝까지 받음). 조각 읽기를 못 하는 환경(React Native fetch)은 전체 120초 제한(`PhotoTimeoutError`). 처음에는 다운로드 전체에 30초를 걸었는데, DEV-328 이전에 올라가 아직 원본 크기 PNG(16~30MB)인 작업 사진이 8Mbps보다 느린 연결에서 매번 실패하게 되어 3차 스캔 뒤 바꿈. 원래 `sourcePageImage`처럼 실패는 `ApiError`.
- 11/17 `sourcePageImage(bid, sid, page, { variant, source })`: `variant=display|thumb&v=<revision>.<sanitizationVersion>`. 미리보기 인자는 필수이고 원본 PNG를 받는 길은 없앴다(사전 스캔 반영, 아래 충돌 정책).
- 11/17 `productWorkspace.photo`도 같은 경로(사진 id 하나는 저장본 하나).

### 머지 순서·충돌 정책 (DEV-346과)
- DEV-346(`farmclub-page-editor`, 진행 중)이 `apps/producer/src/lib/sourcePhoto.ts`를 새로 만들어 `sourcePageImage(batch.id, source.id, 1)`을 부르고, `NewProductComposer`·`SourceAttachments`·`SourceDetailsEditor`의 사진 받는 줄과 worker cleanup 반복문을 같이 고친다.
- 순서: **DEV-341을 먼저 머지**하고, DEV-346이 main을 받아(rebase/merge) `sourcePhotoUrl`(또는 그 자리)에서 `sourcePageImage(..., { variant: "display" | "thumb", source })`로 미리보기 인자를 넘긴다. 대표사진·편집기는 `display`, 첨부 칸은 `thumb`.
- `sourcePageImage`의 미리보기 인자는 **필수**다(원본 PNG를 화면에서 받는 길 없음). 충돌을 DEV-346 쪽으로 풀어 인자를 빠뜨리면 `npm run typecheck`가 실패하므로, 16~30MB PNG로 조용히 돌아가지 않는다. 충돌 때는 인자를 지우지 말고 넘긴다.
- worker cleanup: 두 쪽 변경을 합칠 때 `variant_keys(key)`로 미리보기 키를 지우는 줄과 `used`에 미리보기 키를 넣는 줄을 남긴다(빠지면 미리보기가 매일 지워졌다 다시 만들어지고, 지운 자료의 미리보기는 고아 정리 때까지 남음).
- 반대로 DEV-346이 먼저 머지되면, DEV-341이 main을 받으면서 `sourcePhoto.ts`의 호출에 미리보기 인자를 넣는다(같은 규칙).
