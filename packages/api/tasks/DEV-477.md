### 목표
앱에서 생산자 비공개 사진(자료 썸네일·작업 사진)이 받아지게 한다. 전체 기록은 `apps/producer/tasks/DEV-477.md`.

### 범위 (수정 허용 경로)
- `packages/api/src/privatePhoto.ts`, `packages/api/src/productWorkspace.ts`(404 상태 유지, 11/24 리뷰 반영), `scripts/test-private-photo.mjs`, `scripts/test-producer-source-thumb.mjs`

### 결정 사항
- 11/24 `privatePhotoBlob`은 응답을 조각으로 읽어 `new Blob(chunks)`로 합쳤다. Expo 57 앱은 전역 `fetch`가 expo/fetch라 `res.body.getReader()`가 있고, React Native의 Blob은 ArrayBuffer·Uint8Array로 만들 수 없어 여기서 늘 예외가 났다. `new Blob([new Uint8Array(0)])`가 되는지 한 번 재서, 안 되면 조각 읽기 없이 `res.blob()`으로 받는다(전체 시간 제한 120초만, 기존 '조각 읽기를 못 하는 환경' 길). 웹·Node는 그대로.

- 11/24 리뷰 반영: 앱의 `res.blob()` 길에서 시간 제한이 받기를 실제로 끊는지 확인했다. 코드(expo 57 `winter/fetch/fetch.ts`): `fetch`에 넘긴 `signal`의 abort 리스너는 응답 본문을 다 받을 때까지 남아 있고, abort되면 `response.abort()`와 `request.cancel()`(네이티브 요청 취소)을 부른다. 에뮬레이터(임시 번들, 커밋 안 함, 2.2MB 파일): 받는 중 20ms에 abort하면 `res.blob()`은 거부되지 않고 그때까지 받은 933,888바이트로 끝났다(전송은 끊김). `privatePhotoBlob(…, 30000, 40)`은 298ms에 `PhotoTimeoutError`로 끝났다(`Promise.race`가 시간 제한을 먼저 내고, 잘린 본문은 쓰지 않음). 같은 파일을 제한 없이 받으면 2,233,045바이트 전부. 결론: 시간 제한은 네이티브 전송을 끊고, 잘린 본문이 결과로 쓰이지 않는다. 고칠 것 없음. 근거 `shots/dev-477/logcat-abort.txt`.
- 11/24 리뷰 반영: `productWorkspace.photo`가 오류를 감쌀 때 `ApiError` 상태를 남긴다(문구 '사진을 불러오지 못했어요.'는 그대로).
