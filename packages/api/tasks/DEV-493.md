## DEV-493 앱 사진 업로드 실패 (원스토어 2차 반려)

- 이슈: [DEV-493](https://linear.app/sswp6/issue/DEV-493)
- 브랜치: `nemodleo/dev-493-fix-native-photo-upload`
- 기능·인수 조건: FEAT-03 새 상품(대표 사진·자료 첨부), FEAT-04 상품 수정(SCR-24 composer 대표 사진·사진 추가), 농가 프로필 사진·소식 사진/영상, 대화 사진 첨부. 동작·규칙 변경 없음(앱에서 업로드가 되게 한다)
- 상태: 리뷰 중

### 목표
원스토어가 농가 Android 앱(versionCode 8, 2026-11-25 APK)을 다시 반려했다: 새 상품·상품 수정에서 대표 사진을 고르면 "사진을 변경하지 못했어요. 기존 사진은 유지돼요. 다시 선택해 주세요."와 영어 `Unsupported FormDataPart implementation`이 뜨고 상품 등록이 안 된다. 두 앱의 모든 파일 업로드가 앱에서 실제로 전송되게 하고, 영어 내부 문구가 화면에 나오지 않게 하고, 같은 실수를 검사로 막는다.

### 원인
- Expo SDK 57.0.27은 앱 시작 때 전역 `fetch`를 expo/fetch로 바꾼다(`node_modules/expo/src/winter/runtime.native.ts:41-53`, `EXPO_PUBLIC_USE_RN_FETCH`가 없으면).
- expo/fetch는 본문 FormData를 JS에서 multipart로 만든다. 파트는 문자열·Blob·`bytes()`가 있는 객체만 받고, RN 방식 `{uri, name, type}`이면 `throw new Error('Unsupported FormDataPart implementation')`(`node_modules/expo/src/winter/fetch/convertFormData.ts:69-78`).
- 업로드 네 곳이 `appendFile`(`{uri,name,type}`)로 만든 FormData를 전역 fetch로 보냈다: `client.ts` `uploadMedia`·`uploadAttachment`, `sourceAnalysis.ts` `uploadSource`, `productWorkspace.ts` `uploadPhoto`(호출처 없는 죽은 코드).
- 오류 문구는 composer가 `sourceActionError`에서 "Error의 message는 한국어 화면 검사"라고 보고 그대로 띄웠다(`apps/producer/src/lib/sourceFeedback.ts`).
- 지난 확인(DEV-471 등)은 에뮬레이터 Mock 모드였다. Mock은 업로드 요청을 보내지 않고(`uploadSource`는 바로 throw, `new.tsx`는 수동 입력으로 보냄) 네트워크도 꺼서 "파일을 읽지 못했어요"를 연결 문제로 봤다.
- 업로드가 되는 순간 드러나는 두 번째 원인: expo-image-picker는 quality < 1이면 사진을 다시 압축한다. Android는 출력 확장자가 .png일 때만 PNG이고 그 밖은 JPEG 바이트인데(`expo-image-picker/android/.../MediaHandler.kt` handleImage, `ImagePickerUtils.kt` toBitmapCompressFormat), `mimeType`·`fileName`은 원본(image/heic, IMG.heic)이다. 서버 공개 사진(`/api/media`, 대화 첨부)은 선언 형식과 내용이 다르면 400 "JPEG·PNG·WebP 사진을 골라 주세요"(`server/app/core/images.py` sanitize). 자료(`uploadSource`)는 서버가 내용으로 판단해(`preprocess.identify`) 상관없다. 로컬 서버에 curl로 확인: JPEG 바이트를 image/heic·image/webp로 보내면 400, image/jpeg면 201.

### 결정 사항
- 11/26 업로드만 RN `XMLHttpRequest`로 보낸다(`formPost.native.ts`). 이유: RN 네트워킹이 `{uri}` 파트를 파일에서 바로 스트리밍한다(`react-native/Libraries/Network/FormData.js` getParts, `convertRequestBody.js`). 이미 APK에 있는 RN 코어라 네이티브 변경이 없고 fingerprint가 그대로다.
  - 버린 안 1: `EXPO_PUBLIC_USE_RN_FETCH=1`로 전역 fetch를 RN 것으로 되돌리기. 모든 요청이 바뀌고 EAS 환경 변수에 기대야 한다.
  - 버린 안 2: expo-file-system `File`(APK에 있음)을 파트로 넣기. expo/fetch가 `bytes()`로 파일 전체를 JS 메모리에 올리고 한 번 더 이어 붙여(`convertFormData.ts` joinUint8Arrays) 100MB 영상에서 위험하다.
- 11/26 `appendFile`은 앱 파일을 `{uri, name, type}` 세 칸만 붙인다. 고를 때 붙은 `size`는 RN 네이티브가 읽지 않아 해는 없었지만(getParts가 `{...value}`로 넘김, Android NetworkingModule은 `string`·`uri`만 봄) 섞어 보내지 않는다. expo/fetch에서는 여분 칸과 상관없이 `uri` 파트라 실패했다.
- 11/26 앱 전송 실패는 `ApiError(0, "인터넷 연결을 확인하고 다시 시도해 주세요.")`. `request()`가 이미 쓰는 문구라 새 문구가 아니다. 원인은 `cause`와 `console.warn("[upload] <경로> 전송 실패")`(호스트·토큰 없음)에 남는다.
- 11/26 `sourceActionError`: 한글이 없는 Error message(라이브러리·런타임 영어 문구)는 "처리하지 못했어요. 다시 시도해 주세요."(기존 기본 문구)로 바꾸고 원문은 경고 로그에. `SourceAttachments`의 `String(e)`("Error: …" 접두어까지 보이던 곳)도 같은 판단을 쓴다.
- 11/26 사진 형식·이름은 `pickedImage`(upload.ts) 하나로 정한다: uri가 .png면 image/png, 그 밖은 image/jpeg, 이름은 원본 이름에 확장자만 맞춤. 세 picker(`pick.native.ts`, `sourceFiles.native.ts`, `pickPhoto.native.ts`)가 같은 `PICK_QUALITY`(0.8)를 쓴다. 영상은 다시 만들지 않으므로 원본 형식 그대로.
- 11/26 재발 방지 `scripts/test-native-upload.mjs`(구문 트리, `test:mock`이 글롭으로 모음):
  1. `fetch(…, { body: FormData })` 금지 → postForm.
  2. FormData에 `{uri}`·펼치기 객체 직접 붙이기 금지(upload.ts만 예외) → appendFile.
  3. 직접 `fetch(` 허용 목록: client.ts·formPost.ts·privatePhoto.ts.
  4. expo-image-picker를 쓰는 파일은 pickedImage를 쓰고 결과 mimeType·fileName 직접 읽기 금지(영상 두 줄만 허용).
  - expo/fetch `convertFormData.ts`를 Node에서 그대로 돌려 `{uri}` 파트가 거절되고 문자열·Blob·bytes() 파트는 되는 것을 고정한다(Expo가 바뀌면 이 테스트가 알려 줌).
  - origin/main 스냅샷에서는 업로드 네 곳(규칙 1)과 picker 세 파일(규칙 4)이 걸린다.

### 기록
- 11/26 확인 환경: AVD `Medium_Phone`(Android 37.1 이미지), 제출 APK(`farmclub-*-2026-11-25.apk`, versionCode 8)의 `assets/index.android.bundle`만 `EXPO_PUBLIC_API_MOCK=0 npx expo export --platform android` Hermes 번들로 바꾸고 임시 키로 다시 서명. 로컬 서버(`APP_ENV=local`, DB `farmclub_dev493`, 자료 분석 mock 제공자, 워커 실행), 로컬 전용 아이디 계정(시드 u-kang·u-minji에 로컬 비밀번호). 운영 서버에는 붙지 않았다.
  - 한계 1: 릴리스 APK는 평문 HTTP를 막는다(targetSdk 36, cleartext 설정 없음). 시험 APK만 바이너리 매니페스트의 `fullBackupContent` 속성을 `usesCleartextTraffic=true`로 바꿨고, `adb reverse`로 `http://localhost:8000`에 붙였다(서버가 사진 주소의 호스트를 자기 주소로 검사해서 10.0.2.2로는 프로필 저장이 400). 운영 APK는 HTTPS라 이 차이는 업로드 경로와 무관하다.
  - 한계 2: 이 에뮬레이터 이미지(API 37)에서는 제출 APK의 실제 사진 선택기가 고른 뒤 `ExceptionInInitializerError`로 거절한다(quality 1로도 같음, JS 번들과 무관한 네이티브 쪽). 심사 기기에서는 선택까지는 됐다(반려 문구가 업로드 단계의 것). 그래서 시험 번들에서만 `expo-image-picker`의 `launchImageLibraryAsync`를 대역으로 바꿔, 로컬 시험 서버에서 받은 파일을 앱 캐시에 두고 Android quality 0.8 결과와 같은 모양(출력 uri, 원본 mimeType·fileName)을 돌려주게 했다. 업로드 함수·FormData·XHR·서버 처리는 실제다. 실제 선택기 → 업로드는 실기기 확인이 남는다.
  - 11/26 정정(DEV-494): 한계 2의 원인은 에뮬레이터가 아니라 시험 APK 재포장이었다. 서명을 지우며 `META-INF/*` 전체를 지워 `META-INF/services/…BuiltInsLoader`가 빠졌고, 선택 결과를 JS로 바꾸는 kotlin-reflect가 초기화에 실패했다(jdb로 확인). 서명 파일만 지운 시험 APK로 Android 35 에뮬레이터에서 실제 선택기 → 업로드(JPEG·PNG·HEIC·WebP)를 확인했다.
  - 수정 전(origin/main + 대역): 새 상품 → 대표 사진 → "사진을 변경하지 못했어요…" + 오류 줄 `Unsupported FormDataPart implementation`(반려 화면과 같음), 서버에 업로드 요청 없음.
  - 수정 후: 새 상품 대표 사진(JPEG·HEIC) `POST …/sources` 201 → `PUT …/representative` 200 → 비공개 사진 표시, 상품사진 추가(PNG) 201, 자료 파일 추가(WebP 이름의 JPEG) 201, 품종 → AI로 채우기(워커 mock) → 초안 → 상품명 → 다음: 판매·가격(초안 반영 200) → 중량·받는 시기·환불 날짜·가격·배송비·물량 → 판매 시작 요청(`capacity-requests` 200) → 상품 목록. 상품 수정(판매 중) 대표 사진(WebP) 201·200 "대표사진 수정됨", 사진 추가(HEIC) `/api/media` 201. 농가 프로필 사진 JPEG·PNG·HEIC·WebP 모두 `/api/media` 201 → `PATCH /api/farms/me` 200. 소식 영상 89MB `/api/media` 201, 올리는 동안 앱 PSS 약 187MB로 그대로.
- 11/26 fingerprint(`expo-updates fingerprint:generate --platform android`): 농가 `0a8bf0cf096def06a25d9c7bf2db9d4460d6a3f9`, 소비자 `9c96d63c1cd38b2e302b8a2bd395c38e1b697c11`, main과 같다(JS만 바뀜).
