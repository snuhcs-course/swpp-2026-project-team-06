## DEV-134 데모 시나리오 한 곳 관리와 record·stitch·site·publish 명령

- 이슈: [DEV-134](https://linear.app/sswp6/issue/DEV-134) · GitHub #267
- 브랜치: `nemodleo/dev-134-demo-scenario-commands`
- 기능·인수 조건: 없음(평가용 데모 도구). 영상이 보여 주는 기능은 `demo/spec.md`
- 선행: DEV-133(데모를 main `demo/`로 옮김, 완료). 기준은 I2 때 만든 것(`story.mjs` 구간 p1~p4·a1~a2·c1~c3, `videos.mjs`, `site/**`)

### 목표
영상을 다시 만들 때 손으로 하던 일(구간 이어 붙이기·앱별 자르기, 사이트 단계 목록·길이 옮겨 적기, 로컬·운영 전환)을 시나리오 한 곳 + 명령으로 바꾼다. I3·I4·Final마다 시나리오가 바뀌어도 명령으로 다시 만든다.

### 결정 사항
- 11/06 이름: `demo/scenario.mjs`(이슈 가칭 그대로), 명령은 `demo/cmd/{record,stitch,site,publish}.mjs` + 공용 `demo/cmd/lib.mjs`. `demo/record/`(녹화 스크립트)·`demo/site/`(사이트) 폴더와 이름이 겹치지 않게 한 폴더로 묶음. 길이 기록은 `demo/manifest.json`(커밋)
- 11/06 시나리오 모양: 구간마다 `story`(전체 흐름 페이지 한 줄: 제목·설명·FEAT ID 배열)와 `steps`(앱 페이지 단계: 제목·설명·FEAT ID 배열 + 그 단계의 녹화 자막 `captions`). 역할은 구간 이름 첫 글자(p/a/c). 사이트 문구는 자막보다 짧게 다시 쓴 글이라 같은 자리에 둘 다 둔다(한 파일, 한 번씩). 자막은 지금 `story.mjs` `cap()` 인자와 글자까지 같게 옮겼다(`{farm}`·`{product}`는 녹화 때 채우는 이름)
- 11/06 **#466(DEV-181) 열려 있음 → `story.mjs`는 고치지 않음.** 대신 `demo:site`가 `story.mjs`의 `cap()`을 읽어 시나리오 자막과 다르면 경고한다(지금 main 기준 차이 0). 테스트는 실제 `story.mjs`·`site/**` 대신 작은 고정 HTML·소스로 해서, #466이 자막·사이트를 바꿔도 CI가 깨지지 않게 함. **후속: #466 머지 뒤 시나리오에 I3 구간(p5·c4 등)을 넣고 `story.mjs`가 `cap()` 문구를 `scenario.mjs`에서 읽게 바꾼다**
- 11/06 앱 영상은 전체 영상을 자르는 대신 같은 역할 구간을 원본에서 바로 이어 만든다(결과가 같고 인코딩이 한 번). I2 영상도 앱 영상 길이 합 = 전체 길이(29.57+112.9+152.07 = 294.53초)라 같은 방식이었음을 확인
- 11/06 stitch는 concat 필터로 다시 인코딩(libx264 crf 18, 첫 구간 크기로 맞춤, 30fps, 소리 없음). webm(기본 녹화)·mp4(`DEMO_HQ`)가 섞여도 이어진다. 시스템 ffmpeg만 쓰고 없으면 설치 안내 오류
- 11/06 길이 표기는 반올림 m:ss(I2 실제 길이 294.53s → 4:55, 112.9s → 1:53으로 지금 표기와 같음). I2 `manifest.json`은 Release `demo-i2` 영상을 `--measure`로 잰 값
- 11/06 `demo:site`는 손으로 쓰던 자리만 바꾼다: 흐름 목록·단계 목록(`<ol>`), 영상 길이, 전체 흐름의 앱별 카드 길이, 하단 문구(iteration 이름이 들어 있어서). 제목·소개 문단·스타일은 그대로. 자리를 못 찾으면 멈춤. I2 시나리오로 다시 만든 결과는 지금 사이트와 한 곳만 다름: 전체 흐름 a1 ID `FEAT-01 · DEV-82·83` → `FEAT-01 · DEV-82 · 83`(전체 흐름 ID 줄임 규칙 하나로 통일). 이 변경을 커밋해 `--check`가 통과하게 함
- 11/06 `demo:record`: `--target local`(기본)은 `npm run demo`와 같은 `DEMO_*_PORT`로 주소를 정하고 로컬 주소가 아니면 멈춤, 관리자 구간은 `ADMIN_WEB_PASSWORD` 필수(없으면 story.mjs가 5분 기다림), API `/health`가 안 닿으면 `npm run demo` 안내. `--target prod`는 운영 주소 + `DEMO_KAKAO=1`, `DEMO_PROFILE`과 `--yes`가 있어야 돈다. `make`에는 운영 녹화 타깃을 두지 않음(Makefile 규칙: 운영 명령 없음)
- 11/06 `demo:publish`: 이슈는 R2 `demo/<iteration>/`였지만 DEV-133에서 GitHub Release + 배포 때 받기로 결정했으므로 그 흐름(`videos.mjs upload`)을 감싼다. 태그 기본값 `demo-<iteration>`. 올리기 전에 영상이 다 있는지, 길이가 manifest와 같은지(0.5초 안), 새 태그면 영상 4개가 다 있는지 본다. `--dry-run`은 명령만 보인다. `make demo-publish`는 `CONFIRM=1`이 없으면 dry-run
- 11/06 **iteration 탭은 후속으로 뗌.** 지난 iteration 영상을 남기려면 Release 여러 개를 배포 때 받고(`videos.mjs fetch`·`deploy-demo` job = 고위험 경로 `.github/workflows/**`), 사이트를 iteration별 경로로 나누는 구조 변경이 필요하다. I3 영상(#466)이 올라갈 때 같이 정하는 게 맞음
- 11/06 Makefile이 150줄이라 규칙대로 `make/demo.mk`로 나누고 루트에 `include make/*.mk` 한 줄만 더함
