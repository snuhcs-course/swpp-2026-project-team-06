### 결정 사항
- 11/25 업로드 방식은 git(기본)으로 하고 `make apk`가 작업 트리가 깨끗한지 먼저 본다. eas-cli 27.11 코드와 `build:inspect` 확인 결과:
  - `eas.json`에 `requireCommit`이 없으면 git 방식도 깊이 1 클론 뒤 작업 트리를 그대로 복사한다. 커밋 안 된 변경·새 파일이 둘 다 묶음에 들어간다(새 파일을 두고 inspect해 확인). 그래서 "git 방식 = 커밋된 코드만"은 틀렸고, 어느 방식이든 깨끗한지 검사가 필요하다.
  - `.easignore`에 `.git`(끝 / 없이)을 쓰면 git 방식에서도 `.git`이 빠져 `EAS_NO_VCS=1`과 파일 목록이 같다(1199개, 47MB). `.git/`로 쓰면 빠지지 않는다(eas-cli가 `ignores('.git')`로만 본다).
  - git 방식은 빌드 페이지에 커밋이 남고 NO_VCS 경고가 없다. `requireCommit: true`는 `eas.json`(고위험, fingerprint에 들어감)을 고쳐야 해서 쓰지 않는다.
  - `make apk`는 셸의 `EAS_NO_VCS`를 지우고 실행한다.
- 11/25 `.easignore`가 있으면 eas-cli는 `.gitignore`를 하나도 안 읽는다. 하위 폴더 `.gitignore`(apps의 `*.jks`·`*.p12`·`*.key`·`*.pem`·`.env*.local`, `.vercel` 등)를 2절에 옮겼다. 사용자가 손으로 만든 목록에는 이것들이 빠져 있었다(서명 키를 앱 폴더에 두면 올라갈 수 있었음). `scripts/test-easignore.mjs`가 모든 `.gitignore` 줄을 대조한다.
- 11/25 `/server`는 `tests`·`migrations`만 뺀다. `packages/api/src/sourceTextSafety.ts`가 `server/app/source_analysis/text_safety_lists.json`을 import한다. `server/` 나머지는 5MB라 더 쪼개지 않는다.
- 11/25 `make eas-env`는 `eas env:list --format short`의 `NAME=` 앞부분만 쓰고 값은 버린다. eas가 실패하면 오류 출력도 `=` 뒤를 가린다. 필수·경고 목록은 `app.config.js`의 `checkStoreBusinessInfo`를 불러 고른다(WARN_ONLY는 export되지 않고, 그 파일을 고치면 fingerprint가 바뀔 수 있어 고치지 않음). 값이 공백뿐인지는 이름만으로 알 수 없어 보지 않는다.
- 11/25 `make apk`에 `DRY_RUN=1`(검사와 명령만 보임)을 넣었다. 빌드마다 versionCode가 오르므로 검사만 해 볼 길이 필요하다. 추가 인자는 `EAS_ARGS`(예: `--no-wait`).
- 11/25 "어느 폴더에서나": make는 현재 폴더의 Makefile만 읽고, 루트 Makefile의 `include make/*.mk`가 상대 경로라 `make -f ../../Makefile`은 원래 안 된다. 레시피는 `git rev-parse --show-toplevel`로 루트를 찾고, 하위 폴더에서는 `make -C "$(git rev-parse --show-toplevel)" apk`로 부른다(README).
- 11/25 CI 분류: `.easignore`는 apps job(그 안의 `test-easignore`)을 켜고 integration은 없음. `scripts/eas.mjs`도 integration 없음. `make/**`는 `Makefile`처럼 문서 묶음. 이전에는 둘 다 모르는 경로라 전체를 돌았다.
